## 必要成本与减重结论

分类页新增的能力集中在 `useMappingLinkLayout`：暂存身份顺序与几何尺寸、关闭后恢复参照，以及外部 pointerdown/click 之间的目标保护。应用和网页使用同一个 feature owner；没有复制关联数据、引入第三方库、增加图片或字体。网页原来独立的延迟聚焦回调已删除，避免重复生命周期。通用 popover 仅报告既有关闭事件的原因，其他消费者保持原来的关闭流程。

该能力必须在关联弹层打开和关闭时同步可用。单独懒加载会给首次点击增加等待，拆成支持 chunk 只会转移归属、增加请求；将它放到启动图则让其他页面承担分类页成本。因此保留在 AppMapping 的现有懒加载边界。没有修改原生追踪、SQLite 或启动暖机路径。

History 与 Data 的增量来自此前用户确认的匿名图标、摩斯码名称及交互限制。共享图标与名称已有单一实现，普通应用仍沿用现有图标。更改为图片、额外字体或复制 SVG 都不能减少维护与加载成本；无需为了几十字节移走所属页面的匿名交互判断。

新预算相对必要实测值分别保留约 3.91%、3.33%、3.42%，未超过 feature chunk 10% 缓冲上限。启动入口、公共依赖、CSS、语言、总产物与其他页面预算均不放宽，也不修改运行时性能或测试阈值。
