# 关联操作时卡片与弹层位置稳定执行方案

> 状态：已完成并归档；适用项已勾选，诊断收敛与验证边界见第 9 节。
> 创建日期：2026-10-10
> 执行 owner：分类页前端与其浏览器回归测试。
> 完成条件：真实关联操作的定位稳定、草稿语义正确、必要验证通过，审查后勾选并归档。

## 1. 目标与范围

用户在分类页连续添加或取消关联时，应能继续使用原来的操作位置，不必重新寻找主卡片、搜索框或按钮。关系、成员列表和计数立即反映最新草稿；外层列表在关联弹层关闭后再统一整理。

应用关联是本任务的直接修复范围。网页独立显示、合并回主域名作为相关消费者检查：复用相同的列表位置保护规则，但保持网页自己的身份、分组和关闭流程，不把两类业务合并成一个状态机。

本任务不改变关联规则、持久化格式、统计归属、保存与取消含义，不改分类页视觉方向，不新增拖拽排序、虚拟列表或全局滚动管理器。动画不是首轮交付前提。

用户已授权实施、勾选归档和完成后的对抗式审查。提交与推送仍按 [AGENTS.md](../../AGENTS.md) 的外部动作授权规则另行处理。

## 2. 从第一性原理推导行为

### 2.1 操作需要稳定的空间参照

用户记住的是“鼠标下这个按钮”和“眼前这张卡片”。关联一个成员并不意味着用户想浏览其他位置。数据结构更新与浏览位置变化是两个独立结果，应分别管理。

双列网格中，移除一个前置元素会改变后续元素的序号；序号奇偶变化会交换左右列，每移除两个元素还可能改变一整行。只固定 `scrollTop` 无法阻止这种重排。

**结论：弹层打开期间稳定的是卡片槽位与操作锚点，不能只保存一个滚动数值。**

### 2.2 事实必须实时正确，排版可以稍后整理

已有草稿是关联关系的唯一事实来源。点击关联后，成员关系、按钮状态、计数、脏状态应立即更新；延迟写入草稿会使连续操作、保存与取消难以解释。

可以短暂保留的是显示顺序和卡片占位，不是第二份可编辑的关系数据。

**结论：记录弹层打开时的身份顺序和布局信息；每次渲染仍从最新草稿读取有效卡片。**

### 2.3 焦点、滚动、弹层定位必须配合

焦点用于键盘操作，不应顺带要求浏览器滚动。弹层需要跟随真实锚点，但不应因为成员减少一行就在上下方向来回切换。用户主动滚动、改变窗口尺寸与程序整理列表必须分清。

**结论：取消非必要焦点滚动；在空间允许时保持本次弹层方向；需要整理列表时先结束弹层会话，再做滚动补偿。**

### 2.4 动画不能代替位置正确性

即使卡片以平滑动画移动半屏，用户仍会失去目标。应先消除不必要的重排和跳滚，再判断关闭弹层后的轻微归位是否值得动画。

**结论：首轮使用稳定位置与一次性整理；只有仍存在可感知的归位突兀时才追加短过渡，并支持减少动态效果。**

## 3. 当前证据与待确认根因

| 观察 | 源码依据 | 目前能得出的结论 |
| --- | --- | --- |
| 关联立即改变草稿 | `useAppMappingState.ts` 的 `handleAppLink` | 列表变化发生在保存之前，属于当前交互链 |
| 分组会减少或增加外层卡片 | `groupLinkedAppCatalog` 与 `useAppMappingDerivedState.ts` | 分组结果随草稿重新派生，并重新筛选、排序 |
| 卡片使用稳定身份作为 key | `AppMapping.tsx` 的 `candidate.exeName` | 不能简单把症状归因于数组索引 key |
| 内容面板 key 是对象模式与筛选条件 | `AppMapping.tsx` 的 `contentPaneKey` | 正常关联不应靠重建整个面板才能生效；仍需实际观察挂载情况 |
| 添加与取消关联后直接调用 `focus()` | `LinkedAppMenu.tsx` | 存在浏览器自动滚动的可能，尚未证明是主要原因 |
| 弹层逐帧读取锚点坐标 | `QuietAnchoredPopover.tsx` | 卡片位移会传递给弹层；内容高度变化可能改变上下方向 |
| 外层滚动会关闭弹层 | `QuietAnchoredPopover.tsx` 的 scroll listener | 滚动补偿不能在弹层存活期间随意执行，否则可能造成意外关闭 |
| 网页操作已有独立的焦点恢复 | `LinkedWebMenu.tsx` 的 `focusWebCard` | 不应直接把应用的连续添加流程套到网页上 |

以上属于代码证据，不是运行时根因定论。用户截图来自不同操作位置，不能据此计算同一张卡片的位移量。

- [x] 初查应用关联、分组派生、卡片 key、弹层定位与焦点恢复链路。
- [x] 通过可重复浏览器场景确定重排、自动滚动、排序与弹层翻转各自的贡献。

## 4. 交互契约

| 场景 | 必须发生的行为 |
| --- | --- |
| 打开关联弹层 | 建立一次临时展示会话；记录主卡片身份、当前顺序、主卡片与滚动视口的相对位置 |
| 添加成员 | 最新草稿立即生效；成员按钮变为已添加；外层不立即填补被合并卡片的槽位 |
| 取消成员关联 | 最新成员列表立即移除该成员；新的独立卡片在弹层关闭后进入外层列表 |
| 连续添加、解除、重新添加 | 使用同一会话；主卡片不换列、不跳行；始终按最新关系判定可用操作 |
| 被合并的旧卡片 | 原槽位保留几何尺寸，但不显示可误认的旧卡片内容；占位不接收鼠标与键盘、不进入读屏树 |
| 当前主卡片 | 使用最新名称、成员状态和控制状态，不冻结成旧数据；名称变化不能撑高卡片 |
| 关闭弹层 | 立即用最新草稿恢复正常筛选和排序，移除占位，再补偿浏览位置 |
| 点击另一个关联入口 | 关闭旧弹层，沿用原槽位打开新弹层；本次点击始终指向用户按下时的身份，最后关闭后再整理 |
| 切换搜索、筛选、应用/网页 | 结束旧会话，采用新视图自身的定位规则，不向新视图恢复旧坐标 |
| 用户主动滚动外层列表 | 沿用现有关闭行为；不通过补偿把用户拉回原来的位置 |
| 滚动弹层内的候选列表 | 不关闭弹层，不影响外层滚动位置 |
| 保存、取消、离开页面 | 先结束临时展示会话，不遗留占位；按各自已有数据契约执行 |

临时槽位只维持到弹层关闭，不拖延到保存。顶部数量始终表示真实草稿中的有效卡片数，不把占位计为应用。

### 4.1 关闭后的定位规则

1. 主卡片仍存在：优先维持它相对滚动视口的纵向位置；正常排序可能改变左右列，不承诺关闭后横坐标永远不变。
2. 主卡片消失：优先选择操作前最近的仍存在卡片；没有可用参照时，钳制到合法滚动范围。
3. 网页独立或合并使来源卡片消失：以真实目标卡片或最近存活卡片为参照，不重新聚焦已卸载节点。
4. 内容不足一屏或接近底部：允许由新最大滚动值导致的必要位移，禁止反复补偿与回弹。
5. 用户主动滚动、切换视图或更改窗口尺寸后，不再应用旧会话的补偿。

### 4.2 弹层的几何规则

- 同一次弹层会话在空间允许时保持打开方向。
- 成员列表增减优先由内部滚动承接，避免操作控件因外层高度突变来回移动。
- 从成员视图进入添加视图是明确的视图切换，可重新计算所需高度；之后连续添加应保持搜索框位置稳定。
- 窗口变小、缩放变化或锚点确实不可见时，允许重新定位或按既有规则关闭，以不溢出窗口为优先。
- 不固定屏幕绝对坐标来掩盖锚点变化，不使用任意延时等待布局完成。

## 5. 实现 owner 与状态边界

| 责任 | 主要落点 | 边界 |
| --- | --- | --- |
| 关联关系与保存草稿 | `useAppMappingState.ts` 及既有服务 | 保留唯一事实来源，不新增展示专用 appLinks 副本 |
| 筛选、排序、分组 | `useAppMappingDerivedState.ts` 及既有服务 | 正常结果照常计算，不篡改排序规则来固定位置 |
| 临时展示顺序、占位、滚动参照 | classification feature 内的 hook/局部服务 | 可供应用与网页列表复用布局机制，不进入全局 store，不持久化 |
| 页面编排 | `AppMapping.tsx` | 连接真实列表、临时展示列表与菜单，不承接全部生命周期细节 |
| 应用弹层操作与焦点 | `LinkedAppMenu.tsx` | 明确打开、关闭、视图切换和连续操作通知；保留业务控制 |
| 网页操作与目标焦点 | `LinkedWebMenu.tsx` | 保留 exact domain 与组身份语义，按自己的操作结束会话 |
| 通用弹层定位 | `QuietAnchoredPopover.tsx` | 仅在证据表明共享定位契约需要改动时修改，并复验真实消费者 |
| 卡片布局与样式 | 分类页既有 CSS owner | 复用现有卡片高度、列布局与滚动区域，不复制滚动条实现 |

建议的会话信息限于：会话标识、对象模式、视图条件、主身份、打开时的身份顺序、参照卡片与其相对位置、结束原因。DOM 引用保存在 ref；有效卡片内容从最新派生结果读取。

只读调查完成后再确定是否需要独立 hook。不能为了执行单预先建立一套通用事务框架。身份稳定与布局补偿应有唯一 owner，不能应用、网页各复制一份。

## 6. 详细执行步骤

### 阶段 A：固定基线与复现

- [x] 记录 HEAD、工作树差异和当前依赖状态，区分已有匿名展示改动与本任务改动，不覆盖其他工作。
- [x] 核对当前 `package.json` 的验证命令。此前匿名展示迭代曾出现 Data 包体积门槛失败；重新确认当前状态，不把旧结果直接视为本任务基线。
- [x] 在现有 browser smoke stub 中准备足够让双列列表滚动的数据，至少覆盖前三屏与末屏。
- [x] 选择位于列表中间的主项，分别关联位于其之前、之后、同屏和屏外的成员。
- [x] 分别解除一个成员、连续解除多个成员，以及解除最后一个成员；保持搜索、筛选状态可控。
- [x] 在操作前与后续连续帧采集卡片、搜索框矩形、`scrollTop`、DOM 连接与弹层存在状态；分阶段断言菜单矩形、焦点、滚动边界和真实卡片集合，不依赖截图推测位移。
- [x] 观察主卡片与菜单是否真的卸载重建，区分身份丢失与单纯布局位移。
- [x] 已收敛诊断范围：旧实现的逐帧记录证明重排、滚动与关闭连锁发生；不再分别量化普通 `focus()` 与原生滚动锚定的贡献，避免将未隔离的因素宣称为单一根因。
- [x] 用已有断言或新增失败断言证明至少一个真实跳动场景在修改前可失败，记录根因结论与对应 owner。

阶段出口：能够指出第一处不必要位移来自哪里，而不是仅凭截图猜测。

### 阶段 B：建立临时展示会话

- [x] 在分类页 owner 内管理当前唯一的关联展示会话，协调菜单打开与关闭，避免多个菜单各自冻结列表。
- [x] 打开时记录完整身份顺序与主卡片参照；只记录必要标识与几何数据，不深拷贝完整应用目录。
- [x] 弹层存活期间按记录顺序渲染存活卡片，卡片属性实时读取最新草稿派生结果。
- [x] 对已经合并掉的卡片渲染等尺寸不可交互占位；从 Tab 顺序、读屏树和鼠标事件路径中排除。
- [x] 新独立卡片延迟插入；连续“解除→重新关联”后不留下重复 key、重复卡片或失效占位。
- [x] 保持当前主卡片的 key、所在列和行高；禁止通过改变祖先 key 强行刷新菜单。
- [x] 验证计数、成员按钮、可关联候选、未保存标记始终反映真实草稿，与临时占位相互独立。

阶段出口：弹层内连续操作不会改变主卡片的可见位置，数据状态仍立即正确。

### 阶段 C：整理列表与恢复浏览位置

- [x] 为关闭动作区分原因：完成/关闭、切换入口、主动滚动、筛选切换、保存/取消、页面卸载。
- [x] 普通关闭时记录最后有效参照，结束弹层，再恢复真实列表；在布局提交阶段完成一次纵向补偿。
- [x] 补偿量按参照卡片实际位移计算，并钳制到新的滚动范围，不机械写回旧 `scrollTop`。
- [x] 以取消待执行帧和移除监听器拒绝过期关闭，普通补偿在布局提交阶段同步完成；卸载、再次打开或切换模式后不得执行旧补偿。未额外引入并行的 generation 状态。
- [x] 保证列表整理引起的滚动不与仍存活的 popover scroll listener 互相触发。
- [x] 分类场景验证外层实际滚动后不恢复旧位置；原生键盘与滚动条能力由共享滚动区域回归覆盖，未另做每种物理输入设备的手工录制。
- [x] 处理鼠标点击外部控件造成的关闭：不得在 pointerdown 与 click 之间移动目标并导致误点另一张卡片。
- [x] 实测点击另一个菜单入口、保存、取消、搜索框和筛选按钮，确保本次动作仍落到正确对象上。
- [x] 验证底部卡片数量减少时只发生必要的范围钳制，不出现连续回弹。

阶段出口：关闭后列表准确收拢，用户不丢失浏览参照，外部点击不会被重排改变目标。

### 阶段 D：焦点与弹层稳定

- [x] 为添加后搜索框、解除后后续操作入口的焦点恢复使用禁止滚动的方式，并确认目标仍存在。
- [x] 焦点目标被禁用或移除时，选择当前视图中稳定、可操作的入口，不聚焦旧 DOM。
- [x] 验证成员列表长度改变时的弹层方向与高度；优先在 LinkedAppMenu 的内容布局中消除无谓高度变化。
- [x] 若确需共享弹层能力，使用有明确默认值的定位契约；记录对既有消费者的影响，不复制另一套 popover。
- [x] 覆盖搜索框编辑、连续添加、解除最后一个成员、返回成员视图、Escape 和外部点击关闭。
- [x] 对其他 QuietAnchoredPopover 消费者运行必要回归，确保窗口边缘避让、焦点恢复与卸载清理仍成立。

阶段出口：不靠固定延迟或强制滚动维持位置，键盘和鼠标都能连续操作。

### 阶段 E：网页、保存与异步边界

- [x] 检查网页独立显示与合并入口的实际关闭时机，避免套用应用“保持添加菜单”的规则。
- [x] 为网页受影响列表采用相同参照补偿机制；组消失、成员成为独立卡片时按真实目标恢复浏览位置。
- [x] 保存成功后保持当前浏览参照；保存失败仍能继续编辑或取消，不冻结在过期展示会话中。
- [x] 取消草稿时恢复已保存关系，并清理临时占位与菜单状态。
- [x] 目录异步扩展、刷新或名称变化期间使用当前会话规则；菜单关闭后按最新目录整理，禁止旧结果复活已合并卡片。
- [x] 搜索或筛选导致主卡片不再满足条件时，先正常结束会话，再切换结果，不把不符合条件的卡片永久保留。
- [x] 页面卸载后无残余监听器、frame 回调、portal、冻结标志或滚动恢复动作。

## 7. 验收矩阵与可观察标准

| 维度 | 必测组合 |
| --- | --- |
| 操作 | 添加、连续添加、解除、连续解除、解除后重加、解除最后一个成员 |
| 成员位置 | 主项前/后、同屏/屏外；前置数量变化为奇数和偶数 |
| 列表位置 | 顶部、中部、底部、内容由可滚动变为不足一屏 |
| 布局 | 当前支持的单列与双列宽度，100%/125%/150% 缩放 |
| 弹层 | 上方/下方打开，短/长候选列表，搜索有结果/无结果，成员与添加视图切换 |
| 输入 | 鼠标、键盘、滚轮、滚动条拖动、Escape、外部点击 |
| 视图 | 全部/已分类/未分类/匿名筛选、搜索、应用与网页切换 |
| 异步 | 保存成功/失败、目录迟到结果、菜单打开时刷新、卸载后回调 |
| 可访问性 | 长名称、多语言、浅色/深色、减少动态效果、焦点可见且无隐藏占位可聚焦 |

- [x] 窗口和外层滚动均未主动变化时，从点击开始到布局稳定的每个采样帧，主卡片横纵坐标漂移不超过 1 CSS px；不能只在最终帧相同。

### 9.1 复现与落点

修改前，同一真实浏览器场景记录主卡片从 `(609, 431)` 移到 `(182, 531)`，外层 `scrollTop` 从 849 变成 749，随后弹层因外层 scroll 关闭；卡片 DOM 始终保持连接。这证明稳定 key 不能解决分组后网格重排和滚动事件的连锁影响。新增几何断言在旧代码上失败。

`useMappingLinkLayout` 仅持有身份、尺寸与临时参照。最新草稿仍直接决定计数、成员和卡片内容。缺失身份渲染无内容、无焦点目标的占位；新身份在会话结束后插入。关联菜单的列表高度按视图进入时的实际尺寸保留，内部滚动接收内容变化；返回成员视图时重新测量。没有新增动画或第二份关联关系。

关闭后的纵向补偿在 `useLayoutEffect` 中完成。外部 pointerdown 先隐藏弹层，保持槽位到 click 处理结束；转到另一关联入口时沿用槽位，取消旧监听和待执行帧。主动滚动不回拉，视图变化与窗口 resize 清理会话。网页在操作前记录来源位置，提交后将实际目标卡片放在该参照附近并恢复焦点，受合法滚动范围限制；删除了原来独立的延迟聚焦回调。

### 9.2 审查与实施偏差

- 没有为共享 popover 增加固定方向策略。局部列表高度稳定后，连续操作不再触发无谓翻转；共享组件只补充关闭原因，位置计算保持原实现。
- 不在两个关联入口切换之间整理网格，避免已按下的目标移动或新弹层立即跟着重排；全部菜单关闭时再统一整理。
- 普通补偿没有异步帧，因此不需要额外会话序号。唯一的 pointerup 兜底帧在切换、resize、取消及卸载时显式取消。
- 审查修正了同一行参照排序的歧义，确保主卡片优先于同高的邻居；补充了保存失败、迟到目录、网页组消失和真实外部点击用例。
- 最终复验发现 resize 通知可能晚于新菜单打开。会话现在记录打开时的 viewport 尺寸，忽略已经适应的同尺寸通知；真实尺寸变化仍关闭旧会话。追加回归验证这一时序，原失败的网页操作场景也重新通过。
- 当前卡片因筛选消失且焦点落回 body 时，恢复到页面搜索框；实测关闭 portal、清除占位和焦点归属。最终审查无未解决的可操作缺陷。
