# 切页流畅度与资源稳定性执行记录

2026-11-21 完成并归档。Windows GPUI 开发构建已完成两组反向短测和两组各 12 小时的驻留复验。大目录场景的前台静置私有提交减少 91–99 MiB，分类热切换与历史拖动更快。普通数据详情首开和工作集的代价见[最终对照](#最终构建的两组反向对照)。

用户点击后应立即看到选择反馈，目标页第一次出现时就能读、能操作。切换过程中保持原有排版，消除白屏、空框、“加载中”和同一行图标先通用后换真的过渡。持续录制、草稿、键盘与无障碍操作都是验收的一部分。[窗口与录制架构](../architecture.md) · [Quiet Pro](../ui.md)

## 防止 CPU、内存和线程再次失控

- [x] **积压与取消。** 一次提交 128 个不同的远端键，连续 16 轮，观测到的待处理键峰值为 48。离页丢弃待返回项，执行器回到空闲后下一轮可用满名额。同键共享读操作。远端最多 4 路传输，本地后台解码最多 2 路，远端失败后 60 秒才重试。传输超时为 8 秒，收到取消后保留名额直到操作实际返回。卡住的传输会占用自己的名额，避免重试不断创建工作。离页时每页派生图标至多保留 256 项、8 MiB 键与图像逻辑字节，分类规则原始数据和图形驱动分配另计。1,024 个空结果离页后保留 256 个，淘汰 768 个。实际网络取消的耗时随系统返回而变，8 秒是发出取消的期限。[队列与缓存](../../apps/patina-ui/src/features/source_icon/cache.rs) · [分块传输与取消](../../apps/patina-ui/src/features/source_icon.rs)
- [x] **重复访问与不断出现的新键。** 固定负载八轮，新增键负载二十组，两种访问顺序均已完成。新增键场景的 UI 静置私有提交分别减少 91.3、98.8 MiB，线程、句柄在两组中有小幅双向波动。容量、淘汰、回访像素见图标与积压用例。大数据停手后整树仍用单核约 8%–9%，两对均未出现随轮数持续抬升的资源曲线。[新键路线](../../apps/patina/tests/pages/foreground_churn.rs)
- [x] **托盘与录制。** 常规及新增键路线中，关掉最后一个测试窗口后原 UI PID 均已退出。重开产生新 PID，可读到当日活动，同一会话的录制时间推进，正常退出时数据库已封口。工具计时可在托盘完成并从通知启动一次短休息。两种路线的常驻成本分别记录，久置另行复验。[进程生命周期](../architecture.md) · [资源验收口径](../quality.md#性能与资源生命周期)
- [x] **久置后复查。** 前台与托盘各实际驻留 12 小时，在原有进程与临时数据库上观察 720 次录制心跳。前台滚动和切页成功。两个窗口重开后均可读到当日活动，分别继续采样 210 秒，正常关闭并确认数据库已写入会话结束时间。[两组驻留结果](#12-小时驻留与重开)
