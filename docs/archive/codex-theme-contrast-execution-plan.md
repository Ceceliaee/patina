状态：已完成并归档。完成日期：2026-09-09。

## 1. 结果与范围

保留 Patina 当前外观设置、浅色/深色主题弹窗、配色卡片和确认/取消流程。只在主题弹窗标题区域右侧增加“对比度”滑条及当前数值，位置对应用户提供的 Patina 截图红框。颜色按指定版本 Codex 的实际派生规则生成，接入 Patina 已有语义变量。

用户已明确：默认采用各个主题自己的默认对比度。`0–100` 是滑条范围，不是默认值；不能把所有主题设为 40，也不能在切换主题后无条件沿用上一个主题的数值。

本次包含：

- 浅色、深色预设的基础颜色、默认对比度及必要的颜色派生。
- 当前模式对应主题的对比度预览、取消恢复、确认保存和启动恢复。
- 主窗口与 Widget 使用同一派生规则，已保存设置通过现有同步链路生效。
- 必要的共享颜色与组件状态映射、缺字段默认处理、行为测试及视觉验证。

本次不包含：

- 重做侧栏、页面布局、配色卡片、圆角、间距、字号、字体、图标、控件尺寸或动效。
- 复制 Codex 的完整界面、终端、代码高亮、技能专用组件或全部 CSS token。
- 增加主题 JSON 导入、导出、颜色编辑器、透明窗口开关或跨项目发布的主题包。
- 为另一个 StyleX 应用实现适配器；纯计算边界不依赖 Tailwind 即可。
- 修改 tracking 行为、发布版本、提交、推送、Issue 或 Project 状态。

本方案遵守 [架构规范](../architecture.md)、[Quiet Pro](../quiet-pro-component-guidelines.md)、[产品范围](../product-principles-and-scope.md)、[工程质量](../engineering-quality.md) 与 [本地化契约](../localization.md)。本文持有执行步骤和验证记录，长期规则仍由这些文档持有。

## 2. 从第一性原理确定边界

### 2.1 颜色相同需要输入、函数和合成条件相同

主题颜色可以表达为：`输出颜色 = 派生函数(预设参数, 明暗模式, 对比度)`。复制背景、前景和强调色只复制了输入。只要边框、次级文字或悬停背景的计算不同，界面层次就不同。

透明颜色还取决于它下面的背景。例如，半透明前景覆盖面板，与预先把前景混入页面背景，并不总是同一个颜色。因此既要保留颜色值，也要区分透明叠加与实色混合，核对组件实际使用的背景。

验收范围是“已映射主题颜色及其状态符合参考规则”，不是“Patina 整个界面逐像素等于 Codex”。组件几何继续保持 Patina；新增滑条导致的必要局部排列变化需要单独验证。

### 2.2 默认值属于预设，用户调整属于设置

每个 `(明暗模式, 配色标识)` 有自己的默认对比度。用户没有覆盖时，显示预设默认值；用户拖动后，显示该模式当前所选主题的覆盖值。

本方案采用最小状态模型：浅色和深色各保存一个当前主题及可选对比度覆盖，不保存所有历史主题的调整表。切换到不同主题时清除该模式的覆盖，采用目标主题默认值；再次点击当前主题不清除覆盖。若以后需要记住每个历史主题，应作为独立需求演进。

默认值不是通过观察“看起来差不多”决定。优先读取 Codex 预设显式值，其次使用该版本加载器实际继承的模式默认值。Patina 自有 default 等没有完全对应项的预设须明确记录映射决定，不能宣称存在未经核实的 Codex 原值。

### 2.3 预览不能成为持久化写入

拖动是高频、可撤销的视觉操作；确认是低频、持久的设置操作。两者分开，才能同时满足即时反馈、取消恢复和可靠保存。颜色计算本身不访问数据库、不发 IPC、不读取系统主题。

### 2.4 组件语义决定需要引入多少 token

以 Patina 的实际消费点选择颜色，不按 Codex token 数量复制。`--qp-*` 是现有组件契约；将参考颜色接到该契约即可。若一个现有变量同时承担多个不同状态、无法正确映射，才增加用途明确的变量并迁移对应消费点。

成功、警告、危险、参与状态与分类色由 Patina 的业务语义决定。不能仅因名称相似，就把 Codex 的 skill、diffAdded 或 diffRemoved 当作所有业务状态的通用颜色。

```text

                ↓

                ↓
现有 Quiet Pro CSS 与 Tailwind 组件
```

## 4. 行为契约

| 操作或条件 | 预期结果 |
| --- | --- |
| 首次使用、升级后缺少新字段 | 当前主题采用自身默认对比度，不写死为 0 或 40 |
| 打开当前主题弹窗 | 显示已保存或当前草稿中的覆盖值；无覆盖则显示该主题默认值 |
| 切换到不同配色卡片 | 该模式覆盖置空，滑条显示目标主题默认值 |
| 再次点击当前配色卡片 | 保持用户当前调整 |
| 拖动滑条 | 整数步长 1，范围 0–100；更新草稿和当前可见主题预览，不落盘 |
| 明暗独立 | 调整浅色不覆盖深色，调整深色不覆盖浅色 |
| 编辑非当前生效模式 | 编辑和保存该模式；不自动改变模式开关，当前窗口不会假装预览了另一模式 |
| 确认 | 当前模式的配色和覆盖值作为一个 patch 原子保存，其他设置草稿保持原样 |
| 仅修改对比度后确认 | 必须保存，不能被现有“配色标识未变化”判断跳过 |
| 取消、Escape、允许的遮罩关闭 | 恢复打开弹窗时该模式的配色和覆盖快照 |
| 保存进行中 | 禁止重复提交和编辑；关闭入口保持一致，不能边保存边撤销 |
| 写入失败 | 保留弹窗与草稿，显示已有错误反馈；不把草稿标记为已保存 |
| 落盘成功、运行时同步失败 | 按现有部分成功语义反馈；不得把已提交数据当作未提交而回滚 |
| 重启、Widget 重建 | 从已保存设置解析同样的对比度与颜色 |
| 系统明暗切换 | 切换到相应主题与相应覆盖值，避免沿用另一模式的缓存颜色 |

已新增 `themeContrastLight`、`themeContrastDark` 两个可空数值字段。`null` 表示使用预设默认值；数值表示用户覆盖。滑条调回默认值时规范化为 `null`，无须增加重置按钮。该表示避免把默认值复制为另一份持久化事实。

旧数据缺字段或读取到无效覆盖值时，恢复为默认语义；新写入拒绝非有限数、非整数及越界值。数值 0 是合法覆盖，不能用真假判断当成缺失。
