# 前台切页资源优化与短测

2026-11-21 已完成并归档。现场现象是前台刚打开约 60 MB，切过几页后约 300 MB，停止操作后仍处在高位。本轮在默认开发构建、独立配置和合成活动库中复现了切页后的增长。用户当时查看的任务管理器列及进程范围未知，以下沿用可复现的 Windows 计数器。

## 结果与取舍

A 是修改前的开发版。B 共享日期焦点、合并控件画布，并等工具面板就绪再切页。C 在 B 的基础上让热力格复用绘制轮廓。编号表示同一构建的不同测量轮次。

| 测量 | 初始今天私有提交 MiB | 切页后静置私有提交 / 工作集 MiB | 切页 CPU 单核 % | 空闲 CPU 单核 % | 热切换可读时延 p50 / p95 / 最大 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 11/20 A1 | 125.5 | 273.0 / 287.1 | 9.77 | 3.48 | 84 / 416 / 653 |
| 11/20 B1 | 126.0 | 264.1 / 281.6 | 8.55 | 2.57 | 48 / 275 / 299 |
| 11/20 B2 | 126.6 | 264.3 / 282.1 | 7.71 | 3.03 | 50 / 308 / 370 |
| 11/20 A2 | 125.9 | 272.6 / 285.8 | 8.93 | 2.97 | 48 / 386 / 414 |
| 11/20 C1 | 125.4 | 154.6 / 172.8 | 5.57 | 3.32 | 46 / 213 / 239 |
| 11/21 C2 | 120.0 | 152.0 / 170.6 | 4.65 | 0.78 | 37 / 209 / 246 |
| 11/21 A3 | 121.9 | 269.4 / 281.3 | 6.24 | 1.47 | 39 / 328 / 379 |

每行取同一个前台渲染进程。内存取各窗口的中位数，切页 CPU 取三分钟内的加权均值，空闲取静置末一分钟。单逻辑核满载为 100%。每轮路线包含七页及页内标签，冷访 11 次、热访 88 次。其中包含一次已经选中的总览按钮。时延从输入派发到 UI Automation 可读，包含自动化查询和轮询成本。

**保留 C。** 同日 A2 → C1 节省 118.0 MiB 静置私有提交，逆序 C2 → A3 的配对节省 117.5 MiB，两组均约 43%。暖机回访阶段的 CPU 分别降低 3.36、1.59 个单核百分点，可读时延 p95 分别缩短 173、119 ms。两次同日基线 A1、A2 自身相差 0.46 MiB、0.84 个单核百分点和 30 ms。静置 CPU 的差异方向随组别变化，不能给出稳定降幅。首次为同尺寸的热力格生成两张小遮罩，后续格子复用；工具首次打开仍须等面板返回，短测约 0.8 秒。

七轮静置末分钟的 UI 均为 45 个线程、87 个 GDI 对象、58 个 USER 对象。A2、C1 的内核句柄分别为 686、684，逆序两轮均为 686。没有观察到同一路线越走线程或句柄越多，因此保留录制、IPC 和渲染所需的并发。代表性的 A2、C1 在同阶段整树均为 89 个线程、94 个 GDI 对象、67 个 USER 对象。

- [x] **分离采样与操作。** 用宿主 PID 和创建时间跟踪进程树，以前台窗口确定 UI PID，单列宿主、前台及五类探测进程。驱动和采样器的 CPU 时间、私有提交、线程、句柄另存。首次 A1 缺少部分子进程角色旁证，这些行保留为未分类子进程。工作集整树相加会重复计入共享页。[进程采样器](../../apps/patina/examples/windows-resource-sample.rs)
- [x] **复跑并核验。** 先执行 A1 → B1 → B2 → A2，再以 A2 → C1 和次日 C2 → A3 检查最终改动，A2 复用。每轮 0–1 分钟停今天，1–2 分钟首次遍历，2–5 分钟重复八轮，5–8 分钟停在今天，8–9 分钟关窗回托盘，9–10 分钟重开今天。每轮核对起止事件、每阶段有效 CPU 区间和采样器结束记录。7 轮各 600 秒、各 300 个有效资源样本，共 2,100 个；均按时结束、缺测 0。切页阶段 UI 每轮有效 CPU 覆盖 178.9 秒。另行运行一分钟反证与画面诊断，避免把取样画面的 CPU 开销计入优化收益。
- [x] **区分首次增长与重复增长。** A2 首次走完回到今天比初始今天多 147.5 MiB，C1 多 30.7 MiB。第 1、4、8 轮终点的四秒窗口中位数在 A2 为 272.1、269.7、276.9 MiB，C1 为 153.5、157.5、158.9 MiB。两者第 1 到第 8 轮折算每轮各增加 0.69、0.77 MiB；静置末又分别回到 272.6、154.6 MiB。重复同一组键时可见短时尖峰与稳定平台。保留已有页面和图标缓存容量，新优化针对会随首次绘制出现的高额分配。
- [x] **定位到页面与绘制路径。** 读取同一 UI 进程的虚拟内存区域。首次从历史进入数据总览、详情时，私有类型区域的已提交页在 A2 从 94.3 升至 194.3、234.9 MiB，在 B2 为 93.8、182.6、222.0，在 C1 为 92.1、108.7、121.1。这组分区读数用于定位增量；上表的进程私有提交还包含其他来源。 针对数据页完成三次后返回今天，以及点击数据后立即取消三次，分别测预期分配与取消时的分配。A-data 和 A-cancel 各 60 秒，第 20–36 秒已回到今天，UI 私有提交中位数为 270.7 和 126.1 MiB。完整呈现数据页足以触发高平台，迅速取消则接近初始今天。这两轮同期有构建或独立回归，只比较被测进程的私有提交。
- [x] **降低绘制成本。** B 将日期格共享的全年键盘焦点集合放入一个 `Rc<[FocusHandle]>`，并把控件外框和底色合入一次画布回调。C 将热力图同尺寸的连续圆角轮廓与内填充存入图集，着色复用同一对遮罩。尺寸按四分之一逻辑像素分档，进程最多保留 49 个轮廓尺寸槽；不可见格跳过绘制，特殊尺寸或绘制错误回退到原生路径。保留了原有主题色、键盘移动、日期命中和提示区域。[日期焦点](../../apps/patina-ui/src/features/data/heatmap.rs) · [热力图绘制](../../crates/quietpro/src/controls/heatmap/paint.rs)
- [x] **核对待呈现页面。** 工具页首次打开时马上反馈侧栏选择，已呈现页面持续显示到工具列表与面板准备好。有效的空面板和失败都可以呈现，切走则丢弃已取消的目标；后台刷新继续使用上一次可用的控件。已有输入草稿与录制操作沿原路径处理。[主窗导航](../../apps/patina-ui/src/windows/main/mod.rs) · [工具面板](../../apps/patina-ui/src/features/tools/mod.rs)
- [x] **验收画面与输入。** 同窗口、同 DPI 的独立画面测量只在内存中取样，保存内容区域的明暗、色彩与哈希，以及侧栏选中像素。基线取 285 帧，候选取 287 帧，首屏正对照分别 64/64、71/71。首次打开工具，基线 33 ms 点亮侧栏，781 ms 面板可读；中间 21 帧为加载提示。候选 88 ms 点亮侧栏，769 ms 面板可读；同一等待区间 20 帧均与切换前的分类网页内容哈希相同。两组各 21 次侧栏按钮的反馈中位数为 65 和 63 ms。全程均未采到内容区全白；采样间隔中位数均为 33 ms，最长空隙分别 283 和 217 ms，更短的显示瞬态仍可能漏采。已用独立交互用例核对图标就绪、日期焦点与草稿切换。
- [x] **验收释放与录制。** 每轮关闭最后一个窗口后等待原 UI PID 退出，确认托盘期仍是同一录制会话且心跳前进，再重开窗口检查新的 UI PID 和同一排行条目。宿主正常退出后检查原活动会话封口。A2、C1 的整树静置私有提交从 307.6、189.1 MiB 分别降到托盘时的 34.4、34.3 MiB；重开后的 UI 为 129.1、127.3 MiB。整个测试期间持续使用临时 profile，测量、关窗和退出均针对测试实例。
- [x] **复核边界并归档。** 通过 45 项 Patina UI 单元与无头用例、9 项 QuietPro 单元用例及 9 项无头控件用例。8 项原生交互通过，覆盖数据页、全年热力图、工具键盘与 Mini 指定工具、分类草稿、页头、关于和设置。跨午夜首次验证发现热力图用例把尚未发生的 70 分钟当成当天已有记录，改用上一完整日后按原数值、全年格数与键盘条件通过。最终页面驱动另用新建种子在一分钟内完成画面、托盘和录制验收，画面可区分 23 种内容哈希。改动范围的 Clippy 和 Rust 格式检查通过。 采样使用同机串行的冻结二进制，后台系统活动可能影响单次短延迟。结论覆盖固定数据、窗口尺寸与操作强度。持续引入新应用和日期的缓存增长，以及全天运行期间的慢增长，继续使用长测口径。

## 重跑与核对

默认开发构建通过，运行中的开发预览与最终构建的 SHA-256 一致。现行文档检查通过 20 个文档，归档检查的 603 项历史失效链接在改动前后相同。

在 Windows 仓库根运行。首次构建采样器后，页面驱动自动生成测试库并使用隔离桌面。设置 `PATINA_MEASURE_BINARY` 可比较已冻结的同类型可执行文件，`PATINA_MEASURE_OUTPUT` 指向本轮尚未创建的目录；同一测试日的各轮共享父目录中的种子，跨本地午夜另用新父目录。每轮完整结束再启动下一轮。设置 `PATINA_MEASURE_MODE=frames` 可跑一分钟的画面取样，`data` 和 `cancel` 分别复现数据页呈现和迅速切走；环境变量留空运行完整十分钟。

cargo build --offline --locked -p patina --example windows-resource-sample
