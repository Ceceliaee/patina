## 2. 从第一性原理定义正确结果

### 2.1 时间属于活动事实，归并属于解释方式

一条网页活动包含原始域名、URL、标题、时间区间和所属浏览器会话。把多个域名显示为一个网站，只改变“这一段时间展示在哪里”，不改变“这一段时间发生了什么”。

因此实施必须同时满足：

1. 不重写 `web_activity_segments` 的域名、URL、起止时间和会话归属。
2. 保持现有来源优先级、有效截止、范围裁剪及重叠处理，再对有效结果进行展示归属映射。
3. 在相同事实、时间范围、排除条件下，归并前后的有效网页总量相等。不得用展示分组再次补空档、去重或追加时间。
4. 每个有效原始域名在一次查询中只有一个展示归属。例外成员从汇总集合移出，不能同时出现在两边。
5. 关闭归并后，无需恢复或改写历史事实即可恢复独立展示。

令 `E` 为按现有规则计算出的有效活动集合，`owner(h)` 为原始域名 `h` 的展示归属，则网站 `s` 的用时为：

```text
duration(s) = sum(duration(e) for e in E if owner(e.domain) == s)
sum(duration(s)) = sum(duration(e) for e in E)
```

这里的求和只消费既有有效活动结果，不取代原有重叠、来源及时间资格算法。日期边界和当前时刻也必须来自同一个查询上下文。

### 2.2 域名层级能帮助分组，但不证明同一用途

程序关联是显式成员映射；网页归并是用户开启的域名范围规则。范围决定未来成员，例外决定哪些完整域名继续独立。

主域名使用可注册域名边界，不能截取最后两个标签。Public Suffix List（PSL）定义公共后缀，并区分 ICANN 与 PRIVATE 区段；后者保护共享托管平台下的独立站点边界。依据：[PSL 用途说明](https://publicsuffix.org/learn/)、[格式与匹配算法](https://github.com/publicsuffix/list/wiki/Format)。

**设计选择：** 使用包含两类区段的本地固定规则集；完整匹配规则含通配与例外。运行时无需联网查询域名或下载规则。未知后缀、IP、单标签主机及无法可靠解析的输入保持独立，不能猜测父级。域名匹配不是站点所有权认证。

### 2.3 展示身份和原始身份必须可区分

`example.com` 既可能是一条真实访问记录的域名，也可能是聚合网站的名称。即使字符串相同，它们的选择范围也不同。

**设计选择：** 业务模型显式区分 `domain(h)` 与 `site(r)`；具体类型名由实现 owner 确定。合成网站卡片不是伪造的访问记录，不创建时长为零的数据库事实。根域名没有访问记录时，也能从成员构造网站卡片。

原域名设置仍控制采集、标题和删除；网站展示设置只控制名称、分类、颜色及图标选择。网站设置不得混入原域名的 `enabled` 或 `captureTitle`，否则修改网站可能意外作用于某条真实记录。

### 2.4 精确例外优先，规则关闭可逆

定义 `root(h)` 为当前规则集得出的可注册域名：

```text
root(h) 不可靠或没有开启归并             → domain(h)
h 属于该根的完整域名例外集合             → domain(h)
其他情况                               → site(root(h))
```

例外只匹配完整域名。将 `mail.example.com` 单独统计，不会自动把 `a.mail.example.com` 一起移出；面板说明必须让用户知道这一点。域名根本身也可作为精确例外，类型区分防止其独立卡片与网站卡片冲突。

关闭归并时保留例外和网站展示设置，重新开启时恢复这些选择。所有成员都成为例外时，在管理界面保留已启用规则的入口；统计页面不凭空显示零时长网站。

## 4. 实施基线与边界决策

### 4.1 解析和状态

- Rust 是公共后缀解析与写入合法性校验的唯一权威。前端消费批量解析出的 `domain → root / 不可归并原因`，不另装一套可能版本不同的 PSL。
- 前端可根据权威边界和本地草稿预览归属；这属于页面读模型，不持久化第二套域名目录或派生索引。
- 新规则保存“根、是否启用、精确例外”；不保存自动成员清单。新成员由实际域名和规则计算。
- 网站展示设置与原域名设置分开存储。首次启用时，从入口卡片初始化名称、分类和颜色，随后独立编辑；关闭后成员原设置完整恢复。
- 图标沿用已有本地 favicon 数据：优先根域名已有图标，再选稳定的成员图标，最后使用现有占位。不得为合成卡片增加联网抓取。
- 优先使用现有 settings 存储；不预设 schema migration。单个 key/value 大小必须满足现有限制，不能把无限增长的例外数组塞入一个值。选择分行存储或有明示上限的表示，并覆盖极限输入。
- 保存按同根配置整体处理并检测预期旧值。启用、例外和展示设置在同一事务提交，不能只成功一部分。
- PSL 随应用依赖更新；保留上次用户选择的根值。更新后不再合法的规则保留配置并停用归并解释、提示重新设置，不能静默迁移到更宽范围。

### 4.2 管理界面

- 独立域名卡片点击域名打开面板，展示可归并根、开关、已有域名；不支持的主机显示原因，不提供无效开关。
- 开启后预览收拢卡片，网站域名行显示箭头；不增加数量徽标、搜索添加模式或独立管理页。
- 面板分“已归并”和“单独统计”，分别提供“单独统计”和“恢复归并”。说明未来子域名自动归入。
- 关闭面板只关闭浮层；页面草稿保持。顶部取消回到已保存状态，顶部保存成功后才向其他页面发布新规则。
- 网站卡片保留名称、分类、颜色等展示动作。标题记录、排除、删除从面板内明确标注完整域名的成员行进入；合成根没有记录时不出现假原域名动作。
- 删除仍使用已有精确域名删除流程，确认内容显示完整域名，不提供隐含的“整个网站全部删除”。未保存草稿与删除冲突沿用现有保护，并补充分组场景验证。
- 长成员列表需要可滚动、可搜索定位；若复用搜索控件，搜索仅过滤面板显示，不改变规则集合。被排除或零用时的已配置例外仍可管理。

### 4.3 统计与受保护能力

- 所有当前展示网页汇总的入口接入同一归属；对没有网页汇总的页面不借机新增统计区块。
- 网站分类筛选在归属后执行，采集与原域名排除在归属前执行。成员被排除时，其历史不进入网站用时，恢复后重新纳入且不补记空档。
- 精确详情保留每条记录的原域名、来源及边界。切换网站后不把多个访问片段拼成连续使用区间。
- 原始导出保留原域名与 URL；不新增“网站汇总导出”格式。备份包含规则，现有提醒目标继续按原始域名解释，不随网站命名悄悄扩大范围。
- 不修改 Web Sync 协议、AFK、浏览器前台资格和活动截止；不增加跨根关联、后台采集或通用规则编辑器。
