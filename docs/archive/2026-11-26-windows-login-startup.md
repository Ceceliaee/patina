## 从用户需要的结果出发

用户打开「开机自启动」，是为了下次登录后能接着记录活动。要兑现这个选择，Windows 必须能启动正确的程序和资料，宿主必须能持续运行，录制器必须按用户的暂停或录制状态工作。「静默启动」决定是否展示窗口，「显示托盘图标」决定是否请求图标，两者各有自己的作用。Explorer 什么时候能接收图标，由 Windows 决定。

1. **记录连续。** Explorer 晚到或重启时，同一资料仍由原宿主持锁、采样。用户主动退出时，宿主照常结束。
2. **选择有效。** Patina 保存用户偏好，Windows 管理启动项及其禁用状态。设置页要能告诉用户下次登录是否具备自启条件。系统明确禁用时，普通启动和升级都应尊重该选择。
3. **升级可恢复。** 已启用自启的安装在更新前后都应保有可用的登录命令。更新中断后能安全重试，最终只保留一个指向正确资料的启动项。

## 一、托盘不可用时让宿主继续工作

- [x] 在[托盘模块](../../apps/patina/src/tray.rs)分别维护「按当前偏好应显示图标」与「图标已在本次 Explorer 会话中登记成功」。保留宿主接收单实例唤出、退出和系统通知所需的窗口。仅将图标暂不可用视为可恢复，对窗口创建、资料打开等独立故障保留各自的错误处理。
- [x] 首次添加图标或设置图标版本失败时保留宿主，按原偏好打开窗口或静默运行。收到 `TaskbarCreated` 后，根据最新偏好恢复图标，再次失败也继续录制。覆盖注册期间错过通知的情形，若需补试则限制次数和频率。关闭图标或退出后取消待执行的补试。
- [x] 在[宿主启动入口](../../apps/patina/src/lib.rs)确定资料、取得锁并读出有效设置后核对登录项，使登记可以独立于托盘完成。图标缺席时，手动再次打开 Patina 仍应唤出同一宿主。设置读取失败时保留已有登记。

## 二、让设置页说明下次登录会发生什么

由[登录项模块](../../apps/patina/src/login.rs)读取当前用户、当前资料对应的命令和 Windows 启用状态，由[设置页](../../apps/patina-ui/src/features/settings/mod.rs)呈现。按下表实现和验证。

| 保存的偏好 | Windows 观测 | 行为 |
| --- | --- | --- |
| 关闭 | 本资料的启动项缺失或仍有残留 | 保持关闭。有残留时核实归属，只移除本资料拥有的命令。 |
| 开启 | 命令指向正确程序和资料，系统允许 | 显示已开启。再次启动或保存其他设置时保留现有登记。 |
| 开启 | 能确认是升级丢项或仍指向已替换的本应用，且无禁用证据 | 重建或修正命令，读回核对后显示已开启。 |
| 开启 | Windows 明确禁用了当前项或待迁移的旧项 | 显示「已被 Windows 禁用」，提供打开系统启动设置的入口。用户返回后重新读取实际状态。 |
| 开启 | 登记缺失且原因不明、命令归属冲突、状态不可读或格式未知 | 说明已知事实和下一步。原因不明的缺项可由用户明确要求修复。无法确认归属或禁用状态时保留原项。 |

- [x] 实现上述状态判断。区分正常缺省的 Windows 批准记录与访问失败、无法识别的记录。按当前可执行文件及资料参数核对命令，覆盖带空格路径和显式 `--profile-parent`。
- [x] 用户保存后重新读取系统结果。登记失败或数据库提交失败时，沿用[设置保存与补偿](../../apps/patina/src/requests/settings.rs)恢复原状，补偿失败时保留两次错误供诊断。用户取消草稿不产生系统变更。
- [x] 用现有设置控件呈现异常状态及可用操作，覆盖键盘操作、返回页面刷新和各语言文案。[界面设计](../ui.md) · [本地化](../localization.md)

## 三、让旧启动项安全交给新版本

- [x] 在[安装器](../../packaging/windows/patina.nsi)与[资料迁移](../../crates/storage/src/location.rs)之间沿用同一份旧资料和用户选择。按旧命令、安装目录及所属资料核实归属，并在更名或删除旧项前检查其系统禁用状态。旧项已被禁用时，换名不能产生一个可执行的已启用项。
- [x] 由现有宿主侧登录项逻辑生成目标命令。对原先有效且允许自启的安装，在最终程序就位后写入并读回新项，核对目标程序、参数和资料，再移除已确认归属的旧项。将交接从首次成功显示托盘这一条件中移出。
- [x] 在写新项之前、写入后尚未清旧项、清理失败三个位置分别验证中断与重试。交接失败时保住仍可用的原命令。如果程序文件需要回滚，一并恢复与其匹配的启动配置。重试后本资料只留下一个有效项，其他资料保有各自的登记。
- [x] 覆盖已经升级至 2.0.0 的用户。在补丁安装或下一次手动启动时，结合已采用的旧资料、保存的自启偏好和系统状态识别可修复的缺项。「曾经升级」标记只说明资料来源，删除原因仍不清楚时提供设置页修复入口。全新安装沿用默认关闭。

## 四、隔离桌面验收

每个原生用例在同一用户会话内创建临时 Win32 桌面，使用独立资料和测试注册表值。测试桌面没有 Explorer 任务栏。Windows 是否执行登录命令另由上面的真实登录复测核对。

- [x] **隔离桌面，托盘始终缺席。** 保持「开机自启动」「显示托盘图标」「静默启动」均开启，从登记命令冷启动。观察同一宿主的最后成功采样时间推进，正常退出后从测试数据库读回对应的受控活动。另测已暂停录制时宿主保持运行、数据库没有新增活动。复用[生命周期用例](../../apps/patina/tests/lifecycle.rs)的采样夹具。
- [x] **窗口和托盘偏好。** 关闭静默启动，应按偏好打开主窗口。开启静默启动，应能在没有主窗口时开始记录。两种情况都覆盖显示与隐藏图标。保留[常驻设置用例](../../apps/patina/tests/pages/resident.rs)原有的关闭图标对照。
- [x] **任务栏重建通知。** 给隔离桌面的宿主发送真正的 `TaskbarCreated` 窗口消息。重新登记仍失败时，原宿主继续采样。托盘单元测试另行覆盖四次退避、登记成功、重复回调和关闭图标。实际 Explorer 重启、图标恢复后的可见性与点击不在本次验收范围。
- [x] **设置与注册表。** 在测试项上设置和撤销系统禁用标记，检查 Patina 窗口的刷新、保存、取消、键盘修复、写入失败补偿及重复操作。系统设置入口由 UI Automation 检查，隔离桌面未操作真实 Windows 设置应用。
- [x] **安装与回滚。** 扩展[安装器交接用例](../../crates/updater/tests/installer/handoff.rs)，覆盖 1.10.0 已启用、已关闭、系统已禁用，以及 2.0.0 升级后缺项。核对新旧登记的命令与有效状态、重试结果和原资料位置。
- [x] **隔离桌面的验收范围。** 隔离桌面从注册表取出命令并重放，核实资料、窗口、宿主与落库活动。维护者电脑上的结果另见[真实登录复测](#真实登录复测)。Windows 对已禁用项的实际登录调度仍未实测。
- [x] 在本方案记录候选版本、Windows 版本及架构、测试入口、观测结果和剩余限制。按[工程质量](../quality.md#验证范围)完成受影响的跨模块、安装与本地化检查。发布验收沿用[版本与发布](../release.md#windows-安装与更新)。验收完成后将长期有效的行为写回对应专题，按[文档治理](../documentation.md#工作记录与归档)归档本方案。
