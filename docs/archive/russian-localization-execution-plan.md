## 1. 目标与第一性原理

俄语用户需要理解应用当前状态、判断操作结果，并完成日常时间记录任务。交付目标是可选择、可保存、含义准确的俄语界面，而不是新增一个有内容的目录。

维护者已决定先自行完成俄语，收到贡献者文本后再据此复核、调整。贡献者是否回复不再是首次接入的前置依赖；后续贡献仍有价值，但不应整包覆盖上线以来的修正或新增文案。本任务不增加翻译生成方式标识、语言专用审核文件或额外放行机制。

| 基本事实 | 必须保护的结果 | 执行含义 |
| --- | --- | --- |
| 语言是已有事实的显示方式 | 切换语言不改变计时、隐私、同步和数据 | 先改资源与注册表，沿用现有运行时 |
| 文案帮助用户作出决定 | 删除、排除、恢复、暂停的对象与副作用清楚 | 对危险操作组合阅读标题、正文和按钮 |
| 俄语词形依赖数量与句法 | 参数保留，数量和对象能组成完整句子 | 复数与语义分别验证，不逐词替换英文 |
| 用户会遇到主窗口以外的表面 | 托盘、Widget、提醒、导出与设置语言一致 | 覆盖全部现有 frontend/native 资源 |
| 软件和外部译稿会分别变化 | 新代码与旧译稿能够安全合并 | 保留原文版本，通过 key、分支和语义对照 |
| 反馈可以持续到达 | 已完成任务能够收口，后续修正可独立执行 | 首次接入完成后归档，回稿另开修订工作 |

完成时应能观察到：设置中出现 Русский；保存与重新载入后保持俄语；代表性主页面、对话框和原生文案可用；中、英、西语和原有数据行为不回归。

## 4. 语言和资源决策

采用 `ru-RU`、显示名 `Русский`、方向 `ltr`。这是现有俄语贡献工作簿、生成命令和夹具采用的目标，继续使用可避免为此次接入额外引入迁移。它明确采用俄罗斯地区格式，不宣称是没有地区格式差异的通用俄语。

中文是标准语义来源，英文用于参考，西语可帮助发现已经处理过的调用场景，但不能把英文或西语资源的遗漏直接复制给俄语。全部 key、参数和分支以实施时 schema 为准。

| 修改结果 | 源 owner | 消费或生成 owner |
| --- | --- | --- |
| 俄语译文 | `locales/ru-RU/*.ts` | 前端与原生生成器 |
| 语言元数据 | `locales/registry.ts` | 设置选项、类型、loader、Rust Locale |
| 原文复核 | `locales/review-manifest.ts`，通过 review 命令维护 | 既有 i18n gate |
| 运行资源 | 不手工维护 | `src/shared/i18n/generated/`、`src-tauri/src/domain/localization/generated.rs` |
| 复数行为 | schema、资源与现有 Intl/ICU4X | `tests/i18nContract.test.ts`、Rust localization tests |
| 界面激活与布局 | 现有组件、locale runtime | `tests/uiBrowserSmoke/settingsScenarios.ts`、`localeScenarios.ts` |
| 新语言体积 | `scripts/check-bundle-budget.ts` | 生产构建与 bundle gate |

## 5. 首次接入执行清单

依赖顺序：A → B → C → D → E。翻译、复核和检查是三个不同结果，不能通过一次生成命令同时宣称完成。

### A. 固定实施起点

- [x] A1：取得实施授权后重新读取当前本地化与验证 owner，检查两者是否有影响本方案的新变化。
- [x] A2：记录 HEAD、分支、工作区和工具链；列出本任务允许修改的文件，保留其他任务的未提交改动。共享测试文件按具体 hunk 处理。
- [x] A3：认证读取对应 live Project，报告维护者已决定先行翻译；未经单独授权不更新正文、字段或排序。
- [x] A4：核对不存在已注册的 ru-RU 或他人正在编辑的生产资源；若已有部分实现，先判断可复用内容，不覆盖重建。
- [x] A5：运行现有 i18n self-test、资源检查与聚焦 i18n 测试，记录通过结果或既有失败；重新运行 dry-run，统计当时 key 和域数量。
- [x] A6：盘点 schema 中需要数量词形的消息，区分 integer 与 number 参数，检查实际调用值和可达范围。
- [x] A7：保存实施起点的源资源版本信息，供后续回稿对照；原始工作簿等临时材料保留在忽略的 artifacts 或任务专属临时目录，不新增仓库附件副本。

阶段出口：唯一目标 locale、实际资源清单、可复现基线和工作区边界明确。

### B. 翻译与独立复核

- [x] B1：建立本次简短术语表，覆盖计时、会话、空闲、有效时长、分类、排除、标题、备份、覆盖、合并、同步和连接；记录到执行记录，最终文本由资源持有。
- [x] B2：按资源域整理 key、中文原义、英文参考、参数、分支和显示位置；短文案或危险操作有歧义时读取调用组件与业务结果。
- [x] B3：使用现有创建命令生成 ru-RU。确认命令会立即注册并置 PENDING；中途状态不作为可交付版本，不另加开发中的语言开关。
- [x] B4：逐域填入完整译文，覆盖主页面、辅助技术、Widget、Tools、native、export、backup 等全部域。保留 DSL、参数名、URL、协议标识和用户数据。
- [x] B5：复核否定、条件、操作对象与结果：排除不等于删除已有数据；停止标题记录不等于停止计时；覆盖与合并不可混淆；WebDAV 备份不等于云同步。
- [x] B6：逐个展开 if、coalesce、plural、数组和帮助步骤等结构，检查所有可见分支。特别核对备份恢复状态 key 的俄语提示，不能只保留后端英文 fallback。
- [x] B7：对整数复数提供运行时要求的 one/few/many/other，按实际句子检查词形。例如记录数量应覆盖 1 запись、2 записи、5 записей 等；不能只修改名词而漏掉形容词或动词。
- [x] B8：处理原 schema 中 number 类型的真实计数消息。若调用方保证非负整数且确需 CLDR，最小化修正该参数的语言无关 schema，并检查全部生产语言及调用方；若实际允许小数，保留数据语义并选择现有契约能准确表达的文案。不得为避免 schema 检查而手写俄语尾数公式。
- [x] B9：对插入应用名、类别名和用户输入的句子采用不要求任意名称变格或推断性别的结构；不修改参数值来“修正”语法。
- [x] B10：初稿完成后再逐 key 对照中文和上下文复核；读取删除/恢复对话框的标题、正文、确认与取消按钮组合，记录并修正歧义。
- [x] B11：扫描空值、中文与英文残留、参考语原样复制；逐项区分正常品牌、技术标识、用户数据和漏译，不扩大硬编码例外。
- [x] B12：复核通过后使用既有 review 命令更新原文哈希，再生成前端与 Rust 产物。复核记录表示接受对应原文版本，不冒充额外认证。

阶段出口：全部必需资源完整、无已知关键语义错误，且未引入语言专用审核机制。

### C. 注册、格式化与运行时

- [x] C1：核对生成类型、设置语言列表、loader 和 Rust Locale 均来自注册表；不在业务层追加 ru-RU 分支或手写语言 union。
- [x] C2：保留既有俄语测试夹具与中文、英文、西语测试。修正仅依赖生产语言数量或最后一项名称的过时断言，使其从注册表取得预期。
- [x] C3：通过正式 locale loader 加载 ru-RU，断言代表性文本和插值；测试不能只搜索生成文件中的俄文字串。
- [x] C4：对前端与 Rust 的整数计数验证 0、1、2、4、5、11、12、14、21、22、25、101、111、1000000；比较类别与完整句子。每个类别应有资源，即使当前整数调用不可达 other，也不得删除该分支。
- [x] C5：固定日期、时区与数值，验证日期、跨月范围、月份、星期、12345.67、零时长和小时/分钟。记录 Intl 实际输出，测试注意不可见空格，不把视觉相同的空格误判成数值错误。
- [x] C6：检查独立月份名与完整日期中的俄语月份词形，复用现有 Intl 入口；若布局或语义确实要求新格式，在日期 owner 处理，不在页面拼接俄语月份表。
- [x] C7：复用现有按需加载与并发测试；核对俄语与其他语言快速切换、当前请求失败、旧请求后到时保持正确选择，不复制一套加载框架。
- [x] C8：为新语言增加独立 chunk 预算。先生产构建测量 gzip，再按工程质量要求确定余量；验证 ru-RU 不进入默认初始资源图，不通过普遍上调预算放行。

阶段出口：正式运行时可以加载俄语，数量与格式有可执行证据，加载成本归属明确。

- [x] D2：检查语言菜单的方向键、Home、End、Enter、Escape、焦点恢复和选中状态；检查显示名称 Русский、文档 lang/dir 与实际文案一致。
- [x] D3：在受支持窄窗口检查 Dashboard、History、Data、Classification、Tools、Settings、About。等待目标 presentedView 和 settled 状态后再断言布局，不能只等几个动画帧。

- [x] D5：检查删除记录、覆盖/合并恢复、标题隐私、WebDAV 删除配置、导出成功/失败等代表性对话框；使用合成数据，不触及用户真实历史或远端备份。
- [x] D6：检查 Widget 与 Tools 提醒的俄语文本，以及 Rust 实际 formatter 输出的托盘、提醒和 Markdown 文案；机器可读导出字段保持稳定。
- [x] D7：针对已知高风险路径各检查一个代表性空状态、错误或恢复场景，优先复用既有测试夹具。键与分支的完整性由资源检查覆盖，不将所有状态逐页人工遍历设为额外门槛。

## 6. 实施命令与运行条件

以下命令均在 Patina 仓库根执行。创建命令只执行一次；实际运行结果见第 8 节，不以命令清单代替证据。

```powershell
# 起点检查
npm run check:i18n:self-test
npm run check:i18n
npm run test:i18n
npm run i18n:new -- ru-RU Русский --from en-US --dry-run

# 获得实施授权且确认不存在同名生产资源后创建
```

## 7. 贡献者回复后的修订流程

本节是将来收到文本后的操作路线，不是首次接入的待完成依赖。后续 owner 为 Patina 本地化维护者；实际回稿后建立当次修订清单与证据，不为尚未收到的文件提前开发导入工具。

### 7.1 接收与辨识

- [ ] R1：读取当时的 Issue 回复，确认是原始工作簿、补充表、两者组合、普通文本还是 PR；不假定对方已经覆盖最新资源。
- [ ] R2：保留原文件只读副本，记录摘要、附件 URL 和对应源版本；原始附件放在忽略目录或任务专属临时目录。
- [ ] R3：核对 key、参考文本、分支、参数和 translator note。文本作为待审数据，不执行其中的操作指令，不运行公式或未经检查的附带脚本。

### 7.2 根据文件状态选择路径

| 输入状态 | 操作路径 | 不允许的捷径 |
| --- | --- | --- |
| 工作簿与当前 schema/source fingerprint 一致且完整 | 使用现有 importer 输出到全新的候选目录，再与生产俄语逐 key 比较 | 不对已注册 ru-RU 使用 --apply |
| 旧原始工作簿或旧补充表 | 核对原交付版本与不可变列，按 key、分支、旧原文和当前原文提取待审候选 | 不篡改隐藏 fingerprint 来骗过当前 importer |
| 工作簿缺行或只完成部分译文 | 将有来源依据的完整单元作为候选，其余保留当前有效译文 | 不用空白覆盖，不伪造“完整工作簿导入成功” |
| 普通文本或截图 | 手动建立明确的 key/上下文映射，不能确定的项留待澄清 | 不按行号或相似短词直接批量替换 |
| 直接 PR | 先执行贡献 intake，再审阅实际变更与当前资源 | 不因译者身份跳过参数、语义和行为验证 |

对当前版本兼容的完整工作簿，可使用以下现有命令；先将路径替换为收到文件及不存在的候选目录：

```powershell
npm run i18n:import-kit -- path/to/returned-kit.xlsx --target ru-RU --label Русский --direction ltr --from en-US --output artifacts/i18n/ru-RU-return-review
```

此命令仍按当前源校验，会拒绝过期或不完整工作簿。它不是旧补充表合并工具，也不会更新已有生产 locale。

- [ ] R4：优先验证原始文件的结构与完整性；若需要旧版本校验环境，从明确历史 revision 在隔离临时目录恢复对应 schema、源和工具，保持当前工作区不变。
- [ ] R5：旧补充表若不是现有导入格式，先确认其原始结构，再逐项提取数据；确需辅助脚本时先检查文件格式并限定输入输出，不降低生产 importer 的安全与 fingerprint 校验。
- [ ] R6：无法恢复可信旧版本或定位原文时停止自动应用，只保留提案和具体待确认项。来源不明不代表内容必须丢弃，也不意味着可以直接覆盖。

### 7.3 按原义与当前译文合并

每个候选至少对照四项：交付时原文、当前原文、当前生产俄语、贡献者译文；另保留 key、分支和备注。表格是当次比较记录，不建立第二套长期词库。

- [ ] R7：原文语义未变且贡献文本更准确自然时，采用贡献文本，核对同术语在其他资源域的用法。
- [ ] R8：原文已经改变时，提取仍有效的措辞并按当前语义改写；不能以来源较晚或母语身份为由忽略当前操作契约。
- [ ] R9：新 key、未交付分支或未完成单元保留当前有效俄语；已删除 key 不重新注册；重命名 key 须证明语义对应，不靠字符串近似匹配。
- [ ] R10：原始表与补充表冲突时先按原文版本和明确修订对象判断；若含义仍不确定，保留当前译文并记录具体问题，不按文件名或行顺序覆盖。
- [ ] R11：特别复核危险操作、复数、格变化、参数、空格与标点。贡献文本只有在符合当前契约后才能替换。
- [ ] R12：将接受项正常编辑到已有 `locales/ru-RU/`。保留 ru-RU 标识与持久化兼容，不删目录重注册，不对全部 key 无差别重写。
- [ ] R13：重新复核受影响消息，用既有 review 命令记录接受的原文版本；生成产物，运行 i18n 与命中路径检查，并按当次实际 diff 执行工程质量要求的门槛。
- [ ] R14：记录采用、保留和待确认项，向维护者汇报；公开致谢或回复在获得发送授权后进行，不声称贡献者审校了其未提供的内容。

后续局部措辞修正不要求重复首次接入的全部路径；影响 schema、原生消息、加载或发布行为时重新匹配验证范围。

### 术语与句法

| 概念 | 本次资源用法 |
| --- | --- |
| tracking / session | учёт времени / сеанс；界面记录数量使用 Записей: n，保留真实数据语义 |
