## 1. 目标、范围与依据

将应用与网页的单项排除行为调整为匿名统计：保留实际活动时间，不保存该段活动的真实身份；原有具名历史继续按对象隐藏，恢复追踪后重新显示。匿名记录不可还原，也不归给上一应用。

本文根据已确认的产品要求和仓库代码编制，不保存线上 Project 的条目正文、字段、排序或当前队列。任务进展不自动改变 Project。本次实施授权包括必要的伴生扩展本地修改；不包含提交、推送、发布或真实用户数据清理。

长期依据：

- [架构](../architecture.md)：Rust 写侧、持久化读模型、前端展示与 companion 边界。
- [工程质量](../engineering-quality.md)：风险验证、升级保护与证据要求。

不增加第三种单项模式，不把匿名统计扩成任务计时，不重做页面布局，不匿名化已有具名历史，不补回过去漏记的空白，不改变正常导入来源的既有优先级。

### 1.1 行为变化边界

变化限于选择匿名统计的对象及其必要的统计呈现：新增匿名时长、匿名与具名区间的正确归属，以及由此产生的总计、排行占比和趋势变化。未选择匿名统计的普通应用与普通网页，其计时资格、标题记录偏好、记录完整性、空闲判断、暂停恢复和历史处理保持原契约。

匿名网页经浏览器标题旁路泄露身份的问题属于本项必须解决的交付范围，不是可延后的优化。未知身份采用已确认的隐私优先例外：仅在存在匿名网页规则且无法确认当前网页身份时，不保存浏览器标题，活动时长仍记录。没有匿名网页规则的浏览器、身份已确认的普通网页及非浏览器应用保持原契约；不能全局关闭浏览器标题或扩大例外范围。

## 2. 从事实推导实现约束

### 2.1 时间存在与身份可见是两个独立事实

用户在匿名应用中活动，时间确实发生；不愿保存应用身份，并不表示没有活动。因此计时资格、记录身份和历史可见性必须分开表达。

| 维度 | 回答的问题 | 本项处理 |
| --- | --- | --- |
| 计时资格 | 当前是否存在允许记录的真实活动？ | 沿用空闲、暂停、锁屏、休眠及有效观察边界 |
| 身份策略 | 活动可以保存哪些身份信息？ | 正常记录或匿名记录 |
| 历史可见性 | 已有具名历史是否参与常规展示？ | 沿用对象隐藏与恢复规则 |
| 展示身份 | 多个匿名来源如何呈现？ | 每个统计视图仅一个“匿名活动”汇总项 |

不能继续用一个“是否追踪”的布尔判断同时回答以上问题；也不能为了保留时长绕过活动资格。

### 2.2 匿名发生在写入之前

只把名称显示成“匿名活动”仍然保留了身份。匿名活动事实不得携带名称、exe、路径、域名、URL、标题、favicon、浏览器客户端标识或可关联回具名会话的键。真实身份可在必要的内存判断中短暂存在，但不能随匿名事实写入数据库、缓存、导出、日志或事件载荷。

管理规则需要保存目标身份，旧具名历史也按既定行为保留；匿名不是整库无身份，也不承诺抵抗根据时间和外部信息进行的推测。验证应证明匿名活动本身无身份字段和可反查关联，不能把“隐藏历史”描述成擦除历史。

### 2.3 一份活动时间不能因为多条观察重复增加

原生采样描述桌面活动，网页观察描述浏览器内的活动；二者不是两份独立使用时长。匿名写侧必须确定唯一计时归属，网页维度只能提供受约束的子集。

对新增的正常前台活动链，在任意查询区间内，应满足：

`可见总时长 = 可见具名活动时长 + 匿名活动时长`

同一原生活动区间内，两部分互斥。先按真实区间分配，再裁剪到日期或小时；不从小时总量按比例猜测分钟分布。不用本项的去重规则全局钳制已存在的原生重叠或导入数据；其契约仍由架构与来源 owner 负责。

### 2.4 失去身份后不能按身份还原或删除

匿名活动汇总可合并，时间轴仍保留真实时间段；不能跨正常活动或空闲连接。取消匿名设置只影响后续采样，不能恢复过去匿名段的身份。

同理，删除某个具名应用的记录不能凭推测删除匿名记录；匿名数据必须通过明确的时间范围或全量清理路径处理。匿名记录的备份合并只能依靠无身份的记录标识和来源去重契约，不能重新引入 exe 或域名。

## 3. 已确定的用户可见行为

| 表面 | 结果 |
| --- | --- |
| 分类页操作 | “匿名统计”与“恢复追踪”，操作按钮图标不变，不附加长说明 |
| 状态与筛选 | 使用匿名统计语义，仍可找到和管理原对象 |
| 应用排行 | 一个“匿名活动”项，正常按时长排序和显示占比，不在列表外另列 |
| 应用图标 | 中性灰色 EyeOff，容器尺寸与其他应用一致 |
| 圆环、小时柱、时间条、圆点 | 未分类色加斜纹；圆点仍是圆点，不替换为 EyeOff |
| 分类分布 | 匿名活动独立汇总，不混入普通“其他”或用户分类 |
| 时间轴 | 可有多段匿名活动，名称和样式一致；详情仅有开始、结束与时长 |
| 今天、历史摘要 | 总计、活跃跨度、高峰时段等基于同一有效活动集合 |
| 数据页 | 趋势、总时长、日均和热力图正常纳入匿名活动；悬浮提示沿用原格式 |
| 网页视图 | 仅汇总网页统计口径内的匿名活动，不能把全部匿名时间当成网页时间 |

“像一个特殊应用”只决定呈现方式，不代表伪造一个可执行文件。匿名项不应获得真实应用的重命名、分类、关联、路径打开或标题设置入口。真实对象管理仍在现有分类卡片中进行。

开启匿名时，旧具名历史从常规统计中隐藏，可能使可见历史总计下降；不会生成等量匿名历史。恢复后旧历史重新出现，匿名期间的事实保持不变。

## 5. 阶段一：建立基线与确定数据方案

### 5.1 固定调查输入

- [x] 列出读取 `track`、域名 `enabled` 及排除过滤的真实消费者，分清计时、历史隐藏、目录和工具目标筛选用途。
- [x] 建立隔离测试库：两个普通应用、两个匿名目标、普通与匿名网站、已有具名历史、跨小时记录及导入记录；不用真实浏览历史。
- [x] 保存旧行为的确定性基线：排除后不新增事实，恢复后不补记；标出本项将改变的断言，保留封口与隐私保护断言。
- [x] 为未设置匿名的应用和网页建立受控时间与事件对照，保留基线标题、截止和可见性断言，并增加正常浏览器、普通/匿名站点、Web Sync 关闭及失效场景。采用既有基线测试加真实 transition/SQLite 对照，不声称对两个完整版本做过 Windows 使用回放。

### 5.2 选择一个事实模型

优先验证独立的匿名区间事实表，由 Rust data repository 写入；具名表保持已有身份约束。匿名表仅含无身份记录 ID、开始、结束、必要的有效截止与生命周期字段。网页维度可用不携带网站身份的区间子集或来源种类表达；保留该信息只用于维度计算，不能生成多个匿名展示身份。

最终采用独立表：现有具名表与网页关联要求真实身份，扩展它们会削弱原约束并引入可反查关系。新增表只保存 UUID、开始、结束、有效观察截止与网页子集布尔值；迁移追加到 16，小时聚合算法升级到 3。展示键只存在于派生读模型，未伪造可执行文件或具名外键。

- [x] 对比独立表与现有表显式类型扩展，验证当前约束、聚合、恢复和精确时间线的成本，记录最终选择及理由。
- [x] 定义 `named / anonymous` 领域区别和稳定的展示 key；key 不受语言、原应用及网站影响，不能与真实 exe、域名碰撞。
- [x] 定义匿名总量与匿名网页子集的唯一关系：网页标记不得作为第二份总活动事实累加。
- [x] 定义匿名记录 ID 和备份来源去重方式；可重复导入同一备份而不增长，不误合并两份独立记录。
- [x] 明确每个字段的必要性，移除所有可直接或间接反查真实对象的身份字段与外键。
- [x] 先用小型测试库完成创建、续写、封口、范围裁剪和重启恢复原型；尚未通过前不连接 UI。

### 5.3 冻结设置和升级语义

- [x] 让已有应用排除与域名排除设置从升级后的首次有效观察起采用匿名策略；不回填升级前空白。
- [x] 若持久化 key 继续兼容旧布尔值，在唯一读取 owner 转为明确领域策略，不在页面散布反向布尔解释。
- [x] 全局暂停、网页记录关闭与单项匿名策略分别处理：暂停不记录；网页关闭不产生网页匿名记录；原生浏览器是否计时仍由原生规则决定。
- [x] 标题开关偏好保持原值，匿名期间强制不记录标题，恢复后按原偏好生效。
- [x] 记录旧版本回退和旧备份读取的安全结果。若旧程序无法理解新 schema，不能承诺直接降级可写；明确迁移前备份与正式恢复路径。

阶段出口：模型、设置映射、无身份字段清单和区间归属均有可运行证明；否则暂停依赖这些结论的实现，继续独立测试准备。

## 6. 阶段二：先解决网页与标题的时序边界

网页观察可能晚于原生标题采样，先写入标题再删掉不能证明写前匿名。现有协议也不能独立证明同 exe 的具体窗口或配置身份。此阶段必须用事件顺序证明能力边界，不能靠前端遮盖。

- [x] 构造“原生窗口及标题先到、匿名网页观察后到”的确定性用例，定位第一处可能持久化身份的位置。
- [x] 实现写前策略：存在匿名网页规则时，仅足够新鲜且匹配的普通网页身份允许保存浏览器标题；未确认、过期或断联的不确定区间不保存标题，活动时长仍记录。分别验证没有匿名规则、已确认普通网页和非浏览器应用不受例外影响。
- [x] 为内存待判定状态定义有界容量、生命周期、失效代次和清空时机；不能把原始 payload 放入日志、磁盘队列或崩溃恢复记录。
- [x] 验证普通网页切匿名网页、匿名切普通、窗口/进程不匹配、扩展失效和事件乱序。v1 无接收端 tab/window ID 证明的边界已记录；实际多窗口交替验收转交维护者，不能以受控测试冒充。
- [x] 将标题抑制限制在上述未知身份例外及已确认匿名区间。若需要增加协议字段或修改 companion，完成字段必要性、旧客户端兼容和跨仓落点设计后，在本次跨仓实施授权内推进，不能以当前协议限制为由省略隐私验收。
- [x] 将原生活动资格从“必须有具名持久化 session”中分离为受运行时拥有的有效观察证明；保留前台来源、暂停、代次、新鲜度及截止检查。
- [x] 原始对象身份只参与内存资格判断；匿名网页不能保留指向具名原生会话的持久化关联。用无身份区间及生命周期规则完成截止传播。
- [x] 保留协议中的鉴权、无痕拒绝、来源匹配、停止通知、过期及旧请求拒绝。依照当前协议常量测试边界，不另造一套超时。
- [x] 匿名应用是浏览器时，域名、URL、favicon 和标题均不得沿网页链旁路保存。
- [x] 受控隐私用例配普通记录对照，覆盖身份确认与失效、设置保存与恢复、缺少技术字段的兼容客户端；真实快速切站与同 exe 多窗口矩阵转交维护者。行为例外严格采用第 1.1 节，不把 v1 证据描述为完备窗口证明。

阶段出口：明确已证明的隐私起点与协议兼容范围，匿名身份零落盘及普通记录对照同时通过。普通记录对照允许第 1.1 节已确认的未知网页身份标题抑制；其他身份落盘路径或普通记录损失仍阻塞上线。

## 7. 阶段三：实现持久化与追踪状态转换

### 7.1 schema、repository 与一致性

- [x] 按已选模型新增最小 migration；同时维护新库基线、schema 契约与受支持旧库直升路径，不删除旧迁移保护。
- [x] 添加时间边界、活动记录唯一性和必要索引约束；零长度不产生有效时长，负区间和非法输入被拒绝。
- [x] 通过 typed repository 接收脱敏后的输入，原始 payload 不进入匿名写入 API。
- [x] 匿名事实与派生 dirty/revision 在同一事务中改变；提交失败不发布成功刷新事件。
- [x] 用事务或既有转换锁保证策略保存、旧段封口与新策略观察顺序一致；覆盖设置成功但运行时应用失败的恢复路径。
- [x] 为异常退出和休眠后的未封口匿名记录沿用可信心跳截止原则，不把关机或无观察时间续算进去。

### 7.2 原生转换表

| 输入转换 | 应有结果 |
| --- | --- |
| 普通 A → 匿名 B | 在同一有效边界结束 A，开始匿名段，B 身份不落盘 |

### 写前隐私调查

桌面 `engine/tracking/runtime.rs` 通过 transition 调用 `active_session.rs`，后者把原生窗口标题传给 `repositories/sessions.rs::start_session`；该事务写入 `sessions.window_title` 和 `session_title_samples`。这条路径的标题策略读取全局与应用偏好，不依赖网页域名观察。

扩展两个 background 入口在标签或窗口事件之后异步查询活动标签，再发 HTTP 观察；Chromium 路径还等待 favicon。桌面收到观察后才在 `engine/web_activity/mod.rs::record_active_tab` 中读取域名策略。因此新增字段可以改善匹配和乱序处理，但无法让未送达的观察参与之前的写入决策。

反例：同一浏览器中普通站点与匿名站点都可使用相同窗口标题。扩展消息尚未到达或连接中断时，桌面看到的 exe、窗口身份和标题可完全相同，而两个场景需要不同的保存决策。保存可能泄露匿名标题，丢弃可能损失普通标题；无限等待又无法保证异常退出后的普通标题完整性。此处需要明确未知身份区间的产品策略，不能以测试覆盖率替代缺失的事实。

维护者已确认隐私优先：仅在存在匿名网页规则且无法确认身份的区间不保存浏览器标题，活动时长仍记录。普通行为对照以该明确例外为边界；其余普通活动与已确认普通标题保留。
