# 三页共用目的地详情弹窗执行方案

> 文档类型：How-to / 一次性执行方案
> 目标读者：Patina 维护者、负责本轮实现与审查的工程协作者
> 当前状态：已完成并归档
> 创建日期：2026-07-31
> 迁移结果：数据页试点已提升为 `destination` 独立能力，并接入今天页与历史页当日分布
> 完成去向：全部验收与对抗式审查通过后移入 `docs/archive/`

## 0. 执行结论

本轮不再把详情弹窗理解为“数据页的一个弹窗”，而应把它提升为一个独立的产品能力：

> 用户在 Patina 中看到一个具体应用或网页对象时，可以从该对象的图标进入同一套单对象时间详情。

执行后的唯一长期结构应为：

- [x] `今天`、`历史`、`数据`使用同一个详情弹窗实现。
- [x] 三个页面都以“双击应用或网页图标”作为鼠标入口。
- [x] 双击只决定打开哪个对象，不改变来源页面已有的单击语义。
- [x] 弹窗中的日期、时间轴、缩放、过滤、详情卡片和网页标题浮层完全一致。
- [x] 弹窗打开后拥有自己的日期与时间轴状态，不反向修改来源页面。
- [x] 数据页当前实现只是试点代码，迁移后不能继续成为另外两页依赖的 owner。
- [x] 泛用 Quiet Pro 原语继续留在 `shared/*`；带“应用/网页详情”产品语义的能力归独立 feature。

本方案只定义并执行“试点能力共享化与三页接入”。不重新设计已经确认的详情弹窗。

---

## 1. 第一性原理

### 1.1 用户操作的本质

用户双击的虽然来自三个不同页面，但提出的问题完全相同：

> 这个应用或网页在某一天具体何时出现、持续多久、由哪些片段或标题组成？

因此，页面不是详情能力的 owner，只是打开详情时提供上下文的入口。

- [x] 实现前确认三个入口提供的是同一种领域对象：应用或网页目的地。
- [x] 实现前确认弹窗回答的是同一种问题：单对象、单日、可缩放的活动详情。
- [x] 禁止因为来源页面不同而复制三份弹窗、三份时间轴或三份日期逻辑。
- [x] 禁止把来源页面名称写进弹窗的业务分支，导致三页行为逐渐分叉。

### 1.2 共享不等于全部放进 `shared/*`

`shared/*` 只承接稳定、低上下文依赖的通用能力。当前已经符合该条件的内容包括：

- `QuietDialog`
- `QuietDatePicker` / `QuietCalendar`
- `QuietTimelineTrack`
- `QuietAnchoredPopover`
- `QuietStepperSlider`
- 本地日期、时长、时间轴刻度等通用工具

而下列内容包含明确的产品语义，不应成为通用 UI：

- 应用与网页目标的身份解析
- 单对象活动详情读取
- 单日活动合并与最小时长过滤
- 详情弹窗状态
- 应用详情与网页详情卡片
- 网页标题详情浮层
- 详情弹窗专用文案契约
- 详情时间轴偏好与视口状态

因此长期 owner 应为新 feature，而不是 `shared/components`：

```text
src/features/destination/
├─ components/
├─ hooks/
├─ services/
└─ types.ts
```

- [x] 创建 `src/features/destination/` 作为跨页面“目的地”领域能力 owner；本轮先承载详情弹窗。
- [x] 目的地详情文案接入仓库唯一文案中心 `src/shared/copy/domains/destinationCopy.ts`，不在 feature 内自建 `copy/`。
- [x] 仅把已经稳定且不理解目的地语义的原语保留在 `src/shared/*`。
- [x] 不把详情读取、页面适配或应用/网页判断塞入 `app/*`。
- [x] 不让 `dashboard` 或 `history` 直接导入 `features/data/*`。
- [x] 不建立从 `destination` 反向依赖 `dashboard`、`history` 或 `data` 的关系。

### 1.3 同一能力必须只有一套状态机

三页一致不能只靠“样式看起来一样”，而必须由同一组件、同一读取模型和同一状态机保证。

- [x] 对象切换时，旧对象数据不能被新对象继承。
- [x] 同一对象切换日期时，可保留旧日内容直到新日数据就绪，避免白屏和闪屏。
- [x] 异步请求返回乱序时，只接受最后一次有效请求。
- [x] 关闭弹窗后，来源页面的筛选、多选、滚动和日期保持原状。
- [x] 同一个时间轴缩放偏好在三个入口中一致。
- [x] 同一个最小时长偏好在三个入口中一致。

### 1.4 “图标双击”与可访问性必须同时成立

双击是鼠标手势，不应成为唯一可达路径。

- [x] 鼠标用户仅在对象图标命中区双击时打开详情。
- [x] 图标悬浮时使用手型光标，时间轴色块仍使用普通箭头。
- [x] 键盘用户可在对应对象行获得焦点后按 `Enter` 打开相同详情。
- [x] 需要独立聚焦的图标使用真实 `button`；不得制造嵌套按钮。
- [x] 如果图标位于现有行级 `button` 内，图标只作为双击命中区，键盘入口由行级 `Enter` 提供。
- [x] `Space`、`Ctrl+Click`、单击等页面既有交互不得被重新解释为打开详情。

## 4. 目标架构

### 4.1 依赖方向

```text
Dashboard ─┐
History ───┼──> destination ───> shared Quiet Pro primitives
Data ──────┘              │
                          └──> existing platform/data read gateways
```

必须满足：

- [x] 来源页面只负责构造打开请求与渲染入口。
- [x] `destination` 负责目的地详情弹窗、读取、状态、时间轴和卡片，并从统一 `UI_TEXT` 读取文案。
- [x] `destination` 只通过现有 typed gateway / feature service 读取数据。
- [x] 页面组件不新增 SQL、Tauri `invoke` 或底层数据库访问。
- [x] `shared` UI 原语和通用服务不理解“应用详情”“网页详情”“标题数量”等产品概念；专属文字只登记在既有文案中心。

### 4.2 建议目录

```text
src/features/destination/
├─ components/
│  ├─ DestinationDetailDialog.tsx
│  ├─ DestinationDetailDialogEntry.tsx       # 延迟加载入口与预加载边界
│  ├─ DestinationDetailTimeline.tsx
│  └─ DestinationDetailRecords.tsx
├─ hooks/
│  ├─ useDestinationDetail.ts
│  └─ useDestinationDetailLauncher.ts
├─ services/
│  ├─ destinationDetailReadModel.ts
│  ├─ destinationDetailState.ts
│  ├─ destinationDetailTimelineViewport.ts
│  └─ destinationDetailPreferenceStorage.ts
└─ types.ts

src/shared/copy/domains/
└─ destinationCopy.ts
```

- [x] 公共类型集中在 `types.ts`；来源页面按仓库现有惯例显式导入允许使用的组件、Hook 和类型文件。
- [x] `destinationCopy.ts` 同时提供 `zh-CN` 与 `en-US`，并通过现有 `bundle.ts` 合入 `UI_TEXT`。
- [x] `destination` 组件只从 `src/shared/copy/index.ts` 使用文案，不直接导入 domain 文件。
- [x] 来源页面只允许导入延迟入口 `components/DestinationDetailDialogEntry.tsx`、`hooks/useDestinationDetailLauncher.ts` 和 `types.ts`，不得静态导入厚弹窗实现或 `destination/services/*`。
- [x] 禁止为迁移长期保留 `DataDestinationDetail*` 转发壳。
- [x] 如果短暂兼容壳对分步编译是必要的，必须在本任务结束前删除。

### 4.3 公共打开契约

建议使用来源无关的打开请求：

```ts
type DestinationDetailMode = "app" | "web";

interface DestinationDetailTarget {
  mode: DestinationDetailMode;
  key: string;
  displayName: string;
  secondaryText?: string;
  color: string;
  iconUrl?: string;
}

interface DestinationDetailOpenRequest {
  target: DestinationDetailTarget;
  initialDateKey: string;
}
```

契约原则：

- [x] `target.key` 使用读取层已经认可的稳定对象键，不用显示名当主键。
- [x] `mode` 明确区分应用与网页，不从字符串格式猜测。
- [x] `initialDateKey` 只决定首次聚焦日期。
- [x] 契约不携带 `sourcePage` 来控制弹窗行为。
- [x] 契约不直接携带数据页的 `DataTrendRangeSelection`。
- [x] 契约不允许来源页面把预聚合活动数组直接塞给弹窗。
- [x] 弹窗根据对象与日期读取权威详情，避免三个页面传入三种统计口径。

### 4.4 运行参数

详情能力仍需要已有的读取失效信息与合并规则。建议以独立运行参数传入：

```ts
interface DestinationDetailRuntimeContext {
  refreshKey: number;
  mappingVersion: number;
  mergeThresholdSecs: number;
}
```

- [x] 运行参数只用于缓存失效与读取语义。
- [x] 不把来源页面的视觉状态加入运行参数。
- [x] 三个页面从同一上层设置来源取得这些参数。
- [x] 如果今天页当前没有某参数，优先由现有上层 props 传递，不新增全局单例。

## 5. 日期与状态规则

### 5.1 初始日期

| 来源 | `initialDateKey` | 说明 |
| --- | --- | --- |
| 今天 | 本地今天 | 与今天页语义一致 |
| 历史 | 历史页当前选中日期 | 不跳回今天 |
| 数据 | 按数据页当前范围解析出的试点初始日期 | 保持现有试点行为 |

- [x] 数据页适配器把当前范围转换为一个初始日期后再打开弹窗。
- [x] 迁移后 `DestinationDetailDialog` 不依赖 `DataTrendRangeSelection`。
- [x] 历史页必须传当前历史日期，而不是调用时的系统今天。
- [x] 今天页跨过本地零点后再次打开，应使用新的本地今天。

### 5.2 弹窗内日期

- [x] 弹窗继续使用 `QuietDatePicker` / `QuietCalendar`。
- [x] 中间日期按钮、左右箭头、日历内容与 Quiet Pro 规范一致。
- [x] 日期不是只能在最近七天内选择。
- [x] 最大日期为本地今天，未来日期不可选。
- [x] 左右箭头按一天移动。
- [x] 昨天、今天及普通日期文案继续使用统一格式。
- [x] 弹窗内切换日期不改变历史页日期或数据页范围。
- [x] 切回今天时，时间轴初始视口按当前时间定位，不固定在 12:00。

### 5.3 异步状态

| 状态 | 可见内容 | 是否改变容器尺寸 |
| --- | --- | --- |
| 首次打开 | 稳定弹窗骨架与固定占位 | 否 |
| 同对象换日 | 保留上一日内容，静默刷新 | 否 |
| 换对象 | 固定骨架，禁止显示旧对象 | 否 |
| 刷新失败且有旧数据 | 旧数据 + 轻量重试 | 否 |
| 刷新失败且无数据 | 固定错误态 + 重试 | 否 |
| 无记录 | 固定空态 | 否 |

- [x] 保留当前“同对象换日可保留旧数据”的抗闪策略。
- [x] 对象身份变化时立即隔离旧对象内容。
- [x] 每个请求使用对象、日期与版本组合的 request key。
- [x] 卸载、关闭或再次请求后，旧 Promise 不得更新当前状态。
- [x] 不显示“正在更新”等会跳动的临时文字。
- [x] 快速左右切换时最后一次意图获胜。

### 5.4 偏好持久化

- [x] 时间轴窗口时长成为详情能力共享偏好，不再使用 Data owner 命名。
- [x] 最小时长成为详情能力共享偏好。
- [x] 三个入口读取和写入同一份偏好。
- [x] 兼容读取旧 Data 试点 key，避免用户设置被重置。
- [x] 第一次成功写入新 key 后完成迁移。
- [x] 兼容读取逻辑有测试和明确删除条件，不形成永久双写。

## 6. 入口交互规范

### 6.1 公共准备与打开流程

为避免双击打开时先出现空壳，入口需要复用数据页已有的“意图捕获”思路：

1. 第一次按下对象图标时记录目标并允许预备读取。
2. 第二次点击形成双击后正式打开。
3. 键盘 `Enter` 直接执行准备 + 打开。
4. 关闭时把焦点还给原入口。

- [x] 提供 `useDestinationDetailLauncher`，统一 `prepare`、`open`、`close` 与焦点恢复。
- [x] `prepare` 不改变页面选中状态。
- [x] `open` 使用捕获的对象快照，防止双击期间列表刷新导致目标漂移。
- [x] `close` 清理弹窗状态和锚点引用。
- [x] 入口卸载时不尝试把焦点还给不存在的元素。

### 6.2 数据页

当前数据页既有已选图标，也有列表行图标。迁移时应统一为图标命中：

- [x] 已选图标双击继续打开对应对象详情。
- [x] 列表行只在图标命中区双击时打开详情。
- [x] 移除列表行空白、名称、时长区域的双击详情行为。
- [x] 列表单击保持单选。
- [x] `Ctrl+Click` 保持增减多选。
- [x] 多选后普通单击仍按已确认规则回到单选。
- [x] `Enter` 打开当前聚焦对象详情。
- [x] `Space` 保持选择语义。
- [x] 详情关闭后多选集合、顺序、搜索词、滚动位置不变。
- [x] 图表与热力图双击历史跳转不受影响。

DOM 约束：数据列表当前是行级 `button`。不得在其中再嵌套按钮。

- [x] 图标使用带 `data-destination-detail-trigger` 的命中 span。
- [x] 行级双击处理只在事件路径包含该命中区时打开详情。
- [x] 行级 `Enter` 作为键盘等价入口。
- [x] 为该特殊结构补充“无嵌套 button”测试。

### 6.3 今天页（Dashboard）

当前今天页的“常用应用”卡片具有独立图标容器。

- [x] 为应用图标接入详情入口，不让整张卡片变成双击入口。
- [x] 单击图标不改变卡片或页面状态。
- [x] 图标可聚焦，并提供“查看 {应用名} 详情”的可访问名称。
- [x] 双击图标打开本地今天的详情。
- [x] `Enter` 打开同一详情。
- [x] 分类占比圆点与分类环图不接入单对象详情。
- [x] 今天页当前没有网页对象列表时，不为了本任务制造新的网页 UI。
- [x] 未来今天页出现网页对象图标时，必须复用同一公共入口契约。

### 6.4 历史页

本轮按维护者确认收窄范围：历史页只接“当日分布”右侧列表中的应用与网页图标；时间线主图、时间线列表和时间线放大弹窗不接对象详情。

- [x] 当日分布为应用模式时，应用图标可打开应用详情。
- [x] 当日分布为网页模式时，网页图标可打开网页详情。
- [x] 分类模式的颜色点不开放详情。
- [x] 时间线应用列表、网页列表、主时间轴与放大弹窗保持现有交互，不开放对象详情。
