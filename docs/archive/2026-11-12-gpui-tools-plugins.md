# GPUI 工具页与可安装 Rust 插件执行方案

2026-11-12 完成并归档。GPUI 工具页支持随附的专注、提醒和用户单独安装的 Rust 面板。运行时边界见[架构](../architecture.md#46-gpui-实验版工具插件)，安装与更新步骤见[插件作者指南](../../desktop/plugins/counter/README.md)。

## 从用户动作确定边界

| 用户要做的事 | 由谁保证 | 怎样看出设计成立 |
| --- | --- | --- |
| 安装一个新工具 | 宿主读取插件包，登记身份、版本和面板入口；插件提供内容与可执行动作 | 用原来的 Patina 二进制安装一个新包，立即能进入面板并完成一次操作 |
| 开始专注，关掉窗口去工作 | 常驻宿主保存任务并按时唤起插件；插件决定如何推进阶段；GPUI 负责显示 | 窗口进程退出后仍能到期，重开页面显示同一任务，历史只增加一次 |
| 卸载不再使用的工具 | 宿主撤销该插件的执行资格、调度、订阅和通知；用户数据按插件身份独立保留 | 单独卸载提醒后，旧提醒不再响，专注与活动记录仍向前推进 |
| 用 Rust 写自己的面板 | SDK 提供控件、事件和可测试的 Rust 类型；宿主负责绘制、焦点与跨进程传递 | 作者从独立 Cargo 项目编译、安装、改动和重载面板，整个过程无需重编 Patina |

当前 GPUI [主窗口](../../desktop/patina/src/main_window.rs)已提供分类、设置等页面。[常驻进程](../../desktop/patina/src/window_process.rs)可独立于窗口运行。现版[工具工作区](../../src/features/tools/components/Tools.tsx)、[工具引擎](../../src-tauri/src/engine/tools)和[存储实现](../../src-tauri/src/data/repositories/tools)是迁移行为的对照。工具页归属与共用通知偏好见[产品范围](../product-principles-and-scope.md#76-轻量主动工具页边界)。

## 1. 先走通一个可安装的交互面板

- [x] 在主侧栏「分类」与「设置」之间加入「工具」，使用同级图标按钮、间距、选中态和可访问名称。进入后沿用 Quiet Pro 页头。页内工具列表切换当前面板，「管理工具」承载从本地文件安装和卸载；所有工具卸载后仍能从此处安装或找回附送工具。[主窗口](../../desktop/patina/src/main_window.rs) · [Quiet Pro 页面与组件](../quiet-pro-component-guidelines.md#8-页面骨架与原型)
- [x] 实作最小插件包，由清单、Rust 编译的 Wasm 模块和需要的资源组成。清单声明稳定插件 ID、版本、所需 API 版本、面板入口与所需能力。常驻宿主用 Extism 按需加载；窗口取得面板描述，把用户动作交回同一插件。首版只为示例实现文本、按钮和动作回传。[Extism Rust PDK](https://github.com/extism/rust-pdk)
- [x] 提供独立 Cargo 示例和实际可运行的构建、安装、重载步骤。示例插件显示一个计数，按键后数值加一。改动按钮文字，只重编并重载该包；依次验证鼠标点击、键盘激活、面板关闭重开、卸载后入口消失。以这个包检验 SDK，不在主窗口按插件 ID 特判示例。

## 2. 让安装和卸载具有确定结果

第 1 节复验使用独立编译的两个计数插件包。在临时 Windows 配置下，`pages` 测试中的 `tools::install_update_uninstall_counter` 从真实侧栏和文件选择器完成安装，鼠标与 Enter 各加一，切页返回保留计数，更新文案后再加一，卸载后入口消失。`patina-tool-host` 的 `install_update_restart_uninstall` 另验证预览后文件改变、无效入口的更新回滚、实例代次、插件数据隔离和重装保留计数。[示例与构建步骤](../../desktop/plugins/counter/README.md)

- [x] 首次使用时从随附包安装专注和提醒。随附来源仅用于默认安装和本地重装，两个包与外部包共用加载、更新、卸载路径。保存用户主动卸载的选择；重启和应用升级后检查，只有显式重装才重新出现。
- [x] 安装前展示来源与所需能力，校验包内路径、清单、模块、API 兼容性和插件身份。更新时保护原插件身份与数据，防止同名外部包覆盖官方包；新增权限需获得授权。验证失败、写入中断或新版本启动失败时，重启仍可使用上一可用版本。
- [x] 将数据、计时和事件订阅按插件 ID 隔离。仅开放该插件获准的宿主操作，限制单次调用时间与内存；插件超时或面板渲染失败时，工具页给出失败原因和重试入口，其他工具和自动记录仍可用。验证一个插件不能读取另一插件数据或直接查询 Patina 数据库。
- [x] 卸载前列出会停止的任务和会保留的数据。确认后先停止接收新动作，结算活动任务并撤销该安装实例的调度、订阅、Mini 状态和排队通知，再释放实例。用到期与卸载同时发生、卸载中断后重启、同 ID 重装后收到旧回调三个场景核对结果。保留的历史与规则不能让旧任务自动复活。

## 3. 第一个随附插件：专注

- [x] 从一个番茄钟开始。在 Rust 插件中定义开始、暂停、继续、结束和阶段转换；常驻宿主按任务身份保存状态和下次到期时刻。显示剩余时间以保存的时间点计算，重复唤起同一到期事件只推进一次。按现有[番茄引擎](../../src-tauri/src/engine/tools/pomodoro.rs)逐项比对。
- [x] 补齐自由专注、休息、任务编辑和历史。优先复用现有规则及存储语义，迁移样本覆盖已完成、暂停和运行中任务。记录每条旧记录如何映射到新插件身份；重复迁移、备份合并后核对时长与历史条数。[自由专注](../../src-tauri/src/engine/tools/free_focus.rs) · [现有架构与恢复约定](../architecture.md)
- [x] 用独立测试库走完「开始 → 关闭所有窗口 → 到期 → 从通知操作 → 重开工具页」。再在运行中卸载专注，核对历史截止于卸载时刻，重装可读且计时保持停止。另测休眠唤醒、宿主重启以及通知动作重复到达。

## 4. 第二个随附插件：提醒

- [x] 迁移单次、重复和待确认提醒。插件拥有规则与下一次触发的计算，宿主拥有唤醒和投递。用同一批日期、时区和任务样本核对重复日程、跨日、休眠错过到期与重启后待确认的行为。[日程规则](../../src-tauri/src/domain/reminder_schedule.rs) · [定时提醒引擎](../../src-tauri/src/engine/tools/timed_reminders.rs)
- [x] 按现版范围迁移使用时长提醒。由记录侧按用户选定的目标计算累计时长，宿主向获准的插件投递阈值事件。用应用、分类和网站样本比对暂停记录、切换目标、延后和关闭规则的结果。[使用提醒引擎](../../src-tauri/src/engine/tools/activity_reminders.rs)
- [x] 在专注计时期间卸载提醒。核对到期队列和状态入口已撤销，正在运行的专注及自动记录继续推进；重装后能看到保留的规则，用户重新启用后才开始调度。再以空库验证两个插件都可独立安装。

## 5. 接入通知与 Mini，完成桌面验收

- [x] 共用通知方式与提示音由宿主保存，两个插件提交内容与动作。验证默认独立通知不抢焦点、窗口内呈现偏好、同一事件只响一次，通知失败可重试；过期按钮不能操作已推进或已卸载的任务。[通知生命周期](../architecture.md#工具通知生命周期)
- [x] 按现有筛选、排序和数量规则向主窗口及 Mini 提供状态。点击状态直达对应插件面板。验证主窗已回收、从有未保存编辑的页面跳转、目标已卸载、两个插件均未安装四种情况。[Mini 生命周期](../architecture.md#mini-生命周期)
- [x] 由 Windows UI Automation 从实际侧栏进入，验证折叠及带文字导航、键盘次序、安装取消、卸载确认后的焦点、空列表、插件错误与重试。使用中英文、明暗主题及不同 DPI 检查截断和可读性。宿主及官方插件文案遵循[本地化契约](../localization.md#rust-原生表面)。
- [x] 在独立测试库运行 Rust 插件契约、数据迁移和桌面集成测试。沿用[GPUI 验收方法](../working/2026-11-11-gpui-tray-mini.md)比较无插件、工具空闲、关窗计时和反复装卸后的整棵进程树，记录内存、CPU、句柄及记录连续性。将本次命令、样本、结果与剩余差异记入本方案；实际交付的插件 API 和安装步骤分别归入架构与作者文档。[工程质量](../engineering-quality.md#51-测试分层与稳定性治理)

## 验收记录

### 数据与后台行为

| 场景 | 实际核对 |
| --- | --- |
| 安装、更新与撤销 | 两个独立编译的计数插件在同一宿主更新。包签名绑定发布者，预览摘要绑定用户确认的文件。写入被 Windows 拒绝、新入口缺失、外部包冒用官方 ID 或其他作者 ID 时，已有实例和私有数据仍然可读。卸载过程中断后重开，旧实例不能接收动作，新实例可恢复保留数据。[包测试](../../desktop/tool-host/tests/packages.rs) · [随附包测试](../../desktop/patina/src/bundled_tools.rs) |
| 专注历史 | 专注与提醒沿用原 SQLite 行和备份身份。以运行中任务和既有历史启动宿主，重复处理同一到期时刻只增加一次完成计数，历史仍绑定原任务。共用仓储测试覆盖暂停、自由专注休息、改名、已完成任务和重复备份合并。[专注历史](../../src-tauri/src/data/repositories/tools/focus_history.rs) · [恢复回归](../../src-tauri/src/data/repositories/tools/free_focus_tests.rs) |
| 纯托盘计时 | 在真实窗口创建一分钟番茄钟，启动后关闭主窗口，从到期通知启动短休息，重开后读到运行中的休息及一次完成计数。定时提醒在主窗已释放时单独呈现，保持原前台窗口，确认后记录转为已完成。跨休眠时段以已过期的持久化时刻和重新打开的宿主复验；Windows 恢复与时钟变更消息会唤醒调度。[桌面回归](../../desktop/patina/tests/pages/tools.rs) |
| 提醒与通知 | 应用、分类、网站使用同一组已结束活动，三个阈值均触发，延长后的旧动作被拒绝，关闭规则后停止调度。日历复用已覆盖跨日、缺失与重复本地时间的日程算法。通知分配后修改偏好保留当前载体，重复呈现复用事件身份；模拟呈现失败三次后可手动重试。试听与实际提示共用同一份 Windows 合成音实现。[日程测试](../../src-tauri/src/domain/reminder_schedule.rs) · [通知服务测试](../../desktop/patina/src/tool_service.rs) |
| 导航与卸载 | Windows UI Automation 覆盖图标与文字侧栏、文件选择器取消、无效包重试、Escape、Enter 和卸载后的焦点。Mini 在主窗回收后直接进入提醒面板；存在未保存设置时，分别走过取消和保存后跳转。卸载工具后，状态入口消失。英文深色在 120 DPI、中文浅色在 96 DPI 运行；96 DPI 通过测试进程的 Windows 兼容模式获得。 |

### 托盘资源对照

Windows 交互桌面运行 `tools::tool_tray_resources`，输出为 `artifacts/runtime-smoke/tools-20261112T053559Z/`。四组均使用同一临时库和固定前台应用。每组覆盖 30 秒，以 5 秒间隔采集整棵进程树。内存与句柄取七个样本的中位数，CPU 取六个采样间隔的单核平均占用率。记录进度取同一活动会话最后成功采样的时间差。

| 托盘状态 | 私有提交 MiB | 工作集 MiB | 单核 CPU | 句柄 | 记录推进 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首次启动，随附工具空闲 | 26.64 | 150.49 | 0.16% | 1243 | 27.45 秒 |
| 关闭主窗，专注仍在计时 | 38.78 | 173.99 | 0.42% | 1244 | 30.50 秒 |
| 卸载全部工具，关闭主窗 | 33.44 | 171.98 | 0.16% | 1242 | 30.50 秒 |
| 重装并卸载提醒五轮，再关闭主窗 | 33.65 | 172.22 | 0.57% | 1240 | 30.63 秒 |

空闲组在首次打开工具页前采集，后两组已加载过 Wasm。数字描述这次运行的四个状态。原始 JSONL 同时保留各进程和各采样时刻，可按相同顺序复测。

### 重跑

仓库全量门禁 `pnpm run check:full` 通过，包括 232 个浏览器 UI 用例、Rust 回归、Clippy 和依赖审计。GPUI 的八个 Windows 工具用例另行在真实窗口运行，覆盖纯托盘番茄、独立与窗口内通知、Mini、装卸、键盘及资源采样。插件宿主另验燃料耗尽、无数据库导入、签名与更新回滚；原生服务另验三类使用阈值、中断恢复、跨期推进与通知重试。

在仓库根目录运行。桌面 UI 用例使用独立临时配置和 SQLite 数据库。按[计数插件指南](../../desktop/plugins/counter/README.md)生成两个签名包，第一份保留英文按钮 `Add one`，第二份只把该按钮改为 `Increment`。将两份包的绝对路径分别放入 `PATINA_COUNTER_PACKAGE` 和 `PATINA_COUNTER_UPDATE`，签名测试密钥路径放入 `PATINA_COUNTER_SIGNING_KEY`。将 `PATINA_TOOL_SAMPLES` 指向本次专用的空输出目录；资源测量使用[桌面迁移基线](../working/2026-11-11-gpui-tray-mini.md)的 Windows 采样器。

```powershell
cargo +1.99.1 test --locked --manifest-path desktop/Cargo.toml -p patina-tool-host -- --include-ignored
cargo +1.99.1 test --locked --manifest-path desktop/Cargo.toml -p patina-gpui --lib -- --test-threads=1
cargo +1.99.1 test --locked --manifest-path desktop/Cargo.toml -p patina-gpui --test pages tools:: -- --ignored --test-threads=1
pnpm run check:full
```

GPUI 测试用了继承 `dev` 的独立 Cargo profile，使验收二进制与正在使用的调试程序可以并存。外部安装包采用单个签名 JSON 文件，Wasm 作为数据嵌入，宿主无需解压文件路径。通知的失败重试和逾期恢复采用故障注入与可控时刻；前台焦点、实际计时、安装与窗口回收使用真实 Windows 桌面。交付范围是 GPUI 实验工作区和本地包分发。
