## 1. 目标与非目标

### 1.1 目标

在数据页“应用趋势”区域增加一级“分类”视图，使用户能从应用维度切换到应用分类维度查看同一批前台应用活动数据。

最终一级切换顺序固定为：

```text
应用 ｜ 分类 ｜ 网页
```

当网页同步服务关闭时，显示：

```text
应用 ｜ 分类
```

分类视图必须支持：

- 按应用分类聚合总时长、占比、平均时长、活跃天数和峰值日。
- 分类列表搜索。
- 单选和 `Ctrl` 多选，最多选择 7 个分类。
- 独立保留分类选择状态，不污染应用和网页选择状态。
- 复用既有一级时间范围，包括“总计、近 7 天、近一周、近一月、近一年”。
- “总计”按当前所选分类中所有成员应用的最广始末范围展示。
- 趋势图和热力图随分类选择同步变化。
- 保持 Quiet Pro 的既有视觉、交互和响应式行为。

### 1.2 非目标

本次明确不做：

- [x] 不把网页域名活动并入应用分类统计。
- [x] 不新增“网页分类”或应用、网页统一分类体系。
- [x] 不新增分类详情页、分类历史详情或双击详情行为。
- [x] 不在数据页提供分类管理、拖拽归类或快捷改分类操作。
- [x] 不修改应用分类的持久化模型和分类管理页职责。
- [x] 不新增数据库表、迁移、Tauri 命令、Rust 聚合逻辑或 Web Sync 协议字段。
- [x] 不重新设计数据页布局、图表或热力图。
- [x] 不借本任务重构无关的数据页代码或共享组件。
- [x] 不在本方案阶段直接决定下一个发布版本号。

## 2. 第一性原理

### 2.1 数据事实与展示视图必须分离

Patina 记录的事实是活动时段及其应用身份。分类不是新的事实来源，而是对既有应用事实施加的一层映射：

```text
活动时段 → 应用身份 → 有效应用分类 → 分类聚合结果
```

因此，本次实现应复用数据页已经加载的应用聚合上下文，在前端 read model 中派生分类结果，不能为了一个展示维度复制采集、存储或 IPC 链路。

- [x] 分类被定义为“应用聚合结果的派生视图”。
- [x] 分类不拥有独立活动事实。
- [x] 实现中只消费现有应用聚合上下文，不发起第二套分类事实查询。
- [x] 分类映射变更后，仅使派生 read model 失效并重算，不重写历史活动事实。

### 2.2 守恒优先于视觉完整

同一统计范围内，每个有效应用只能归入一个有效分类。分类聚合后的总量必须与应用聚合总量守恒：

```text
Σ 分类总时长 = Σ 纳入统计的应用总时长
```

逐日和逐月也必须满足同一不变量：

```text
对任意日期 d：Σ 分类日时长(d) = Σ 应用日时长(d)
对任意月份 m：Σ 分类月时长(m) = Σ 应用月时长(m)
```

- [x] 使用整数时长值聚合，避免先换算再求和造成舍入误差。
- [x] 未分类应用统一进入现有“未分类”有效分类，不能被静默丢弃。
- [x] 对重复应用桶先沿用现有应用 read model 的身份合并规则，再做分类映射。
- [x] 单元测试对总量、逐日量和逐月量分别验证守恒。

### 2.3 不重复计算网页活动

网页活动通常发生在浏览器应用活动内部。若将浏览器应用时长和网页域名时长同时汇入分类，就会产生重叠：

```text
浏览器前台时长 ⊇ 可识别的网页活动时长
```

在没有“网页区间从浏览器区间扣除”或其他可证明的重叠消解模型前，应用分类与网页分类不能直接相加。因此 v1 只聚合应用维度。

- [x] “分类”在本版本中完整名称是“应用分类”。
- [x] 网页同步是否启用，不改变分类统计来源。
- [x] 浏览器应用仍按其应用分类参与统计，网页域名不额外加入。
- [x] 文案、类型名和测试名称不得暗示这是应用与网页的统一分类。

### 2.4 交互状态必须可预测

“应用”“分类”“网页”是三个并列的观察镜头。切换镜头不应清空其他镜头的选择，也不应把一种对象的选择解释为另一种对象。

- [x] 三种模式分别维护选择状态。
- [x] 分类多选上限与现有目标选择规则一致，为 7。
- [x] 切换离开分类再切回时，恢复本次会话中的分类选择。
- [x] 网页同步关闭时，应用和分类状态仍正常工作。
- [x] 分类搜索词独立维护，不能覆盖应用或网页搜索词。
- [x] 被删去、重命名或重新映射后失效的分类选择应通过既有 reconcile 规则安全收敛。

### 2.5 最小所有权与可逆性

该功能属于数据页展示域，且不改变持久化契约。最小正确实现应停留在 `features/data` 与必要的本地化、测试、样式入口中。

- [x] 主要所有者是 `src/features/data`。
- [x] 分类标签和颜色继续由 `shared/classification` 提供，不复制分类定义。
- [x] 一级切换继续使用现有 Quiet Pro 分段控件，不新增共享组件。
- [x] 若实现被移除，现有应用、网页和“总计”逻辑仍能独立保留。
- [x] 若发现必须修改 Rust、数据库、Web Sync 协议或分类持久化，停止实施并重新确认范围。

## 3. 已确认的产品与交互决策

### 3.1 模式可见性

| 网页同步状态 | 一级切换 | 默认模式 | 说明 |
| --- | --- | --- | --- |
| 开启 | `应用｜分类｜网页` | 应用 | 分类始终位于应用和网页之间 |
| 关闭 | `应用｜分类` | 应用 | 不再因网页关闭而隐藏整个一级切换 |
| 运行中关闭网页同步 | `应用｜分类` | 应用或当前分类 | 若当前为网页，安全回退应用；若当前为分类，保持分类 |
| 运行中开启网页同步 | `应用｜分类｜网页` | 保持当前模式 | 不自动跳转网页 |

确认项：

- [x] 固定顺序为“应用、分类、网页”。
- [x] “分类”不是“应用”下的二级筛选。
- [x] 网页关闭时仍显示“应用、分类”。
- [x] 当前网页模式在网页能力消失后回退到应用。
- [x] 当前分类模式不受网页能力开关影响。

### 3.2 分类列表项信息结构

每个分类列表项从左到右包含：

1. 分类色标或现有分类识别元素。
2. 分类名称。
3. 次要信息：该分类包含的应用数量。
4. 当前范围内的分类总时长。
5. 当前范围内的分类占比。

约束：

- [x] 分类色使用现有 `AppClassification.getCategoryColor(...)` 结果。
- [x] 分类名称使用现有本地化标签，不创建第二套分类命名。
- [x] 应用数量按合并后的唯一应用身份计数，不按原始活动片段计数。
- [x] 分类项只负责选择，不提供双击详情、右键详情或快捷归类。
- [x] 色标不能成为唯一的分类识别方式，文本名称必须始终可见。
- [x] 分类色只用于信息识别，列表容器、选中背景和周围界面继续使用 Quiet Pro 语义 token。

### 3.3 选择行为

- [x] 普通点击：用当前分类替换选择。
- [x] `Ctrl + 点击`：切换当前分类是否在多选集合中。
- [x] 最多选择 7 个分类，沿用既有上限反馈方式。
- [x] 多选趋势按多个分类分别显示系列，汇总指标按所选分类合计。
- [x] 多选热力图按所有所选分类的成员应用并集计算。
- [x] 分类选择集合不与应用或网页选择集合互相转换。
- [x] 键盘操作、焦点环、选中态和禁用态沿用现有列表项契约。

### 3.4 “总计”行为

分类模式下，“总计”按所选分类成员应用的最广有效始末范围展示：

```text
起点 = 所有所选分类成员应用中最早的有效活动时间
终点 = 所有所选分类成员应用中最晚的有效活动时间
```

补充规则：

- [x] 单选分类时，范围是该分类全部成员应用的最广范围。
- [x] 多选分类时，范围是所有所选分类成员应用并集的最广范围。
- [x] 未选择或选择失效时，沿用现有安全默认选择策略，不创建空选择特例。
- [x] “总计”只改变范围解析，不改变活动事实和分类映射。
- [x] 分类模式的总计标签、左右切换和边界禁用状态与应用模式一致。

### 3.5 详情与管理边界

- [x] 应用模式继续支持既有应用详情能力。
- [x] 网页模式继续支持既有网页详情能力。
- [x] 分类模式不显示可点击的对象详情入口。
- [x] 分类模式不显示快捷分类操作，因为分类本身不是待归类对象。
- [x] 修改分类归属仍由分类管理页负责。
- [x] 组件实现应通过明确的能力参数区分，而不是依靠 DOM 阻止点击或对分类伪造应用身份。

## 4. 统计口径与数据契约

### 4.1 输入

分类 read model 的唯一事实输入是现有 `DataTrendAggregateContext` 中的应用聚合桶及当前分类映射版本。

每个应用桶至少提供：

- 应用稳定键。
- 展示名称。
- 可执行文件名。
- 总时长。
- 逐日时长。
- 逐月时长。

分类映射由现有 `AppClassification` 服务解析。

### 4.2 有效分类

对每个合并后的应用选项执行一次有效分类解析：

```text
effectiveCategory(app) = AppClassification.mapApp(exeName, hints)
```

如果当前分类系统返回“未分类”，它仍是一个有效聚合桶。

- [x] 同一应用身份在一次 read model 构建中只解析一次有效分类。
- [x] 分类键使用稳定内部标识，显示标签变化不能造成选择键变化。
- [x] 分类标签和颜色在输出阶段从稳定分类键解析。
- [x] 分类映射版本变化时重建分类选项并 reconcile 选择。

### 4.3 分类桶

对每个有效分类 `c`：

```text
category.totalDuration(c)
  = Σ app.totalDuration，条件为 effectiveCategory(app) = c

category.dayDurations(c, d)
  = Σ app.dayDurations(d)，条件为 effectiveCategory(app) = c

category.monthDurations(c, m)
  = Σ app.monthDurations(m)，条件为 effectiveCategory(app) = c

category.appKeys(c)
  = 所有属于 c 的唯一应用键集合
```

实现检查：

- [x] 使用 `Map` 或等价的单遍聚合结构，避免分类数 × 应用数的重复扫描。
- [x] 成员应用键去重。
- [x] 逐日和逐月键沿用现有规范化格式。
- [x] 时长为 0 的日期可以保留在图表补点阶段，不应制造虚假活动日。
- [x] 输出顺序默认按当前范围总时长降序；相同时使用稳定分类顺序或稳定键排序。

### 4.4 列表指标

分类列表中的指标按当前一级时间范围计算：

| 指标 | 定义 |
| --- | --- |
| 总时长 | 分类内所有成员应用在当前范围的时长和 |
| 占比 | 分类总时长 ÷ 当前范围全部应用总时长 |
| 应用数量 | 分类内合并后的唯一应用身份数 |
| 平均时长 | 沿用现有数据页“平均”口径与除数，不创建分类专属公式 |
| 活跃天数 | 分类成员应用有正时长的日期并集数量 |
| 峰值日 | 分类成员应用合计时长最高的日期；并列规则沿用现有 read model |

- [x] 百分比的分母与应用列表现有分母一致。
- [x] 搜索只过滤可见列表，不改变汇总分母和统计结果。
- [x] 应用数量不随搜索词变化。
- [x] 所有格式化继续使用现有时长和百分比格式化工具。

### 4.5 已选分类汇总

令已选分类集合为 `S`：

```text
selectedAppKeys = ⋃ category.appKeys(c)，c ∈ S
selectedTotal = Σ category.totalDuration(c)，c ∈ S
selectedDay(d) = Σ category.dayDurations(c, d)，c ∈ S
```

- [x] 趋势图每个分类对应一个系列，系列颜色与分类识别色一致且符合图表可读性要求。
- [x] 顶部总时长等于已选分类总时长和。
- [x] 平均、活跃天数和峰值日从已选分类合计后的日期序列计算，不能把分类级指标直接相加。
- [x] 热力图输入使用 `selectedAppKeys` 并集，复用现有应用热力图聚合。
- [x] 同一应用不得因别名、重复桶或多选而在热力图中重复计入。

### 4.6 空状态与异常数据

- [x] 没有任何应用活动时，显示分类空状态，不渲染伪分类。
- [x] 有分类数据但搜索无结果时，显示“无匹配分类”，不显示全局空状态。
- [x] 所选分类因映射更新消失时，优先选择当前可用的首个分类；无可用项时进入空状态。
- [x] 未识别的分类键回退到现有安全标签/未分类规则，不直接暴露内部键。
- [x] 无有效日期时，图表、指标和范围控制保持安全空值，不产生 `NaN`、无穷值或无效日期。

## 5. UX 与组件状态规范

### 5.1 一级分段控件

继续使用 `QuietSegmentedFilter`，不新增 page-local 仿制控件。

- [x] 顺序固定为应用、分类、网页。
- [x] 网页选项根据 Web Sync 能力动态存在或缺席。
- [x] 使用稳定模式键：`app`、`category`、`web`。
- [x] 切换按钮具备现有 `default`、`hover`、`active`、`focus-visible` 和 `disabled` 状态。
- [x] 分类文案在中英文下不截断、不挤压标题和右侧范围控件。
- [x] 小宽度下沿用数据页既有换行策略，不新增横向滚动。

### 5.2 分类列表

| 状态 | 预期行为 |
| --- | --- |
| 默认 | 中性背景，显示分类色、名称、应用数、占比和时长 |
| 悬浮 | 使用现有可选列表项 hover token，鼠标为手型 |
| 选中 | 使用现有列表项 selected/active 层级，不用分类色铺满背景 |
| 键盘焦点 | `focus-visible` 清晰可见，不依赖 hover |
| 多选 | 每个已选项均有一致选中态，顺序稳定 |
| 上限 | 第 8 个选择沿用现有上限反馈，不破坏已有 7 项 |
| 加载 | 分类派生本地同步完成，通常不需要独立骨架；上游加载时沿用数据页加载态 |
| 空数据 | 显示分类空状态 |
| 搜索无结果 | 显示无匹配结果，并保留搜索输入 |

- [x] 列表项的可点击区域与现有应用/网页列表一致。
- [x] 分类项不显示应用图标、网站 favicon 或伪造的详情图标。
- [x] 分类项不响应双击详情和上下文详情菜单。
- [x] 列表滚动、底部提示和搜索框位置不因新增模式改变。

### 5.3 已选对象标识

现有应用/网页已选对象可能通过可交互图标进入详情；分类不能继承该语义。

- [x] 分类已选标识使用非详情按钮语义。
- [x] 若仍可用于移除选择，必须有明确的无障碍名称和键盘行为；若不可操作，则不得渲染成按钮。
- [x] 不添加 tooltip。
- [x] 不通过悬浮文案解释分类，避免制造新交互层。
- [x] 颜色之外必须有可读分类名称或等价无障碍文本。

### 5.4 图表与热力图

- [x] 趋势图标题、辅助文案和空状态切换为分类语义。
- [x] 横纵轴、网格、tooltip、曲线交互沿用现有实现。
- [x] 分类系列颜色来自分类语义色，但应检查浅色、深色和多选叠加下的辨识度。
- [x] 热力图标题和说明切换为分类语义。
- [x] 热力图每日/每周切换、近一年范围和导航保持不变。
- [x] 分类模式不改变热力图单元格的活动时长口径。

### 5.5 响应式与密度
