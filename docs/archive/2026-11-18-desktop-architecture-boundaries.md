# Patina 桌面架构优化执行与验收

2026-11-18 · 已完成并归档。本文以当前 GPUI 工作树为起点，覆盖录制器、桌面请求、插件宿主和共享模型四个方向。最终仍交付一个 `patina.exe`，后台常驻，主窗口和 Mini 共用按需启动的 GPUI 进程，系统探测继续在独立工作进程中运行。[当前运行架构](../architecture.md#桌面进程)

## 1. 从四个变化判断边界

一个模块应该能独立完成它承诺的事情。需要同成同败的写入应由同一事务负责。需要在不同时间启动、停止或测试的能力应有独立入口。共享一个数据库、线程池或进程，都不足以说明两项业务应当共享同一个对象。按下面四个实际变化判断最终设计。

| 变化 | 应该改哪里 | 完成的证据 |
| --- | --- | --- |
| 调整历史统计，或为已有应用编辑分类 | 活动查询或分类模块，以及消费结果的页面 | 用一个临时 SQLite 库调用正式入口，能读历史、改分类并读回结果。无需启动采样、托盘、GPUI 或 Probe。 |
| 修改开机启动设置，或改写冲突提示文案 | 桌面设置用例负责系统效果与写入，界面负责显示，协议负责传递结果 | 实际窗口入口与直接调用用例遵守同一套回滚规则。更换诊断文字后，客户端仍收到同一类冲突。 |
| 安装一个只保存自身状态的插件，或调整官方提醒规则 | 前者使用通用插件宿主，后者由提醒插件及其受控数据适配器处理 | Counter 能独立装卸和升级。修改提醒规则只涉及提醒及确实受影响的消费方。 |
| 调整 Mini 的宽度或鼠标离开后的收起时机 | Mini 窗口模块及其布局、交互测试 | 改动可在 UI 内完成。既有停靠位置样本、数据库迁移和活动录制照常工作。 |

实现原则是按**调用者所需的最小能力**传递依赖。后台入口组装服务并控制退出顺序。需要抽离 crate 时，先指出哪条真实编译依赖必须切断。一个模块或具体类型已经能建立的边界，就在原 crate 中完成。

### 目标落点

| 边界 | 目标位置与依赖方向 |
| --- | --- |
| 后台组装、查询与写入 | `apps/patina` 组装录制、查询、分类、维护和插件服务，各入口显式取得所需能力。活动查询和分类事务留在 `crates/activity`，数据库初始化与可恢复的位置切换留在 `crates/storage`。 |
| 桌面用例与传输 | 同时涉及托盘、登录项与持久化的设置操作由 `apps/patina` 中独立的宿主模块协调。`window_process` 和 UI 客户端使用 `desktop-protocol`，各业务模块在自己的边界报告结构化结果。 |
| 插件与数据适配 | `plugin-sdk` 拥有面向作者的接口，`plugin-host` 负责执行。专注与提醒各自拥有 guest 逻辑及对应的原生数据适配，适配器由后台装配。仅用于窗口展示的结果在桌面边界转换。 |
| Mini 与共享数据 | Mini 的几何计算、动画状态和交互测试放在 `apps/patina-ui/src/windows/mini`。多个读写方需要的持久化字段由资料格式的所有者定义。历史迁移测试读取原始样本，活动领域与 UI 之间只共享双方实际使用的数据。 |

## 4. 分开窗口连接、业务操作和错误呈现

实施前 `window_process.rs` 负责启动、握手和断线，也在消息分支里决定设置保存、安装、存储重启及并发方式。当时冲突类别还依赖一组英文错误字符串。目标是窗口管理掌握真实连接状态，业务用例掌握副作用，客户端能依据稳定错误类别决定提示或重试。[窗口管理与请求](../../apps/patina/src/window_process.rs) · [桌面协议](../../crates/desktop-protocol/src/lib.rs) · [窗口客户端](../../apps/patina-ui/src/client/mod.rs)

- [x] 逐组登记普通读取、需要顺序的写入、主窗口限定操作和要求退出或重启的操作。记录现有的调用条件、串行位置、并发上限、回复及退出时机。窗口管理继续负责子进程代次、握手、请求编号、连接失效与窗口身份。分派从真实连接取得调用上下文。
- [x] 先提取“保存桌面偏好”用例。用例统一核对旧值，按现有顺序应用开机启动和托盘状态、提交偏好、返回结果。系统调用或入库失败时恢复已执行的副作用。补偿也失败时保留两次失败的诊断。设置页保留草稿与预览。用成功、旧值冲突、部分执行失败三个场景核对最终数据库值与系统状态。[偏好持久化](../../crates/activity/src/recording/preferences.rs) · [常驻设置测试](../../apps/patina/tests/pages/resident.rs)
- [x] 将更新、存储维护和普通数据请求转给相应处理入口。处理器返回回复及必要的退出或重启决定，由宿主执行生命周期动作。保留主窗口安装确认、WebDAV 凭据显示的调用方检查、忙时返回、窗口退出后的旧回复丢弃，以及安装失败后继续运行。核对主窗口、Mini 和窗口重开后的实际行为。
- [x] 在业务发现冲突的地方产生有类型的错误。集中转换成既有的 `RequestError`，保留其类别直到客户端最后需要展示文字的位置。覆盖设置旧值冲突、删除预览失效、插件预览过期和普通拒绝。更换其中一条诊断文本后，分类断言仍通过。对已有版本二消息做双向样本测试，包括线上 `Query` 标签、错误载荷和握手。
- [x] **验收**。从真实设置页保存并重开读取，从真实更新确认走完验签、退出回执、安装和原资料重启。用断线、失效请求和并发请求验证传输层的回复与顺序。复核窗口管理代码仅编排连接和生命周期，业务测试可以直接调用设置或更新处理入口。[更新窗口用例](../../apps/patina/tests/updater.rs) · [安装交接回归](../../crates/updater/tests/installer.rs)

部署保持版本二协议。主窗口、Mini、通知共用一条连接，安装入口由关于页确认触发，并要求该连接当前登记了主 HWND。WebDAV 密码显示另核对请求 HWND、窗口所属 PID 及前台窗口。普通请求受 `MAX_PENDING` 限制；缩放、模式与设置保存按接收顺序执行；替换数据库前排空已接收的请求。

## 7. 如何验证、勾选和归档

建议先贯通历史与分类的独立入口，再将桌面分派接到这些入口。插件改造复用已经明确的请求与错误边界。Mini 的模型盘点可提前做，最终导出清理在消费者迁完后进行。每完成一条真实调用链就去掉其旧内部入口，并留下具体测试结果。需要退回某一批时，按该调用链一起退回实现和调用方。已有数据库、签名包、备份及安装身份继续使用原格式。

从仓库根目录运行。下表给出现有入口。实施时若移动或改名，用 `-- --list` 核对等价用例和实际执行数量。每个方向的“验收”条目还包含入口当前没有覆盖、实施时应补足的行为。

| 范围 | 验证入口与判据 |
| --- | --- |

### 最终验收

Windows x64 上，`cargo xtask check native` 的格式、工作区无头测试和全目标全特性严格 Clippy 均通过。默认执行 776 项、按各 target 约定忽略 13 项。按需另外执行的原生、签名包与 WebDAV 用例见上表。`cargo xtask check tools` 通过，覆盖桌面依赖树、仓库工具测试、4 种语言的 1046 个消息键，以及官方插件、Counter、远程状态示例的 Wasm 发布构建。CI 增加设置失败重试与 Mini 原生定位的精确筛选。

基线有 795 个默认可枚举用例，最终有 789 个。按测试全名比较，移出 29 个旧 `mini_window` 模型用例，新增 23 个。当前 GPUI 的工作区居中、DPI 裁剪、反向动画、悬停保护与焦点由窗口模块测试，旧资料字段由存储兼容测试，任务快捷项由活动数据适配器测试。现有活跃进程和 Tokio 工作线程数量保持原配置。历史和趋势的数据库读取及结果聚合仍在已有工作线程执行。

29 个旧测试中，8 个在 Mini 主模型、14 个在多显示器选取、3 个在过渡模型、4 个在工具投影。重构前 GPUI 通过 Windows 选择工作区，两处正式布局都传入 `Placement::default()`。跨屏拖动、侧边停靠和悬浮位置恢复属于历史 Widget 实现。历史 Tauri 工具页保留过已完成状态的五秒时效。此次重构前，GPUI 正式快捷项只选取运行中的专注和已安排的提醒。现有 GPUI 行为和旧资料的字节级保真分别使用原生交互与 SQLite 重开验证。[历史拖动验收](widget-cross-monitor-drag-snap-execution-plan.md) · [原生 Mini 用例](../../apps/patina/tests/today/mini.rs) · [现行工具快捷项](../../crates/activity/src/recording/tools/shortcuts.rs)
