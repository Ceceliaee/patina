# 网页按主域名自动分组执行方案

状态：已完成并归档；独立门槛失败已转交下列具名待办。日期：2026-10-09。

用户已授权完整实施、验证、勾选归档及完成后的对抗式审查。未勾选项不表示已验收。现有未提交的应用关联、详情和分类性能改动需保留。应用关联继续采用手动方式。

## 1. 从第一性原理确定行为

用户关心“在哪个网站花了多少时间”，采集得到的却是具体主机、URL、标题与时间片段。一个网站可以包含多个子域名，所以记录身份与统计身份需要分开。

原始事实回答“实际访问了哪里”；分组规则回答“这条事实现在归到哪个展示对象”。自动分组只能改变后者。独立显示、恢复分组和迁移均不得重写原始域名、URL、标题、时间或浏览器来源，也不能增加、丢失或重复计算时长。

定义标准化完整域名为 H，可靠识别的可注册主域名为 R(H)，用户明确选择独立显示的域名集合为 E。建议采用以下归属规则：

1. 匿名事实继续走匿名统计，不尝试从分组恢复其身份。
2. H 在 E 中时，以完整域名 H 独立展示。
3. H 可识别 R(H) 时，归入主域名组，例如 `deepseek.com`，不添加前缀。
4. 不能可靠识别主域名的地址保持独立，不猜测归属。

域名值统一使用 `deepseek.com`。实际访问的根域名与整组通过独立的类型字段区分，不在域名前拼接标记。前者是原始记录对象，后者是统计容器；即使从未访问根域名，容器也可以由子域名的实际历史形成。详情目标、设置和删除操作均需携带明确类型，不能仅凭域名字符串推断范围。

时长沿用当前有效片段和来源去重规则：同一浏览器来源内按现有区间语义汇总，不用各卡片显示值简单相加替代；独立来源的累计规则不变。任何归属调整前后，按同一时间范围计算的网页总量必须守恒。

## 2. 已确定的范围与尚需收敛的细节

### 已确定的产品方向

- [x] 默认按主域名自动归组，新出现的同站子域名自动加入。
- [x] 主项显示 `deepseek.com`，展开列出实际访问过的完整域名。
- [x] 允许成员独立显示，保存后刷新和重启不重新归组；提供恢复自动分组的入口。
- [x] 不保留旧网页手动关联，不再提供跨主域名手动添加关联。
- [x] 主项图标由组内使用时长最多的成员提供。
- [x] 用户提出保留自动分组现有卡片与展开 UI；独立卡片底部增加一个按钮，形成五个操作。

### 本方案采用的交互建议

自动分组卡片继续使用域名下拉入口；成员行提供“独立显示”。独立例外卡片底部顺序为“颜色、标题记录、匿名统计、合并到目标主域名、删除”，删除保持末位。新按钮复用现有图标操作组件，提示文字为“合并到 {主域名}”，例如“合并到 deepseek.com”。这与用户所说的五按钮方案一致，具体图标在实现时核对现有图标库。

这里只给具有有效归组目标的独立例外显示第五个按钮。IP、localhost 等天然独立对象没有可恢复的主域名，不显示无效操作。自动分组只有一个成员时仍保持分组身份，避免第二个子域名出现后卡片设置和详情目标突然换身份。

### 实施前需明确的行为决策

2026-10-09 用户已确认旧组设置处置和组级操作；其余默认行为按以下方案执行：

- [x] 确定旧分组专属名称、分类和颜色的迁移方式。建议不自动套用到新主域名；原始域名设置完整保留。若要删除旧组专属设置，先展示具体字段及恢复方式，获得明确决定；未决定时可在迁移备份中保留，不能静默清除。
- [x] 确定新组的默认名称、分类和颜色。建议名称默认主域名，可单独重命名；未设组分类时为未分类，不用图标来源隐式决定分类。组颜色可跟随代表图标颜色，显式设置优先。成员独立后恢复自身设置。
- [x] 确定组卡片的标题/匿名开关作用范围。建议明确作用于当前实际成员、支持混合状态；新成员按自身默认策略加入，不隐式继承匿名或标题关闭规则。必须避免把合成组身份当真实采集域名。
- [x] 确定组卡片删除的范围。根域名可能没有记录，不能沿用“删主域名”得到无操作，也不能悄悄改为删全部成员。建议确认框列明“删除当前组内 N 个域名的历史”，独立成员不包含在内；取消无副作用。
- [x] 确定根域名自身独立时的辨识方式。它与组容器可以同时存在，需以“独立显示”状态、展开入口和详情来源区分，不得因显示文字相同而混为一个对象。

这些决策只阻断相应设置迁移或交互实现；域名解析、统计一致性测试、隔离基线等不依赖项可以先进行。

## 5. 阶段 B：统一域名与归属规则

- [x] 检查锁定的公共后缀依赖及其公共/私有后缀处理，用可执行样例确认边界。复用现有依赖前先确认适合新规则，不把旧兼容函数改名视为验证。
- [x] 明确标准化顺序：合法主机解析、大小写、末尾点和 IDN 一致化；路径、查询和端口不能混入主域名键。
- [x] 以公共后缀规则识别可注册域，覆盖多级后缀、私有托管后缀、未知后缀、非法地址、IPv4/IPv6 与本地主机；不可靠输入独立处理。
- [x] 对 `chat.deepseek.com`、更深层子域名及实际根域名得到同一组；对恶意相似后缀或其他站点不得误归组。
- [x] 明确私有托管后缀测试预期，例如不同租户不能被合并为托管平台一个组；将预期与锁定规则版本绑定。
- [x] 实现独立例外优先级。例外按完整域名匹配，不能使其兄弟域名或后代自动独立；恢复分组仅移除该例外。
- [x] 选定唯一归属计算 owner。优先由 Rust 快照提供规范化域名到根域的映射，前端草稿只叠加例外；不得让前后端各自维护不一致的公共后缀表。
- [x] 记录公共后缀数据升级导致归属变化时的处理方式；不默认添加联网查询或运行时下载。
- [x] 对相同输入建立 Rust/前端共享验收样例，覆盖已保存规则和草稿结果的一致性。

验收：每条具名事实恰有一个展示归属；输入顺序不影响归属；例外不改变原始事实。
