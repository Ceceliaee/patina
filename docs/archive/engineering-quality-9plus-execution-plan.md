## 1. 从第一性原理确定改进方向

Patina 的核心价值是可信地记录、保留和解释个人活动事实。功能数量、目录整齐程度、测试数量和覆盖率都是辅助指标，不能替代这个结果。由此推导本轮工作的顺序：

| 基本事实 | 必须成立的性质 | 本轮对应工作 |
| --- | --- | --- |
| 用户依赖已保存的活动数据 | 所有事实写入经过同一个受控边界，事实与派生状态保持一致 | 关闭 SQL 读接口实际可写的通路 |
| 一次保存对用户只有一个结果 | 保存失败保留可用旧状态；成功后各资源属于同一配置 | 协调 WebDAV 配置与凭据的提交 |
| 异步请求的完成顺序不等于事实顺序 | 旧响应不能覆盖已经接受的新状态 | 统一 tracking 快照的接受规则 |
| 每条重复实现都会增加需要保持一致的关系 | 同一汇总语义使用唯一生产路径 | 收敛 Dashboard / History 读模型及其测试、基准 |
| 维护成本主要来自可变化状态及其相互影响 | 状态属于最小实际 owner，派生值不形成第二份事实 | 按职责拆解复杂页面状态，删除有证据的冗余 |
| 测试只能证明它实际观察到的行为 | 断言观察真实边界、失败和恢复，并可被有意破坏的生产代码触发 | 补充真实 IPC、故障注入、乱序和跨层测试 |
| 性能取决于生产路径上的工作量 | 测量真实调用链、数据规模和资源释放，遵守既有预算 | 修正基准路径，运行合成数据与短时资源实验 |

执行取舍遵循[产品范围](../product-principles-and-scope.md)、[优先级](../roadmap-and-prioritization.md)、[架构](../architecture.md)、[工程质量](../engineering-quality.md)和[修复边界](../issue-fix-boundary-guardrails.md)。本文只记录这轮工作及其证据，不建立第二套长期规范。

综合分数 = 各维度分数乘以权重后相加。表中目标组合为 **92/100**，为 90 分验收线保留余量；这是执行方向，不是预先授予的分数。评分仍需说明每个维度尚存的扣分项及其依据。

同一尺度下，80–89 表示基础较好但仍有明显一致性或维护负担；90–94 要求已知重要缺陷闭环、关键边界有有效反证测试、剩余问题局部且可控。95 分以上需要更强的同口径证据，不因本轮清单完成自动授予。

最终“9+”同时满足以下条件：

- [x] 综合复评分至少 90/100，五个维度分别给出证据和剩余扣分原因。
- [x] 本轮范围内没有未解决的 P1，也没有影响数据、凭据或 tracking 状态一致性的已知 P2；把它们转交其他任务不能视为达标。
- [x] 适用的完整检查、真实桌面测试、修正后的性能检查均通过，未降低门槛或绕过失败来取得绿色结果。
- [x] 新增结构的收益大于复杂度：重复实现、跨层责任或独立状态组合实际减少，不能仅把大文件移成大 hook。
- [x] 每项主要结论都能关联到当前源码、输入范围和验证结果；无法观测的部分明确保留为限制。

### 2.3 保持的产品行为

本轮保持个人、本地优先、Windows 范围。活动事实、来源优先级、排除与匿名规则、精确时间线、分类与应用关联、备份恢复和用户已有数据是受保护行为。UI 重构遵循 [Quiet Pro](../quiet-pro-component-guidelines.md)，保留独立筛选条件、键盘操作、焦点、加载与错误状态。

不要求数日常驻、真实用户长期历史或长期真实使用观察；性能验收使用可重复的合成数据和有时间上限的实验。也不以此次方案为由扩大产品功能、重做视觉系统、合并备份与导出调度器，或删除仍受[升级与兼容政策](../versioning-and-release-policy.md)保护的迁移代码。

## 5. 阶段 A：关闭任意 SQL 的前端写入口

**依据：** `sql:allow-select` 的名字并不使连接只读。当前 writable pool 被注入 plugin，真实主窗口可通过 `plugin:sql|select` 执行 `INSERT ... RETURNING`，绕开 Rust 写服务。只禁止 `execute`、检查 SQL 前缀或改 TypeScript 类型都无法证明权限边界。

**主要 owner：** [sqlite_pool.rs](../../src-tauri/src/data/sqlite_pool.rs)、`src-tauri/src/data/repositories/`、`src-tauri/src/commands/`、[default capability](../../src-tauri/capabilities/default.json)、已移除的前端 SQL wrapper、前端 persistence repositories，以及 [真实 runtime 测试](../../tests/tauriRuntimeSmoke.test.ts)。

**默认方案：** 将剩余本地读取迁到按数据域定义的 typed Rust command，然后撤掉前端 plugin SQL 权限及连接注入。后端继续使用其受控读写连接。现有 typed gateway 已提供可复用方向，无需新增通用查询语言或“传 SQL 给 Rust”的代理。

### A1. 收集并冻结读取契约

- [x] **A1.1** 搜索 `Database`、`getDatabase`、`.select`、`plugin:sql` 和数据库加载入口，按实际调用方列出 settings、classification、History 会话 / 标题 / 图标、网页明细及 bootstrap 缓存读取。
- [x] **A1.2** 为每类读取记录输入、返回形状、排序、范围端点、分页、空结果、错误语义和一致性需求。确认是否已存在等价 Rust repository / command，优先复用。
- [x] **A1.3** 需要同一时间点的数据在 Rust 同一读取快照中取得。对批量图标、标题和设置保持批量读取，避免将一次 SQL 改成逐行 IPC。
- [x] **A1.4** 在本节记录最终命令落点和删除清单。若存在不能迁移的真实契约，先给出调用方与原因；任何保留任意 SQL 的替代设计都必须另证数据库层拒写及重开后仍拒写，不能靠 `query_only` 可切换状态或前缀过滤宣称完成。

### A2. 在真实 owner 实现并迁移调用方

- [x] **A2.1** 将参数与返回 DTO 放在现有契约 owner；SQL 留在对应 Rust repository。参数化查询，不接受任意 SQL、任意路径或不受限表名。
- [x] **A2.2** 沿用 command manifest、窗口 permission set、capability 和 invoke 注册机制，新增读取只授予实际需要的窗口。Widget 继续仅使用专属快照与精确 allowlist。
- [x] **A2.3** 迁移前端 persistence 调用方，保持 feature service 的展示组合职责；删除已无调用方的 plugin DB wrapper 与导入。若 plugin 仍有 Rust 生命周期用途，明确保留用途，不能顺带破坏迁移或恢复。
- [x] **A2.4** 撤掉主窗口 SQL load / select / execute 权限和可写池对前端 plugin 的暴露；保留 Rust 事实写入与派生状态在同一事务的路径。
- [x] **A2.5** 检查数据库覆盖恢复、迁移、关闭与重开：新 command 必须解析到当前 pool / 数据代次，旧连接或旧响应不能继续指向被替换数据库。

### A3. 用攻击性输入和正向业务证明边界

- [x] **A3.1** 真实 main 和 Widget 分别直接调用 plugin SQL，覆盖 load、普通 select、`INSERT/UPDATE/DELETE ... RETURNING`、DDL、写 PRAGMA、`ATTACH` 和多语句尝试；所有未授权入口在触及数据前被拒绝。
- [x] **A3.2** 拒绝后比较事实表、settings、schema、派生 revision 和临时目录，确认没有副作用。不要仅断言错误字符串。
- [x] **A3.3** 正向验证新读取返回正确数据；typed 写入仍能成功，事务失败仍整体回滚，变更事件与 revision 只反映已提交结果。
- [x] **A3.4** 覆盖恢复 / 重开后重复边界与正向读取测试，包含执行中的旧请求；验证 History、Settings、Data 和启动缓存的实际使用路径。
- [x] **A3.5** 为 permission 或 pool 暴露的回归保留负向控制，证明放回原始漏洞时正式测试会失败。
- [x] **A3.6** 按变更更新架构文档中的本地读取边界；运行 IPC / 架构检查及其受影响 self-test，最终进入完整门槛和真实 runtime 验证。

**完成条件：** WebView 无任意 SQL 能力，合法读取和 Rust 写入都成立，数据库替换后的边界仍成立。若迁移发现缺失查询，补齐 typed 读取；不能以重新开放原可写通路作为修复后的回退方案。

## 6. 阶段 B：让 WebDAV 配置与凭据保持一致

**依据：** 当前 hook 先覆盖 Windows 凭据再保存配置；已有配置遇到 URL 校验或存储失败时，会出现旧配置配新密码。SQLite 与 Credential Manager 没有共享事务，仅交换两次写入顺序仍会留下另一种部分成功。

**主要 owner：** [useRemoteBackupState.ts](../../src/features/settings/hooks/useRemoteBackupState.ts)、[settings_payload_service.rs](../../src-tauri/src/data/settings_payload_service.rs)、[remote_backup_settings repository](../../src-tauri/src/data/repositories/remote_backup_settings.rs)、[credentials.rs](../../src-tauri/src/platform/credentials.rs)、`data/remote_backup.rs` 和相关 command。

**不变量：** 提交前旧配置与旧凭据始终可用；提交后读取到配对的新配置和凭据；失败不谎报成功；崩溃后能够确定使用哪一代。秘密不得进入 SQLite、日志、普通事件或用于补偿的前端状态。

### B1. 确定一个保存 owner 与提交点

- [x] **B1.1** 梳理保存、测试连接、上传、自动备份、删除配置、显式显示密码和旧凭据导入的全部调用方，记录它们如何取得配置与密码。
- [x] **B1.2** 把 URL、用户名、目录及密码更新意图的完整验证放在任何写副作用之前，使用 Rust 当前规范化规则作为权威；前端校验仅负责即时提示。
- [x] **B1.3** 定义一个 typed 保存操作和可识别的结果：未提交、已提交、已提交但待清理。空密码的“保留已有密码”与删除凭据必须是明确意图，不由模糊字符串猜测。
- [x] **B1.4** 将跨资源协调放在当前 data 保存服务，平台模块只操作凭据、repository 只操作数据。command 与 hook 保持薄，不建立通用跨资源事务框架。

### B2. 实现可以恢复的最小提交协议

采用“先创建候选凭据，SQLite 原子切换配置及凭据引用，最后清理旧凭据”的默认方向。凭据引用是非秘密标识；标识必须受 profile 和本机归属约束，不能允许客户端指定任意 Credential Manager target。

- [x] **B2.1** 在 profile 范围内串行化保存 / 删除，或使用明确的预期 revision 冲突检查；同一次操作读取一致的旧配置和凭据引用。
- [x] **B2.2** 密码变更时在独立候选 target 写入并由 Rust 读回验证，保留旧 target；不变更密码时复用当前有效引用。候选写入或验证失败不得修改已提交配置。
- [x] **B2.3** 在一个 SQLite 事务中写入规范化配置、受控引用及所需 revision。事务提交是生效点；读配置与读凭据按该引用解析成配对快照。
- [x] **B2.4** 事务失败只清理本次候选，保留旧配对。事务成功后再清理已无使用者的旧凭据；清理失败记录可重试状态，不能把已成功的保存误报为未保存。
- [x] **B2.5** 定义崩溃恢复：提交前遗留候选可按本 profile 的精确归属回收；提交后新引用继续有效，旧 target 延后清理。恢复操作幂等，不扫描或删除其他应用、profile 的凭据。
- [x] **B2.6** 协调正在运行的测试连接 / 上传 / 自动备份：它们使用已经取得的配置与密码快照，不能读取旧配置后再取得新密码。以实际锁顺序检查死锁和取消行为。
- [x] **B2.7** 处理无引用的既有凭据和既有配置，验证首次转换及重复启动。只保留服务真实升级边界的窄读取入口，并记录退出条件。
- [x] **B2.8** 明确备份覆盖 / 合并恢复、异机恢复和配置删除对本机凭据引用的处理；来自备份的引用不得绑定目标机上无归属证明的秘密。按照现有恢复语义保留、解绑或要求重新配置，并为选择补测试。

| 三个 selection revision ref | 相应选项调和及 session 选择记忆 | 防止后台刷新重复重置手动选择 |
| `dataRootRef`、`appListRef` | React DOM 绑定；卸载清除 | 布局测量、搜索后回到列表顶部 |
| 两个 active trend date ref | 指针事件与离开事件 | 图表悬停交互，不产生查询事实 |
| `hasInitialBootstrapSnapshotRef` | 挂载时一次初始化 | 区分冷启动与已有首屏缓存的调度，不随后续快照变化 |

Data 的 effect 分别负责：缓存读取；首屏预热；模式可用性；选择记忆；最早年份校正；延后新模型发布；应用 / 分类 / 网页三组选择调和；搜索与模式切换后的两处列表定位；三组已选项展示记忆；已就绪模式发布；完整 bootstrap 保存；导航结构标记；导航就绪标记。请求与接受规则继续由趋势、热图、网页三个已有私有 owner 管理。本轮修改趋势快照内部的关联状态，没有把上述职责搬进新的大 hook，也没有声称 Data 文件行数下降。

History 的精确会话、标题和网页片段服务于明细，不与 Rust 汇总重复；实际删除的是 raw 汇总分支、可选模式位和无生产调用方的月会话读取。mapping 的编辑快照用于取消单个名称编辑，和全页未保存草稿不同，保留。Settings 的存储迁移、备份导出与恢复各有独立操作状态，保留以避免一个忙碌标志误锁所有动作。

新增 WebDAV 协调器、Windows 凭据 ledger 和 typed 查询模块分别承担提交协议、平台秘密存储及既有查询领域；移除了前端 SQL plugin、数据库通用 wrapper、旧 tracking 事件更新器及其重复路径。新增覆盖工具归验证基础设施，不成为产品运行依赖。
