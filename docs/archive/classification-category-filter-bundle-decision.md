# 分类筛选体积决策

> 决策日期：2026-09-08。已落实并验证，作为历史证据归档。

本次引入分类筛选弹层后，共享定位组件由 Classification 与 Destination detail 两个懒加载消费者使用，构建器将其提取为独立 chunk。为这个真实 owner 单独计量，同时为两份语言包新增的必要文案保留既有最低余量；启动、feature、总产物及无主 support 上限不变。

## 排查与决定

- 将最初六个新增文案收敛为两个；复用已有分类搜索、无匹配与页面空结果文案。没有新增依赖，使用已有图标及交互组件，未引入另一份定位实现。
- 分类入口保持在既有懒加载页面中。共享弹层沿用自动分块，避免为小组件新增动态加载与等待状态；首次进入分类页承担必要筛选逻辑和弹层成本。
- 旧中文预算 9.9 KiB、英文 9.4 KiB；分别调整为 9.92 与 9.42 KiB（均 +0.02 KiB，约 +0.20%/+0.21%）。对应实际值的缓冲为 3.21%/3.23%，满足最低 3%，低于公共依赖最高 5%。西班牙语预算不变。
- QuietAnchoredPopover 原无独立上限；新预算 1.21 KiB，对实际 1192 B 留约 3.95% 缓冲。只新增该 owner，不提高无主 support 总额。
- Destination detail 的减少来自本次拆包，不能把迁出的代码当作删除；保持消费者上限，避免在尚未发布确认稳定前将一次分块结果当作新的长期基线。
- 最终启动 JS+CSS 191.58 KiB、总产物 360.75 KiB、无主 support 6.25 KiB；相应全局上限均未改变。未发现初始加载图引入分类页；本次不构成需要原生启动性能测量的高风险增长。
