## 1. 从原始事实推导实现边界

### 1.1 三个不同的问题

原始会话回答“哪个程序在什么时间被使用”，应用识别回答“这个可执行文件属于哪个已识别应用”，用户关联回答“我想把这些应用的时间归到哪个主程序下面”。三者不能共用一个可变身份字段。

采用以下概念；名称是方案中的领域概念，不要求直接采用同名字段：

| 概念 | 来源 | 关联时是否改变 |
| --- | --- | --- |
| 原始身份 | 会话中的 exe、名称、来源、时间和标题样本 | 不改变 |
| 已识别应用键 | 现有 executable normalization / canonicalization | 不因用户关联而改变 |
| 统计归属键 | 用户保存的成员到主程序关系 | 改变，可解除 |
| 显示名称、图标、分类、颜色 | 统计归属对应的展示配置 | 使用主程序配置 |
| 记录与隐私策略 | 全局和应用级设置 | 不由“关联”操作隐式开启 |

如果直接把成员会话的 exe 改成主程序，解除关联时就无法可靠还原；如果只把名称改成一样，按 exe 聚合的消费者仍然分开。因此需要保存一个独立的归属关系，并在已得到可信活动事实后使用它。

### 1.2 最小数学契约

设 `K(r)` 为记录的已识别应用键，`L(k)` 为用户保存的主程序键，未关联时 `L(k) = k`。每个成员最多有一个主程序，主程序本身不能是成员；合法关系满足 `L(L(k)) = L(k)`。

对查询范围 `R`，先沿用现有来源优先级、排除可见性和时间裁剪规则，得到各记录的有效时长 `D(r, R)`，再按 `L(K(r))` 汇总。关联操作本身不改变这些时长：

`主程序总时长 = 所有归属该主程序的可见有效记录时长之和`。

由此得到四项必须可测试的不变量：

1. 只改关联、不改记录策略时，全局总时长保持不变。
2. 新旧统计的差异仅是应用和分类的归属分布，不能重复计入主程序及其成员。
3. 解除关联后，原始记录和成员原展示配置仍可使用。
4. 关联前先完成原生、精确导入和桶导入的来源分配；不能因归属相同重新去重，也不能把桶时长伪造成精确片段。

原生重叠记录是否累计、网页活动如何归属，继续服从现有活动契约；本项不新增跨程序区间取并集或浏览器／网页双计规则。

## 2. 产品行为与执行决策

### 2.1 实施目标

分类页以主卡片管理关联关系。点击 exe 名称打开锚定面板；无成员时不显示箭头，有成员时显示 `▾`，始终不显示数量。悬停只有轻微底色反馈，不弹 tooltip，也不使用原生 `title` 代替 tooltip。

面板默认列出主程序和成员，主程序不可移除；成员可解除关联。底部提供“＋ 添加应用”，切换到同一面板内的搜索选择状态，允许连续添加。保存／取消沿用分类页草稿，不建立面板内第二套持久化入口。

已关联成员从主列表收拢，但成员名称和 exe 仍能搜索到所属主卡片。统计按当前保存关系解释历史和未来数据，精确明细保留真实程序身份。关联不要求主程序当前有活动记录；成员仍有记录时，主卡片不能凭空消失。

### 2.2 执行决策表

关联只改变展示归属，以下操作继续按原程序执行。

| 操作 | 实际范围与结果 |
| --- | --- |
| 主卡片排除、标题开关 | 只作用于主程序；成员在关联面板保留各自开关 |
| 主开／成员开 | 两者有效记录都汇总 |
| 主关／成员开 | 只汇总成员，主卡片仍可管理 |
| 主开／成员关 | 只汇总主程序 |
| 主关／成员关 | 整组进入排除筛选，不恢复任一程序 |
| 全局标题关闭 | 覆盖单项设置；成员开关禁用，原偏好保留 |
| 删除主卡片记录 | 确认显示名称与 exe；只删除主程序，保留成员记录和关联引用的身份资产 |
| 主程序无记录 | 成员仍有记录时由关系生成主卡片；解除后按真实目录收敛 |
| 提醒与导出 | 原始 exe 和已有应用提醒目标保持原义；分类依主程序的当前归属解释 |
| 挂件 | 专用 bootstrap 读取关联，显示主名称与图标，不扩大 Widget 写权限 |

本项不做自动厂商匹配、层级分组、拖拽排序、主程序切换向导、独立分组页面或按生效日期分段归属。若确实需要新增这些能力，另行界定范围。

- [x] A3. 沿一次分类保存追踪到 Rust repository、运行时策略应用和前端缓存失效，记录实际调用点。
- [x] A4. 沿 Dashboard、History、Data、目标详情各追踪一个真实应用键，区分 raw key、canonical key、显示名称和选择键。
- [x] A5. 完成第 2.2 节决策，记录主卡片与成员控件的行为表；删除范围未确定时不实现整组删除。
- [x] A6. 建立隔离测试资料：主程序 A 为 10 分钟，成员 B 为 20 分钟，独立 C 为 5 分钟；另加同名不同 exe、已排除成员、无标题、跨日片段和无记录主程序。

阶段出口：有具体数据、预期结果和控件作用范围；任何尚未确定项都指出依赖它的后续步骤。

### 阶段 B：归属模型与持久化设计

推荐从“成员键 → 主程序键”的单向关系开始。它直接表达唯一归属，无需额外的组 ID、组名称和树结构。主程序显示信息仍来自已有应用配置。

- [x] B1. 明确归属键使用现有已识别应用键；原始 exe 留在会话、导出原始字段和诊断中。
- [x] B2. 在现有 settings 体系内比较逐成员 key 和独立表方案。优先逐成员 key，以避免单个 JSON 大对象触及现有长度限制；若需要数据库约束、规模或恢复语义支持独立表，写明证据后重新评估迁移。
- [x] B3. 定义关联设置的允许前缀、value 格式、键规范化和长度上限；检查 UWP 及导入键，不能直接截断身份。
- [x] B4. 将关系与 `AppOverride` 展示偏好分离，保证成员 displayName/category/color 原值不被复制覆盖；解除关联只删除关系。
- [x] B5. 定义纯函数：验证完整关系、解析统计归属、列出成员和构造可添加候选。普通读取是一次查表，不递归遍历用户图。
- [x] B6. 定义不合法输入的明确错误：自身关联、重复归属、主程序已是成员、成员已拥有成员、循环、空键、非法 key/value。
- [x] B7. 定义未观测主身份的保留策略：历史清理后仍能加载主卡片；从备份读取的合法关系不依赖当前分页窗口验证。
- [x] B8. 定义配置修订与缓存失效策略，区分活动事实 revision 与归属配置变化；不因改组强制重建整段历史派生表。
- [x] B9. 若 TypeScript 和 Rust 均需归属解析，各自放入对应 domain owner，并用相同输入／预期的契约用例验证，禁止页面与导出器分别实现一套规则。
- [x] B10. 新增领域回归用例，覆盖合法一对多、无关联退化、重复／循环拒绝和解除后配置恢复。

阶段出口：保存格式、唯一 owner、跨语言边界和异常行为能直接指导编码；未使用新表时也要评估新设置语义的备份与降级风险。

### 阶段 C：事务写入、加载和故障恢复

- [x] C1. 在分类 repository 扩展加载过滤与允许前缀；在 Rust classification snapshot 中读取独立关系，不把它解释成应用别名。
- [x] C2. 在同一 SQLite 事务中读取现有关系、应用本次变更并验证最终关系，再写入；两条单独合法的边不能组合成循环。
- [x] C3. 对多窗口或恢复并发的 stale draft，采用已确认的冲突检测或重新校验方式；不可静默覆盖他人刚保存的归属。
- [x] C4. 将关系变化和本次分类草稿的其他设置放在同一提交边界。任何校验或写入失败均回滚，不出现关系成功、展示偏好失败的半份保存。
- [x] C5. 检查 `classification_service.rs` 的恢复／重试路径：相同请求重复提交结果一致；不要重复触发需要准确时间边界的策略动作。
- [x] C6. 持久化成功后再替换前端已保存快照并广播配置变化；失败保留草稿、错误原因和重试入口。
- [x] C7. 只有第 2.2 节明确的策略变化才进入运行时应用链；仅关联不得封口、改名或重开当前真实会话。
- [x] C8. 对已提交但通知失败的情况重新加载已保存配置，不误报“全部未保存”并撤回到错误的前端状态。
- [x] C9. 覆盖新安装无关系、旧数据无新 key、重启加载、非法设置输入、事务中途失败、重复提交和并发关系冲突。
- [x] C10. 若 IPC 参数或命令注册发生变化，核对 manifest、权限分类、前端网关和 Rust handler；不得放宽 Widget 权限。

阶段出口：真实 SQLite 证明原子性和持久化；仅用前端 mock 保存成功不足以通过本阶段。

### 阶段 D：统计与明细一致性

- [x] D1. 在现有共享应用语义 owner 中提供统计归属解析入口，调用方显式选择统计键或原始键，不全局替换 canonicalization。
- [x] D2. 保持来源优先级、原始排除判断和时间裁剪顺序，之后再聚合归属；按已确定的主程序排除语义应用额外可见性门槛。
- [x] D3. Dashboard 汇总合并成员时长，使用主程序名称、颜色及图标；校验 Top Apps、百分比和小时分类总量一致。
- [x] D4. History 汇总按归属合并，精确时间线仍按真实成员保留切换边界；不要因共享主程序而将 A/B 切换抹掉。
- [x] D5. Data 的应用趋势、热力图、分类趋势和应用选项均调用同一归属规则，移除对本功能新增的显示名称拼接分组依赖。
- [x] D6. 主程序选择向目标明细传递成员集合；已有成员选中状态在保存关系后映射到主程序，解除后重算，避免空详情或重复选择。
- [x] D7. 目标明细展示成员真实 exe 和标题样本；桶导入继续显示其精度限制，不能生成不存在的起止片段。
- [x] D8. 保存／解除关联时失效所有受影响的分类 bootstrap、Data 快照、热力图、Dashboard 和详情缓存；保存前的异步响应不能覆盖新归属结果。
- [x] D9. 核对 app live 状态、挂件、快捷分类和导出消费者：需要展示归属时使用主名称，需要操作原始对象时保留原键。已有应用提醒目标不能无提示扩大到成员集合。
- [x] D10. 如果导出或提醒必须改变已公开语义才能保持一致，先列出具体输入／输出变化并界定范围；不顺手增加组提醒或导出新格式。
- [x] D11. 用阶段 A 数据验证：A+B 显示 30 分钟、C 为 5 分钟，全局仍为 35 分钟；解除后恢复 10/20/5。
- [x] D12. 比较关联前后代表性查询的耗时与输入规模；构建一次映射后线性归并，不对每条会话查询关系或重复扫描全目录。

阶段出口：所有统计入口采用同一归属，详情保留原始事实；实时、导入和缓存更新均有可观察证据。

### 阶段 E：分类草稿、目录与搜索

- [x] E1. 扩展 `ClassificationDraftState` 的加载、深克隆、相等比较和 change plan；空关系表示未关联，加入再移除同一成员应回到未修改状态。
- [x] E2. 已保存关系只在 commit 成功后生效于全局统计；分类页可按草稿预览收拢状态，取消后完整恢复。
- [x] E3. 从完整可信目录和关系构造主卡片，不能先按当前页过滤再找成员；对未加载完的目录显示加载状态，不误显示“没有可添加应用”。
- [x] E4. 搜索同时匹配主程序及成员的名称、exe 和现有合法搜索字段，命中成员返回唯一主卡片。
- [x] E5. 明确全部／已分类／未分类计数按可管理主卡片计算，并与当前筛选结果一致；成员不因收拢被误记为删除。
- [x] E6. 添加候选排除自身、其他组成员及已有成员的主程序；当前已选成员可以勾选禁用展示，用于连续添加反馈。
- [x] E7. 删除／清理后保留成员仍有记录的主卡片；加载配置但暂时无图标时使用既有回退，不把展示资产失败当关系丢失。
- [x] E8. 覆盖快速添加移除、切换应用／网页模式、取消、离页未保存提示、保存失败重试和外部配置更新。

阶段出口：目录规模与分页不影响关系正确性，成员仍能被找到和管理。

### 阶段 F：exe 入口和关联面板

弹层定位优先复用 `QuietAnchoredPopover`。它当前提供锚定、边缘适配和 region 外壳，不能假设它已经负责所有业务焦点返回。混合搜索、添加和移除按钮的面板不应伪装成单选 `select`。
