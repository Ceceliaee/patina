## 1. 目标与依据

在保留应用管理全部能力和数据语义的前提下，提高同一内容区内可扫读的应用数量。本文依据用户确认的交互方向和当前代码组织执行步骤，不保存私有 Project 的正文、字段、排序或截图。

长期规则由 [Quiet Pro](../quiet-pro-component-guidelines.md)、[架构](../architecture.md)、[工程质量](../engineering-quality.md)、[产品范围](../product-principles-and-scope.md) 和 [本地化](../localization.md) 拥有。本文仅拥有本次实现步骤、验收口径和执行记录。

### 1.1 从基本任务推导布局

用户管理一个应用时，需要依次完成识别对象、判断当前设置、执行修改、确认修改结果。空间首先分给识别和判断，再给操作入口。

1. 应用名称是首要识别信息；可执行文件名用于区分同名程序和确认实际对象，应保持可见但降低视觉权重。
2. 分类名称帮助用户判断归属，应直接显示并可修改。颜色用于视觉识别，精确色值只在编辑时需要，因此行内显示色块，弹层承载色值。
3. 标题、排除、删除均需直接可达。用图标压缩入口宽度，同时用状态语义、提示和焦点保证可理解性。
4. 标题和排除是可保存的设置，删除是需确认的危险动作。布局可以改变，草稿、保存、取消和删除执行时机必须保持原契约。
5. 增加首屏数量主要依靠移除独立操作排、重复色值展示和过大的间距。可点击区域、可读字号和异常状态不作为压缩代价。

### 1.2 空间判断方法

一行所需宽度由左右内边距、图标、身份信息最小宽度、分类选择、色块、三个操作按钮及间距共同决定。实施时测量这些部分，不能只因屏幕变宽就提前切成两列。

若列表可用高度为 H，行高为 h，行间距为 g，完整可见行数约为 floor((H + g) / (h + g))。比较前后布局时固定视口、缩放、工具栏、数据和滚动位置，实际测量完整行数，不把截图像素估计当成实现结果。

## 2. 已确认的布局契约

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 图标  应用名称 ✎            [ 分类 ▾ ]  [色块]  [标题] [排除] [删除]  │
│       executable.exe                                                 │
└──────────────────────────────────────────────────────────────────────┘
```

示意中的标题、排除和删除实际为纯图标按钮，没有常驻文字标签。图标和右侧控件相对左侧两行信息整体垂直居中。应用图标保留 40px 外壳、内边距和随应用颜色变化的淡色光圈，移除容器自带的灰黑描边。排除提示缩短为“停止追踪并隐藏历史”，恢复提示为“恢复追踪与历史”。

| 部位 | 实施契约 |
| --- | --- |
| 名称 | 保留原字重与改名图标；名称和文件名作为两行整体，与图标及右侧控件垂直居中 |
| 文件名 | 保留原有 QuietBadge 的字体、11px 字号、500 字重和间距，移除胶囊边框与底色，放在名称下方 |
| 文件名截断 | 仅确实截断时提供完整内容提示；键盘也能访问，完整文本保留在可访问内容中 |
| 分类 | 保留 QuietSelect 和分类名称；长分类名称有完整读取路径 |
| 颜色 | 行内只显示色点，去掉按钮常驻外框与背景，保留 hover/focus 和点击区域；弹层保留 HEX/RGB/HSL，右上角并排提供恢复默认与取色图标 |
| 标题记录 | 纯图标切换，正常／斜线形态表示单项设置；有明确按下状态和状态说明 |
| 排除统计 | 纯图标切换，排除动作用原橙色、恢复动作用原蓝色；保留 aria-pressed，去掉常驻选中外框与底色；名称附近保留“已排除”状态，恢复入口仍直接可见 |
| 删除记录 | 垃圾桶按钮，使用现有危险语义，仍进入确认流程；色点和三个操作采用 28px 点击区域并排，组内无额外间距 |
| 保存区 | 保留页面级未保存提示、保存和取消，不增加行级自动保存 |

当前窗口优先紧凑单列。常规行约 80 CSS px、行间距约 8 CSS px，长名称、编辑和状态文本需要时允许增高。按维护者后续确认，列表依实际可用 CSS 宽度自动切换一至三列，不设手动开关；每列最小 640px，列间距 16px，1296px 起两列、1952px 起三列，更宽时仍最多三列。缩放或侧栏改变可用宽度时由 CSS 自动重排；窄窗口只在确实容纳不下时将控件组移至下一排。

本次不新增更多菜单或右键菜单，不重做网页域名卡片、工具栏、分类筛选、分页或数据模型，不改变记录、排除和清理的业务语义。共享组件变更需保护其他消费者。

## 3. 状态与副作用契约

| 输入状态／操作 | 显示与行为 |
| --- | --- |
| 单项标题开启，全局开启 | 正常标题图标，切换语义为开启；提示当前已开启及点击关闭 |
| 单项标题关闭，全局开启 | 斜线标题图标，切换语义为关闭；提示当前已关闭及点击开启 |
| 全局标题关闭 | 单项偏好不被改写；按钮禁用，页面可见说明实际不记录标题，辅助描述说明单项偏好与全局限制 |
| 已排除应用 | 排除按钮保持选中，显示已排除状态；标题图标不应被解读为仍在采集，沿用既有排除业务规则 |
| 点击分类、颜色、标题、排除 | 沿现有 handler 修改草稿；保存前不新增持久化调用 |
| 恢复默认颜色 | 清除应用颜色覆盖，沿现有颜色 resolver 重新显示默认值；不硬编码为分类色或写入当前颜色常量 |
| 保存成功／失败 | 成功后清除对应未保存状态；失败保留可重试草稿和错误反馈 |
| 取消 | 恢复原有名称、分类、颜色及记录偏好，不残留仅存在于新控件内部的第二份草稿 |
| 删除取消／失败 | 取消不执行删除；失败保留错误和可重试路径，不误移除应用行 |
| 删除确认／进行中 | 沿现有删除流程，防止重复提交；删除不被包装为等待页面保存的设置 |
| 加载／保存／删除忙碌 | 继承实际 busy 约束；不能通过色块、快捷键或双击绕过禁用 |

Tooltip 补充当前状态和下一步动作，按钮始终有独立可访问名称。切换按钮使用稳定名称配合 aria-pressed；不通过交换动作图标暗示当前状态。全局禁用原因不能只藏在原生 disabled 按钮无法获得的键盘提示里。
