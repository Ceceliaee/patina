## 1. 目标与第一性原理

用户已经确认了当前页面的字号、字重、badge 比例和图表布局。本次收敛的目标是：保留这些结果，减少表达同一规则所需的重复声明、覆盖关系和维护位置。

浏览器最终展示由 DOM、样式层叠、继承、状态和容器几何共同决定。因此，两个声明的值相同，并不直接证明其中一个可以删除；删除后仍在所有支持场景得到相同的计算样式和布局，才构成有效去重。

从这个事实推导执行原则：

1. **视觉契约先于代码数量。** 字号、行高、字重和交互不能因减少代码而改变。行数只是辅助观察值。
2. **取值统一与声明复用是两件事。** token 统一“是多少”；文字角色和组件统一“在哪里使用”。把所有数值换成变量，只完成前者。
3. **同一事实只有一个实际 owner。** 字体尺度归 token，文字角色归已有角色类，控件默认样式归控件，页面只拥有其独有布局和确实不同的展示语义。
4. **共享必须有共同变化的理由。** 两段代码恰好都是 12px，不意味着它们应共享一个新组件。应看阅读任务、状态和未来修改是否属于同一契约。
5. **消除复杂度，而非转移复杂度。** 不把 CSS 重复换成大量 JSX 类组合、跨页面选择器列表、全局覆盖或新的包装组件。
6. **先取得低风险收益，再判断抽象。** 先删无效覆盖，再复用现有类；只有已证明的剩余问题才进入结构调整。

本方案服从 [Quiet Pro](../quiet-pro-component-guidelines.md)、[架构规范](../architecture.md)、[工程质量](../engineering-quality.md) 和 [修复边界守则](../issue-fix-boundary-guardrails.md)。这里只记录一次性执行步骤，不另设长期样式规范。

## 4. 选择样式 owner 的判断顺序

对每组重复声明依次回答以下问题，并将结论写入第 9 节的执行记录。

1. 删除它之后，是否由同一元素已有规则提供完全相同的结果？是则优先删除。
2. 它是否属于一个共享控件的默认行为？是则让控件 owner 持有默认值，清除无意义的调用方覆盖。
3. 它是否只是已有文字角色的字号与行高？是则尝试给实际文字节点复用现有 `qp-text-*` 类，字重独立复用 `qp-weight-*`。
4. 它是否只是同一个 feature 内一组固定语义节点的共有规则？若 JSX 复用反而分散 owner，可在该 owner 内合并有限的选择器。
5. 它是否承担 SVG 坐标、图表测量、特殊控件继承或独有布局约束？保留明确的局部规则，记录必要性。
6. 前述方法都不能降低维护成本时，保留原实现并说明原因，不强行引入抽象。

层叠判断必须包含来源、层、优先级、顺序和继承。未分层组件规则通常会压过普通 `@layer utilities` 规则，不能只给 JSX 加类就认为迁移成功。迁移时删除被替代的字体声明，并观察实际计算值。

禁止用 `!important`、不断加深的选择器或 `font` 简写掩盖迁移问题；`font` 简写可能重置字体族等未打算改变的属性。不得因为 compact 与 regular 当前某些取值一样，就合并它们不同的密度语义。
