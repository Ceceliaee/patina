# 工具软件通知的体积决策

本次范围是已确认的软件通知与提醒弹窗分流、工具页通用通知设置、立即保存和提示音。独立通知窗口复用现有提醒内容，没有新增前端依赖。

## 同环境比较

使用 Node 24.22.1、Vite 8.2.4 和预算脚本的 Node gzip 默认口径，在临时目录重建当前提交 `296134c4` 的前端，复用工作区相同依赖，不修改当前源码。发布重建记录沿用[循环提醒体积决策](2026-11-01-recurring-reminders-bundle-decision.md)的 v1.9.11 数值；未重测已发布安装包。

| 指标，KiB gzip | v1.9.11 历史重建记录 | 296134c4 本次重建 | 当前候选 |
| --- | ---: | ---: | ---: |
| 全部 JS/CSS | 384.91 | 397.49 | 400.42 |
| 初始 JS/CSS | 198.81 | 201.21 | 203.01 |
| Tools 页面 | 9.81 | 13.07 | 13.48 |

候选总量比当前提交增加 2.93 KiB（0.74%），初始图增加 1.81 KiB（0.90%）；比发布历史重建记录增加 15.51 KiB（4.03%）。比较包含工作区原有的工具编辑与文案改动，不能将全部差额归于本次通知。体积数字不代表启动耗时。

## 增长归属与减重

通知呈现 store、typed gateway 和订阅 hook 被主窗提醒、工具设置及通知窗共同使用，构建归入 `useToolPresentation`，2.03 KiB gzip。独立通知入口按需加载，`ToolNotificationShell` 为 0.286 KiB。四种语言的通知设置与失败文案、工具页控件及通知专用布局构成其余直接成本。原来的 `useToolAlerts` 队列 hook 和设置空状态样式已经移除。

三个提醒组件继续共享内容与动作，不复制通知版界面。没有新前端音频库；提示音在 Rust 中合成并调用本地音频接口。通知入口已懒加载，主窗需要的呈现订阅必须在工具页未打开时工作，不能延迟到工具页导航后才加载。将其继续拆为细碎异步块会增加首次提醒的装配及失败分支；不为这次局部增长改动其他页面或国际化生成协议。

首次提醒仍等待内容与尺寸就绪后显示，主窗口后台生命周期不延长。已通过的完整浏览器测试覆盖启动就绪与导航；真实原生呈现、恢复证据及未完成验收由[执行记录](2026-11-04-tools-notification-settings-plan.md)持有。

## 限定预算决定

- 总量预算从 410 调整至 413 KiB，增加 3 KiB（0.73%），保持 3% headroom。有效上限从 397.70 变为 400.61 KiB，候选剩余 0.19 KiB，未增加额外长期缓冲。
- 给明确 owner 的通知入口单列 0.31 KiB 局部预算，约为当前必要体积加 8.3%；它不再计入未归属 support。原 support 预算保持 4.36 KiB，按新归属后的实际值约 4.17 KiB。
- 入口、公共依赖、CSS、locale、Tools、现有提醒组件及其他页面预算均不变。

此记录只决定已确认通知能力的必要成本归属；功能和运行时验证仍须独立通过，不以预算调整代替验收。
