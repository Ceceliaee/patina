## 1. 目标

在不改变 Patina 图标结构的前提下，让 Windows 系统托盘中的图标同时表达两个事实：

1. 它能在当前 Windows 任务栏背景上保持清晰可见；
2. 用户能在不打开菜单或主窗口的情况下判断 Patina 正在追踪还是已经暂停。

最终模型固定为：

```text
托盘图标 = Windows 任务栏明暗 × 追踪中/已暂停
```

这会产生四个资源变体，但只表达两种业务状态：

| 目标任务栏 | 追踪状态 | 资源语义名 | 视觉原则 |
| --- | --- | --- | --- |
| 浅色 | 追踪中 | `on_light_active` | 深色图形；箭头和圆点最清晰 |
| 浅色 | 已暂停 | `on_light_paused` | 整体降低对比；箭头和圆点仍强于外环 |
| 深色 | 追踪中 | `on_dark_active` | 浅色图形；箭头和圆点最清晰 |
| 深色 | 已暂停 | `on_dark_paused` | 整体降低对比；箭头和圆点仍强于外环 |

这里的 `on_light` / `on_dark` 指图标要显示在什么颜色的任务栏上，不是图标自身的颜色，也不是 Patina 主窗口的主题。

## 2. 第一性原理与不可变约束

### 2.1 为什么由任务栏主题决定配色

托盘图标的直接背景是 Windows 任务栏，而不是 Patina 主窗口。因此，决定图标可读性的环境变量只能是任务栏明暗。即使用户在深色 Windows 上把 Patina 固定为浅色，托盘仍位于深色任务栏上，必须选用 `on_dark_*` 资源。

由此得到以下选择函数：

```text
select(taskbar_theme, tracking_state) -> one of four tray icon variants
```

Patina 的 `theme_mode`、WebView 的 `prefers-color-scheme` 和页面 CSS 变量都不得成为此函数的输入。

### 2.2 为什么只有两个业务状态

用户在托盘中需要回答的核心问题只有一个：“Patina 此刻是否在记录？”因此只保留：

- `Active`：追踪中；
- `Paused`：已暂停。

不引入“启动中”“TUN 开启”“异常”等来自其他产品的第三种语义，也不把标题记录开关、窗口可见性或同步状态混入托盘主图标。

### 2.3 图形结构为什么必须完全一致

如果追踪和暂停使用不同轮廓、不同箭头位置或不同圆点大小，用户需要先辨认两个图形，再推断状态。保持几何结构不变后，差异只来自明度、颜色、饱和度和透明度，状态比较更快，也不会损害 Patina 的品牌识别。

四个变体必须共享：

- 相同画布、`viewBox`、路径、圆点和箭头位置；
- 相同描边宽度、圆角、留白和非透明像素边界；
- 相同缩放和导出流程；
- 相同 alpha 蒙版；仅颜色相关值允许不同。

### 2.4 箭头和圆点为什么是主状态信号

外环负责识别 Patina，箭头和圆点负责表达“正在运行/记录”的方向感和落点。即使在暂停态，箭头和圆点也必须比外环更清楚，不能把整个图标统一降成一团灰。

视觉层级固定为：

```text
箭头与圆点 > 外环 > 透明背景
```

## 4. 设计决策

### 4.1 状态与资源命名

- [x] 定义 `TaskbarTheme::{Light, Dark, Unknown}`。
- [x] 定义 `TrackingState::{Active, Paused}`，或在选择边界把现有 `tracking_paused: bool` 显式转换为该语义。
- [x] 定义 `TrayIconVariant::{OnLightActive, OnLightPaused, OnDarkActive, OnDarkPaused}`。
- [x] 用纯函数实现完整 2 × 2 真值表。
- [x] 在代码注释中明确 `OnLight` 表示“用于浅色任务栏”，避免后续反向理解。
- [x] `Unknown` 不伪装成已知主题；由明确的回退策略处理。

### 4.2 初始颜色提案

以下值只是首轮视觉打样输入，必须通过真实任务栏和 DPI 验收后才能定稿；组件代码中不得散落硬编码颜色。

| 变体 | 外环 | 箭头与圆点 |
| --- | --- | --- |
| `on_light_active` | `#5F6B7A` | `#394657` |
| `on_light_paused` | `#A8AFB8` | `#7B8592` |
| `on_dark_active` | `#C9D1DC` | `#EEF2F6` |
| `on_dark_paused` | `#484C51` | `#656A71` |

定稿判断不以十六进制值本身为准，而以以下结果为准：

- [x] 两种活动态在目标任务栏上第一眼清晰；
- [x] 两种暂停态明显弱于同背景的活动态；
- [x] 暂停态仍可辨认箭头、圆点与 Patina 外环；
- [x] 四个变体没有产生彩色徽章或告警感；
- [x] 箭头与圆点在每个变体中都比外环更突出。

### 4.3 Windows 明暗来源

采用 Windows 的系统界面/任务栏主题信号，而不是应用主题信号：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize
SystemUsesLightTheme
```

- 值为 `0`：`Dark`；
- 非零值：`Light`；
- 键缺失、类型不正确或读取失败：`Unknown`。

不要读取 `AppsUseLightTheme` 来驱动托盘图标，因为它描述应用表面，而用户可能让应用主题与任务栏主题相反。

## 6. 回退与故障隔离

回退目标不是猜出一个可能正确的变体，而是保证托盘可见且绝不影响追踪。

优先级如下：

1. 当前任务栏主题 + 当前追踪状态的目标资源；
2. 最近一次成功识别的任务栏主题 + 当前追踪状态的资源；
3. `app.default_window_icon()`；
4. 若连默认图标也不可用，沿用 Tauri/系统当前托盘图标，不主动清空。

- [x] 图标失败不返回到追踪设置提交链路。
- [x] 图标失败不阻止菜单更新。
- [x] 图标失败不关闭主题监听；下一次有效事件应可自愈。
- [x] 日志包含失败阶段和变体名，但不循环刷屏。
- [x] 回滚代码时只需恢复默认窗口图标路径并移除主题监听，不涉及数据迁移。
