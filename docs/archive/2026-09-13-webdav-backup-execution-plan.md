> 执行 owner：本任务实施者；产品行为由维护者确认。

## 1. 目标与基本约束

用户配置一次远端位置，之后能将备份可靠地放到这个位置；每次手动上传前，用户能看清目标并决定文件名。要实现这个结果，需要分别保证位置可用、上传意图明确、对象不被误覆盖、索引能找到实际文件。

配置界面保留服务器地址输入框与固定 `/Patina` 后缀。例如输入 `https://example.test/dav/tt`，最终目录为 `/dav/tt/Patina/`。输入框不增加独立目录字段，服务地址不限定为某个供应商。

手动入口改为“选择 WebDAV → 确认目标和文件名 → 上传”。确认窗口展示只读目标目录，预填带日期时间的 ZIP 文件名，允许编辑和取消。自动备份继续无人值守，本地备份继续使用本地另存为流程。

现有远端备份列表沿用同类选择窗口的右上角 × 关闭入口，移除底部单独的“关闭”按钮及其操作栏。每条备份的恢复入口和后续恢复确认继续保留。

### 1.1 从基本事实推导设计

| 基本事实 | 对实现的约束 | 应观察到的证据 |
| --- | --- | --- |
| URL 表示地址，不证明资源存在 | 不能把路径拼接成功等同于目录可用 | 缺失父目录时先创建，再上传 |
| 服务入口可能有多级路径 | 不能硬编码 `/dav`，也不能从主机根开始盲目创建每段路径 | 嵌套入口、无父级访问权限和非 DAV 响应均有明确结果 |
| 远端文件与界面草稿是不同事实 | 打开确认窗口只编辑草稿，确认后才开始备份副作用 | 取消时没有导出、MKCOL、备份 PUT 或索引更新 |
| 用户确认的是具体目标与名字 | 确认后不得默默换目标或生成另一个名字 | 实际请求与确认值一致；重名返回可处理错误 |
| 显示文件名不等于对象身份 | 索引 ID 必须与可编辑文件名独立 | 同一秒不同名字的备份同时保留在索引中 |
| 网络可能在服务端完成后断开 | “客户端没收到成功”不等于“远端没有文件” | 不确定结果不自动覆盖、删除或无限重传 |
| 看见某个文件不代表拥有它 | 目录切换与手动改名不能扩大自动清理权限 | 旧目录、手动对象及其他实例对象不被误删 |

目录创建的协议依据见 [RFC 4918 §9.3](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.3)：MKCOL 要求父集合已存在，409 不能直接作为成功；405 也需要结合资源性质判断。集合探测使用 [§9.1](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.1) 的 PROPFIND 与 resourcetype，不能用登录页的 HTTP 200 证明目录成立。

### 1.2 范围与受保护边界

- 只修改现有 WebDAV 备份链路、上传确认和远端备份列表关闭入口所需的设置交互、消息和验证。
- 不提供远端文件管理器、目录搬迁、旧备份重命名、覆盖上传或多目标调度。
- 不改变备份容器、SQLite schema、恢复策略、密码存储位置或自动备份成功门槛。
- 保留已有地址、用户名和 remoteDir 配置的可读取性；不为保持界面后缀而静默改写历史配置。
- 新目录创建失败可能留下本次已经创建的空父目录。报告失败，不递归删除目录“回滚”。
- 方案完成与代码实现完成分别记录；文档勾选不能代替运行证据。

## 4. 阶段 B：目标解析与目录创建

### 4.1 先确定探测边界

完整 URL 不自带“服务根”和“用户目录”的分界。优先方案是在同源路径祖先中查找最近的、已验证存在的 WebDAV 集合，将它作为创建锚点；这不是推断供应商根目录，也不应新增长期缓存或供应商名单。

- [x] B1：在 WebDAV owner 内统一目标 URL 生成。保留配置已有路径，按段追加目录；避免已编码 `%xx` 被再次编码，并明确拒绝可导致路径越界的输入。
- [x] B2：覆盖地址有无末尾斜杠、固定后缀输入、中文、空格、字面百分号、编码分隔符、点段、重复斜杠、query/fragment。为每项写明拒绝或规范化结果，不让显示路径与请求路径分叉。
- [x] B3：用 Depth: 0 的 PROPFIND 请求最少的 resourcetype 信息；限制响应体与解析资源。只接受匹配请求资源的成功属性结果和 collection 类型，不按 XML 子串或任意 207 放行。
- [x] B4：先探测配置地址。已存在且是集合则直接作为锚点；只有明确不存在时才向父路径查找。权限失败、认证失败、普通文件、解析失败或不可识别响应直接报错，不能当成“不存在”。
- [x] B5：祖先查找限制在同一 origin 的路径链内，最多到主机根，只读探测；禁止跨源重定向、向兄弟路径探测或在未验证锚点上创建。
- [x] B6：若找不到可信集合，返回可操作错误，提示检查服务地址或权限。不得以“尽力上传”绕过；若目标服务不支持该方案，在本阶段记录响应并重新判断，不能靠硬编码 `/dav` 解决。
- [x] B7：用嵌套入口 `/dav/user/files/` 和普通 `/dav/` 两类 fixture 验证算法不依赖固定服务根；该嵌套形状替代原计划的 `/remote.php/dav/files/user/`。已有配置地址能访问时不探测它的祖先。

### 4.2 在已验证集合下面创建

- [x] B8：将从锚点到配置地址的缺失路径段，与 remoteDir 中的路径段组合，按父到子顺序创建。已有配置地址与已有子目录可幂等复用。
- [x] B9：MKCOL 返回 201 时记录该级创建完成；405 或并发创建冲突时重新探测准确目标，只有确认是集合才继续。409 在无法验证集合存在时必须失败。
- [x] B10：处理目录名被普通文件占用、401/403、配额错误、5xx、超时和断网，返回失败阶段及可操作原因；诊断中不输出密码、Authorization 或完整私密响应。
- [x] B11：只在整条目录链成立后进入备份 PUT。中途失败不上传、不更新备份索引、不更新成功时间，也不删除已经创建的目录。
- [x] B12：让连接测试和手动、自动备份共用该目录准备实现；列表与下载不因读取而自动创建目录。
- [x] B13：连接测试成功仅表示本次验证的目录条件成立，不承诺之后 ZIP 写入不会遭遇权限变化、配额或网络失败；上传仍处理真实写入结果。
- [x] B14：测试整段操作的请求数、超时和重试上限，防止每级重试形成无界等待；保留当前 HTTPS、凭据和重定向约束。

阶段终点：fixture 可观察到“探测可信锚点 → 创建缺失父目录 → 创建 Patina”，且失败条件不会变成成功。

## 5. 阶段 C：手动上传名字与索引身份

本版采用明确语义：用户确认的名字就是上传名字；同名冲突时保留草稿并要求修改，不自动添加后缀、不弹覆盖确认。自动备份已有避重策略继续由自动备份 owner 持有。

- [x] C1：在 settings 的页面逻辑生成默认 `Patina-backup-YYYYMMDD-HHmmss.zip` 草稿名，时间取打开确认窗口的本地时间，窗口打开期间保持稳定。该值是建议名，不承担身份或安全校验。
- [x] C2：扩展现有上传 IPC，显式传递最终 fileName 与确认的 config。Rust 对来自 IPC 的名字独立校验；不要新增一套上传命令或把业务移进 command handler。
- [x] C3：确认所有真实调用方后同步更新签名、gateway、fixture 和 IPC 契约。无受支持旧调用方时不保留无文件名的手动上传分支；确需兼容时记录具体对象及退出条件。
- [x] C4：确定文件名输入规则：完整名字可编辑，必须为有效 ZIP 文件名；遗漏扩展名时在界面明确提示，禁止提交后偷偷更名。允许正常中文和空格。
- [x] C5：拒绝空名、单独扩展名、控制字符、目录分隔符、绝对路径、越界段以及不能安全下载到 Windows 临时目录的名字。结合当前校验函数确定长度、保留名和尾部字符规则，前端提前提示，Rust 最终拒绝。
- [x] C6：区分新上传输入校验与已支持历史索引读取，不因新增命名限制让已有合法备份无法列出或恢复。仅对有事实依据的历史边界保留必要读取支持。
- [x] C7：新手动备份使用独立、碰撞风险足够低的 ID，可复用现有 uuid v4 依赖。检查所有 ID 消费处，将“ID 必须是时间戳”的隐含假设消除；不改写旧索引 ID。
- [x] C8：本地快照临时文件使用内部安全唯一名，不直接用可编辑远端名字决定本地路径；继续使用既有快照导出和校验能力。
- [x] C9：上传保留 `If-None-Match: *`，不使用“先 HEAD 再无条件 PUT”。412 返回名字冲突；409 区分父目录问题，不误归类为重名。
- [x] C10：核对成功状态码，异常的覆盖响应不能被当作新对象创建成功；声明不可覆盖保证依赖服务端正确执行条件写入，并在测试服务上验证。
- [x] C11：只有文件已上传才发布索引；索引中的 fileName、remotePath、ID 与实际对象一致。保持条件索引更新，验证同一秒上传两个不同名字不会覆盖其中一个索引条目。
- [x] C12：保留“对象已上传但索引发布失败”的部分成功反馈，不能显示成完全未上传并诱导覆盖重试；不自动删除远端已上传对象。
- [x] C13：网络结果不确定时不自动换名重传；报告需要核查，重试仍使用不可覆盖写入。临时文件清理失败不得反转已经成立的远端成功事实。
- [x] C14：验证自定义名字从上传、列表、下载预览到隔离恢复全链路可用，恢复仍根据可信索引 ID 解析目标，不信任界面任意传入的远端路径。

阶段终点：上传命令能接收并保留合法名字，拒绝危险输入，条件写入和索引身份测试通过。

## 6. 阶段 D：确认窗口与交互状态

复用 [QuietDialog](../../src/shared/components/QuietDialog.tsx) 和现有表单、按钮原型。确认内容属于 settings，可建一个职责单一的 feature 组件；不把 WebDAV 业务做成 shared 组件，不在现有大型面板里继续堆协议逻辑。

| 状态 | 用户可见内容与操作 | 副作用 |
| --- | --- | --- |
| 编辑 | 只读完整目标、文件名输入、取消、上传 | 无备份网络写入 |
| 输入无效 | 字段错误，保留输入，上传不可用 | 无 |
| 上传中 | 输入与重复提交禁用，显示实际阶段或忙碌状态 | 创建目录、导出、上传、发布索引 |
| 可恢复失败 | 显示原因，保留目标和名字，可编辑后重试或取消 | 不自动重试 |
| 完全成功 | 关闭窗口并反馈实际文件名 | 更新成功信息 |
| 部分成功或结果不确定 | 明确对象/索引结果，说明下一步 | 不伪装失败后直接重传 |

- [x] D1：WebDAV 选择动作只关闭位置选择层并打开确认层，不调用 uploadBackup；保留本地备份入口与调度图标的独立行为。
- [x] D2：打开确认层时捕获已保存配置的快照；缺少配置或凭据时进入既有配置提示。不得读取或显示密码。
- [x] D3：显示完整目标地址，长地址允许换行或横向阅读而不撑破窗口；复用目标摘要 owner，以跨端用例验证它与实际请求一致。
- [x] D4：输入框预填默认名并选择便于改名的文本；提供明确字段标签、ZIP 提示、行内错误和“取消 / 上传”按钮。
- [x] D5：如果确认期间配置已变化，使草稿失效并要求重新确认；不得显示目标 A 却上传到 B，也不得用过期配置覆盖新的设置。
- [x] D6：确认前按取消、Escape、关闭按钮或背景关闭均不导出、不建目录、不上传；下一次打开生成新草稿，不残留上次错误。
- [x] D7：确认提交同步建立防重复保护，再进入异步调用。上传期间禁用关闭与取消，避免假装能取消尚无中止支持的网络操作；保持可见忙碌状态。
- [x] D8：失败后解除忙碌状态、保留编辑内容并使重试可达；成功后关闭并将焦点还给仍在页面上的备份入口，而非已经卸载的位置选择按钮。
