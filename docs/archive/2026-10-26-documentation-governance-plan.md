## 1. 目标与完成边界

本轮让后续开发更容易找到正确规则，减少重复阅读和无关文档维护，关注三个结果：

- **当前说明准确。** 功能、命令和支持边界与实际实现一致，入口没有失效操作要求。
- **规则容易找到。** 每条规则有明确的权威归属，其他入口保留必要摘要和链接，避免重复维护完整流程。
- **任务状态可信。** 完成、未验证、取消和转交分别说明，历史记录不会被误当成当前待办或通过证据。

现行 [AGENTS.md](../../AGENTS.md#documentation-hygiene)拥有文档准入、归属和生命周期；[工程质量](../engineering-quality.md#46-prose-质量)拥有 prose 与验证要求；[CONTRIBUTING](../../CONTRIBUTING.md)是贡献入口。命令、schema 和配置事实继续由实现持有。本文只记录此次问题、处置与验收，不增加长期规则来源。

本轮完成以核实范围内的问题有明确处置为准，不以改了多少文档、增加多少规则或活动文档数量归零衡量。未发现缺口可以记录“已核对，无需修改”；不能为完成步骤制造改动。

复核普通文档与政策修改是否被混同、定向反馈是否误替代完整验收、Mini 展开/收起与超时表述是否符合实际状态、历史链接处理是否丢失原意，以及归档是否篡改旧勾选项或验收结果。对照实际裁剪/确认实现、原有测试断言、中英验证入口及 Git 差异，未发现尚待处置的问题。复核中明确了记录中的工程质量第 8 节归属，并把旧行号问题限定为历史定位失效；没有据此增加检查器能力或新规则。

三项任务均已执行，条件项明确不触发；旧任务的人工、安装、跨架构和事故归因限制继续保留。审查结论仅覆盖本轮文档增量，验证范围见第 6.2 节。
