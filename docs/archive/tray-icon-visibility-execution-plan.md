## 1. 目标与第一性原理

用户需要减少通知区域中的常驻图标，同时继续使用后台时间追踪，并能重新打开和退出应用。成功标准是三个独立事实同时成立：用户选择隐藏后图标不可见；后台行为仍符合设置；恢复和退出始终存在可用路径。

从资源和控制权出发，必须区分以下概念：

| 概念 | 拥有的事实 | 不能据此推断的事实 |
| --- | --- | --- |
| 图标显示偏好 | 用户是否允许展示托盘图标 | 进程是否应退出、追踪是否暂停 |
| 关闭行为 | 点击关闭后驻留还是退出 | 托盘图标是否可见 |
| 启动行为 | 本次启动显示主窗口还是进入后台 | 此后用户主动唤出是否仍需隐藏 |
| 窗口生命周期 | 主窗口可见、隐藏、销毁、重建 | tracker 是否需要重新启动 |
| 明确退出意图 | 用户请求结束应用 | 普通窗口销毁是否等于退出 |

因此，实施顺序是先拆开生命周期判断，再接入偏好、界面与错误反馈。仅在一个位置调用 `set_visible(false)` 不足以满足目标：其他启动和恢复路径仍可能重新显示图标，或把图标隐藏误解为取消后台驻留。

### 1.1 必须保持的不变量

- 图标显隐不修改追踪暂停、标题记录、会话、挂件或自启动偏好。
- 关闭后驻留不依赖图标可见；关闭后退出不因新增设置而被阻止。
- 用户主动再次启动时，已有实例恢复主窗口；后台优化已销毁 WebView 时仍走既有重建路径。
- 最小化、自启动、更新重启和目录切换重启保留各自的语义。
- 明确退出优先于驻留和窗口恢复；退出过程中不重新拉起主窗口。
- 保存成功、持久化成功但即时应用失败、保存失败三种结果可区分。
- 缺少新字段的旧配置沿用原有表现；隐藏偏好不通过修改旧字段来模拟。

### 1.2 范围与非目标

本项包含一个托盘显示偏好、设置保存与恢复、桌面生命周期解耦、现有单实例恢复验证、相关文案和必要测试。设置页不新增“退出 Patina”按钮，也不新增退出命令或权限。隐藏图标后，用户可重新打开主窗口并恢复图标，再从原有托盘菜单退出；关闭行为设为退出时，仍可直接关闭窗口退出。

不修改系统通知区域配置，不引入服务、快捷键或第二个追踪进程，不改变采样与统计算法，不重构整个设置系统，不修改备份格式或数据库 schema。若发现确实需要后两类变化，先在对应 owner 处重新判断范围与兼容风险。

长期规则分别由[架构](../architecture.md)、[工程质量](../engineering-quality.md)、[稳定期边界守则](../issue-fix-boundary-guardrails.md)、[Quiet Pro](../quiet-pro-component-guidelines.md)和[本地化](../localization.md)拥有。本文完成后归档，不成为第二套长期规则。

## 3. 行为契约与兼容选择

### 3.1 偏好模型

建议增加 `showTrayIcon` / `show_tray_icon`，默认 `true`，含义为“允许按现有桌面策略显示托盘图标”。`false` 明确抑制正常路径下的图标显示；`true` 恢复既有显示策略，不把过去关闭后退出、前台无图标的组合改成始终显示。

这保留旧配置行为，也避免升级后新增常驻图标。用户可见文案采用第 3.4 节的短说明，开启时仍按此处定义恢复现有显示策略。如产品最终要求开启后无条件常驻图标，先明确这是另一个可观察行为变化，再调整此契约与测试。

存储继续使用现有 settings key/value 通道。缺失值与非法值采用一致的兼容默认；Rust 和 TypeScript 使用相同的布尔解析口径。不要通过更改 `close_behavior`、`start_minimized` 或暂停状态实现隐藏。

### 3.2 正常路径决策表

| 条件或动作 | 图标 | 窗口与进程结果 |
| --- | --- | --- |
| 新字段缺失或开启 | 沿用旧策略 | 旧配置行为保持 |
| 关闭显示并保存成功 | 隐藏 | 当前主窗口不被关闭，追踪状态不变 |
| 隐藏图标，关闭行为为驻留，点击关闭 | 隐藏 | 主窗口隐藏；无窗口时进程继续运行 |
| 隐藏图标，关闭行为为退出，点击关闭 | 隐藏 | 沿用现有正常退出行为 |
| 隐藏图标，最小化到任务栏或挂件 | 隐藏 | 分别沿用既有最小化目标 |
| 隐藏图标，启动时最小化 | 隐藏 | 按既有启动来源规则进入后台；后台优化可释放 WebView |
| 隐藏图标，再次启动已有实例 | 保持隐藏 | 已有实例显示并激活主窗口；重建时保持单一恢复链 |
| 从隐藏改回开启 | 恢复旧策略计算的结果 | 不修改其他桌面偏好 |
| 更新重启、目录切换重启或设置恢复 | 根据已保存偏好 | 保留对应启动来源的主窗口显示要求 |
| 用户选择明确退出 | 随进程退出消失 | 绕过驻留拦截，执行既有清理，不触发恢复重开 |

### 3.3 异常路径与恢复入口

正常后台启动不再以强制托盘可见作为成功条件。仍保留实际恢复故障的兜底：优先显示主窗口；窗口确实无法显示且没有可用交互入口时，才允许临时暴露托盘恢复入口。该状态不写回用户偏好，恢复成功后清除，并重新应用已保存偏好。

需区分“用户选择后台运行”与“恢复失败”：前者不应触发安全图标。`TraySafetyState` 若同时承担驻留和图标语义，应按实际生命周期需要拆开状态职责；不要增加一组可以独立漂移的互斥布尔量，也不要建立通用窗口管理框架。

保存采用明确的分阶段结果：

- 持久化失败：保留旧运行时和已保存值，草稿可继续编辑或重试。
- 持久化成功、显隐应用失败：新偏好已保存，提示即时应用失败并提供重试或重启路径；不得展示“全部生效”。保存值与实际表现的差异必须可解释。
- 重试成功：应用最后一次已提交偏好，清除错误；迟到请求不得覆盖更新后的偏好。
- 启动读取失败：走既有设置恢复策略，优先保留可操作窗口；不要把未知配置当作用户主动隐藏。

### 3.4 常驻卡片布局与文案

常驻卡片从五项增加到六项，沿用现有字体、间距和右侧开关。卡片随内容增高，页面继续滚动；保存和取消仍使用页面顶部入口，不增加退出按钮。

| 顺序 | 标签 | 说明 |
| --- | --- | --- |
| 1 | 最小化到挂件 | 保留现有说明 |
| 2 | 关闭时隐藏 | 关闭窗口时隐藏主窗口，并继续在后台运行。 |
| 3 | 显示托盘图标 | 关闭后隐藏托盘图标。 |
| 4 | 开机自启动 | 保留现有说明 |
| 5 | 静默启动 | 启动后隐藏主窗口。 |
| 6 | 低耗后台 | 保留现有说明 |

“关闭时隐藏”替换原“关闭到托盘”标签，不改变开关对应的关闭行为或存储值。“显示托盘图标”紧跟其后，关闭该开关只修改图标显示偏好。静默启动说明不再包含“进入托盘”或额外的后台运行描述。

### 3.5 隐藏图标后的使用影响

- 托盘菜单暂时不可访问，暂停／恢复追踪和标题记录控制需在主窗口操作，或恢复图标后使用原有菜单。
- 托盘图标原有的追踪／暂停状态提示不再可见；隐藏本身不会改变追踪状态。
- 主窗口隐藏后，从开始菜单或应用快捷方式唤出原实例。低耗后台已释放界面时，重建窗口可能稍有延迟，沿用现有低耗后台说明。
- 退出沿用第 1.2 节的现有路径，不新增设置页退出入口。
- 后台计时、静默启动、开机自启动、挂件和最小化保持各自既有行为；验收重点是图标隐藏不触发退出，再次启动能够恢复原实例。

这些影响用于设计与验收，不要求全部堆入设置卡片说明。

### 7.1 归档后的对抗式审查

审查对象为本任务相对 HEAD 的本地 diff，包含持久化、命令、effect、原生事件循环、窗口恢复和新增测试。未发现当前证据下需阻止交付的新问题；这不是安装包发布批准。

- **失败是否误报成功：** 核对数据库事务错误、提交后应用错误、通知错误和页面 toast 分支；新增浏览器用例分别观察原值保留与新值保留，不能只靠 mock 的调用次数判定。
- **旧状态能否覆盖新状态：** 设置提交与 effect 都在提交锁下读取已保存值，原生队列执行时再读取桌面快照；桌面字段更新不覆盖启动与后台优化字段。
- **隐藏是否造成退出：** 图标偏好不参与驻留判断；真实 IPC 关闭图标后销毁最后窗口，第二实例唤回成功且日志没有重新显示图标。
- **冷启动能否泄露图标：** 运行时断言隐藏冷启动 `created=false`，保存开启后 `created=true`；没有把先创建后隐藏当作无闪现证据。
- **退出是否死锁：** 主题监听回调不等待事件循环，退出 join 与刷新不形成循环等待；明确退出优先的规则测试通过。原生菜单点击与极端迟到回调仍受第 6 节证据边界限制。
- **菜单与权限：** 首次创建从当前运行时读取菜单状态；保留原有退出菜单；没有新增退出 IPC 或权限。
- **开发版恢复：** 确认 debug 默认关闭单实例，文档要求在第一实例启动前开启；不能只给第二实例设置变量，也不能用正式安装版入口代替。

审查保留的缺口为第 6 节的安装版人工矩阵、极端原生双重故障与并发压力验证；没有将其标记为已经通过。一次分类控件超时在完整单独复跑未再现，未修改断言来掩盖失败。
