## 1. 目标与第一性原理

同一批会话事实只能有一套基础解释。History 与应用详情可以采用不同的展示策略，但不得分别实现身份归一、实时会话截断、标题编译、活动计数和时长计算。

本次统一遵循以下不变量：

- [x] 真实时长等于来源会话有效时长之和，不把合并间隔计入使用时长。
- [x] 活动跨度可以覆盖间隔，但必须与真实时长保持两个独立概念。
- [x] 未闭合会话先按 tracker health 物化，再进入日期裁剪与活动编译。
- [x] 标题明细来自已经保存的历史事实；当前标题记录开关只控制未来采集。
- [x] 图形时间轴与详情卡片从同一份编译后活动派生，渲染层不得再次合并。
- [x] 最小时长过滤发生在活动编译之后，不改变底层统计事实。
- [x] History 与详情的差异必须由显式策略参数表达，而不是复制算法。

## 2. 最终语义矩阵

| 规则 | History | 应用详情弹窗 |
| --- | --- | --- |
| 默认缩放 | 4 小时 | 24 小时 |
| 缩放范围 | 1～24 小时 | 1～24 小时 |
| 最小时长偏好 | History 独立保存 | 详情弹窗独立保存 |
| 身份归一与排除 | 共享编译器 | 共享编译器 |
| 当前会话物化 | 共享 tracker health 规则 | 共享 tracker health 规则 |
| 同应用、无其他应用穿插 | 按活动保持阈值合并 | 按相同阈值合并 |
| A → B → A | 可按活动保持时间桥接 A | 与 History 相同；B 的时长不计入 A |
| 标题明细与标题数 | 共享标题行编译结果 | 复用相同编译结果 |
| 活动数 | 编译来源段数 | 复用编译来源段数 |
| 图形与卡片分段 | 同一编译结果 | 同一编译结果 |

History 与详情统一使用“活动保持时间”解释短暂应用切换；详情只投影目标应用，因此中间应用的时长不会计入目标活动。两边仅保留目标范围、默认缩放和最小时长偏好差异。

- [x] 保留来源会话 ID、真实 duration、标题明细、诊断信息与 live 状态。

### 3.3 应用详情读模型

- [x] 加载当天完整应用会话，而不是先过滤目标后再推断上下文。
- [x] 使用共享 `materializeLiveSessions` 处理健康与 stale tracker。
- [x] 使用共享 `compileSessions` 完成身份归一、排除和日期裁剪。
- [x] 在完整应用序列中复用 History 的活动保持策略，再投影目标应用。
- [x] 投影目标应用并建立来源会话到编译活动的稳定归属。
- [x] 卡片活动数按编译活动的来源段数计算。
- [x] 标题数与标题弹层复用编译后的标题明细行。
- [x] 应用名与窗口标题相同时不把应用名误算成标题。
- [x] 没有实际标题记录时不生成“未记录标题”明细或展开入口。
- [x] 未覆盖标题采样的时间仍作为无标题事实保留，不丢失时长。
- [x] 当前会话在 tracker stale 时截断到最后可信心跳。

### 3.4 图形时间轴与卡片一致性

- [x] 移除 destination 图形层的二次相邻片段合并。
- [x] 一个编译活动对应一个图形时间段。
- [x] 视口裁剪同时裁剪活动记录与标题明细。
- [x] 30 秒可见性下限在编译活动形成后应用。
- [x] 图形段与卡片共享活动 ID、起止时间、真实时长和 current 状态。
- [x] 详情默认 24 小时及其独立偏好键保持不变。
- [x] History 默认 4 小时及其独立偏好键保持不变。

### 3.5 历史标题与键盘交互

- [x] History 始终允许读取已经存在的标题明细。
- [x] 关闭标题记录不会隐藏过去已经保存的标题。
- [x] History 放大时间线支持 `ArrowLeft` 和 `ArrowRight` 按视口 10% 平移。
- [x] `Home` 跳到当天开头，`End` 跳到当天结尾。
- [x] 未支持按键不拦截默认行为。
- [x] 时间线交互区域可获得键盘焦点。

### 3.6 刷新与防闪烁

- [x] 日期、映射版本、数据刷新、合并阈值和重试仍能触发正确请求。
- [x] 请求使用递增身份和取消检查，旧响应不能覆盖新目标或新日期。
- [x] 同目标刷新保留当前可用内容，不退回空白首屏。
- [x] 每次真正加载时更新当前时间，避免详情弹窗长期冻结在首次打开时刻。
- [x] 健康 tracker 的持续心跳变化不触发详情重载。
- [x] 仅 stale tracker 的最后心跳变化触发截断结果重算。

- [x] A → 空隙 → A 是否仍按 History 阈值合并？会，且真实时长不包含空隙。
- [x] 图形层是否可能把读模型已经拆开的活动重新合并？不会，二次合并已删除。

- [x] 应用名是否可能伪装成窗口标题？对应回归测试已覆盖并通过。
- [x] stale live session 是否会继续增长？不会，使用共享最后可信心跳截断。
- [x] 旧异步请求是否可能覆盖双击后的新目标？请求身份和取消守卫仍生效。

- [x] 默认缩放与最小时长偏好是否被错误统一？没有，两边继续独立。
