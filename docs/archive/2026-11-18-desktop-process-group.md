# Windows 桌面进程分组

交付一个 `patina.exe`。后台持有录制和数据写锁，GPUI 进程承载主窗口与 Mini，各探测保留独立的退出、超时与回收边界。沿用现有桌面通信协议、数据格式与安装更新回滚机制。

- [x] 从同一个程序启动后台、窗口和探测，验证真实进程树、关窗续录及单个工作进程的故障恢复。
- [x] 更新开发与 CI 构建、安装包和升级回滚，验证从多个程序文件升级到一个文件。
- [x] 在本机任务管理器核对分组，用隔离 profile 对比窗口打开时间和关闭后的整组内存。
- [x] 验证工作区、原生和当前文档检查，更新架构及发布说明后归档。

## Windows 11 本机验收

开发版在「进程」页显示为可展开的 `Patina (5)`。核对进程命令行时，五行分别对应一个录制后台和四个探测进程。打开主窗口和 Mini 会共用一个额外的 GPUI 进程。真实进程数随活跃窗口和探测任务变化。各子行默认沿用同一个 EXE 的文件描述 `Patina`。「详细信息」中的「命令行」列可以区分窗口和探测角色。

使用相同的 Windows x64 隔离桌面、活动数据与调试构建，各运行三轮。内存取每次采样中整组进程私有提交字节数之和的中位数。打开时间从托盘操作计到主窗口控件可用，覆盖三种窗口状态下共 27 次打开，系统文件缓存已预热。

| 指标 | 原多文件构建 | 单文件构建 |
| --- | ---: | ---: |
| 关闭最后一个窗口后，整组私有内存 | 18.12 MiB | 19.48 MiB |
| Mini 折叠时，整组私有内存 | 88.53 MiB | 90.36 MiB |
| Mini 展开时，整组私有内存 | 89.09 MiB | 90.80 MiB |
| 从托盘打开主窗口，中位数 | 710 ms | 571 ms |

后台和常驻探测进程延迟加载 Windows 图形及辅助功能库，本机模块快照验证它们在打开窗口前保持未加载。连续开关 15 轮后主窗口和 Mini 仍共用一个窗口进程，后台保留。使用同一优化候选完成全新安装、从旧三程序安装升级、文件占用回滚及卸载数据保留验证。安装升级与回滚沿用[发布策略](../release.md)，各角色的运行边界见[架构规范](../architecture.md)。

ARM64 已在 x64 本机交叉链接。两种架构的 PE 导入表均将九个目标库列为延迟加载项。运行时和安装验收覆盖 Windows x64。
