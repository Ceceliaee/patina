## 必要性与替代方案

bootstrap 的新增成本对应 load/save/clear 的代际判定、真实存储操作串行化、UTF-8 字节上限、按查询/语言/分类身份限流，以及保存成功后记账并允许时钟倒退后的重试。仅阻止内存回填无法阻止旧 IPC 晚完成重新写入磁盘；仅限制字符串长度会漏掉多字节负载；全局时间限流会阻止不同查询身份保存。

随后针对损坏的嵌套内容，实际消费路径复现了缺失图轴、指标标签、图点、应用范围或热力图单元时的异常，以及缺失 summary 时显示假零。最终校验限制在首屏实际消费字段，验证 33 种损坏形状会清除缓存并返回 null、8 种正常构建结果仍可读取；Data 套件共 130 项通过。这是生产 loader 与模型消费者的行为证据，尚不是每种损坏内容的浏览器挂载证明。原 07:45 的 1.2 KiB 暂定值只包含竞态保护，未包含后来确认的形状缺陷，旧测量和失败日志保留，不将它冒充最终预算。

Data 的新增反馈、焦点和跨日行为有真实浏览器反例。减重已经包括：Data 指定范围状态实例从 49 降至 38；移除最后视图模型副本、测试专用读取路径、两个双击转发回调；趋势面板删除四个 ref 和两个重试 effect；合并重复菜单快捷键；布局同帧重复通知合并。产物 raw 从 73,652 B 降至 73,469 B，但 gzip 仍增加 113 B，说明源码长度不能代替包体测量。

已排查的其他选择：

- 当前功能没有可替换的大依赖；局部新增成本属于自身控制流和文案。
- Data 和 bootstrap 都不在 HTML 初始图，仍由原路径懒加载；资产数和初始资产数保持 66/24。
- 再拆分这两个模块不能消除实际成本，会增加入口和维护面；不通过改变 chunk 归属掩盖增长。
- 删除持久化缓存会改变首屏缓存能力，删除限流会增加常驻写入，删除竞态或字节保护会复现已确认缺陷。没有证据支持这些取舍。
- 原 owner 内重复验证、相同异常分支和重复发布出口已合并。没有证明所有可能写法数学上都更大；本轮停止为几十字节继续引入可读性或维护成本。

相对当前必要体积，两项名义预算缓冲分别约为 3.23% 和 6.05%，均低于政策允许的 feature 缓冲上限。扣除统一 3% 余量后，有效上限分别留下 29 B 和 49 B 空间。这是不同口径，不混算。未提高总包预算，不能由此自动扩大其他 owner 的额度。
