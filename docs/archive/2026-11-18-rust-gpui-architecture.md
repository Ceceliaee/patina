# Patina 全 Rust 与 GPUI 架构执行方案

2026-11-18 已在本机 Windows x64 完成验收，36 项全部勾选。基线为本地提交 `50518161`，本次交付为其上的工作区变更。第五节保留最终源码指纹、测量条件、安装包摘要和环境限制。首次正式发布继续由发布规范管理。

## 一、从产品行为推导架构

Patina 首先要解决两件事：用户关掉界面后仍能准确记录，用户回来时能理解并控制这些记录。架构是否成立，可以通过取走一个部件、打断一次操作或重放一段历史来判断。

| 必须成立的事实 | 推导出的边界 | 怎样证明 |
| --- | --- | --- |
| 关窗、切页或界面异常都不能中断桌面活动记录。 | 每个 profile 一个写入宿主。托盘、采样和到期调度跟随宿主；所有可见界面由按需启动的 GPUI 进程管理。 | 关掉最后一个窗口，确认窗口进程退出。制造一段可识别的活动和一条到期提醒，重新打开后核对两者。 |
| 同一段活动在今日、历史和统计中应有一致的含义。 | 活动模块决定区间、归属、去重和统计。窗口只接收具名读模型。 | 用同一组含跨日、重叠和匿名记录的样本请求三个表面，逐项对照事实与预期。 |
| 一次写入要么完整可见，要么维持原状。 | 数据库生命周期归 storage，业务事实和修订由所属业务在同一事务内更新。 | 在写入与提交之间注入失败；重新打开数据库，核对事实、修订和可见汇总。 |
| 用户正看的窗口、正在输入的草稿和键盘焦点有各自的寿命。 | GPUI 实体持有交互状态，窗口持有导航和焦点恢复。持久偏好经宿主保存。 | 快速切换日期、离开有草稿的页面、销毁并重开窗口，检查晚到响应、草稿确认和焦点。 |
| 外部系统可能延迟、失效或提供不完整信息。 | 不可可靠取消的 Windows 探测在受控子进程内工作。浏览器扩展、备份与更新各自保有明确的协议。 | 让探测超时、窗口断线或更新中断，观察原记录、进程回收和重试结果。 |
| Rust 应用的开发和发布准备可以从干净环境复现。 | Cargo 管理依赖与版本，仓库自有检查和发布逻辑由 Rust 实现。翻译、SQL、工作流及安装器使用各自的数据或声明格式。 | 在无 Node/pnpm 的干净 Windows 环境编译、检查、生成双架构发布准备产物，保留 Linux 独立运行仓库工具的 CI 入口。 |

本次签收使用维护者指定的本机 Windows 环境。双架构产物与依赖树可在本机交叉验证；ARM64 原生运行、Linux 原生运行及专用交互会话的实机数据只在有实际证据时记录。日常桌面使用隔离桌面和临时 profile，保留 CI 原生验收入口。

产品行为以[产品原则](../product.md)为准，数据和进程保证见[现行架构](../architecture.md)。本方案定义目标结构及替换顺序。已有[GPUI 桌面验收单](../working/2026-11-11-desktop-tray-mini.md)继续持有逐页体验和资源基线；本方案复用其证据，单独验证进程、编译依赖和发布物变化。

| 消费方 | 允许知道什么 | 所有权检查 |
| --- | --- | --- |
| 常驻 `patina` | 活动、存储、平台、工具、更新及桌面协议，由入口装配具体实现。 | 常规构建依赖无 GPUI/QuietPro；无窗口时仍能关闭数据库、调度任务和退出。 |
| `patina-ui` | 桌面协议、GPUI、QuietPro、i18n 及绘制窗口所需的系统 API。 | 常规构建依赖无 SQLx、活动写服务及 Wasm 执行引擎。页面调用对应业务的类型化客户端。 |
| `activity` 与 `storage` | 活动模块使用存储事务和快照。storage 管理连接、文件和可恢复切换。 | 同一事务中调用业务写入与修订更新。storage 不反向引用窗口或活动页面；备份合并由业务提供表级语义。 |
| `patina-probe` 与 `windows-integration` | 探测只取得采样请求、平台资源及有界响应。 | 探测进程可以在无 profile、无数据库、无 UI 的环境单独运行；Job 和回收期限由启动它的宿主持有。 |
| 桌面协议、QuietPro、插件 SDK | 分别拥有跨进程消息、通用控件、插件接口。 | 协议类型不引用 SQLite 行或 GPUI 实体。QuietPro 可单独渲染测试。SDK 可单独构建 Wasm；插件的数据写入通过宿主能力。 |

一个 crate 拥有一项可独立解释和验证的职责。某个页面独有的布局、动作、草稿和测试随该功能放置；只有共享行为形成稳定契约时才进入 QuietPro。Windows 窗口焦点属于 UI，前台活动观察属于采样，两者按消费者分别落位。能力内部的文件数量和命名由实现决定。

## 四、执行顺序与验收

先完成 A，再建立 B 的 Cargo 入口。B 后可分别开展 C 的核心拆分、D 的窗口协议和 F 的工具替换。D 的三程序联调需要 C 交付独立探测程序；E 使用 C 的活动接口和 D 的类型化协议。G 的发布工具可提前开发，安装验收需要 D 的完整程序组。H 在各路径汇合后执行。

### A　固定可比较的输入和预期

- [x] 从临时 profile 和可合法分发的合成样本建立基线。覆盖跨日会话、原生与网页重叠、匿名活动、应用关联、现有工具数据及历史 SQLite 备份。记录输入、时区、预期区间、统计和可恢复状态。
- [x] 在隔离 Windows 环境记录后台采样、托盘开今日、Mini 开合、定时提醒以及关掉最后一个窗口的行为。按进程记录 CPU、内存、句柄和重开耗时，注明构建配置、DPI、样本和采样时段。[工程质量](../quality.md)
- [x] 从 `package.json`、三个工作流、各 Cargo manifest 和安装脚本列出实际入口。为每个将退出的命令标记调用者、替代入口和一项能识别退化的样本；直接由 workflow 调用的候选 SHA 校验也进入清单。

基线结果（`50518161`）：`pnpm run check` 通过，包括 48 个 PR/固定候选用例；Recorder 契约 11 通过，1 个凭据与 WebDAV 专项按原配置忽略。快照模块 19 个测试通过，含合并晚期故障回滚。入口与替代关系见 F 表；安装器交接和示例的替换见 G。

旧版工具与数据契约分别在基线工作副本的根目录及 `desktop/` 执行。新旧二进制的资源测量共用[当前 Windows 测试入口](../../apps/patina/Cargo.toml)和同一套隔离环境，实测结果见第五节。

旧、新 Recorder 均通过纽约时区跨日与夏令时回放。3 月三个本地日的原始与投影时长分别为 86,400,500、82,801,500 与 86,402,000 ms；11 月中间一天为 90,001,500 ms。网页历史契约中的归并合计为 27 分钟，归组源为 17 分钟。匿名、工具、历史备份及失败回滚沿用同一组合成输入。

### B　建立 Cargo 工作区与独立构建路径

- [x] 建立根 workspace 和 `xtask`，迁入桌面工具链要求、Cargo 别名、GPUI feature 配置、SQLite 固定来源及 AccessKit 补丁。用 `cargo metadata --locked` 核对成员、依赖来源和实际补丁。
- [x] 桌面产品版本由 `workspace.package.version` 提供。先核对当前仓库版本与实验 crate 版本差异；对照发布规范确定产品版本，保留 SDK、插件、数据库和外部协议各自的版本含义。
- [x] 交付 `cargo xtask dev`，保留开发 profile 隔离、预览重启和编译失败时可继续操作上一成功构建的行为。根目录默认启动路径可发现且可复现，预览退出后没有遗留采样宿主。
- [x] 按维护者确认从本机 Windows 根目录构建桌面产品并运行独立 `xtask` 测试。Linux 原生执行由 Verify 的 Ubuntu tooling job 持有，本机未执行。对官方插件和示例插件显式指定 Wasm 目标，验证冻结构建及锁文件归属。记录编译命令、目标三元组和产物名称。

冻结解析得到 15 个根 workspace 成员。SQLite 继续使用 `10462fa4`，AccessKit 和两个 GPUI 平台选择器使用仓库内补丁。编译失败、修复重启和旧预览正常退出由 `dev::tests::failed_build_keeps_preview_until_fixed_save` 验证。

### C　拆分活动、存储和系统探测

- [x] 把会话切分、AFK、锁屏、睡眠、网页观察以及分类规则收进活动模块。用可控时钟和 A 的输入重放，核对原始记录、今日汇总和精确历史。宿主只负责提供时钟与观察、调度和退出。
- [x] 将连接、WAL、数据库位置、迁移与恢复切换集中到 storage。活动专用 SQL、来源优先级和归属与业务一起维护。用一次事务写入活动事实和派生修订；模拟提交失败、并发读取和重启，检查没有半次写入。历史会话与标题样本应来自同一快照。
- [x] 明确配置与业务数据归属。主题和语言的持久偏好由宿主通过存储读写，窗口拥有实时预览；专注与提醒的存储经现有宿主能力访问。验证取消预览、卸载后历史保留、导出和备份恢复的行为。
- [x] 将原生探测入口放入 `patina-probe`。保留固定通道、请求编号、时限和 Job 回收。让子进程超时或提前退出，确认旧进程及通信线程回收后才能重建，迟到回复不能污染新一代观察。
- [x] 在旧版本数据库和备份的副本上演练迁移、合并、覆盖恢复和中断重启。比较记录身份、关联、用户配置和自定义路径。失败时按现有恢复日志回到完整副本，保留原始样本。[存储与备份边界](../architecture.md)

独立 probe 的原生测试 `native_probe_processes_are_reused_reaped_and_recovered` 通过，覆盖 100 次复用、超时、半响应、重建与 Job 回收。存储、平台、活动模型和 Recorder 的测试分别从 `patina-storage`、`patina-windows-integration`、`patina-activity-model` 和 `patina-recorder` 运行。

并发与故障复核包括 `concurrent_title_changes_do_not_mix_history_snapshots`、`native_web_boundary_failure_rolls_back_facts_and_revision_together`、`snapshot_merge_preserves_all_record_domains_and_rolls_back_late_failure` 和 `storage_round_trip_and_migration`。本机另通过 `storage::storage_webdav_round_trip`，使用临时凭据与回环服务完成上传、预览和恢复。

### D　交付类型化协议与三程序生命周期

- [x] 先打通“托盘 → 打开今日 → 读取摘要”。协议为请求定义配套结果和可处理的错误；宿主把活动数据映射为传输类型，UI 客户端返回具名结果。用序列化往返和真实管道测试证明调用方无需猜测 JSON 字段。
- [x] 逐组切换历史、分类、设置、存储、工具和更新请求。将通知事件与请求回应区分，保留现有冲突、过期操作和取消语义。在最终构建移除通用 `Result<Value, String>` 回应；插件扩展载荷限于其独立协议边界。
- [x] 宿主从安装目录定位同版 UI 与 probe，传递受控通信句柄。用错配程序验证启动握手拒绝不兼容协议。区分请求编号、窗口进程世代和数据修订；对端断开时结束挂起请求。测试重开后先取快照、丢弃旧回应，写操作结果不明时重新读取状态再决定是否提交。
- [x] 宿主持有 profile 单实例锁，处理同时启动、登录自启、托盘与正常退出。模拟 UI 崩溃、最后一窗关闭和一个探测通道故障，验证采样继续；宿主退出时验证写入完成、子进程与句柄回收。
- [x] 用实际 x64 和 ARM64 Windows 目标导出各包生产依赖树，按第三节检查直接和传递依赖。区分运行依赖、构建依赖和测试设施，验证宿主可独立于 GPUI 编译，UI 可独立于 SQLite 编译。

两个 Windows 目标都已导出 `cargo tree --locked -e normal,build`。x64 的宿主、UI、probe 分别有 386、352、107 个不同的包名，ARM64 分别有 382、350、104 个。宿主没有 GPUI，UI 没有 SQLx 或插件执行引擎，probe 三者均为零。`cargo xtask check tools` 持续检查这六棵树。

真实故障用例 `concurrent_launch_and_renderer_crash_reopen_the_committed_snapshot` 通过。在同一 profile 并发启动，只有一个写入者；临时锁住 SQLite，在设置写入等待时终止窗口进程，放行后宿主提交并继续采样。重开读取已提交的设置与当前应用，正常退出后无遗留子进程。

### E　让界面状态跟随 GPUI 实体

- [x] 主窗口只持有导航、窗口级动作、关闭及草稿确认。各页面通过 `Entity` 持有选择、焦点、当前查询和局部缓存。以历史页验证连续切换两天，即使先发请求晚返回，仍显示最后所选日期。
- [x] 让视图持有订阅和异步任务的生命周期，在视图销毁或重建时结束或忽略失效结果。同一数据修订只刷新依赖它的可见内容。用可控任务先验证乱序，再用真实窗口验证关窗、重开和焦点恢复。
- [x] 有业务含义的控件组合留在功能目录。通用选择、输入、主题、图表绘制和键盘交互归 QuietPro。用无头测试覆盖控件状态；用真实 UIA/键盘覆盖中文和英文导航、主题预览、缩放、草稿取消和屏幕阅读名称。[Quiet Pro](../ui.md)
