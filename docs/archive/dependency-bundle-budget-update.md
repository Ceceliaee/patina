## 版本与收益

- React/React DOM 19.2.4 → 19.3.0，配套类型声明 19.3.0。[官方发行说明](https://github.com/facebook/react/releases/tag/v19.3.0)包含 Suspense 上下文传播、延迟值停滞和 lazy/memo 热更新修复。本项目保留既有 React 渲染体系，接受公共运行时的体积成本；不为本轮升级引入 ViewTransition 或其他新产品功能。
- Vite 8.1.4 → 8.2.2。[官方变更记录](https://github.com/vitejs/vite/blob/v8.2.2/packages/vite/CHANGELOG.md)包含 Windows 路径、符号链接、模块运行与打包依赖修复。实测更积极的合并减少了请求文件数量，没有将 Settings 导出加载到启动入口。
- Lucide 1.7.0 → 1.44.0。[官方发行说明](https://github.com/lucide-icons/lucide/releases/tag/1.44.0)列出图标实现与清晰度修复。按新版本真实模块路径改为 `.mjs`，未保留 `.js` 回退；仍只导入使用中的图标。

## 构建证据与预算决定

同机四组构建使用 Node 24.21.0、pnpm 12.3.4 和预算检查器相同的 Node `gzipSync` 口径。统计最终写出的文件，模块归因由打包器提供。Python gzip 与生成过程中的中间代码都不作为最终体积依据。

| 组合 | 启动 JS+CSS（KiB） | 总 JS+CSS（KiB） | JS/CSS 文件数 |
| --- | ---: | ---: | ---: |
| 本轮升级前 | 187.480 | 368.116 | 80 |
| 仅升级 React 组 | 195.871 | 376.474 | 80 |
| 再升级 Vite | 194.368 | 373.747 | 66 |
| 再升级 Lucide，最终组合 | 195.385 | 375.730 | 66 |

最终相对本轮起点：启动资源增加 7.905 KiB（4.22%），总资源增加 7.614 KiB（2.07%）。启动总预算 310 KiB、总预算 391.75 KiB、入口预算 65 KiB 及其余未受影响的预算保持不变。

发布基线取自 v1.9.6 的[成功发布运行](https://github.com/Ceceliaee/patina/actions/runs/34555772816)：启动 187.71 KiB、总产物 368.36 KiB。它使用发布当时的工具链，和上表的同机升级前对照分别记录，不混成同一基线。

| 预算对象 | 旧预算 | v1.9.6 实际 | 本轮起点 | 最终实际 | 变化（KiB / 比例） | 新预算 | 相对实际缓冲 |
| --- | ---: | ---: | ---: | ---: | --- | ---: | ---: |
| React 公共运行时 | 60 | 55.36 | 55.364 | 63.624 | +8.260 / 14.92% | 66.8 | 4.99% |
| Settings 导出界面 | 6 | 5.19 | 5.187 | 5.933 | +0.746 / 14.38% | 6.5 | 9.56% |
| QuietSelect | 2.4 | 2.31 | 2.307 | 2.584 | +0.277 / 12.01% | 2.71 | 4.88% |
| 域名颜色共享块 | 0.4 | 0.37 | 0.373 | 0.411 | +0.038 / 10.19% | 0.43 | 4.62% |

单位均为 KiB gzip。初始/共享块缓冲不超过 5%，feature 块不超过 10%；检查器继续要求 3% 可用余量，不根据每次构建结果自动提高预算。表格为此次决策快照，当前阈值仍由 `scripts/check-bundle-budget.ts` 拥有。

归因与优化排查：

- React 增长主要来自 `react-dom-client.production.js`，调度器同步到 0.28.0。生产图中没有重复输出模块或 React DOM 开发模块；拆成另一个启动必需文件不能减少启动成本，替换 React 超出本轮范围。
- 新版 Vite 将约 0.19 KiB 的浏览器存储块合入已有启动入口，将约 0.59 KiB 的数据导出协议块合入原本懒加载的导出界面。前者仍受入口和启动总预算约束，后者由导出界面预算承担；不为维持旧文件名强制重新拆包。
- 构建生成 `.vite/bundle-ownership.json`，检查器依据实际模块归属继续拒绝存储模块缺失、重复归属及导出协议进入启动图。两个过时的独立小文件预算由加载阶段和新 owner 检查取代，没有将预期文件改成可选。
- QuietSelect 的增加主要是打包器合入它使用的保存/删除图标；域名颜色块的变化来自新版地球图标。图标总共按需输出 82 个模块，没有打入整库入口。将它们一并塞入初始 icons 块会扩大无关启动成本，因此保留现有使用方归属。
- Lucide 组在 Vite 组之后使总资源增加约 1.98 KiB；懒加载支持块最终约 5.15 KiB，低于原 6.55 KiB 预算。没有提高全局预算来吸收局部增长。

## 验证记录

冻结安装、`pnpm run check:full` 与 `pnpm run test:tauri-runtime-smoke` 均通过，包括类型、lint、治理、115 项冷缓存浏览器场景、708 项 Rust 测试、27 项 mutation、构建预算、依赖审计，以及真实 Tauri/WebView2/SQLite/权限和冷重启场景。日志分别为 `full-check.log` 和 `runtime-check.log`，没有将失败后的重复执行当作成功证据。

生产构建首屏计时使用同一 Tauri 测试夹具、独立浏览器 profile、禁用浏览器缓存、同机交替执行升级前后各五次。从导航开始计时，到 Dashboard 内容和主窗口就绪证据同时成立：

| 组合 | 五次耗时（ms） | 中位数（ms） |
| --- | --- | ---: |
| 升级前 | 180.4、158.2、156.7、171.6、178.4 | 171.6 |
| 升级后 | 150.0、172.8、156.1、170.5、155.1 | 156.1 |

该夹具中未观察到首屏退化；五次本机样本不能证明普遍提速，也不替代真实桌面验证。计时前已完成其他构建/验证工作，没有并发编译。`startup-results.json` 和 `startup-probe.ts` 保留原始结果与方法。

对抗式复核覆盖实际 CLI 与生成产物：六项子进程探针分别确认有效产物通过、导出协议移入启动图失败、缺失模块归属失败、重复归属失败、React 体积超过新上限失败，以及恢复产物后重新通过。`budget-probes.json` 保存输出。检查器内部正反例继续由正常 `check:bundle` 入口运行。

最终语义锁图只变化于这三个依赖组及其配套包：React 调度器、Vite 的 Rolldown/OXC 和原生绑定。Vite 退出的 WASM 回退依赖随之移除，Windows x64/ARM64 绑定均保留。既有业务源文件、数据结构和本任务前的未提交改动未改变；本轮只修改四个既有文件，并新增构建归属 owner 与本文。

最终审查没有剩余已确认缺陷。原生 ARM64、远端 CI 和签名发布验收继续由后续获授权的发布执行者承担，没有提交、推送或外部状态修改。
