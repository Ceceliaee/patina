## 1. 目标与阶段边界

用户在 Classification 中通过一个纯图标按钮打开分类弹层，选择某个分类后查看对应应用或网页。按钮放在对象模式切换左侧。先让筛选逻辑和最小可操作入口成立，再调整图标、间距、弹层尺寸和视觉细节。

本方案依据用户确认的功能方向和仓库代码编写，不保存私有队列的正文、字段、排序或截图。任务步骤归本文；长期规范继续由 [架构](../architecture.md)、[Quiet Pro](../quiet-pro-component-guidelines.md)、[工程质量](../engineering-quality.md) 和 [本地化](../localization.md) 拥有。

阶段 A 完成后，底层筛选可独立验证；阶段 B 完成后，用户可以实际操作并讨论 UI；阶段 C 完成后，界面和功能一起验收。仅完成 A 不表示功能已经交付。

## 2. 从问题推导实现

### 2.1 筛选是视图条件

用户想改变当前看到的项目，不是在修改分类数据。因此选中的分类只属于页面状态，不进入分类草稿、保存请求、数据库、备份或持久化偏好；选择与清除不应触发未保存提示。

分类以稳定 ID 比较，名称和颜色只负责显示。重命名、换语言和重配颜色不应使筛选失效；不同 ID 的同名分类也不能被合并。

### 2.2 选项集合与结果集合用途不同

分类选项回答“当前对象模式有哪些可选分类”；列表回答“哪些项目同时符合当前条件”。选项从当前模式的完整、可信候选快照和有效草稿映射推导，不从搜索结果反推。否则搜索或选择分类会使其他入口消失，用户难以继续操作。

结果遵循：对象模式候选集合 ∩ 基础筛选 ∩ 分类条件 ∩ 搜索条件，然后沿用现有排序。这里的“底层”是前端 feature 的筛选与读模型，不需要新增 Rust command、SQL 查询或持久化索引。

### 2.3 数据正确性先于视觉细节

把匹配、选项推导和状态转换写在 feature owner 中，组件只展示选项并发送选择事件。后续调整弹层布局不重写筛选逻辑。最小入口仍必须有可访问名称、键盘操作、焦点和错误处理；这些是功能的一部分。

## 3. 功能契约与实施默认值

单个纯图标入口及后续调整 UI 是已确认方向。下表给出可直接实施的行为默认值；尚未实际验证的项目保留未勾选，维护者调整行为时先修改本节及对应测试。

| 情况 | 预期行为 |
| --- | --- |
| 未选分类 | 分类条件不限制结果；保留现有基础筛选和搜索 |
| 选择分类 | 单选，以 ID 过滤，选中后关闭弹层 |
| 清除分类 | 弹层提供“不限分类”；只清除分类条件 |
| 全部 / 已分类 | 与具体分类取交集；“全部”沿用现有不包含已排除项目的语义 |
| 已排除 | 在已排除项目内按分类过滤，不恢复统计或记录 |
| 未分类 | 清除具体分类并禁用具体分类选择，避免必然为空的互斥组合；基础条件仍按现有 `other` 语义执行 |
| 分类候选 | 仅列出当前模式中实际有项目的具体分类，包含只存在于已排除项目中的分类；`other` 由“未分类”入口处理 |
| 搜索 | 页面搜索继续匹配现有字段；弹层搜索仅缩小选项，不改页面搜索词或当前选择 |
| 切换对象模式 | 目标模式也有该分类则保留，否则在可信快照就绪后清除；网页功能关闭时按应用模式执行相同规则 |
| 修改名称或颜色 | 通过草稿 resolver 立即显示更新，选择仍绑定原 ID |
| 新建空分类 | 不加入筛选选项；有项目分配到该分类后才加入 |
| 修改项目分类 | 按有效草稿即时更新列表与选项；取消编辑后按恢复的草稿重新计算 |
| 已选分类最后一个项目被移出 | 保持当前分类条件及其可识别的选中展示，显示空结果，允许主动清除；不自动展示所有项目造成列表突变 |
| 删除选中分类 | 在分类定义实际删除时清除选择；不能只凭过滤结果为空认定分类被删除 |
| 保存或取消草稿 | 筛选本身不参与保存；草稿恢复后重新派生选项和结果，不自动复活已清除的筛选 |
| 初次加载 / 加载失败 | 禁止无可信数据的选择；沿用页面加载、错误和重试入口 |
| 后台刷新失败 | 有已提交快照时沿用快照，不把暂时缺失误判为分类消失；保留既有错误提示 |
| 空结果 | 明确是当前条件下无匹配，仍可清除分类或搜索 |

已选分类因草稿编辑暂时没有项目时，弹层保留当前选中项作为清除上下文；其余候选仍遵守“有项目才显示”。对象切换、定义删除和暂时零结果是不同事件，应分别处理。

## 6. 阶段 B：最小可用图标入口

### 首版 UI 规格

首版使用漏斗形筛选图标，放在“应用 / 网页”左侧，与现有工具栏控件垂直居中。按钮使用现有 icon action 尺度；未筛选为中性外观，筛选生效使用已有选中样式。图标不附常驻文字，也不在工具栏额外增加分类标签。

弹层默认从按钮下方展开，空间不足时交由共享定位逻辑翻转或收敛到窗口内。内部顺序为搜索框、“不限分类”、分类列表；每个分类项显示小色点、名称及右侧选中勾。初版不增加数量 badge、分组标题或底部确认按钮。选择即时生效并关闭。

```text
工具栏： [基础筛选]  [搜索应用或分类…]       [漏斗图标] [应用 | 网页] [管理分类]
                                               │
                                               ┌──────────────────────┐
                                               │ 搜索分类…            │
                                               │ 不限分类             │
                                               │ ● 工具             ✓ │
                                               │ ● 工作               │
                                               │ ● 学习               │
                                               └──────────────────────┘
```

图示仅表达信息顺序，实际宽高按现有 token、长名称和 viewport 约束确定。弹层搜索框打开时获得焦点，列表用匹配的单选语义；搜索框到选项的方向键路径由最终采用的复合控件明确负责。打开时让当前选项处于可见范围。工具栏空间不足时沿用页面响应式布局，不能为保持单行而把图标命中区压小。

## 8. 验证矩阵与完成门槛

| 验证层 | 必须证明的结果 | 主要证据 |
| --- | --- | --- |
| 纯筛选 | 不限等价、交集正确、排序不变、选项与搜索独立、模式集合独立 | 分类确定性测试 |
| 草稿与生命周期 | 新建、重命名、删除、重新分配、取消、模式切换和加载不产生幽灵选择或错误清除 | 状态转换及集成断言 |
