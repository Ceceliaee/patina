## 1. 目标与第一性原理

用户需要通过西班牙语理解当前状态、预测操作结果并完成日常任务。因此交付单位是完整的用户路径，而不是翻译文件数量。桌面端已经显示西语，但托盘、扩展错误或恢复确认仍让用户误解，都不能算完成。

本次采用 翻译、文案复核、程序与界面验证后进入正式版，再根据用户反馈持续纠正的路线。发布前不要求母语者完成逐项审校；这不代表翻译已经获得母语认可，也不允许把生成、哈希更新或测试通过描述成人工审校。

从用户需要推导出五个不变量：

| 基本事实 | 必须保护的结果 | 对执行顺序的影响 |
| --- | --- | --- |
| 文案帮助用户决定是否操作 | 删除、恢复、排除与隐私含义不能反转或缺失条件 | 先确定语义和术语，再逐域翻译 |
| 同一句话会携带数量、日期和用户数据 | 参数必须完整，格式规则不能改变真实数值 | 资源校验与语义复核分别进行 |
| 语言只是事实的显示方式 | 切换语言不改变统计、同步、数据库和协议事实 | 先定位资源 owner，避免改动业务分支 |
| 用户会遇到多个窗口和浏览器 | 主窗口、Widget、托盘、Popup、Options 均须可用 | 以表面和状态矩阵验收 |
| 两个产品独立分发和升级 | 西语接入不能制造同日升级或版本锁步要求 | 分仓实现、分仓验证，再做组合验证 |

实施完成的可观察结果：用户可以在桌面端及扩展选择 Español，重启后保持语言，能够理解关键操作与错误，并且中文、英文和原有数据行为不回归。

## 3. 范围、非目标与语言决策

### 3.1 交付范围

- 桌面端全部必需资源：主页面、设置、对话框、辅助技术标签、Widget、托盘、Tools 提醒及语言相关导出。
- 扩展 Popup、Options、状态、错误、帮助、辅助技术标签，以及资源契约中的 manifest 名称与描述。
- 两端一致的产品术语，独立的语言存储，符合各自布局的西语文案。
- 如实表达 文案复核来源的审核记录、相应校验和长期规范。
- 两仓可供正式发布使用的本地实现及验收证据；实际发布按另行授权执行。

### 3.2 不包含的工作

- 不改变追踪、同步资格、Token、端口、协议字段、数据库 schema 或备份格式。
- 不增加云翻译、语言包在线下载、账号、遥测或远端权限。
- 不重建本地化框架，不复制扩展源码到桌面仓库。
- 不把本次西语策略推广为其他语言的默认放行规则，不改变俄语人工贡献流程。
- 不自动新增多套西语地区选项，不增加桌面端与扩展语言联动协议。
- 完整商店长描述、营销图片和 README 全文西语化不属于本次必要范围；现有资源中的短描述仍须覆盖。
- 本文不是提交、推送、标签、商店提交、签名、Release、Issue 评论或关闭的授权。

### 3.3 在创建资源前固定 locale

本次确定通用 `es`，显示名称 Español，方向 ltr，扩展目录映射为 `es`。措辞尽量兼顾西班牙与拉美，但格式遵循运行时 Intl/CLDR 的 `es`，不宣称没有地区差异。

- [x] L1：验证 `es` 能被桌面新语言命令规范化、资源生成器、前端 Intl 与 Rust locale 生成链接受。
- L2（已处置：剩余验证不纳入本次收口，未记为通过）：验证扩展 `webExtensionLocale` 的西语映射及 Chromium、Firefox 构建与实际加载结果；必要时查阅对应浏览器官方规范。
- [x] L3：列出固定日期、数字、时间长度样例，记录 `es` 在实际运行时的输出；不要把通用语言标签宣传为没有地区格式差异。
- [x] L4（不适用：通用 es 链路已通过，无需地区别名）：若现有链路要求地区标签，比较 `es-ES` 与 `es-419` 的实际限制和格式后记录单一选择；不要同时注册多个别名绕过问题。
- [x] L5：将 locale 与平台映射写入注册表，格式预期记录在本次执行记录。按维护者后续要求，长期文档不增加逐语言约定或特例章节。

完成条件：只有一个明确的生产西语 locale，两个项目的显示名称一致，平台目录映射和格式预期有验证依据。

## 4. 修改归属与保护边界

本文中桌面路径相对 Patina 根，扩展路径相对独立 Patina Web Sync 根。

| 结果 | 人工维护 owner | 生成或消费 owner | 不变量 |
| --- | --- | --- | --- |
| 桌面西语消息 | `locales/<locale>/*.ts` | `src/shared/i18n/generated/` | key 与参数符合 schema |
| 桌面语言元数据 | `locales/registry.ts` | 前端类型、loader、Rust locale | 注册信息单源 |
| 桌面原生显示 | locale 中的 native 等资源 | `src-tauri/src/domain/localization/` | 不在 command 中加语言分支 |
| 桌面复核语义 | `docs/localization.md`、`locales/review-manifest.ts`、`scripts/i18n/` | i18n 检查 | 不把哈希当成人工证明 |
| 桌面资源体积 | `scripts/check-bundle-budget.ts` | build 与 bundle gate | 新语言不进入默认启动图 |
| 扩展西语消息 | `locales/<locale>/ui.ts`、`manifest.ts` | 两个浏览器目标目录 | 不手改生成副本 |
| 扩展语言菜单 | `src/shared/ui/options.html` 及必要的共享 UI 行为 | Chromium、Firefox UI 副本 | 保持键盘与持久化语义 |
| 扩展审核策略 | `locales/review-manifest.ts`、`scripts/i18n/check*.ts` | 正式发布 gate | 所有语言使用统一审核规则 |
| 跨端协议 | 两仓 `docs/web-activity-protocol.md` 及既有实现 | HTTP 与持久化 | 只换语言，不改传输事实 |

### 阶段 A：固定起点和基线

- [x] A1：在两仓分别记录当前分支、HEAD、工作区差异和工具链版本，区分已有改动与本次工作；不重置用户文件。
- [x] A2：重新读取两仓 AGENTS 和相关长期 owner；读取实时 Project 以确认范围，私有内容仅用于本次协作，不抄入仓库。
- [x] A3：执行两仓现有 i18n self-test 和 i18n 检查；记录已有失败、命令、环境和退出码。
- [x] A4：读取 schema 与源资源，计算桌面 key、消息分支和扩展 UI/manifest key 清单；以执行时统计为准，不预填数量。
- [x] A5：检查是否已有西语目录、未提交资源或生成残留；存在时先判断来源，不重复创建或覆盖。
- [x] A6：完成 L1–L5，固定 locale；用 dry-run 检查桌面预计改动。
- [x] A7：固定两仓用于对照的构建体积基线；若暂时不能构建，明确阻塞原因，预算决策等待真实测量。（桌面已测量；扩展没有本次需调整的包体积门禁，未取得变更前包体积，不作体积增减声明。）

产出：可复现起点、实际失败清单、唯一 locale 选择。既有失败不能作为本次变更通过的理由。

### 阶段 B：先让审核规则准确表达本次路线

这一步应先于把资源标为已复核。维护者已选择 翻译进入正式版，但生成器和发布检查不会因为聊天中的决定自动改变。

- [x] B1：修改桌面 `docs/localization.md`，保留通用的审核安排与质量要求，不按语言或翻译生成方式新增规则。
- [x] B2：修改扩展对应 owner，区分“允许发布”“复核方式”和“母语审校”三个事实，删除只能用两种语言描述生产语言集合的过时表述。
- [x] B3：桌面沿用逐 key source hash 记录，不增加独立来源文件或译文哈希 gate。
- [x] B4：取消本次新增的专用审核元数据；扩展沿用现有 review manifest，保留真实 reviewer、日期及内容哈希。
- [x] B5：扩展使用普通 copy-review 记录，不按语言或生成方式设置放行例外；未知方式、pending 和 stale hash 仍失败。
- [x] B6：核对扩展 `check.ts`、`check-release.ts` 与 self-test 使用一致的审核判断；如需复用判断函数，放在现有 `scripts/i18n/`，不要复制两套放行条件。
- [x] B7：验证普通文案复核与既有维护者复核可通过；缺少 reviewer、未知方式、过期内容、未复核状态仍失败。
- [x] B8：核对桌面原文变更仍会让翻译复核失效；本次不弱化 key、参数、生成一致性和硬编码检查。
- [x] B9：运行命中的 i18n self-test；回看变更，确认没有删除整个 release gate 或批量改写中英文审核记录。

产出：规则、记录和检查器含义一致。译文仍必须在完成 C–F 后才能签署为已复核。

### 阶段 C：建立语义清单并完成 翻译复核

- [x] C1：按桌面资源域和扩展表面分批整理中文原文、英文参考、key、参数类型、分支条件、上下文与显示位置。
- [x] C2：先确定术语表，至少覆盖 tracking、session、AFK、有效时长、分类、排除统计、标题记录、备份、覆盖恢复、合并恢复、同步、连接与 Token。
- [x] C3：为关键概念写出应保留的含义。例如排除统计不是删除历史；关闭标题记录不是停止计时；扩展“已连接”不等于云端备份完成。
- [x] C4：明确 Patina、Patina Web Sync、Token、协议字段、URL 和用户自行命名的内容不机械翻译；与两仓现有规范核对。
- [x] C5：按资源域生成初稿，只改可翻译文本；保留参数名称、DSL 节点和业务条件，不将整份英文资源原样当作完成品。
- [x] C6：对每个批次另做一次逐 key 文案复核，对照中文原义、英文参考、术语表和实际调用位置；把复核与初稿生成分成两轮。
- [x] C7：逐项检查否定、条件、时态、数量范围、动作对象和可恢复性；对危险操作同时读标题、说明、主按钮和取消按钮。
- [x] C8：对复数、选择和格式化消息枚举所有 schema 分支，确认没有漏掉不可见于默认界面的文本。
- [x] C9：扫描与原文相同的值、英文残留、中文残留和空值；逐项区分品牌/技术标识与漏译，不能以字符串相等直接判定错误或扩大硬编码例外。
- [x] C10：将本次共同术语和用法记录在本文，译文由各仓资源源文件持有；长期文档仅保留通用的术语一致性要求，不添加西语特例。

产出：完整候选译文、术语依据、未解决语义问题清单。关键操作存在已知含义错误时，先修复再进入发布验收。

### 阶段 D：接入桌面端

- [x] D1：阶段 B 和 locale 选择完成后，使用现有新语言命令创建候选资源。该命令会立即注册语言并置 PENDING，因此不将中途状态当作可发布版本。
- [x] D2：填入 C 阶段译文，逐域覆盖当前 `locales/en-US/` 对应的全部生产域；以 schema 为完整性标准。
- [x] D3：核对 `native`、`tools`、`export`、`categories`、`accessibility` 和 `widget` 域，不能只完成主页面文案。
- [x] D4：以目标运行时实际 CLDR 类别建立复数分支。测试 0、1、2、21、1000000，并使用运行时找到每个类别的代表值；非整数仅在 schema 允许时加入。
- [x] D5：使用既有格式化入口验证固定日期、跨月范围、秒/分钟/小时和零时长；不得用手写地区分支替代 Intl 或 Rust 规则。
- [x] D6：按 B 阶段调整后的真实语义登记复核来源，再对已复核 key 更新 source hash；不要在翻译开始前执行全量签署。
- [x] D7：运行生成器，检查前端 locale 模块、loader、类型与 Rust 生成产物均由同一注册表派生；不直接修 generated 文件。
- [x] D8：验证设置语言列表出现 Español，保留预览、保存、取消和失败语义；仅在现有 owner 确实缺少接入时修改组件。
- [x] D9：核对主窗口和 Widget 的 locale 激活、并发加载与缓存；新增测试聚焦西语接入新暴露的失败模式，已有覆盖不重复复制。
- [x] D10：为新 locale 添加独立 chunk 预算，并测量实际 gzip、默认启动图和总体积。预算调整遵循工程质量文档的证据流程，不为通过检查普遍上调阈值。
- [x] D11：运行桌面聚焦检查；若修改布局，使用既有 Quiet Pro 组件和语义 token，不添加西语专属字号、页面硬编码宽度或特殊主题样式。

产出：桌面端可选择、可保存、前端与原生表面一致的西语候选版本。
