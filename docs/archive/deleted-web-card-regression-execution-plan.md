> 状态：实现、验证与对抗式审查完成，全部适用事项已勾选并归档。
> 创建日期：2026-09-17。
> 执行责任：本任务执行者完成实现、测试与审查；维护者负责发布决策。
> 当前交付：真实记录驱动的网页目录、删除后状态失效与刷新、完整域名删除目标、键盘焦点恢复及回归测试。归档时尚未提交、推送或发布。

## 1. 目标与第一性原理

用户删除一个网页的历史记录后，没有新活动写入时，该网页不应仅因刷新、重启或升级重新出现在普通分类卡片列表中。已经触发回归的旧数据应自动得到正确展示，不要求用户再次逐项删除。

从用户可控制的事实出发，需要区分四件事：

| 概念 | 代表什么 | 不能据此推导什么 |
| --- | --- | --- |
| 活动记录 | 某完整域名真实发生过且仍保存在库中的活动 | 无记录不等于从未访问过，也不等于明确删除过 |
| 域名设置 | 分类、别名、颜色、排除和标题记录偏好 | 保存过设置不等于当前仍有历史，也不自动获得普通卡片展示资格 |
| 关联规则 | 用户明确设置的主项与成员关系 | 关联身份不等于可删除的真实域名，主项操作不能隐式扩散到成员 |
| 卡片 | 对记录与必要管理入口的展示 | UI 列表或缓存不能成为独立的活动事实来源 |

由此推导本次修复的不变量：

1. 删除历史必须以完整域名为边界，成功后的历史事实确实消失；不得靠隐藏卡片冒充删除。
2. 普通独立卡片不能仅由残留的名称、分类、颜色或标题偏好生成。
3. 排除规则负责阻止后续记录，应保留可恢复的管理入口；删除历史不能静默开启追踪。
4. 关联配置的管理入口与活动卡片分开判断；删除某域名的历史不自动删除关联或其他成员记录。
5. 新的真实活动可以使允许记录的域名重新出现；旧缓存、旧配置和升级过程不能制造这种新事实。
6. 保留域名偏好与“彻底忘记这个网站”是不同的数据操作。本次修复现有“删除网页记录”的行为，不新增彻底清除所有设置的操作。

这些约束沿用[产品范围](../product-principles-and-scope.md)、[架构](../architecture.md)和[稳定期修复规则](../issue-fix-boundary-guardrails.md)。若执行中发现现有管理入口无法同时满足上述行为，应记录具体冲突再决定交互，不直接扩大删除范围。

## 3. 方案选择与范围

推荐在事实 owner 处区分“当前有记录的域名”与“仅设置或关系引用的域名”，由现有候选 owner 决定普通卡片与管理入口。优先复用已有事实集合；只有现有快照无法无歧义表达时，才增加用途明确的字段，并同步 Rust、解析器、类型和 fixture。

实施决定：`domains` 的生产消费者只有 gateway 标记转换；关系与设置已有独立字段。因此将其收窄为全部仍有活动记录的域名，保留原协议结构，无需新增字段、migration 或删除标记。近期候选仍保留原来的 30 天、120 条加载范围，完整记录域名用于补足管理项；未加载不等于不存在。空关联组沿用已有主项管理卡片与关系入口，成员由显式规则补足；未引入另一套管理页面。手动解除关系后，无历史的独立成员消失。

不能直接把快照的域名并集改成仅历史域名而不检查调用方：关联验证、成员管理和恢复可能仍需要完整配置域名。也不能只删除 `knownDomain` 补卡分支：近期候选可能受天数、数量限制，这会误隐藏仍有较早记录的域名。先调查集合的真实范围，再收窄其用途。

默认不新增删除标记表、数据库 migration、永久隐藏列表或第二套目录缓存。没有历史删除标记时，无法从残留偏好还原每一次过去的删除动作；本方案用当前记录存在性恢复展示契约，不猜测用户历史操作。零历史配置可以保留供未来合法访问复用，但不据此显示普通卡片。

本次范围包括分类网页候选、快照适配、删除后刷新以及直接相关的关系/排除管理回归保护。真实删除或活动写入若被反例证明有缺陷，再在既有 owner 内修复。非目标包括应用目录重构、网页自动归并、新增管理页、清空用户设置、采集协议扩展、统计算法重写、自动改版本或发布。

## 4. 预期行为矩阵

以下为逐项验证的目标。无记录独立偏好不计入普通卡片；排除项沿用排除筛选，明确关联组保留既有关系管理卡片及其计数，计数表达管理对象而非活动条数。

| 场景 | 普通列表与统计 | 设置或关系管理 |
| --- | --- | --- |
| 独立域名有记录，允许记录 | 按现有分类范围展示 | 原偏好生效 |
| 独立域名无记录，仅有分类/名称/颜色/标题偏好 | 不补普通卡片，不增加计数，不产生统计 | 偏好可保留 |
| 删除独立域名全部历史 | 成功刷新后消失，重启后仍消失 | 不隐式改变记录开关 |
| 无历史且已排除 | 不显示为有活动的普通卡片 | 在既有排除管理入口可恢复；不计入普通已分类/未分类数量 |
| 有历史但被排除 | 维持现有隐藏历史契约 | 可恢复，恢复后只显示仍存在的历史 |
| 有关系但某成员已无历史 | 不虚构成员活动或时长 | 成员关系可查看和解除 |
| 主项无历史、其他成员有历史 | 汇总保留其余成员真实活动 | 删除目标仍需明确，不能自动选中任意剩余成员 |
| 整个关联组无历史 | 不伪造活动；沿用带关联入口的主项卡片，关系成员仍可见 | 可解除关系；解除后无历史独立成员不再展示 |
| 域名有历史但不在近期候选窗口或超过候选数量上限 | 不将“未加载”误判为“已删除” | 不损失仍受支持的分类管理能力 |
| 删除后产生新活动 | 可重新出现，仅含删除后合法写入的记录 | 保留偏好正常应用 |
| 刷新/重启/升级但没有新活动 | 不使已删除独立域名回来 | 读取配置不生成活动事实 |
| 用户明确恢复含旧历史的备份 | 按正式恢复契约显示被恢复的事实 | 不把主动恢复误判成此回归，也不私改恢复语义 |
