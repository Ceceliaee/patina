## 2. 从阅读任务推导设计

### 2.1 用户首先需要辨认什么

用户打开页面时先确认位置，再找到所需内容区，最后阅读数值或执行操作。这对应页面、板块、内容三个基本层次。设置等页面在板块内部还有分组，需要额外的分组层；没有分组的页面不必为了凑层级增加标题。

字号只是建立层次的一个因素。字重、颜色、对齐、容器和留白都参与层次表达。为每一处文字增加一个字号，会提高维护成本，也会削弱用户对相同角色的识别。因此先定义角色，再给角色分配有限的字号，不按历史上的每一个数字建立 token。

### 2.2 可读性和空间约束

辅助信息虽然次要，仍必须可读。图表刻度、占比和文件名从 10–11px 提升到 12px 后会占用更多宽度；这需要同步调整刻度密度、边距和允许的换行，不能靠截掉状态或缩小字体恢复旧密度。

列表名称可以省略，但应保留完整内容的可访问入口；状态、时间、金额式数值和危险操作不能因长名称而被挤截。对四种语言不能只用中文字数估计宽度，必须用实际渲染结果验证。

核心统计值和计时读数是优先寻找的信息，可使用一档大数字。大数字表达的是阅读任务的重要性，而不是所有数字都自动放大。列表里的时长仍属于普通内容。

### 2.3 实现应有一个明确来源

语义 HTML 层级与视觉角色分开：`h2` 表达文档结构，不应意外决定所有板块必须同一个历史遗留字号。视觉样式由角色类和 token 控制，基础标签样式不得压过组件明确选择的角色。

尽量保留现有组件和 feature owner。无需为了统一字号增加通用 React Typography 组件，也不引入逐页缩放比例或新主题系统。

## 3. 当前基线与候选映射

以下是实施前基于代码的历史基线，`rem` 按默认根字号 16px 换算，不包含 Windows DPI 放大。它是盘点入口，不替代第一阶段的浏览器计算样式检查；弹窗、响应式断点和字体回退需逐项补齐。

| 角色 | 当前示例 | 候选字号 / 行高 | 历史候选字重（已由字重方案替代） |
|---|---|---|---|
| 页面标题 | 七页公共页头 17.6px | 18 / 24px | 600 |
| 板块与弹窗标题 | 今天、历史、数据卡片 15.04px；设置、工具板块 17.92px；共享弹窗 15.68px | 16 / 22px | 600 |
| 分组标题 | 设置 15px；工具部分分组 13px | 15 / 20px | 600 |
| 内容与操作 | 设置项 14px；分类名称 15px；历史分布名称 12px | 14 / 20px | 正文 400–500，主要名称与操作 600 |
| 辅助信息 | 占比、刻度、文件名、标签散布于 10–13px | 12 / 18px | 400–500 |
| 核心数字 | 今天 22px；历史摘要 18px；工具读数 28.48px，窄屏 27.2px | 24 / 28px | 600 |
| 紧凑信息 | 数量、图例、分段导航原为 9–11px | 10 / 14px | 600 |

初始候选为六档；实施反馈要求紧凑信息统一，不保留局部例外。最终共七个数值：10、12、14、15、16、18、24px。实现时使用以默认 16px 根字号换算的 `rem` token，不设置用户不可调整的根字号；字体栈保持现状。图表 SVG 使用同一角色的 CSS 字号来源，避免把图形坐标缩放误当成文字字号。

实际 token 还包括 `--qp-font-size-compact`；其他 token 为 `--qp-font-size-page-title`、`--qp-font-size-section-title`、`--qp-font-size-group-title`、`--qp-font-size-body`、`--qp-font-size-caption`、`--qp-font-size-metric`，配套行高由相同角色持有。角色数值只在 token owner 定义；不保留功能重复的别名。

当前字重契约与验证记录见 [字重执行记录](./font-weight-unification-execution-plan.md)，下表中的旧候选字重不作为现行规范。
