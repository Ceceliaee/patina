## 1. 目标与授权

本方案用于指导后续本地精简：保留能发现真实产品故障的保护，减少一次性测量设施、重复测试和维护同一事实的多套实现。完成依据是实际消失的机制和仍有效的行为验证，不再追求质量分数或测试数量。

用户已授权执行本方案、完成后勾选归档并开展对抗式审查。提交、推送、发布仍遵循 [AGENTS.md](../../AGENTS.md) 的授权范围；本轮没有新的提交或推送请求。

本计划属于工作文档，执行证据直接填写在本文，不另建一套报告、自动评分器或测试清单生成器。长期规则由 [工程质量](../engineering-quality.md)、[架构](../architecture.md) 和 [边界守则](../issue-fix-boundary-guardrails.md) 持有。

## 2. 从第一性原理判断一项测试是否值得存在

用户依赖的是时间记录可信、数据不丢、操作可完成。测试的价值在于提前发现会破坏这些结果的缺陷；测试本身的复杂程度、数量、运行时长不是产品价值。

可用以下问题判断保留价值，不计算虚假的精确分数：

1. **损失是什么？** 删除后可能漏掉的是数据错误、用户操作失败，还是已经结束用途的测量报告字段错误？
2. **它能独立发现什么？** 能指出具体失败条件及错误结果，还是只重复另一个测试的断言？
3. **为什么要在这一层发现？** SQLite 事务、真实浏览器焦点、Tauri 权限分别需要对应环境；用更多低层测试不能替代缺失的真实边界验证。
4. **维护成本来自哪里？** 是否重复实现 DOM、计时器、进程树、夹具格式、状态机或数据算法？
5. **被保护对象还需要存在吗？** 如果工具没有当前用途，优先退役工具及其专属测试，而不是继续完善工具的异常处理测试。

判断顺序为：先确认受保护能力，再确认唯一 owner，再选择足够低且真实的验证层，最后精简实现。名称相近或覆盖率重叠不足以证明测试重复。

| 判断结果 | 执行动作 | 必须留下的依据 |
| --- | --- | --- |
| 保护真实产品或受支持边界，且有独有失败模式 | 保留 | 场景、错误结果及实际入口 |
| 多项测试保护相同事实，较稳定的一项已覆盖全部相关条件 | 合并或删除重复项 | 被保留的具体测试及差异核对 |
| 只保护已决定退役的工具或分支 | 与工具一起删除 | 消费者已经移除，能力退出条件成立 |
| 只固定内部组织方式，无独立行为价值 | 删除实现绑定的断言 | 产品行为仍由其他测试验证 |
| 消费者、边界或替代覆盖不清楚 | 暂时保留 | 明确的不确定点，不能以代码长为删除理由 |

## 3. 受保护范围与停止条件

以下行为继续保留：数据库迁移及已发布数据读取；备份恢复和失败回滚；计时提交及暂停资格；工具写入后的状态恢复；读取失败与合法空数据的区分；跨日期、跨请求的旧结果隔离；开发/正式数据隔离；main/Widget 权限；可信 CI 候选绑定。

正常浏览器 smoke、真实 Tauri runtime smoke、已有稳定性能套件及独立资源采样器不因本计划整体退出。正式安装、八小时运行、人工读屏等已排除的验收，不重新加入本轮任务。

精简过程中不新增通用测试框架、共享生命周期控制器、评分系统或长期巡检任务。不通过移动到 ignored 目录、改成 skip/ignore、降低 coverage 或放宽性能预算制造减少。新抽象如果不能连同旧机制一起删除，就撤回该候选。

发现产品缺陷时先单独记录；只有会使当前删除不安全的缺陷阻塞对应步骤。其他候选继续处理，不把本轮改成全项目修复。

- [x] **A1 核对执行基线。** 运行 `git status --short`、`git rev-parse HEAD`，检查从 `dcc579b` 至当前的相关变化。若出现其他任务修改，记录重叠文件，保留未确认归属的内容。没有新变化时沿用本表，不重新审计全仓。

- [x] **A3 确认消费者。** 对候选模块及其导出符号运行 `rg -n`，检查 `src`、`src-tauri`、`scripts`、`tests`、`package.json` 和 `.github`。检查 CLI 参数、环境变量、Cargo module/example 注册，以及活跃文档中的命令；归档引用只作为历史证据。
- [x] **A4 写出删除映射。** 每个拟删除机制只记一行：当前用途、消费者、删除内容、保留行为、替代保护、可观察验收。先填第一优先级候选，证据成立后再展开后置候选。

本阶段出口：能够说明每个首批候选为什么可删。存在 package/CI 消费但用途不明的候选不能进入删除步骤。

- [x] **B3 先断开 History 的产品测试依赖。** 逐项审查导入 `navigationExpression` 的场景。保护请求日期、实际内容日期、映射版本、失败/旧快照和真实可见内容的断言继续存在；改用当前 `browserHarness` 的等待及 DOM 观察能力。只验证计时报告字段、采样时刻或表达式自身完成竞态的场景，在测量编排退役后删除。不复制一份 `navigationExpression` 到测试目录。

- [x] **B5 清理 profile 测试。** 保留文件末尾的开发默认配置、显式配置、正式命令和身份隔离四项测试及所需输入。前 19 项逐项对照 B2：只删除退役测量能力的专属测试及 VM/计时器/临时文件夹具。若某个函数被其他受支持工具复用，保留其必要测试，不能按行号直接裁剪文件。

本阶段出口：不存在已经失去上层用途却仍被自身测试维持的夹具/导出机制；保留独立采样和产品聚合正确性保护。找不到安全候选时记录保留理由并结束该阶段。

## 6. 验证选择与停止重测

命令以执行时的 [package.json](../../package.json) 为准。下表是本次工作选择检查的依据，不替代 [工程质量的默认门槛](../engineering-quality.md#5-默认验证门槛)。

| 改动 | 首先验证 | 完成前要求 |
| --- | --- | --- |
| 仅编写本方案 | `pnpm run check:docs`，UTF-8、链接、路径及命令核对 | 不为文档运行全套应用测试 |
| profile/测试入口/脚本接线 | `pnpm run test:tauri-profile`、`pnpm run check:test-governance`、`pnpm run check:types` | 按混合 diff 执行默认门槛；既有入口保留 |
| History browser 场景合并或解除测量依赖 | 相关浏览器场景与 `pnpm run test:history-timeline` | `pnpm run check`；复用其中已通过的检查 |
| 普通 Tauri smoke 的初始化/执行/退出路径 | 类型检查及现有 profile 测试 | `pnpm run test:tauri-runtime-smoke`，用隔离环境确认普通入口；不以 stub 替代 IPC/进程结果 |
| Rust 夹具、模块或生产边界 | 受影响 Rust 测试、格式和模块可达性 | 涉及 Rust/架构实现按 `pnpm run check:full`；无需因归档重复已有效的组成检查 |

最终检查通过且受影响输入没有再变动时结束验证。测试失败先定位原因；若源于误删保护，恢复该候选并保留失败记录。环境无法完成必要验证时明确该项缺证，不能标为通过或用新的模拟层替代。
