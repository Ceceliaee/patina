## 2. 第一性原理

### 2.1 用户真正要解决的问题

用户不是在“给列表增加复选框”，而是在回答三个不同问题：

- 某一个应用或网页在这段时期如何变化？
- 多个对象之间的节奏是否相同？
- 这些对象合在一起，占用了多少时间、分布在哪些日期？

因此必须明确区分两种可视化语义：

- **比较语义**：趋势图一对象一条线，不能提前相加。
- **集合语义**：总时长、平均、活跃天数、峰值日和热力图对已选对象求和。

### 2.2 选择是有序集合，不是多个布尔值

选择状态必须同时满足：

- 唯一性：同一对象不能出现两次。
- 顺序性：图例、Tooltip、样式分配按加入顺序稳定排列。
- 有界性：最多 5 项，避免图表不可读和查询无界增长。
- 非空性：存在可用对象时至少保留 1 项。
- 可协调性：数据刷新后，已经不存在的对象必须被安全剔除。

禁止把多选实现成散落在组件中的 `includes`、`filter` 和临时条件分支；选择规则应由 feature-owned 纯函数统一管理。

### 2.3 颜色表达身份，但颜色不能成为唯一识别方式

“使用应用色”在本方案中有精确定义：

1. 应用：从当前应用图标提取的主题色。
2. 网页：从当前域名 favicon 提取的主题色。
3. 图标不存在或颜色提取失败：使用按稳定 key 计算的 Quiet Pro 兼容后备色。
4. 两个颜色相同或视觉上过于接近：保留对象色，同时用实线、虚线、点线等线型辅助区分。
5. 列表标记、图例、曲线和 Tooltip 色点必须使用同一份已解析样式。

这保证颜色跨刷新稳定，同时满足“不能只依赖颜色传达信息”的可访问性要求。

### 2.4 时间口径只能有一份

同一模式下的所有已选对象必须共享：

- 相同时间范围；
- 相同日/月粒度；
- 相同 bucket 边界；
- 相同排除规则；
- 相同本地时区语义。

应用时间和网页时间是两种分析域。网页时间包含在浏览器应用时间中，二者不得跨模式相加，也不得出现在同一图表中。

### 2.5 视觉稳定优先于动画

多选会同时改变多条曲线、图例、指标和热力图。为避免闪屏和误读：

- 图表容器尺寸保持不变；
- 新结果准备期间保留旧快照；
- 不用整块卸载/重建表达加载；
- 曲线关闭入场动画；
- 仅用克制的刷新状态提示数据正在更新。

## 5. 交互契约

### 5.1 鼠标选择状态机

设当前有序选择集合为 `S`，点击对象为 `K`：

| 操作 | 条件 | 结果 |
| --- | --- | --- |
| 普通点击 `K` | 任意 | `S = [K]` |
| `Ctrl` 点击 `K` | `K` 未选且 `S.length < 5` | 将 `K` 追加到 `S` 尾部 |
| `Ctrl` 点击 `K` | `K` 已选且 `S.length > 1` | 从 `S` 移除 `K`，其余顺序不变 |
| `Ctrl` 点击 `K` | `K` 是唯一已选项 | 不变，并给出可访问状态说明 |
| `Ctrl` 点击 `K` | `K` 未选且已达 5 项 | 不变，并提示“最多选择 5 项” |

执行清单：

- [x] 在 feature-owned 纯函数中实现 `replaceSelection`。
- [x] 实现 `toggleSelection`。
- [x] 实现最大数量常量 `DATA_DESTINATION_SELECTION_LIMIT = 5`。
- [x] 实现“至少一项”保护。
- [x] 返回结构化结果，例如 `{ keys, outcome }`，供界面区分 `added`、`removed`、`limit-reached`、`last-item`。
- [x] 禁止在列表组件中重复实现选择业务规则。

### 5.2 键盘契约

- [x] 列表项保持原生 `button`，保留标准焦点行为。
- [x] `Enter` 或 `Space`：等同普通点击，替换为当前对象。
- [x] `Ctrl+Enter` 或 `Ctrl+Space`：等同 `Ctrl` 点击，加入或移除。
- [x] `aria-pressed="true"` 标识每一个已选项，不只标识最后点击项。
- [x] 列表容器的可访问名称明确它是可多选的趋势对象列表。

### 5.3 搜索契约

- [x] 已选对象被搜索隐藏时，仍通过图例明确呈现，不增加常驻数量文案。
- [x] 清空搜索后，所有已选状态重新可见。
- [x] 搜索无匹配时不自动替换为第一个对象。

### 5.4 应用 / 网页切换契约

- [x] `appSelectionKeys` 和 `webSelectionKeys` 分别维护。
- [x] 从应用切到网页不清空应用选择。
- [x] 从网页切回应用恢复原应用集合和加入顺序。
- [x] Web Sync 关闭时模式强制回到应用，网页入口隐藏。
- [x] Web Sync 关闭不把网页选择写入持久设置；当前运行期内可保留内存值。
- [x] Web Sync 重新开启时先协调网页集合与当前可用域名，再决定恢复或回退。

### 5.5 数据变化协调契约

当应用映射、统计排除、域名设置、缓存版本或底层数据变化时：

- [x] 按原顺序保留仍然存在且可统计的 key。
- [x] 删除不存在或被排除的 key。
- [x] 协调后仍有选择时不得擅自补满。
- [x] 协调后为空且存在候选项时选择排序第一项。
- [x] 没有候选项时允许空集合，并进入现有空状态。
- [x] 时间范围变化不改变选择集合。
- [x] 刷新结果不得按列表新顺序重排已选集合。

### 5.6 会话保留契约

- [x] 应用与网页的选择集合由 Data feature 的会话级 owner 持有，不由列表组件私有持有。
- [x] 搜索、趋势时间范围、热力图年份和每日/每周切换不清空选择。
- [x] 从 Data 页导航到其他页面后再返回，恢复本次 Patina 运行期间的选择集合。
- [x] 关闭并重新启动 Patina 后，不恢复上一次多选，而是按当前候选数据进入默认单选。
- [x] 不写入数据库、设置表、localStorage 或其他跨重启存储。
- [x] 会话内恢复后仍要与最新候选项协调；已删除或已排除对象不得成为幽灵选择。
- [x] 空状态恢复为有数据状态时，按当前排序选择第一项，不恢复已经失效的旧 key。

## 7. 颜色与线型解析

### 7.1 颜色来源优先级

应用：

1. `useIconThemeColors` 对当前应用图标解析出的主题色；
2. 已存在且语义等价的应用颜色配置；
3. 对稳定应用 key 计算的后备色；
4. 最后才使用 Quiet Pro accent。

网页：

1. `useIconThemeColors` 对当前 favicon 解析出的主题色；
2. 域名覆盖配置中的颜色；
3. 对 `normalizedDomain` 计算的稳定后备色；
4. 最后才使用 Quiet Pro accent。

执行清单：

- [x] 复用 `src/shared/hooks/useIconThemeColors.ts`，不复制颜色提取逻辑。
- [x] 复用 History 已验证的网页颜色解析优先级，避免 Data 和 History 对同一域名显示不同颜色。
- [x] 后备色函数以稳定 key 为输入，同一 key 跨刷新结果一致。
- [x] 后备色使用既有语义色板或 token，不在组件内硬编码随机 hex。
- [x] 图标异步加载前后，已显示曲线不可频繁闪色；主题色准备好后至多稳定替换一次。

### 7.2 近似色消歧

- [x] 为每个已选对象生成 `strokeColor` 与 `strokeDasharray`。
- [x] 第一条默认实线。
- [x] 颜色相同或达到“近似”阈值时，依次使用虚线、点线、点划线。
- [x] 线型分配以选择顺序为输入，选择集合不变时保持稳定。
- [x] 即使线型不同，图例仍显示对象名称。
- [x] 不通过改变应用色本身来强行制造高饱和色差。
- [x] 深色和浅色主题下验证曲线相对背景的可见性。
- [x] Windows 高对比度模式下验证颜色之外仍可辨认。

### 13.8 实际审查发现与结论

1. **时间范围切换会丢失已选对象**：已修复。读模型为当前范围无记录的已选对象保留零序列；选择协调仅在映射版本变化时剔除失效身份。
2. **网页热力图旧 revision 响应可能覆盖新状态**：已修复。请求、快照和显示匹配均纳入 `cacheVersion + selection + ordered keys`。
3. **五个完全同色对象只有四种可辨样式**：已修复。补齐四种碰撞虚线，加上首条实线，五项均可由线型和文字识别。
4. **多域名覆盖起点可能把未知历史误写成 0**：已修复。有正时长的格子始终表达事实；只有全部已选域名进入完整覆盖期后，空格才表达“未记录到网页活动”。
5. **会话身份缓存可能随候选列表增长**：已修复。只缓存当前已选对象，选择集合仍限制为 5。
6. **热力图 Tooltip 未说明集合对象数**：已修复。小型集合热力图在悬浮内容中显示对象数。
7. **同一范围的毫秒级 `nowMs` 更新触发重复网页请求并短暂移除重试按钮**：已修复。趋势请求身份只由数据版本和范围决定，失败态保留到重试成功。
8. **浏览器 Widget 等待器在导航空隙读取 `null.dataset`**：已修复测试竞态，不改变 Widget 产品行为。
9. **未来双击详情与普通点击的消歧**：移出本轮。本轮按确认不实现弹窗；接入详情时必须新增双击/单击仲裁，不能让双击先把多选集合替换为单选。

高风险与中风险问题均已解决；仅保留第 9 项作为未来弹窗功能的触发式约束。
