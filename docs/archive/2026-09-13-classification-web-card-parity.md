# 网页分类卡片与应用卡片一致性执行方案

日期：2026-09-13。状态：已完成，已归档。

本方案用于补齐分类页“网页”页签遗漏的紧凑卡片改造。执行者按清单修改、验证并记录结果；完成项只能依据实际代码或验证证据勾选。

## 1. 从使用目的推导设计

用户在分类页完成三件事：识别对象、调整分类与展示属性、控制记录。应用用可执行文件名识别，网页用规范化域名识别；这一区别影响数据来源和动作目标，不要求用户学习两套卡片操作。

因此，相同操作应占据相同位置，具有相同的图标、状态提示和键盘行为。名称与文件名或域名组成一个信息整体，和左侧图标垂直居中。右侧上方选择分类，下方依次显示颜色、标题记录、排除统计、删除记录。

屏幕能放下多少列取决于列表实际可用的 CSS 宽度。列宽应首先保证内容和点击区域可用，然后才增加列数；窗口宽度、侧栏占用与缩放都会改变可用空间。沿用应用列表的自适应规则，最多三列，上下与左右间距均为 8 CSS px。

这次遗漏的直接原因是两种卡片分别维护布局：应用已经使用紧凑布局，网页仍使用带 HEX 色值、独立恢复按钮和文字操作行的旧实现。仅复制一次样式会继续留下两个维护点。共同的展示与交互结构应由分类 feature 内一个组件持有，应用和网页入口仅绑定各自对象与动作。

## 2. 范围和受保护边界

依据：[Quiet Pro](../quiet-pro-component-guidelines.md)、[架构](../architecture.md)、[修复边界](../issue-fix-boundary-guardrails.md)、[工程验证](../engineering-quality.md)。

- 本次改变网页卡片布局、操作呈现、长文本可读性和键盘交互，并统一应用与网页的卡片实现。
- 应用现有外观是对齐基准。颜色保持无外框色点；铅笔默认浅色，悬浮及键盘聚焦时加深；域名采用与文件名相同的普通文本样式。
- 保留网页规范化域名、favicon、网页专用重命名与删除提示，以及原有草稿、保存、取消、排除和删除行为。
- 不修改采集、数据库、Web Sync 协议、分类匹配、分页、持久化或权限。排除不等于删除，删除仍经过原有确认流程。
- 保留工作区原有无关改动；本任务开始时已有 `pnpm-lock.yaml` 修改，不纳入本次 UI 修复。
- 本方案不授权提交、推送、Issue、Project 或发布操作。

## 3. 实施步骤

### A. 核对现状与落点

- [x] 对照用户截图检查网页页签：仍为旧式卡片与文字操作，列表没有沿用应用的 8px 自适应网格。
- [x] 检查 `AppMapping.tsx` 中两种列表入口，以及 `AppMappingCandidateCard.tsx`、`WebDomainMappingCard.tsx` 的属性与回调。
- [x] 确认视觉结构属于分类 feature；颜色弹层、分类选择器、图标按钮继续使用现有 Quiet Pro 组件。
- [x] 确认共同实现仅承载展示和交互，不搬入网页或应用的业务状态管理。

### B. 统一卡片结构

- [x] 建立 `ClassificationMappingCard.tsx`，承接应用现有的卡片布局、名称编辑、文本截断提示和操作按钮。
- [x] 将应用与网页的标识、图标、名称编辑提示、删除提示和回调显式传入共同组件；保留两种对象的可定位标记。
- [x] 将网页列表切换到应用使用的网格，保留最多三列、每列最小 400 CSS px、双向 8px 间距。
- [x] 保留网页 favicon，缺失时显示网页图标；使用同一图标容器和颜色描边。
- [x] 将网页名称与域名作为两行整体垂直居中；域名取消胶囊外框，字体、字号、字重沿用应用文件名样式。
- [x] 将分类选择器放在右上方，下方紧排四个操作入口，不再额外保留文字操作行。

### C. 对齐操作和状态

- [x] 使用无外框色点打开现有颜色弹层，将恢复默认颜色放入弹层。
- [x] 铅笔使用与应用一致的尺寸、距离和默认浅色状态。
- [x] 标题记录图标表示当前开关状态，悬浮提示说明动作；全局标题记录关闭时禁用并说明原因。
- [x] 排除按钮沿用黄色与恢复蓝色区别，并保留“已排除”标记及可访问的按下状态。
- [x] 删除按钮保留红色与网页专用提示，继续调用网页原有删除回调。
- [x] 名称编辑支持 Enter 提交、Escape 取消，并将焦点还给铅笔；忙碌时禁用相关入口。
- [x] 实际验证上述操作不会误调用应用记录接口，不会绕过删除确认，不会丢失失败后的重试入口。

## 4. 验证步骤与验收标准

使用浏览器桩数据验证，禁止为测试删除真实历史记录。测试必须能在旧网页实现上失败，避免只检查应用页签或组件静态源码。

### 布局

- [x] 进入分类页并切换网页页签，确认渲染真实网页候选项。
- [x] 在窄、中、宽视口下测量网格，验证一、二、三列切换，列数最多为三。
- [x] 检查实际行间距与列间距均为 8 CSS px，卡片与列表无横向溢出。
- [x] 检查右侧分类在上、图标在下；色点旁不再常驻 HEX；域名没有胶囊外框。
- [x] 检查长域名与长显示名：截断后可通过悬浮或键盘聚焦读取完整内容，不挤压分类与操作区。
- [x] 检查生产语言中的长文案及深色主题；窄屏时控件仍可见、可点击。

### 交互

- [x] 修改网页颜色并恢复默认，验证色点与草稿一致；Escape 只关闭当前颜色弹层并恢复焦点。
- [x] 重命名网页，分别验证 Enter 与 Escape；域名作为稳定标识保持不变。
- [x] 切换标题记录，检查图标、提示、按下状态与保存的草稿一致；检查全局关闭时的禁用状态。
- [x] 排除网页后恢复，确认原有历史保留，按钮颜色和“已排除”状态一致。
- [x] 打开删除确认并取消，确认记录仍在；用桩数据确认删除成功、失败与重复点击保护。
- [x] 用键盘遍历分类、色点、标题、排除和删除入口，检查焦点可见、顺序合理，弹层关闭后焦点有效。
- [x] 返回应用页签，确认已有布局与业务交互没有回归。

### 工程检查

- [x] 运行命中网页与应用卡片的浏览器场景，并记录通过或失败原因。
- [x] 按工程质量默认入口运行 `pnpm run check`；命令组合以 `package.json` 为准，不因局部测试通过而省略默认门槛。
- [x] 检查 `git diff --check`、UTF-8、文档相对链接和无关文件，确认没有附带锁文件修改。
- [x] 对照最终差异复核对象标识、回调绑定、禁用状态、焦点恢复与旧重复实现的清理情况。

## 5. 失败处理与交付

布局不通过时，先检查可用宽度、网格和卡片内部收缩约束，不以缩小文字或点击区域掩盖问题。交互失败时沿现有回调检查对象标识与状态，不新增业务分支绕过原流程。工程检查如被环境或无关改动阻塞，记录命令、具体错误和受影响结论，不勾选通过。

- [x] 修复验证发现的问题，并只重跑受影响证据及必要门槛。
- [x] 记录最终改动、实测结果和剩余限制，向用户展示可检查的结果。
- [x] 所有适用事项完成，或未完成事项明确移交后，将方案移入 `docs/archive/` 并修复相对链接。
