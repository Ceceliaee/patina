## 1. 第一性原理

### 1.1 准确性与舒适性分别保护什么

准确性要求有效活动不能多记、少记或因显示处理而改变归属。舒适性要求短暂切换不会把时间线和时间轴变成大量碎片。

两者可以同时成立：保留完整有效片段，在片段之上构造显示组。一个组可以跨过空档或其他对象，但它的有效用时只取自身成员的有效区间。**显示组的包络不能成为新的计时事实。**

### 1.2 产品术语

| 名称 | 实际界面 | 主要代码入口 |
| --- | --- | --- |
| 总览 | History 当日分布及同上下文的 Data 统计 | `historyWebActivityViewModel.ts`、Data read models 和 aggregate gateway |
| 时间线 | “打开时间线”后的应用/网页活动列表 | `HistoryTimelineLists.tsx`、`buildTimelineSessions`、`buildWebTimelineItems` |
| 时间轴 | History 横向色块、缩放窗口和分轨 | `HistoryHorizontalTimeline.tsx`、`HistoryTimelineZoomDialog.tsx`、`historyTimelineViewModel.ts` |
| 详情 | 单个应用/网页的独立弹窗，内部有日内时间轴和活动记录 | `DestinationDetailDialog.tsx`、`destinationDetailReadModel.ts` |

`Timeline` 在代码中同时用于时间线和时间轴。实施报告必须写清实际产品对象，不仅凭英文名判断职责。本次不进行大规模重命名。

### 1.3 五种量不能互相替代

| 量 | 定义 | 使用限制 |
| --- | --- | --- |
| 有效片段 | 上游确认有效的半开区间 `[start,end)`，包含对象、来源与记录身份 | 是计量输入 |
| 有效用时 | 固定范围、来源和去重政策下的有效区间累计长度 | 保持毫秒精度 |
| 起止跨度 | 组最早开始到最晚结束的包络 | 可以包含空档或其他对象，不能反算有效用时 |
| 可见用时 | 当前视窗内通过最短时长筛选的组的有效用时之和 | 不覆盖全天总量 |
| 格式化文本 | 用时和起止时刻的现有紧凑文本 | 不参与统计，不解析文本反算时间 |

### 1.4 必须成立的不变量

先固定比较上下文：日期/时区、时间范围、对象身份、数据来源、纳入规则、事实版本、有效截止。不同范围或刷新时刻的数值不能强行对齐。

```text
I = 固定上下文内裁剪、按已确定来源政策去重后的有效片段
G = 从 I 构造的显示组，每份有效时间只在所属计量集合中贡献一次

总览精确总量 = 未筛选时间线中该对象精确总量 = 未筛选详情精确总量
分组前有效量 = 分组后各组有效量之和
当前范围可见有效量 + 隐藏有效量 = 当前范围未筛选有效量
分组、筛选、缩放、标题展开、格式化不能改变固定上下文的事实总量
```

可见量和隐藏量是内部测试量，不新增 UI。显示取整不满足可加性，多行分别省略秒数后，文本之和可以小于总计文本；不通过分摊分钟或修改总量凑数。

### 1.5 对象归属与来源边界

其他对象可以影响全局展示顺序，不能使目标对象合法事实在详情中被覆盖。详情先确定目标对象及允许来源，再进行该集合内部的归组和计量。

同计量集合内重复覆盖按并集计量。不同浏览器或来源是否属于同集合，必须从协议、持久化字段和聚合契约核对，不能凭域名相同就全局去重。标题归属采用稳定优先规则，保留来源追溯；不得依赖数组偶然顺序，也不得改写原始历史。

## 2. 范围与受保护行为

### 2.1 已确认目标

- 保留现有布局、色块、列表、标题展开、紧凑格式化，以及有效用时和起止跨度的分别显示。
- 保留短间隔合并。同对象前后间隔不超过一分钟时，在合并阈值60秒的场景中可以归组；穿插对象的时间不进入该组。
- 合并阈值与最短活动时长是两个设置。时间线右上的“1分钟”是筛选值。不得把反例中的60秒硬编码成所有用户的合并阈值或默认值。
- 时间轴保留主要对象概括和合并色块，不要求放大后强制拆组，不新增混合标记或说明弹层。
- 移除时间轴固定30秒硬过滤，合法短活动保留在完整计量集合；短活动不要求在每种缩放比例都有独立主色块。
- 分轨和图例累计基于完整有效事实，不只累计每分钟胜出的对象。
- 详情按自身记录独立分组，空档不计入自身有效用时，其他对象不参与详情覆盖竞争。
- 时间线与详情现有筛选均改为0～10分钟，步长1分钟。0表示不过滤当前范围内的有效活动组，不表示取消合并或显示零时长无效记录。两处保留各自默认值和偏好存储，不自动同步所选值。
- 隐藏短活动不重新分配时间，也不重新决定合并成员。

### 2.2 排除项

- 新增总计/当前显示/隐藏量卡片、新按钮、准确值弹层、提示说明或“显示全部”入口。
- 修改全局格式化、强制逐行显示秒/毫秒、强行让显示文本相加相等。
- 新的按像素聚合产品设计、强制拆色块或扩大视觉改造。
- 重做采集、AFK、暂停、浏览器资格、睡眠恢复、网页协议或轻量工具。
- 清洗历史、回填空档、数据库迁移、新兼容层、新通用计时框架或无关重命名。
- 自动提交、推送、分支、发布或远程事项变更。检查与方案不授予这些权限。

### 2.3 前置交接

应用与网页计时修复提供有效片段、有效截止和事实变更通知。本方案消费这些结果，不用浏览器应用总量替代网页有效事实。

复用现有[计时事实 fixture](../../tests/fixtures/activity-timing-facts.json)作为联调输入。实施前按当前代码和长期协议核对其语义，归档方案不作为当前执行规则。

## 4. 优化后各部分的固定样例

### 4.1 Codex 1分钟 → Chrome 20秒 → Codex 2分钟

有效区间为Codex `[0,60000)`、Chrome `[60000,80000)`、Codex `[80000,200000)`，合并阈值60秒。

| 部分 | 期望结果 |
| --- | --- |
| 总览 | Codex180000ms，Chrome20000ms，共200000ms |
| 时间线 | Codex可归一组，活动2，有效180000ms、跨度200000ms；Chrome仍在未筛选集合中 |
| 时间线1分钟筛选 | Chrome行隐藏，Codex组及用时不变 |
| 时间线0分钟筛选 | Chrome出现，不取消Codex合并，不拆成全部原始片段 |
| 时间轴 | 允许Codex合并概括块；其用时不能取跨度200000ms；Chrome自己的分轨计量仍保留 |
| Codex详情 | 自身两段可归一组，180000ms，其他对象不覆盖它，也不将中间20秒补给它 |
| Chrome详情0分钟筛选 | 显示自身20000ms活动，活动记录与日内时间轴均不再额外按30秒淘汰 |
| 详情空档视窗 | 完全落在 `[60000,80000)` 时，Codex有效量为0，不凭包络制造活动 |

全范围可画合并包络、窗口计量按真实子区间裁剪，两者必须同时成立，不要求始终拆开色块。

### 4.2 小空档与显示取整

同来源同标题/URL的网页两段 `[0,60000)`、`[60800,120800)`，各入口有效量必须为120000ms，跨度允许为120800ms。旧详情可能补入800ms，需要正式反例保护。

六段11分40秒、1分40秒、5分40秒、2分40秒、3分40秒、6分40秒，共32分钟。现有逐行文本为11m、1m、5m、2m、3m、6m，相加28m。这个显示保持不变，内部总量必须为1920000ms。真实截图的差额仍需原始数据归因，不认定这就是截图的唯一原因。

## 5. Owner 与边界判断

本方案先完成边界判断，再分阶段实施。优先复用既有owner；不得因函数相似就新增shared抽象。

| 责任 | 优先owner | 禁止替代 |
| --- | --- | --- |
| 有效事实/截止 | 既有持久化读边界、Rust data聚合、协议契约 | 详情复制追踪资格规则 |
| 网页计量/分组 | 现有网页读模型及稳定compiler职责 | 每个组件各写去重算法 |
| 应用时间线 | `sessionReadCompiler`、History read model | 为显示组改写会话事实 |
| 详情组/标题/来源 | `destinationDetailReadModel` | 使用全局主要对象覆盖详情 |
| 时间轴/分轨/图例 | `historyTimelineViewModel` | 胜出色块冒充完整计量集合 |
| 视窗 | 现有History视窗与`destinationDetailTimelineViewport` | 按组包络重算有效时长 |
| 时间线与详情0～10 | History控件、settings归一化、详情控件与各自原存储路径 | 新版本键、迁移或将两处偏好强制同步 |
| 异步更新 | 原History/Data请求owner、`useDestinationDetail` | 新全局缓存或每秒全库重读 |

需要新增共享抽象、跨层移动、协议/schema变化时，记录具体反例、候选owner和最小替代方案，按长期边界规则重新评估，不能直接扩张本方案。

退出条件是既有概括可用，所有合法对象的有效量完整进入相应累计。
