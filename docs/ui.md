# 界面设计

Quiet Pro 定义 Patina 桌面的视觉与交互契约。[共享控件](../crates/quietpro/src/controls)负责可复用行为，窗口与页面负责业务状态。修改配色可从[预览与保存](#配色预览与保存)进入，修改键盘操作可从[对话框焦点](#dialog-焦点与关闭)进入。

## Quiet Pro

安静、专业、克制、可长时间使用的桌面效率工具界面：信息清晰、层级稳定、易扩展，避免模板化 AI 设计。

## 桌面工作面

Patina 使用 GPUI 提供桌面窗口。今日、历史、数据、分类、工具、设置与关于是主窗口的工作面；Mini、更新和备份恢复支持持续使用。

## 核心设计原则

### 信息优先于装饰

用字重、间距、对齐、留白、信息分组和语义状态帮助理解与操作。

### 中性系统优先于单页特效

重点区域也使用系统样式，不以单页独有强效果抢夺注意力。

### 产品气质重于内容皮肤

组件优先体现可靠、清晰、稳定和易扫读的桌面工具特征。

### 主题变化必须建立在稳定骨架之上

主题演进复用 token、语义颜色、圆角、边框/阴影和密度尺度，不靠页面内大量硬编码换皮。

### 好看必须可复用

只适合一个页面、依赖专属背景或大量硬编码、在其他页面不协调的效果，通常不适合作为长期设计。

## 明确允许与明确禁止

### 允许的整体气质

色彩与排版遵循[Quiet Pro](#quiet-pro)的中性基线。

### 明确禁止

- 玻璃拟态、重模糊、霓虹发光、大面积炫目渐变。
- 过度圆角、装饰性大阴影、单页面专属花哨特效。
- 明显的 AI 模板感。

### 对“高级感”的正确理解

质量来自干净排版、明确层级、一致控件、克制颜色、稳定节奏和准确比例；避免大面积装饰、强品牌色占满页面、到处悬浮或无必要的复杂设计。

## Token 与样式规则

### 一切优先走语义 token

新增视觉角色时，优先：

1. 复用现有 token
2. 如果现有 token 语义不够，再新增语义 token

不要直接在组件里硬编码：

- 新颜色
- 新圆角
- 新阴影
- 新边框风格
- 新动效尺度

### Token 必须描述语义，不描述一次性外观

优先形成的是下面这类语义角色：

- `panel`
- `control`
- `chip`
- `status`
- `track`
- `muted text`
- `danger`

而不是“这个页面看起来大概需要一个什么值”。

### 分类色可以丰富，但外围 chrome 必须克制

分类色、图表色、状态点颜色允许相对丰富，但只服务业务识别。

周围界面 chrome 仍应保持 Quiet Pro 的中性骨架，不要让彩色元素反过来主导整页。

外部品牌色属于例外，只能在确实表达外部品牌、平台或第三方入口时使用，并且应收敛到最小元素，例如图标、品牌词或一小段文本。不要为了品牌色把整枚按钮、整张卡片或整块页面 chrome 改成强色。

### 尺度应可预测

长期上，控件应尽量收敛在有限的档位内：

- 圆角档位
- padding 档位
- 字级层级
- 边框与阴影强度

Quiet Pro 不鼓励“这个页面再发明一个更顺眼的新档位”。

GPUI 组件的内边距、组件间距和普通圆角按 4 px 网格取值。同层级、同用途的组件共用一个圆角档位。字号与图标尺寸按阅读和识别需要取值，细边框可使用 1 px。

GPUI 方形按钮的整圈外轮廓采用指数 n = 4 的超椭圆，由键面边长决定。设置页的滑动开关使用胶囊轨道和圆形滑块，左关右开，点击范围限于开关本体。

GPUI 按钮的鼠标点击与选中状态不添加强调色描边。图标切换按钮共用透明背景和中性图标色，悬浮与按下时提供中性底色反馈。显示方式切换（如导航名称、图表分组）不突出某一种状态；功能开关用图标形态表达状态，例如迷你窗未钉住时使用线框图钉，钉住时使用实心图钉。切换值仍通过可访问状态表达。键盘操作通过中性色焦点环标出当前位置，保留 Tab、Enter 和空格等既有交互。

主页面按阅读任务选择文字角色，具体字号和行高由 token 持有：

| 阅读任务 | 文字角色 |
| --- | --- |
| 页面标题 | `page-title` |
| 板块与弹窗标题 | `section-title` |
| 容器内部的分组标题 | `group-title` |
| 名称、正文与操作 | `body` |
| 占比、刻度、文件名和状态标签 | `caption` |
| 核心汇总与计时读数 | `metric` |
| 数量标记、时间轴图例和紧凑分段导航 | `compact` |

没有分组的页面不额外增加层级；列表内的时长仍属于内容，不因为是数字就使用核心读数角色。

字号、间距和布局由[原生布局](../crates/quietpro/src/layout.rs)及共享控件持有。窄空间先调整换行和刻度密度，保留标题、状态和数值的层级。

### 样式事实要有清楚 owner

[配色预设](../crates/quietpro/src/theme/presets.json)保存明暗配色和默认对比度。[QuietPro 调色板](../crates/quietpro/src/theme.rs)派生界面颜色，主窗口、Mini 与工具通知消费相同的主题。

#### 主题与颜色派生

浅色和深色分别保存主题预设，颜色派生采用各预设默认对比度，不提供用户对比度选项，也不读取或保存自定义覆盖值。普通与强调边框保留 Patina 各主题既有配色，由预设持有；主按钮文字保持白色。

主按钮背景由 QuietPro 调色板派生；仅当强调色与白字的对比度低于 [WCAG 4.5:1 阈值](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)时，以最小必要幅度向黑色混合。主按钮边框和交互态使用该 token，保留既有混色比例；全局强调色和其他控件配色不变。

命名主题调整基础色和背景派生；文字、滑条、开关、滚动条与交互状态继续使用共享调色板的语义角色和混色规则。默认主题保留独立的基础与语义配色。

统计图表的空轨道与开关分别使用调色板提供的角色。调整对比度时核对各自的可读性。

内层卡片底色在浅色和深色下均略暗于所在面板，以表达嵌入关系；浅色保留柔和色差，避免与面板同色。具体混色由颜色派生 owner 维护。

#### 配色预览与保存

预览只影响当前窗口草稿；取消、Escape 或遮罩关闭恢复打开弹窗时的配色。确认保存当前模式的配色，并通过现有设置事件同步 Mini，不提交其他设置草稿。保存期间锁定编辑与关闭；写入失败保留草稿供重试或取消。关闭选择器后，焦点返回打开它的配色按钮。[选择器实现](../apps/patina-ui/src/features/settings/schemes.rs) · [设置页原生用例](../apps/patina/tests/pages/schemes.rs)

## 页面骨架与原型

### 壳层

导航稳定、页头清晰、主内容边界明确，页面切换克制。

### 面板

面板以清晰分组、克制边界和足够留白建立层次，不依赖重阴影。

### 页头

页头提供页面身份、简短上下文和必要的 controls、status、actions，不承载品牌展示、hero 或页面私有视觉实验。

### 列表与工作台

列表、映射表单和设置区块优先保证行级扫读、平衡密度、稳定操作入口与明确状态对比，避免堆成卡片墙。

## 组件规则

### 组件原型优先复用

新组件优先归入已有原型之一：

- `panel`
- `control`
- `chip`
- `status`

如果无法归类，再考虑新增原型，而且必须非常谨慎。

### 状态必须完整

新组件至少应定义：

- `default`
- `hover`
- `active`
- `focus`
- `disabled`

需要时再补：

- `loading`
- `empty`
- `selected`
- `error`

不能只做静态样子，不定义交互状态。

### 图标只做辅助识别

图标的职责是辅助识别，而不是成为视觉主角。

因此：

- 图标尺寸要克制
- 图标颜色不抢主信息
- 图标背景只服务识别，不应变成装饰噪音
- 同一组同层级 action 里的图标默认保持同一视觉强度；只有明确语义需要时，才允许某个图标单独使用 `danger / warning / success` 等语义色

### 按钮与输入控件应利落、清晰、可预期

默认不要引入：

- 过分圆润
- 拟物感
- 强阴影营造的“高级感”

同一组 action 按钮默认应使用统一的按钮原型、边框、背景、尺寸和 hover 反馈。不要因为某个按钮是支持、反馈、外链或品牌入口，就默认给它单独的边框、背景、阴影或更强 hover；如果需要强调，只优先在图标或小段文本上表达。

### 状态类组件必须有语义

紧邻文字的行内 badge 和徽标式辅助操作，字号比其依附文字低一个已有档位，而不是固定为 12px。例如 14px 名称旁用 12px，12px 说明旁用 10px；字重仍复用 emphasis。不新增局部字号，10px 已是最小档。独立状态不按附近无关文字推导大小。

`badge`、`chip`、`status` 之类组件只应用于：

- 当前状态
- 风险提示
- 筛选条件
- 轻量标签

不应用于：

- 大块装饰
- 替代标题
- 没有语义必要的“彩色点缀”

各窗口遵循相同的状态语义。Mini 的布局和动作由[窗口实现](../apps/patina-ui/src/windows/mini/mod.rs)维护，打开工具和保留设置草稿的交互由[原生用例](../apps/patina/tests/pages/tools.rs)验证。

### 共享组件的归属

判断组件是否归入 QuietPro 时，先看它提供的交互语义和长期维护职责。

共享组件默认应满足：

- 已经存在两个独立 feature 的真实消费者，或本身属于稳定的全局 UI 原型；
- 控件参数使用产品或交互语言，不暴露单个页面的内部状态名；
- 由页面注入业务动作，共享控件独立于存储、宿主服务和平台接口；
- 多数消费者预期在未来一起改变；
- 能明确写出状态、键盘、焦点和测试责任。

只服务一个 feature 的业务组合默认留在该 feature。标题栏、侧栏和 Mini 专用操作留在对应的[窗口模块](../apps/patina-ui/src/windows)。两个组件只是外观相近，但操作目标、状态机或未来变化方向不同，不构成共享理由。

GPUI 的定稿组件外观由 [`crates/quietpro`](../crates/quietpro/src/lib.rs) 持有：主题配色在 `theme.rs`，页面与卡片的公共尺寸在 `layout.rs`，控件的轮廓、文字、悬浮、按下、焦点和禁用样式在 `controls/`。新消费者直接使用公共组件；已定稿原型不在业务文件中另存一份样式。

`apps/patina-ui/src` 保留页面组合、本地化文案、业务状态和操作。例如存储模块管理导入方式与字段草稿，历史模块管理日期计算，分类模块管理颜色草稿与系统取色；对应的选择卡片、复选框、日历格和色板外观由 QuietPro 提供。系统文件选择器和托盘菜单保留系统外观，图表数据绘制仍由相应页面负责。

专用输入可沿用 GPUI 提供的元素与事件。页面负责业务状态，共享控件负责通用的键盘操作与可访问语义。

### 普通按钮契约

跨 feature 的普通文本 action 优先使用共享按钮原型，并只使用稳定语义：

- `primary`：当前表面最主要的确认或推进动作；
- `secondary`：取消、稍后、辅助或并列动作；
- `danger`：会造成删除、清理或其他高风险结果的确认动作。

尺寸、排列和局部密度可以由消费者布局决定，但 tone、disabled、busy、focus 与 hover 行为应由共享原型负责。

以下情况不应强行改成普通按钮：

- 语义上应是链接的外部导航；
- 时间线、日期格、格式选项等复合控件内部元素；
- 标题栏、侧栏或 mini 的专用按钮；
- 尺寸和交互契约明确不同的 feature-owned 图标操作。

不要为按钮增加没有真实消费者的多态渲染、大量布尔变体。

### Dialog、Popover 与复合输入契约

#### Dialog 焦点与关闭

到期通知以有名称的独立窗口呈现。显示时保留前台应用的焦点，用户主动进入后可以通过键盘操作。普通对话框的焦点约定如下。

Dialog 至少应保证：

- 打开后有明确可访问名称和初始焦点；
- 初始焦点由当前任务决定；
- 说明、帮助或长内容默认聚焦标题；标题可接收程序化焦点，常规 Tab 顺序只包含可操作项；
- 输入任务聚焦第一个必要输入，选项任务聚焦当前选项，危险确认聚焦取消或最安全动作；
- 禁用、隐藏、加载中的控件和 Tooltip 辅助图标不得成为初始焦点；目标不可用时稳定回退到标题；
- Tab 与 Shift+Tab 不泄漏到背景；
- Escape 只由最上层 Dialog 响应；
- 关闭后焦点返回真实触发元素；
- 嵌套 Dialog 关闭后返回父 Dialog 内的打开者；内容刷新不得再次抢焦点；
- backdrop 是否可关闭由显式契约决定；
- loading 或 disabled action 不重复提交。

#### Select、Tooltip 与复合输入

Select、Tooltip、日期、时间、颜色等复合控件至少应保证：

- 触发器具有正确的 expanded、controls、popup 或描述关系；
- 键盘可以完成核心选择路径；
- 选项数量较多且支持方向键时，优先使用单一或分组的 roving tab stop，避免几十个选项全部进入 Tab 顺序；如因包体、兼容性或原生交互保留 Tab 顺序，必须保证核心路径可完成并记录边界理由；
- Escape 关闭并按契约恢复焦点；
- 对话框打开时将焦点移入内部。焦点留在触发器的展开控件提供与操作相符的选择或展开语义；
- 浮层跟随窗口布局，在关闭与卸载时释放资源；
- 弹层在窗口边缘不产生新的横向溢出；
- Tooltip 不能作为图标操作唯一的可访问名称。
- Tooltip 应继续响应用户主动的键盘焦点；弹窗打开时意外出现 Tooltip，应修正弹窗初始焦点，不得全局禁用 focus Tooltip 或使用延迟隐藏掩盖焦点错误。
- 需要提示时使用 Quiet Pro 的提示表面，并为操作提供独立可访问名称或可见文字。
- 自解释内容不重复提供 Tooltip。名称、日期、时长、已有文字标签，以及已经可通过 disclosure 查看完整信息的字段，默认不在 hover 时再次弹出内容；只有图标含义不明确、文本确实被截断且没有其他完整读取路径，或时间线色块需要补充精确数据时才保留提示。

### 组件验证责任

根据行为选择能观测该行为的测试。控件状态与事件归控件测试，操作系统焦点、窗口几何与前台激活需要原生窗口证据。涉及以下行为时，覆盖其失败路径：

- 浮层定位和关闭；
- 窗口事件订阅与释放；
- 键盘导航；
- 焦点陷阱或焦点恢复；
- 日期、时间、范围或复合输入；
- 危险操作、loading 或重复提交防护。

测试应保护独有失败模式，不要为同一事实增加多层重复断言。组件测试必须进入现有测试执行图；不得通过引入独立、不可达的测试入口制造“已经覆盖”的假象。

### 共享组件与页面组合

相同的视觉骨架和交互应复用现有控件。单页特有的内容和业务状态留在页面。跨页面复用的方案需有真实消费者和可验证的交互约定。改变产品视觉方向需要维护者明确确认。

### 跨页面交互

跨页面复用的弹窗、菜单、选择和日历交互归 QuietPro。页面组合领域数据与文案，复用公共控件的焦点、关闭、定位和键盘行为。

长期通用契约只有：

- overlay 的焦点、Escape 和焦点恢复遵循[对话框焦点与关闭](#dialog-焦点与关闭)，并须有明确的外部关闭语义；非模态 Popover 不伪装成 Dialog；
- listbox、menu、calendar 和分段选择使用正确 role、单一可操作焦点与键盘移动，视觉选中不能代替语义状态；
- icon-only 入口必须有可访问名称、可见焦点和足够命中区，不能只靠 hover tooltip 解释；
- 日期、范围、时区和 locale 语义由共享组件与领域 resolver 分工，feature 不自行复制日期算法；
- 键盘、焦点和关闭行为由[控件测试](../crates/quietpro/tests)验证。弹层定位、窗口尺寸和具体页面操作由[原生页面测试](../apps/patina/tests/pages)验证。

页面通过 GPUI 滚动容器设置可视范围、内边距与滚动方向。需要还原或定位当前选项时由视图持有滚动位置，见[配色选择器](../apps/patina-ui/src/features/settings/schemes.rs)。为滚动条预留空间时，用窗口几何测试核对内容溢出前后的宽度，并保留键盘、指针和系统辅助显示设置的行为。

单个 feature 的卡片布局、迷你窗状态、具体日期入口、详情弹窗内容和消费者选择规则归最近的 feature 源码与测试。只有跨页面契约发生变化时才更新本文。

## 排版、密度与数据展示

### 排版质量优先

Quiet Pro 的质量感很大程度来自排版。

优先保证：

- 标题层级清楚
- 副文案简短
- 数字与时间信息易扫读
- 长段说明尽量少

### 密度要服务效率，不服务压迫感

本项目是效率工具，不是海报。

默认应保持：

- 比营销页更高的信息密度
- 比传统后台更克制的噪音
- 在紧凑和可读之间偏专业的平衡

### 图表与分类色只服务信息理解

应用和网站按同一顺序确定原色：对象自定义色、图标代表色、已分配的分类色、按对象标识确定的备用色。分类管理的颜色编辑器显示原色。图表、时间线和排行按实际背景计算显示色。原色对比度足够时直接使用；不足时沿 OKLCH 明度轴调整，超出 sRGB 色域时降低色度。浅色模式的图形对比度下限为 2:1，深色模式为 3:1。

匿名活动使用未分类固定色叠加低对比稀疏微点，身份图标沿用匿名活动固定色，由实色中心向四周均匀淡出，形成柔和的雾状轮廓，沿用所在列表的图标底框。分类模式保留普通分类名和色点。今日排行、当日分布的应用与网页模式，以及数据趋势对象列表中的匿名项以 ANON 的摩斯码 `.-  -.  ---  -.` 作为可见名称，使用居中点字符 `·` 替代句点，使用 Consolas 等宽字体并保留字母间隔，字号沿用所在列表的名称角色；通过可访问名称提供身份说明，不显示悬停提示，也不提供双击或 Enter 打开详情的动作；趋势选择仍然可用。时间条与图表复用共享纹理，小圆点保持圆形裁切；共享纹理在不同实例间独立，不依赖颜色或微点作为唯一提示。

图表可以丰富，但图表周围的 UI 不应跟着一起变花。

如果分类色较多，应主动压低：

- 轨道色
- 面板边框
- 背景层次

## 动效规则

Quiet Pro 的动效应当：

- 短
- 轻
- 有反馈意义
- 不打断使用节奏

可以有：

- 页面切换的轻过渡
- 悬停反馈
- `toast / modal` 的短入场

不应有：

- 大幅位移动画
- 浮夸弹跳
- 为了显得灵动而增加的表演性动效

去掉动效后，组件和页面仍应成立。

## 实现偏好

- 先扩展设计系统，再做页面局部 workaround
- 能复用现有模式，就不要为单个场景发明新视觉语言
- 没有明确需求时，不改变现有功能语义和操作路径
- 新视觉角色优先进入共享 token 或共享组件，而不是页面私有实现
- 局部例外必须显式、可解释，而且尽量变薄

## 界面审查

UI review 同时检查 owner、token、状态、键盘、焦点、可访问性和可重复测试。明显偏离 Quiet Pro 或需要新视觉方向时先确认；可见 UI PR 的截图只通过仓库外附件提供，不能提交审查媒体或用截图替代测试。
