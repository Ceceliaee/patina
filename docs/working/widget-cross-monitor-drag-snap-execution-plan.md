## 2. 一句话问题定义

挂件跨显示器拖动结束后，系统没有把“目标显示器”作为位置的一部分贯穿保存与吸附流程，导致 Rust 端重新按当前窗口或主显示器选屏，最终可能把挂件弹回原屏或主屏。

## 3. 当前事实与根因证据

### 3.1 已确认事实

- [x] 前端拖动结束路径能够读取挂件最终物理位置与尺寸。
- [x] 前端现有逻辑能够根据窗口矩形找到一个显示器。
- [x] `applyWidgetLayout` 只向 Rust 传递 `side`、`anchorY`、展开状态等布局信息，没有传递目标显示器。
- [x] Rust 的 `resolve_widget_monitor` 会再次依次尝试挂件当前显示器、主窗口当前显示器和主显示器。
- [x] 持久化目前只有 `widget_side` 与 `widget_anchor_y`，无法表达显示器归属。
- [x] 当前物理坐标计算已经覆盖负坐标显示器与不同 DPI 下的窗口尺寸转换，可在其基础上收敛而不必重建整套几何系统。
- [x] 用户当前没有第二块物理显示器，因此开发阶段必须以确定性纯逻辑测试和合成显示器矩阵为主，真机验收单独列为发布前条件。

### 3.2 根因链

1. 用户把挂件从显示器 A 拖到显示器 B。
2. 前端在拖动结束时看到了位于 B 的最终窗口矩形。
3. 前端把矩形归一化为 `side + anchorY`，但丢弃了 B 的身份。
4. Rust 收到不完整的位置描述后，只能再次猜测目标显示器。
5. 此时窗口管理器报告的 `current_monitor()` 可能仍是 A，或代码回退到主显示器 A。
6. Rust 使用 A 的工作区重新计算吸附坐标，窗口因此回弹。

### 3.3 第一处应被红测锁定的故障

- [x] 写出一个失败测试：最终窗口矩形明确位于显示器 B，但运行时若重新读取 `current_monitor()` 得到 A，最终保存与吸附仍必须使用 B。
- [x] 确认该测试在修改生产代码前失败，且失败原因是缺少显示器亲和类型与目标选择函数，而不是测试桩错误。

## 4. 第一性原理

### 4.1 桌面坐标的本质

Windows 多显示器桌面是一个统一的物理坐标空间，而不是若干个各自从 `(0, 0)` 开始的画布。副屏可以位于主屏左、右、上、下，坐标可以为负，屏幕之间也可以有间隙。

由此得到：

- [x] 所有跨屏归属判断使用物理像素矩形。
- [x] 不假设主显示器原点是整个桌面原点。
- [x] 不假设显示器相邻、同高、同宽或按固定顺序排列。
- [x] 不用 CSS 像素或逻辑像素直接比较显示器物理工作区。

### 4.2 挂件位置的最小完整信息

`side + anchorY` 只描述“在某块屏幕中的相对位置”，没有描述“哪块屏幕”。所以完整位置至少是：

```text
位置 = 显示器亲和信息 + 水平吸附边 + 垂直归一化锚点
```

由此得到：

- [x] 将显示器亲和信息纳入 `WidgetPlacement`。
- [x] 不把绝对窗口坐标作为长期位置真相。
- [x] 不把 DPI 比例作为显示器身份或长期真相，因为比例可能变化。
- [x] 保留相对锚点，使分辨率、工作区或任务栏变化后仍能恢复到合理位置。

### 4.3 单一所有者原则

一次拖动结束只能有一个组件决定目标显示器。任何后续层再次猜测，都会制造竞态与分歧。

由此得到：

- [x] 将拖动完成事务的所有权放在 Rust 运行时。
- [x] 前端只发出“结束本次用户拖动”的意图，不再枚举并决定目标显示器。
- [x] Rust 在同一次事务中读取最终窗口矩形和显示器快照，只选择一次目标显示器。
- [x] 后续计算、保存和吸附复用同一个已选目标，不再次调用 `current_monitor()` 覆盖它。

### 4.4 原子完成原则

拖动结束不是四个彼此独立的动作，而是一笔逻辑事务：

```text
读取最终窗口矩形
→ 选择目标显示器
→ 计算相对位置
→ 持久化
→ 在同一目标显示器内吸附
```

由此得到：

- [x] 任何一步失败时返回可诊断错误，不把半成品位置报告为成功。
- [x] 持久化和实际吸附使用同一个 `WidgetPlacement` 值。
- [x] 防止两个拖动结束回调并发执行或旧回调覆盖新回调。

### 4.5 可恢复原则

已保存的显示器可能暂时断开。安全回退的目标是“让挂件可见”，不是“偷偷忘记用户原来的显示器”。

由此得到：

- [x] 恢复时若目标显示器缺失，可临时显示在安全回退屏幕。
- [x] 临时回退不得自动覆盖原有显示器亲和信息。
- [x] 只有用户完成新的明确拖动，才用新目标显示器覆盖已保存亲和信息。

## 10. 新位置数据契约

建议领域结构：

```rust
pub struct WidgetPlacement {
    pub monitor: Option<WidgetMonitorAffinity>,
    pub side: WidgetSide,
    pub anchor_y: f64,
}

pub struct WidgetMonitorAffinity {
    pub name: Option<String>,
    pub work_area: WidgetPhysicalRect,
}
```

建议 JSON：

```json
{
  "monitor": {
    "name": "\\\\.\\DISPLAY2",
    "work_area": {
      "x": 1920,
      "y": 0,
      "width": 2560,
      "height": 1392
    }
  },
  "side": "right",
  "anchor_y": 0.28
}
```

执行要求：

- [x] 确认 Tauri 返回的显示器名称可选且可能为空。
- [x] 名称允许为空，因此工作区几何作为辅助亲和信息。
- [x] 不在 JSON 中加入 `version` 字段；当前已明确不做旧格式兼容。
- [x] 不保存 scale factor 作为显示器身份。
- [x] 宽高必须为正；无效工作区使 `monitor` 视为不可用，而不是传播异常几何。
- [x] `monitor: null` 仅表示首次运行、非法数据回退或尚未发生明确跨屏定位。
- [x] 因新增非 `Copy` 字段，移除 `WidgetPlacement` 的 `Copy` 假设并在必要处显式 `Clone`。
- [x] TypeScript 与 Rust 的 snake_case/camelCase 映射由一个网关边界集中完成。

## 11. 目标显示器选择算法

输入：

- 最终挂件物理矩形；
- 同一时刻的全部显示器物理工作区快照；
- 每块显示器的稳定描述信息。

选择顺序：

1. 计算挂件矩形与每块显示器工作区的相交面积。
2. 选择相交面积最大的显示器。
3. 若最大相交面积相同，优先选择包含挂件中心点的显示器。
4. 若没有任何相交，选择距离挂件中心最近的工作区；距离应按“点到矩形的最短距离”计算，而非只比屏幕中心。
5. 仍然相同则使用稳定排序，例如规范化名称、工作区坐标与尺寸组成的元组。

执行清单：

- [x] 明确定义半开矩形边界，避免共享边缘被重复计入。
- [x] 使用 `i64` 边界和 `u64` 面积计算，避免常见高分辨率坐标乘法溢出。
- [x] 对零宽、零高窗口矩形定义确定行为。
- [x] 对空显示器列表返回可诊断错误，由上层决定安全处理。
- [x] 对重复或重叠显示器描述保持确定性。
- [x] 确认算法不依赖显示器枚举顺序。
- [x] 把选择结果连同该次显示器快照传给后续布局，不再重新枚举。

## 12. 拖动结束原子流程

目标时序：

```text
WidgetShell 检测鼠标释放
→ controller.endUserDrag()
→ 等待最后一次 move 事件稳定
→ IPC: finalizeWidgetDrag(generation)
→ Rust 读取最终 outer_position / outer_size
→ Rust 枚举一次 available_monitors
→ 纯函数选择目标显示器
→ 计算 side / anchorY / monitor affinity
→ SQLite 保存 widget_placement
→ 按同一个目标显示器 DPI 和工作区应用边界
→ 返回规范化后的 WidgetPlacement
→ 前端仅更新本地显示状态
```

执行清单：

- [x] 保留现有短暂稳定等待，并用尾部 move 与 release 竞态测试锁定用途。
- [x] 每次 `beginUserDrag` 生成递增 generation/token。
- [x] `endUserDrag` 只允许当前 generation 发起完成事务。
- [x] 同一 generation 已在完成中时合并重复请求。
- [x] 新一代拖动开始后，上一代完成结果不得更新本地状态或再次移动窗口。
- [x] 窗口被隐藏、销毁或应用退出时，完成事务安全忽略结果。
- [x] Rust 在读取最终矩形之后选择屏幕，不使用拖动开始时的屏幕。
- [x] Rust 返回实际保存的规范化位置，使前端不自行重算。
- [x] 保存失败返回错误且不执行后续吸附，不把失败报告为成功。
- [x] 吸附失败保留已保存位置并返回带阶段上下文的错误，使下次恢复仍可重试。

## 13. 位置计算规则

对已选目标显示器：

- `side`：比较挂件中心到目标工作区左右边缘的距离，选择更近一侧。
- `anchorY`：以目标工作区内可移动的纵向范围归一化。
- `anchorY = clamp((window_y - work_area_y) / (work_area_height - widget_height), 0, 1)`。
- 目标物理尺寸：由挂件逻辑尺寸乘以目标显示器 scale factor 后统一取整。
- 目标 X：目标工作区左边或右边减去挂件物理宽度。
- 目标 Y：`work_area_y + anchorY * 可移动纵向范围`，最后统一取整并夹紧。

执行清单：

- [x] 对 `work_area_height <= widget_height` 定义为顶端对齐且 `anchorY = 0`。
- [x] 使用目标显示器的工作区而不是完整屏幕边界，避开任务栏。
- [x] 对偏移工作区和顶部、左侧任务栏加入测试；底部、右侧由宽高收缩矩阵覆盖。
- [x] 统一取整策略，并在测试中只允许一次物理像素取整。
- [x] 不在前端和 Rust 各实现一套公式。

## 14. 恢复与缺屏回退

### 14.1 显示器亲和匹配顺序

1. 名称完全匹配。
2. 名称不可用或未匹配时，在当前显示器中选择与保存工作区几何最接近者。
3. 无可靠匹配时选择当前可见/主显示器作为安全回退。

几何匹配至少考虑：

- 工作区宽高差；
- 原点距离；
- 宽高比例；
- 结果是否唯一且明显优于其他候选。

执行清单：

- [x] 为名称变化但同一物理布局的情况提供几何回退测试。
- [x] 为同名双屏但不同坐标提供几何消歧测试。
- [x] 断开目标屏幕后由既有首选 / 当前 / 主屏链路安全回退。
- [x] 恢复目标屏幕后名称或几何亲和能再次匹配。
- [x] 临时回退期间不调用位置保存。
- [x] 用户在回退屏幕上明确拖动结束后，才将亲和更新为该屏幕。
- [x] 所有恢复结果都经过工作区夹紧，保证窗口可见。
