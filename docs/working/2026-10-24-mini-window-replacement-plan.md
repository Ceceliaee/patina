# 桌面迷你窗替换挂件执行方案

> 状态：方案已整理，尚未开始实现
> 创建 / 更新：2026-10-24
> 实施 owner：承接本方案的实现者；产品体验验收：SYBao
> 范围：Windows 桌面迷你窗、现有挂件替换、相关设置与窗口生命周期、数据投影、权限及验证

目标是让用户在主窗口收起后，仍能用很小的桌面占用查看记录状态和操作正在运行的工具：贴边时留下小条，鼠标靠近时展开，离开后收回；拖离边缘后成为持续显示的浮动小窗。用户已经确认这一交互方向。本文把它转成实现规则、改动范围和可逐项验收的工作，不代表原生实现或验收已经完成。

本方案以当前工作区源码为检查基线，其中包含其他任务尚未提交的后台生命周期修改。实施时重新核对基线，不回退这些修改。对照的交互原型仅证明设计方向；浏览器中的模拟屏幕不能证明 Windows 命中区域、前台焦点、多屏、DPI 或后台资源行为。

长期约束分别由[产品范围](../product-principles-and-scope.md)、[优先级](../roadmap-and-prioritization.md)、[架构](../architecture.md)、[Quiet Pro](../quiet-pro-component-guidelines.md)、[工程质量](../engineering-quality.md)和[本地化](../localization.md)持有。本文拥有本次实施步骤及验收记录。代码实现、提交、推送与发布不因写成此方案而视为已经执行。

## 1. 从第一性原理确定边界

### 1.1 用户需要什么

用户打开迷你窗，通常只想回答三个问题：Patina 是否在正常记录、正在记录什么、正在运行的计时工具还剩多久。只有在暂停记录、暂停工具或查看完整详情时，才需要主动操作。由此推导以下约束。

| 必要条件 | 推导出的规则 | 如何验证 |
| --- | --- | --- |
| 查看状态不能干扰正在做的工作 | 鼠标靠近展开不激活窗口、不改变前台应用；明确点击或键盘打开才进入交互 | 原生前台窗口句柄与焦点断言 |
| 不使用时应减少占用 | 贴边留下可发现的小条；展开内容离开后延迟收回 | 命中区域与收起计时测试 |
| 用户主动摆放的位置具有意义 | 浮动显示不因鼠标离开或失焦而收起；拖动结束不再一律吸到左右边缘 | 桌面中部释放、失焦与重启恢复测试 |
| 状态可信比显示连续更重要 | UI 隐藏不停止记录或工具；过期快照不得继续伪装成正在记录 | 权威快照、失效及后台恢复测试 |
| 查看和控制是不同权限 | 查看采用专用投影；暂停等操作调用既有业务 owner，只开放必需命令 | IPC 允许与拒绝矩阵 |
| 收起后仍要找得到 | 小条保留入口；关闭小窗前保证托盘或任务栏有可用入口 | 无托盘、主窗口已销毁等恢复测试 |
| 常驻能力必须成本有界 | 唤出检测不依赖高频 JS IPC；收起不继续绘制大面板、查询统计或加载页面 | 隔离实例 CPU、查询数、订阅与进程测量 |

### 1.2 本轮交付范围

必须交付：顶部 / 左侧 / 右侧贴边、鼠标靠近唤出、离开延迟收起、自由浮动、保持展开、拖动吸附、键盘替代入口，以及主窗口最小化到迷你窗的完整替换。

内容采用“活动 / 计时”两个固定页签。活动显示记录状态、当前活动和本段时长；计时显示既有计时器与番茄钟，保留二者同时运行的能力。轻量今日汇总在窗口与数据边界稳定后接入，仍属于本执行单的后续批次。若实施中决定移出范围，必须在收口处说明原因和承接事项，不能留下看似完成的静态数字。

本轮不增加底边吸附、可安装内容模块、任意聊天或网页容器、透明度调节、离开后整窗隐身、全局快捷键配置、任务管理或新的计时模式。QQ 的贴边收起与隐私隐身是两个功能，本轮采用前者。主题继续使用 Quiet Pro，不复制 QQ 的透明灰色外观。

### 1.3 不可破坏的行为

- 主窗口、迷你窗、托盘都不是 tracker 或工具计时器的运行 owner；关闭、收起、销毁和重建 UI 不改变其计时事实。
- 记录暂停与工具暂停独立。按钮必须明确写“暂停记录”“暂停计时器”或“暂停番茄钟”，不能使用一个含义不明的全局暂停。
- 匿名活动不暴露原应用、域名、标题或图标；排除、关联应用、持续参与、AFK、锁屏和异常状态沿用现有业务语义。
- 不把前台转到 Patina 的时间自动算作上一个应用的时长。保留最近活动用于显示时，必须标明其是最近活动，并停止无权威依据的外推。
- 显式退出优先于所有唤出、延迟布局、资源回收和窗口恢复任务。

## 3. 明确交互规则

### 3.1 状态分解与优先级

避免用一个 `expanded` 同时代表“原生窗口存在”“内容展开”“保持展开”和“可以抢焦点”。状态至少分为下列维度；类型名称由实现 owner 确定。

| 维度 | 取值 / 含义 | 是否持久化 |
| --- | --- | --- |
| 用户显示意图 | 打开 / 关闭 | 不新建永久关闭偏好；遵循启动及最小化行为 |
| 原生生命周期 | 未创建、创建中、可用、隐藏、销毁 / 恢复中 | 否，复用现有生命周期 owner |
| 位置 | 顶部、左侧、右侧、浮动；显示器及归一化位置 | 是 |
| 内容状态 | 小条、展开、拖动中；过渡为暂态 | 否，从位置与偏好恢复 |
| 保持展开 | 开 / 关，沿用已有展开偏好 | 是 |
| 交互保护 | 菜单打开、键盘交互、触屏明确打开、指针按下 / 拖动、未完成的控件操作 | 否，按窗口世代清理 |
| 系统抑制 | 同屏前台全屏、锁屏 / 会话不可交互 | 否，不改用户意图或位置 |

优先级：退出或窗口世代失效 → 用户关闭 / 主窗口恢复 → 系统抑制 → 拖动与必要操作保护 → 保持展开 / 浮动 → 鼠标靠近与离开。低优先级回调不得重新打开被高优先级动作关闭的窗口。

浮动必定显示完整面板；保持展开只决定贴边时是否自动收起。浮动期间保留该偏好，回到边缘时继续适用。置顶是原生层级策略，第一版沿用已有置顶行为，不新增独立开关，也不把“保持展开”的图钉解释成置顶。

### 3.2 初始位置、尺寸与命中区域

以下数字是实现起点和测试输入，不是已测性能结果。若原生验证需要调整，在本方案和唯一几何 owner 中一起记录理由；不能由 Rust 和 CSS 各维护一套不同尺寸。

| 项目 | 首版规则 |
| --- | --- |
| 新用户默认 | 当前目标显示器工作区顶部居中，自动收起；无有效目标时使用主显示器 |
| 已有用户 | 保留原显示器、左右侧和纵向位置；原 pinned 仍表示保持展开，不强制迁到顶部 |
| 展开尺寸 | 以 304 × 384 逻辑像素为初始面板；两个页签和 0 / 1 / 2 个工具不改变外框 |
| 小条 | 顶部 112 × 24；左右 24 × 88 逻辑像素；左右使用竖条，避免大面积遮挡 |
| 小条外观 | 安静的抓手与必要状态点；不放运行秒数、滚动文字或闪烁通知；可访问名称包含状态 |
| 靠近区域 | 顶部：小条两端各加 10、向工作区内总深度 32；左右旋转同一规则；裁剪到所在显示器 |
| 面板区域 | 展开后以实际面板及其窗口内菜单为保留区域；圆角和阴影不能形成大块透明拦截层 |
| 吸附阈值 | 拖动释放时面板对应边与工作区边缘距离不超过 24 逻辑像素；顶部 / 左右候选取最近者 |
| 同距规则 | 优先原停靠边；原边不在候选时依次顶部、左侧、右侧，保证确定性 |
| 小工作区 | 外框收敛到工作区，内容内部滚动，标题栏和恢复入口保持可达；不能把操作挤到屏幕外 |

“边缘”统一按显示器工作区计算，避开任务栏。多屏相接也只在小条所在区域唤出，不监听整条屏幕边缘。第一版不在底边停靠；任务栏位于顶部或侧边时，小条位于该屏可用工作区的相应边。

原生窗口缩成小条尺寸即可表达“缩进去”，不要求把一个完整 WebView 移到屏幕外。外扩靠近区域由原生坐标检测，不能用一块透明大窗口拦截桌面点击。靠近区域不等于点击区域：只有实际小条和展开面板接收点击。

### 3.3 鼠标靠近与离开

1. 小条可见且没有系统抑制时，指针进入靠近区域即可请求展开，不要求点击；不另加长时间悬停门槛。
2. 展开从停靠边朝工作区内部进行，沿边锚点保持稳定。初始过渡时长为 180 ms；减少动态效果模式直接切换，状态与命中区域仍正确。
3. hover 展开只改变可见几何，不激活窗口、不移动键盘焦点、不改变当前正在记录的前台应用。
4. 指针离开面板与有效入口后，且没有交互保护，开始 450 ms 收起等待。期间返回立即取消等待；菜单打开、键盘进入、开始拖动也取消等待。
5. 到期再次检查位置、指针、保护条件、显示意图和窗口世代，再收起。过渡中重新靠近应中断收起并展开；旧回调不能在其后缩小原生窗口。
6. 收起完成后只剩小条，其余桌面区域立即恢复正常输入。面板内不可见控件不接受 Tab、鼠标点击或读屏导航。
7. 单纯点击后留下的 DOM focus 不永久阻止收起。只有实际键盘操作且原生窗口仍持有焦点时保持键盘保护；切换到别的窗口或明确收起会释放保护。
8. 指针位置读取失败时保持最后安全的可见状态，停止不可靠的自动转换并记录受限诊断；下一次有效读数、明确点击或重新打开可恢复，不能把失败读数当作“鼠标已离开”。

原生靠近检测首选一个可停止的有界任务，初始采样间隔 75 ms，只读光标、已有几何和交互状态，不查询数据库、不调用前端 IPC 轮询。隐藏、锁屏、同屏全屏抑制、退出时停止靠近检测；浮动或保持展开时也无需靠近 / 离开轮询。自动收起模式展开时只保留必要的离开判定。是否采用其他原生事件机制，先用 P1 的焦点和成本实验决定，不能为此引入常驻高频全局鼠标 hook。

### 3.4 拖动、吸附与自由浮动

1. 标题栏空白处和小条是拖动把手；页签、按钮、菜单项和内容选择不触发拖动。按下后移动达到 4 逻辑像素才认定拖动，短按小条展开。
2. 拖动开始即取消靠近 / 离开任务，记录窗口世代和拖动世代；不在每次 moved 事件写数据库或重新吸附。
3. 从小条拖动时先形成完整面板并保持指针抓取点连续，再交给原生拖动；不能突然跳到屏幕另一侧。该过渡需专门进行真实 DPI 验证。
4. 拖动中仅提示可吸附的候选边。释放时以实际释放点选择目标显示器，再使用目标 DPI 计算最终面板和距离；没有释放点时按实际原生窗口矩形回退。
5. 释放在阈值内则停靠；否则停留在释放位置，进入浮动。到桌面中央释放不会再按左右半屏自动归边。
6. 停靠后指针还在面板上则保持展开，离开后走 450 ms 规则。浮动不因离开、失焦或计时完成而收起。
7. 位置菜单提供“顶部 / 左侧 / 右侧 / 浮动显示”，与拖动共用同一位置转换。浮动命令恢复最近浮动位置；从未浮动时放在当前显示器工作区中央。
8. 接受一次拖动结果后才保存位置。保存失败保留本次可用位置，显示“位置未保存”，允许重试；不谎称重启后可恢复，也不强制跳回旧位置。
9. 拖动取消、失去捕获、窗口关闭或显示器拔出都必须结束拖动保护。拖动结束后的 click 不应再误触展开 / 收起或触发内容按钮。

### 3.5 明确按钮和键盘行为

| 操作 | 规则 |
| --- | --- |
| 点击小条 | 展开并允许交互；鼠标仍按离开规则收起，不因点击留下的 DOM focus 永久保持展开 |
| 触屏轻触小条 | 展开并临时保护；点“收至边缘”或原生窗口失焦解除保护，随后按条件收起；不改保存偏好 |
| 键盘打开迷你窗 | 通过主窗口 / 托盘的明确入口进入，展开并聚焦当前页签；不依赖隐藏的小条恰好获得 Tab |
| 页签 | “活动 / 计时”；方向键切换，Tab 进入内容；保持外框、位置和运行工具不变 |
| 保持展开 | 开启时贴边也不自动收起；关闭时若鼠标仍在窗内则等离开，再延迟收起；保存失败还原勾选并提示 |
| 标题栏收起 | 显示名称“收至边缘”；贴边时收成小条，浮动时回到最近停靠位置，缺省顶部居中；明确关闭保持展开偏好，保存失败不假装成功 |
| Escape | 先关闭最上层菜单并返回触发器；无菜单时，自动收起模式下的贴边展开窗收起并回到小条；浮动或保持展开时不改变位置 / 偏好 |
| 返回主窗口 | main 成功显示后隐藏 mini；进入工具详情时将目标交给既有导航 owner，不重复创建工具页 |
| 关闭 mini / Alt+F4 | 只关闭迷你窗，不退出、不暂停记录或工具；按 3.6 保证可找回；不复用“收成小条”操作 |
| 计时暂停 / 恢复 | 只作用于按钮明确指向的现有工具实例；请求中禁用重复提交，成功后按权威投影更新，失败保留可重试状态 |

工具创建、修改时长、分段、重置和跳过阶段先留在主窗口工具页，mini 首版只提供暂停 / 恢复。原型的重启按钮不直接作为正式业务契约，避免在小窗误重置正在运行的工具。没有工具时显示说明与“打开工具”，不显示无作用的暂停按钮。

所有图标按钮有独立可访问名称；提示采用既有 Quiet Pro Tooltip。菜单优先在当前窗口内避让，不因 portal 越过 DOM 边界而误判离开。状态变化可播报，秒数刷新不逐秒读出。

### 3.6 主窗口、关闭、全屏与恢复

- **互斥关系：** 第一版保留主窗口与迷你窗互斥。浮动指的是桌面位置自由，并不自动扩成两个工作面同时常开。main 被用户恢复后隐藏 mini，但保留位置、页签和展开偏好。
- **最小化：** 设置选择迷你窗时，先创建并确认 mini 可用，再隐藏 main；失败保留 / 恢复 main。选择任务栏时保持已有最小化语义。明确“打开迷你窗”入口不偷偷改写该偏好。
- **首次显示：** 自动收起的停靠位置显示小条；浮动或保持展开位置显示面板。键盘明确打开覆盖本次初始收起状态，直接进入可操作面板，但不改保存偏好。
- **关闭 mini：** 若原生确认托盘入口已经可见且可用，隐藏 mini 后留在后台；若没有托盘入口，先建立主窗口的任务栏最小化入口，再隐藏 mini。该路径不改“最小化到迷你窗”设置，不能递归触发 mini。若入口建立失败，显示 main；main 也恢复失败时保留 mini 和明确错误。两者都没有入口时不提交关闭。
- **任务栏回退：** 主窗口若已被后台回收，先按已有 ready / 恢复流程创建，再以无激活方式建立任务栏入口。原生最小化但可找回与隐藏待回收必须区分，旧回收世代不能随后销毁唯一任务栏入口。
- **重新打开：** 从主窗口或可见托盘的“打开迷你窗”进入，同一运行期恢复当前页签；程序重启默认“活动”。位置 / 保持展开跨重启保留。不开启新的隐藏自启动策略。
- **同屏全屏：** 保留现有同显示器全屏抑制。自动隐藏小条与浮动面板，停止靠近检测；另一显示器上的全屏不抑制 mini。退出全屏后，只有显示意图仍有效且 main 没有恢复时才恢复；自动收起停靠恢复小条，浮动 / 保持展开恢复面板，不抢焦点。
- **锁屏、睡眠与解锁：** 不在不可交互会话唤出。恢复后重新取得显示器、DPI、光标与权威状态，清除失效菜单 / 拖动 / 计时等待，不能补放一串旧动画。
- **显示器变化：** 匹配保存的显示器；不存在则选择可用主显示器。归一化坐标与工作区夹取保证小条、标题栏可见；支持负坐标与上下排列，不只测试左右双屏。
- **程序退出：** 遵循已有显式退出策略，取消检测、布局、重建、收起和销毁等待。关闭 mini 本身不调用退出策略。

| 初态 | 输入 | 结果 | 不应发生 |
| --- | --- | --- | --- |
| 贴边小条 | 指针进入靠近区域 | 无激活展开 | 更换前台应用、记录被切到 Patina |
| 贴边展开 | 离开且无保护 | 450 ms 后复核并收起 | 一离开就闪回、透明面板挡住桌面 |

## 4. 数据、状态与实现所有权

### 4.1 窗口状态只有一个权威 owner

原生运行时持有最终位置、展开状态、交互世代和抑制结果，因为靠近检测及窗口是否存在不能依赖 WebView 正在执行 JS。纯状态转换和几何规则放在 `domain/widget`；运行编排在既有 widget engine 范围；Tauri 创建、移动、改尺寸和焦点动作留在 `app/widget`。如需拆文件，按几何、交互或窗口运行等真实职责拆分，不另建通用桌面窗口框架。

前端 controller 改为提交交互意图、报告菜单 / 键盘 / 操作保护、消费已应用快照。它可以管理 CSS 过渡和请求状态，但不再独立决定另一套最终 native bounds。快照至少包含窗口世代、递增修订、位置、内容状态、展开来源及持久化结果；旧窗口事件、旧 drag finalize、旧异步保存和旧收起等待都不得覆盖更新的状态。

原生布局失败时不广播“已经成功收起 / 展开”。返回最后成功应用状态和可重试错误；无法保持安全几何时回到可见小条或主窗口。持久化失败与原生应用失败分开处理，避免“数据库说已展开、实际窗已消失”。

### 4.2 活动与工具投影

| 内容 | 数据规则 |
| --- | --- |
| 记录状态 | 健康、暂停、AFK / 空闲、持续参与、正常记录分清；健康异常优先提示，暂停标志仍来自同一快照；健康正常时暂停优先于活动展示 |
| 当前活动 | 使用规范化应用身份 / 分类 / 关联规则；匿名显示“匿名活动”和通用图标；不显示标题，避免新增隐私面 |
| 本段时长 | 明确是当前活动段的时长，不伪装为该应用今日累计；仅在有效 running 样本上按单调时间外推 |
| Patina 自身前台 | 可以显示最近非 Patina 活动，但改为“最近活动”；时长按权威状态冻结或刷新，不延长上个活动段 |
| 计时器与番茄钟 | 保留两个独立实例，顺序固定；显示状态、阶段、剩余 / 已用时间；不能把两个工具合成一个暂停目标 |
| 完成状态 | 到期与通知由 Rust 工具 owner 处理；mini 不自行推进番茄阶段或重复发通知。沿用已有短暂完成投影，再转为空态 / 下一权威状态 |
| 错误与恢复 | 初次加载显示占位；没有工具显示空态；获取失败保留最后有效值并标记未同步，停止不可靠外推；重开重新订阅并拉取 |

原有工具投影缺少实例标识、版本和部分阶段信息。新增暂停 / 恢复时要附带目标实例与预期状态：若用户同时在 main 替换了工具，mini 的旧点击应返回冲突并刷新，不能作用于后来创建的实例。业务层复用现有工具运行实现，不在 widget 内建立第二个计时器。

暂停记录采用窄命令，只传目标暂停值，复用现有 transition 锁、保存与广播流程；不向 widget 开放通用设置写入。工具动作同样采用窄返回值，避免为暂停一个计时器返回完整提醒规则和不相关工具历史。

### 4.3 今日汇总接入规则

活动页下半部分可显示“今日已记录”总时长及少量分类分布。先核对 [Dashboard read model](../../src/features/dashboard/services/dashboardReadModel.ts)、共享 session compiler 与 [活动聚合 owner](../../src-tauri/src/data/activity_read_model/mod.rs)，确定与主窗口相同的日期区间、匿名、关联、排除、导入优先级和实时活动裁剪语义。

只查询今日所需的聚合，不加载昨天、全量历史、图表库或 Dashboard 页面。不能重新把应用时间与网页时间相加制造双重统计。分类显示前三项及“其他”，总计与主窗口在相同样本截点下相符；如果复用需要提取纯统计函数，只提取真正共用的计算，不把页面缓存搬进 shared。

刷新采用展开时读取、相关数据变更时合并失效、日期 / 时区切换时重读；收起时只标记失效，不执行汇总查询。汇总加载失败不阻塞小窗唤出或工具控制。不为总数字每秒重新查库，不把页面绘制时钟当作事实推进器。

### 4.4 资源生命周期

- 贴边小条仍是可操作入口，不能当成“完全隐藏”套用现有延迟销毁；保持小条的最小渲染，不保留展开内容的秒级更新、统计查询和预加载。
- 完全关闭、main 恢复或系统抑制时按对应原因处理：关闭 / main 恢复沿用 park 和带 generation 的回收；短期全屏抑制不等于用户关闭，恢复需重新检查意图。
- 展开内容只保留一套订阅和显示时钟。窗口重建、StrictMode、延迟 listen 返回及请求失败都需要清理；隐藏期间事件可合并成失效标记，重新展开取一次最新快照。
- 主窗口后台资源回收继续由现有 owner 管理。新增 mini 不得让主窗口和整个工具 / 数据页面长期驻留，也不恢复已删除的后台优化开关。
- 不预先引入第二个原生小条窗口、永久透明覆盖窗或全局输入 hook。若单窗口方案无法同时满足唤出与资源门槛，先在 P1 提供测量和边界结论，再修订这一处方案。

## 5. 持久化和升级规则

保留 `minimize_behavior=widget` 和 `widget` 窗口 label；这两个内部值不影响用户看到“迷你窗”。位置存储需要描述停靠与浮动，使用显式版本化的持久化结构。当前运行模型只有一种，旧格式读取只服务已发布设置迁移。

| 输入 | 迁移 / 恢复结果 |
| --- | --- |
| 当前 JSON 的 monitor、left / right、anchor_y | 原显示器和侧边不变，纵向比例归一化；新浮动位置暂缺省 |
| `widget_expansion_preference=pinned` | 保持展开开启；不转换成置顶选项 |
| `auto_collapse` 或缺失 | 自动收起；浮动位置仍完整显示 |
| 无位置记录 | 新默认顶部居中 |
| 损坏 / 非有限数字 / 超出范围 | 读取使用安全默认或夹取；保留可诊断原值，不在失败读取时静默覆盖 |
| 无法识别的未来格式 | 不按旧格式误解析，不自动覆盖原值；本次使用安全默认并报告不能恢复位置，只有用户明确重新设置位置才替换 |
| 原显示器移除 | 恢复到可用显示器工作区；旧显示器信息是否更新只在成功应用 / 保存后决定 |

浮动保存工作区内归一化 x / y 及显示器亲和信息；停靠保存边及沿边归一化位置；另保留最近停靠位置用于“收至边缘”。不要把菜单、hover、拖动中坐标、动画进度、倒计时剩余秒数持久化为偏好。

迁移在既有仓储事务边界进行，支持重复读取而不重复写。不触碰追踪记录、工具计时事实或历史数据。设置备份 / 恢复覆盖新字段，旧备份能恢复到合法位置。降级到旧应用是否能识别新位置格式不作无证据保证；升级测试保留隔离配置副本，需要回退时恢复配置，不恢复或回滚追踪数据库。
