# 桌面迷你窗骨架执行方案（保留现有挂件）

> 状态：范围已收敛，尚未开始实现
> 创建：2026-10-24；更新：2026-10-25
> 实施 owner：承接本方案的实现者；产品体验验收：Ceceliaee
> 本阶段：新增标题栏入口与独立 mini 窗，完成三个核心窗口交互，展示现有挂件内容
> 后续方向：mini 窗完善并验收后，再单独安排挂件替换和拆除

本阶段先把 mini 窗骨架做出来。主窗口标题栏在最小化按钮左侧新增“打开迷你窗”按钮，位置对应用户截图中的红色虚线框。用户可以单独打开和体验 mini 窗；现有挂件继续提供原来的内容、功能、入口和设置。当前任务只更新这份执行方案，不实现产品代码。

本轮只包含三组核心改造：顶部 / 左右贴边收成小条、鼠标靠近展开并在离开后延迟收起、拖离边缘后自由浮动并可重新吸附。mini 窗内沿用现有挂件的信息和能力，不增加记录暂停 / 恢复、工具暂停 / 恢复或今日统计。现有计时器和番茄钟仍显示状态，操作继续在原有工具页完成。

长期规则由[产品范围](../product-principles-and-scope.md)、[架构](../architecture.md)、[Quiet Pro](../quiet-pro-component-guidelines.md)、[工程质量](../engineering-quality.md)和[本地化](../localization.md)持有。本文记录本阶段的边界、步骤和验收；后续替换挂件不是本阶段完成的前提。

## 1. 从第一性原理收敛范围

### 1.1 先验证窗口交互，业务内容保持稳定

本阶段要验证的是：用户能否方便地打开小窗，是否能在需要时靠近查看，以及不使用时能否减少桌面占用。现有挂件已经提供记录和工具状态，因此 mini 窗可以使用相同的数据事实来验证窗口骨架，无需同时增加业务能力。

| 必要条件 | 本阶段规则 | 验证方式 |
| --- | --- | --- |
| 新入口应容易找到 | 标题栏最小化按钮左侧增加一个 mini 按钮，原三个窗口按钮保持语义 | 标题栏结构、键盘和 browser 测试 |
| 试用新窗口不能破坏现有入口 | 挂件继续使用原路径；mini 有独立窗口身份、状态和偏好 | main / widget / mini 三窗口路由及回归 |
| 查看不干扰工作 | 鼠标靠近展开不激活窗口，不改变前台应用 | Windows 前台句柄与焦点检查 |
| 收起确实减少遮挡 | 原生窗口缩成小条；透明区域不拦截桌面点击 | 原生命中和下层窗口点击检查 |
| 主动摆放的位置应保持 | 浮动不因失焦或鼠标离开而收起 | 拖动、失焦、重开测试 |
| 数据应保持可信 | mini 复用已有只读投影，不持有 tracker 或工具运行状态 | 同源快照、只读权限与隐藏恢复测试 |
| 并行试用应有退出条件 | mini 验收后由维护者决定何时替换挂件；本轮不拆挂件 | 阶段验收和后续事项边界 |

### 1.2 功能范围

| 分类 | 本阶段处理 |
| --- | --- |
| 核心一：贴边收起 | 支持顶部、左侧、右侧，留下可点击的小条 |
| 核心二：鼠标唤出 | 靠近展开、离开延迟 450 ms 收起，交互期间防误收起 |
| 核心三：自由浮动 | 拖离边缘保持完整显示；拖回阈值内重新吸附 |
| 现有内容 | 记录状态、当前活动名称 / 图标、本段时长、最多两个工具状态与时间 |
| 现有能力 | 打开主窗口、保持展开，以及主题 / 语言同步；在 mini 中保留相同语义 |
| 配套窗口操作 | 新标题栏入口、小条点击、拖动、位置菜单、收至边缘、关闭、键盘访问 |
| 本轮移出 | 在小窗暂停 / 恢复记录，在小窗暂停 / 恢复工具，今日总时长及分类汇总 |
| 本轮不做 | 活动 / 计时双页签、工具实例控制协议、统计读取入口、挂件设置迁移、旧挂件拆除 |

mini 首版采用一个简单面板，按“当前记录状态 + 现有工具状态”组织内容。没有工具时使用简洁空态；有两个工具时都能看到。无需为了留出扩展位增加空页签、占位功能卡片或模块安装机制。

### 1.3 现有挂件保护范围

- 现有挂件的 DOM、样式、左右吸附、固定展开、工具槽和打开主窗口能力继续保留。
- 原最小化按钮继续调用现有路径；`minimize_behavior=widget` 与任务栏选项保持原义。设置中仍称“挂件”，不整体改名。
- 不迁移、清空或覆盖 `widget_placement`、`widget_expansion_preference`，mini 不借用它们保存自己的位置。
- 不移除 widget 的命令、capability、事件、测试和恢复逻辑，不把旧行为测试改成 mini 的预期。
- 共用应用入口、窗口识别、命令注册和退出清理可以做识别第三个窗口必需的接线；不借此重构挂件实现。
- tracker、工具计时、通知与主窗口后台回收仍由原 owner 负责，mini 的开关与收起不改变这些业务。

## 2. 入口、内容和窗口之间的关系

### 2.1 标题栏按钮

截图对应的现有 owner 是 [AppTitleBar](../../src/app/components/AppTitleBar.tsx)。按钮放在 `app-titlebar-controls` 内，顺序为：

**迷你窗 → 最小化 → 最大化 / 还原 → 关闭。**

- 按钮使用现有标题栏按钮尺寸和 Quiet Pro 状态，不占用拖动区，也不挤掉更新入口或工具状态入口。
- 可访问名称与 Tooltip 为“打开迷你窗”；使用现有图标系统选择小窗口含义明确的图标，不与最小化符号混淆。
- 点击只打开 / 唤出 mini，不调用主窗口最小化，不修改最小化设置，不隐藏主窗口。
- mini 已存在时复用同一个实例：显示、展开并允许交互；连续点击不创建多个窗口，也不切换成“关闭”。
- 键盘可以 Tab 到按钮并用 Enter / Space 打开。打开成功后焦点进入 mini 的第一个有效窗口操作；失败留在原按钮并反馈错误。
- 程序启动不自动创建 mini；本阶段只从该按钮主动进入，不额外增加托盘入口或全局快捷键。

### 2.2 三个窗口的行为

| 场景 | 本阶段规则 |
| --- | --- |
| main 中点击 mini 按钮 | main 保持原状态，打开或唤出 mini |
| mini 打开时点击原最小化按钮 | 仍执行原有最小化策略；配置为挂件时仍出现原挂件 |
| main 重新获得焦点 | 原有 main / widget 关系不变；不因 main 聚焦而自动关闭 mini |
| widget 与 mini 同时存在 | 本阶段允许并存；mini 不主动隐藏、移动或改写 widget |
| mini 内点击“打开主窗口” | 使用已有主窗口恢复能力；mini 的显示状态不因此被另一套互斥逻辑控制 |
| mini 点击关闭或 Alt+F4 | 只关闭 mini，停止其新增检测与显示工作，不退出程序、不暂停记录或工具 |
| mini 关闭后重新打开 | 通过标题栏按钮恢复 mini 自己的位置与展开偏好 |
| main 按原策略退出 / 托盘中明确退出 | 退出必须关闭 mini 并取消所有回调，不能因新增窗口阻止原有退出 |
| main 按原策略退到后台 | 保留原语义；mini 不强制重开 main，也不修改托盘可见性 |

因此本轮无需新增“关闭 mini 后建立任务栏回退窗口”的流程：打开 mini 不主动移走主窗口入口，用户之后对主窗口的操作继续遵循既有桌面策略。mini 自身故障不扩大到 main 或 widget。

### 2.3 内容保持同源

mini 展示现有挂件已经拥有的状态，不复制新的业务状态机。

| 内容 / 能力 | mini 的处理 |
| --- | --- |
| 记录健康、暂停、空闲、持续参与和正常记录 | 沿用现有状态语义和优先级；只有展示，没有暂停 / 恢复按钮 |
| 当前活动、图标、本段时长 | 复用现有分类、关联、匿名 / 排除和时长口径；不新增标题或今日累计 |
| 计时器、番茄钟 | 保留 0 / 1 / 2 个工具及其运行、暂停、完成投影；只有状态显示 |
| 保持展开 | 与现有固定展开含义相同，但保存到 mini 自己的偏好，不控制 widget |
| 打开主窗口 | 保留已有导航能力，主窗口仍承接完整业务操作 |
| 主题、语言 | 跟随现有设置与 Provider，不创建 mini 专属主题配置 |

时长只在有效 running 样本上外推；数据未同步时保留最后有效值并明确状态，不无限延长旧活动。Patina 自身获得焦点时不能把其时间记到上一个应用；匿名活动不能泄露名称、标题或图标。这里是复用内容的正确性要求，不扩成修改旧挂件业务的专项。

## 3. mini 核心交互规则

### 3.1 状态及持久化

| 状态维度 | 规则 |
| --- | --- |
| 窗口身份 | 独立 label `mini`；与 `main`、`widget` 明确区分 |
| 显示意图 | 由标题栏打开 / mini 关闭改变；程序启动默认关闭 |
| 位置 | 顶部、左侧、右侧、浮动；保存显示器及归一化坐标 |
| 内容状态 | 小条、展开、拖动中；浮动始终展开 |
| 保持展开 | mini 独立偏好，只决定停靠时是否自动收起 |
| 交互保护 | 菜单、键盘操作、触屏明确打开、指针按下 / 拖动；随窗口世代清理 |
| 系统抑制 | 同屏前台全屏、锁屏等临时不可交互状态；不改用户保存偏好 |

优先级为：退出 / 世代失效 → 用户关闭 → 系统抑制 → 拖动和操作保护 → 浮动 / 保持展开 → 靠近 / 离开。main 恢复不再是关闭 mini 的信号；widget 的 shown / collapsed 事件不能改变 mini 状态。

mini 使用独立偏好，例如 `mini_window_placement`、`mini_window_expansion_preference`。位置包含最近停靠位置，供“收至边缘”使用；不保存动画进度、鼠标位置或倒计时秒数。新偏好缺失时使用默认值，不从 widget 设置自动迁移。

### 3.2 位置、尺寸与命中区域

以下是原生验证的起始参数，由唯一几何 owner 持有；实际调整需同步更新测试和本文，不由 Rust 与 CSS 各自定义一套数值。

| 项目 | 初始规则 |
| --- | --- |
| 首次位置 | 主窗口所在显示器的工作区顶部居中；无有效目标时使用主显示器 |
| 主动打开 | 直接展开，方便看到入口效果和操作；保持展开关闭时，鼠标离开后按规则收起 |
| 小条 | 顶部 112 × 24；左右 24 × 88 逻辑像素 |
| 面板 | 初始 304 × 240 逻辑像素，容纳现有信息；工具数量变化不改变外框，不为未来功能预留大块空白 |
| 小工作区 | 尺寸收敛到可用工作区，必要时内容内部滚动，标题栏与关闭 / 返回入口可达 |
| 靠近区域 | 顶部小条两端各加 10，向工作区内总深度 32；侧边旋转同一规则并裁剪到所在屏 |
| 吸附阈值 | 释放时面板对应边距工作区边不超过 24 逻辑像素；只考虑顶 / 左 / 右 |
| 同距候选 | 优先原停靠边，其余依次顶部、左侧、右侧 |
| 展开过渡 | 初始 180 ms；减少动态效果模式直接切换 |

“边缘”以显示器工作区为准，避开任务栏。顶部停靠显示横条，左右停靠显示竖条。只在小条所在局部区域唤出，不监听整个屏幕边缘。

原生窗口缩成小条即可表达收起。扩展靠近区域通过原生光标坐标检测，不创建透明大窗口拦截下方应用；只有实际小条与面板接收点击。小条只显示抓手及必要状态，不滚动显示秒数。

### 3.3 靠近展开和离开收起

1. 小条可见且未受系统抑制时，鼠标进入靠近区域即请求展开，不要求点击。
2. hover 展开只调整可见几何，不调用激活焦点路径，不改变前台应用。明确点击、触屏或键盘打开才允许进入交互焦点。
3. 指针离开面板及有效入口、且没有操作保护时，启动 450 ms 收起等待。返回、打开菜单、键盘操作或开始拖动立即取消等待。
4. 到期重新检查位置、保护、显示意图和窗口世代；满足条件才收起。收起动画中再次靠近也应取消旧布局任务。
5. 收起后面板控件退出 Tab 顺序和可访问树，原面板覆盖的桌面立即恢复输入。
6. 单纯鼠标点击留下的 DOM focus 不永久阻止收起。键盘保护只在实际键盘交互且原生窗口仍持焦点时成立。
7. 触屏点击小条后临时保持展开；点“收至边缘”或原生窗口失焦解除临时保护，不修改保存偏好。
8. 光标读取失败不当作“已离开”；保留安全可见状态，允许明确点击或下一次有效读数恢复。

靠近检测使用一个可停止的原生有界任务作为首选验证方案，初始间隔 75 ms，只读光标与已有几何，不查数据库、不通过高频 JS IPC 轮询。关闭、系统抑制、退出、浮动及保持展开时不运行靠近检测；自动收起模式展开时只保留必要的离开判定。先测量再决定是否需要其他原生机制，不引入常驻全局输入 hook。

### 3.4 拖动、吸附与浮动

- 标题栏空白和小条是拖动区。按下移动达到 4 逻辑像素再认定拖动；按钮、菜单、内容选择不启动拖动。
- 拖动开始取消自动收起。小条拖出时形成完整面板并保持抓取点连续；每次 moved 不写数据库、不立即吸附。
- 释放时优先使用实际释放点选目标屏；缺失时根据实际原生窗口矩形回退。按目标屏 DPI 计算尺寸与距离。
- 阈值内吸附到最近的顶 / 左 / 右边；阈值外停在释放位置并进入浮动，不按左右半屏强制归边。
- 停靠后鼠标仍在面板内就保持展开，离开后按 450 ms 规则收起。浮动不因失焦、离开或工具完成而隐藏。
- 位置菜单提供顶部 / 左侧 / 右侧 / 浮动，与拖动使用同一转换。选择浮动恢复最近浮动位置，没有历史则放在当前工作区中央。
- 成功接受拖动结果后保存 mini 位置。保存失败保留本次位置并提示未保存，不改 widget 位置，也不宣称重启能恢复。
- 取消拖动、失去捕获、关闭或拔屏都要释放保护；拖动结束产生的 click 不再次触发窗口按钮。

### 3.5 窗口操作与恢复

| 操作 / 事件 | 结果 |
| --- | --- |
| 小条鼠标点击 | 展开；之后仍执行离开规则 |
| 标题栏入口键盘打开 | 展开并聚焦第一个有效窗口操作；无需先找到屏幕边缘的小条 |
| 保持展开 | 开启后停靠不自动收起；关闭后等指针离开再收起；保存失败还原勾选并提示 |
| 收至边缘 | 停靠时收成小条；浮动时回到最近停靠位置，缺省顶部；关闭保持展开，保存失败不显示虚假成功 |
| Escape | 先关闭最上层菜单并返回触发器；无菜单时仅自动收起的停靠窗收起；浮动 / 保持展开不改位置或偏好 |
| 关闭 / Alt+F4 | 仅关闭 mini；不影响 main、widget、记录和工具 |
| 同屏全屏 | 暂时抑制 mini 与靠近检测；异屏全屏不抑制；退出全屏仅在 mini 显示意图仍有效时恢复，不抢焦点 |
| 锁屏 / 睡眠恢复 | 重新读取显示器、DPI、光标及业务快照，清理旧菜单 / 拖动 / 等待，不补放旧动画 |
| 拔屏 / DPI / 工作区变化 | 匹配 mini 保存的显示器，失效时回到可用主显示器并夹取坐标，支持负坐标与上下排列 |
| 完全关闭后重开 | 复用或重建一个 mini，重新订阅并读取最新快照；旧销毁任务不能关闭新实例 |

全屏恢复时，自动收起的停靠位置恢复小条；浮动 / 保持展开恢复面板。点击标题栏入口属于明确唤出，不因保存的自动收起偏好而只闪一下小条。第一版窗口置顶采用现有挂件的产品口径，但由 mini 自己的原生窗口执行；“保持展开”不等于置顶设置。

### 4.1 接线与新增职责

### 4.2 数据共用，窗口状态隔离

mini 的最终位置、展开状态和系统抑制由原生 owner 统一决定。前端提交意图并消费带窗口世代 / 修订的已应用状态，只管理视图暂态；两边不能竞争最终 bounds。widget 继续使用自己的现有 owner，不将 mini 状态机移入旧 controller。

只读数据复用已有 bootstrap、图标、tracking / tool 投影的实际实现，不另建 tracker、工具引擎或统计查询。若现有读取返回 widget 的 pinned 字段，mini 不采用该字段作为自己的展开偏好。需要共用纯格式化时选择最小提取，保持旧调用结果不变；不要为复用外观创建通用窗口平台。

mini 仅获得明确的读取命令、自身布局 / 偏好命令和必要的打开主窗口能力。不能直接复用整个 `widget-window-commands` 集合，因为其中包含改变旧挂件位置和展开状态的动作。mini 不允许写追踪暂停、修改工具、读写通用设置、调用 SQL、备份恢复、凭据或更新安装；widget 也不应能修改 mini。

所有新事件有明确 mini 目标或命名空间，所有延迟任务绑定 mini 生命周期世代。窗口关闭、重建、布局失败和持久化失败分别处理，不能广播“已成功”来掩盖原生失败。

### 4.3 资源与偏好

- 同时只有一个 mini 原生窗口。小条是该窗口的收起几何，不另建一层透明覆盖窗或第二个抓手窗口。
- 小条仍可操作，不当作完全隐藏销毁；停止内容秒级重绘与不必要刷新。没有今日统计，自然不新增汇总查询。
- 完全关闭后停止 mini 的靠近检测、显示时钟与非必要订阅；若沿用 park 后回收思路，使用独立世代，保留即刻重开的体验。
- 主窗口、widget 和 mini 的创建、释放、订阅计数分开观察；不能为运行 mini 强制保留主窗口页面缓存。
- mini 偏好保存归一化位置和显示器亲和信息。缺失、坏值、越界、显示器不存在均安全回退；读取错误不静默覆盖原值。
- 备份没有 mini 字段时使用默认值。通过已有通用设置备份路径承接新增偏好，不新增迁移旧挂件格式的工作。

### 4.4 挂件保留与未来退出条件

用户已明确要求挂件先保留，因此本阶段存在两种独立桌面表面：widget 服务原最小化流程，mini 服务新标题栏入口。它们共用业务事实，但窗口控制不相互转发。这是有明确用途和阶段边界的并行期。

未来由维护者在 mini 核心交互、内容完整性、恢复和资源成本验收后，单独决定是否将原挂件入口迁到 mini。届时再安排偏好迁移、用户说明、旧权限 / 命令 / 样式 / 测试清理。当前不自动启动拆除，不以“剩余挂件代码未删除”为本阶段未完成的理由。

记录控制、工具控制、今日汇总同样留作后续独立范围，不作为 mini 完善或拆除挂件的默认必要条件。
