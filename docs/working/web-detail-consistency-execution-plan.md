## 1. 从第一性原理定义问题

### 1.1 用户要验证的是同一份时间

总览回答“这个网站在指定范围内用了多久”；详情回答“这些时间由哪些活动组成”。两者可以有不同布局和筛选，但必须能从同一份有效记录推导，差额应能由范围、筛选或显示精度解释。

记录是否真实、什么时候应停止，由前置计时方案负责。本文接收已经确定有效起止时刻的事实，不能在详情里再判断 AFK、暂停或浏览器资格，也不能用浏览器总量截断网页数字。

### 1.2 四个不同的量

| 名称 | 定义 | 允许怎样变化 |
| --- | --- | --- |
| 有效时长 | 确定范围、来源、身份和截止后，实际有效区间的长度 | 随源事实或统计范围变化，不能因显示分组阈值改变 |
| 活动跨度 | 一个分组最早起点到最晚终点 | 可以包含空档，因此可能大于有效时长 |
| 可见时长 | 当前视窗内通过最短时长筛选的活动有效时长之和 | 随视窗和筛选变化，不能覆盖全天真实总量 |
| 显示字符串 | 有效时长经过秒、分钟或小时格式化后的文本 | 允许损失显示精度，不能被反向解析用于统计 |

例如 09:36–09:48 的跨度是 12 分钟，其中两次活动各 4 分钟、相隔 4 分钟，有效时长就是 8 分钟。分组可以保留，但界面不能暗示用户连续使用了 12 分钟。

### 1.3 必须成立的不变量

先固定比较上下文 `C = 日期/时区、时间范围、域名身份、数据来源、纳入规则、事实版本、有效截止`。对上下文内确认属于同一计量集合的区间使用 `[start,end)`：

```text
裁剪后有效区间集合 = clip(输入事实, 范围, 已确定的有效截止)
T_all = 该集合按已确定去重规则计算的有效总时长
T_visible = 通过详情筛选的活动有效时长之和
T_hidden = 当前范围内被筛选隐藏的有效时长
T_visible + T_hidden = T_all
未筛选详情总量 = 相同上下文的总览总量
分组前有效总量 = 分组后有效总量
```

重叠处理先确定身份和来源，不能跨设备、不同来源或不同浏览器仅凭时间相交就删除记录。对同一计量集合内已判定需要去重的重叠计算并集；不同标题的归属采用明确、稳定的规则，且保留源记录追溯。原始数据库不因读侧去重而被改写。

显示取整不满足可加性：`format(a) + format(b)` 不等于 `format(a+b)`。验收比较毫秒值，用户需要核对时提供准确时长和被隐藏量，不要求通过分摊或篡改每行分钟数让文本强行相加一致。

## 2. 已有证据与待确认项

### 2.1 已确认的代码路径

以下路径相对仓库根目录，均已只读核对：

| 路径 | 当前行为 | 本文关注点 |
| --- | --- | --- |
| `src/features/history/services/historyWebActivityViewModel.ts::buildWebDomainDistribution` | 按域名累加裁剪后的每个网页片段，无详情最短时长筛选 | 总览与详情的纳入集合及重叠处理必须一致 |

## 3. 范围、顺序与交接

### 3.1 纳入

- 固定网页事实在 History 总览、网页详情、详情时间轴和标题明细中的计算一致性。
- 同计量集合的重叠去重、小空档处理、分组、视窗裁剪和最短时长筛选。
- 总量、可见量、隐藏量、活动跨度和准确时长的可解释显示。
- History 和详情的日期、快照截止、刷新失效与旧请求覆盖问题。
- Data 同域名明细入口及相关读模型核对；存在相同口径差异时在原 owner 最小修复。
- 共用详情处理函数对应用详情的必要回归，避免网页修复破坏应用标题明细。

### 3.2 排除

- 应用/网页采集、浏览器身份、AFK、暂停、电源和崩溃恢复算法；归前置计时方案。
- 轻量工具全部排除，包括工具计时、累计、提醒和到期行为。
- 数据库清洗、旧记录回填、迁移、协议升级、兼容层、双读双写或新通用计时框架。
- 无关全局格式化重写、重新设计整页视觉或新增导航。
- 远程发布、提交、推送、Issue 操作；Project 协作独立按维护规则执行。

### 3.3 实施前置和交接

- [ ] 确认计时准确性方案完成其适用实现、验证与源事实交付，再开始本方案代码实施。
- [ ] 接收封闭区间、开放片段有效截止、归属语义及事实变更通知，不要求上游为了本文新增 schema 或协议。
- [ ] 记录上游修复后的代码基线，重新核对本文旧实现证据是否仍适用。
- [ ] 保留源记录有误和读模型有误的分别归因；上游回归回到准确性 owner，不在详情补一套追踪规则。
- [ ] 计时方案无需等待本方案的 UI 修复才能完成，双方以源事实接口交接，避免循环依赖。

## 4. Owner 与最小实现原则

| 能力 | 优先检查的 owner | 约束 |
| --- | --- | --- |
| 网页总览区间汇总 | `history/services/historyWebActivityViewModel.ts`；Data 对应 read model | 不逐行重复累计已确定应去重的重叠，不受详情显示阈值影响 |
| 详情记录与活动分组 | `destination/services/destinationDetailReadModel.ts` | 源有效区间保留空档，活动组只提供成员关系与跨度 |
| 视窗裁剪 | `destination/services/destinationDetailTimelineViewport.ts` | 列表和时间轴使用同一视窗、同一有效时长，不按外包络补空档 |
| 展示与筛选 | `DestinationDetailDialog.tsx`、`DestinationDetailRecords.tsx`、`DestinationDetailTimeline.tsx` | 准确区分总量与可见量；保持 Quiet Pro 和键盘交互 |
| 偏好 | `destinationDetailPreferenceStorage.ts` | 优先复用现有键和语义，不为新增可见选项创建版本化兼容链 |
| 格式化 | 详情原 owner；已有 `durationFormatting.ts` 仅在必要范围复用 | 不改变全产品格式化规则来修复局部对账体验 |
| 快照与刷新 | History runtime 和 `useDestinationDetail.ts` | 读取上下文一致，旧请求不能覆盖新上下文 |

上表中简写路径位于 `src/features/`。跨 feature 的纯区间规则若确需统一，先审查现有 `shared/lib/webActivityTimelineCompiler.ts` 和相关 interval 能力的职责；一个函数抽取必须有稳定共享语义及至少两个真实消费者。优先原 owner 最小修改，不因两处代码相似就建立新 shared 层。

### 阶段一：冻结有效区间与分组契约

退出条件：归属、重叠、空档、分组和裁剪均有唯一的可测试解释。

- [ ] 从计时方案读取有效截止，不在详情重新推测未结束片段可以增长多久。
- [ ] 定义同一计量集合的身份键与来源政策，核对同域名跨浏览器/设备/导入来源是否应分别计算；不擅自抹平来源。
- [ ] 同集合重叠按并集计量；不同标题发生重叠时，冻结稳定优先规则和追溯信息，不依赖数组偶然顺序。
- [ ] 定义“有效区间列表”和“活动分组包络”的区别：分组跨度可跨空档，时长必须来自成员区间。
- [ ] 决定同标题小空档的呈现方式，推荐保留两个真实区间、仅在展示组内归并；禁止通过延长 endTime 补出时长。
- [ ] 明确跨其他域名的片段不得只因最后筛到同域名而被伪装成连续访问。
- [ ] 固定处理顺序：校验上下文→裁剪有效事实→按身份去重→活动分组→视窗裁剪→最短时长筛选→格式化。
- [ ] 说明全天总量和视窗总量的区别，不能拿缩放后的详情之和对比全天值而不标识范围。
- [ ] 记录精度：统计保持毫秒，时长准确查看可展示到秒；所有显示损失留到最后一步。

### 阶段二：修复读模型，保持事实守恒

退出条件：固定上下文下，分组和阈值调整不能改变未筛选有效总量。

- [ ] 沿真实调用链修改 `normalizeDetailRecords` 的小空档合并：不再把空档加入 duration，并保持标题/URL 的来源追溯。
- [ ] 如继续合并标题展示行，保留可用于视窗重新裁剪的真实子区间；不能只改 duration 而仍用包络二次算时长。
- [ ] 在总览与详情使用一致的同集合重叠处理；先比较现有实现，再决定原 owner 复用方式，避免新增平行算法。
- [ ] 检查重叠被裁掉部分的标题归属、sourceActivityIds、活动数和 titleCount，数字变化须有明确定义。
- [ ] 检查完全重复、包含、相交、相接、无交集及乱序输入，不产生负时长、重复活动或输入顺序依赖。
- [ ] 检查同域名跨日与多浏览器，先按既有来源契约分集合再计量，不把所有区间全局并集。
- [ ] 视窗裁剪对真实子区间逐段处理，位于活动空档内的窗口返回零时长，不画成连续活动。
- [ ] 让详情列表和顶部时间轴使用同一组经过裁剪和过滤的活动，显示阈值不改变全天总量。
- [ ] 对 Data 总量与明细入口执行同一 fixture 对账；若 Rust 聚合有相同差异，明确实际 data owner 后最小修复，不回写原记录。
- [ ] 共用规范化函数如影响应用详情，补充正常会话、标题切换、无标题和空档回归，不改变原生计时规则。
- [ ] 运行 D01–D10 的实际函数测试并记录原始毫秒值，不用截图像素或格式化字符串代替断言。

### 阶段三：让筛选和时长可核对

- [ ] 在实际筛选生效时明确显示隐藏的活动数量/时长或可见量与范围总量，选择最少但足够解释差额的信息。
- [ ] 全天总量只由未筛选事实计算；可见量单独命名，不能随着筛选偷偷改掉“全天”数字。
- [ ] 为用户提供准确时长查看方式，优先局部补充到秒的文本或可聚焦说明，不改全局紧凑格式化惯例。
- [ ] 活动跨度与有效时长存在空档时，使用清楚文案区分；不将时间轴组包络描述为连续使用。
- [ ] 只有数据变化时刷新结果；展开标题、缩放和调整阈值不产生新的追踪记录。
- [ ] 复用 Quiet Pro 现有控件、排版与语义 token，覆盖默认、悬停、焦点、禁用、加载、空态和错误态。

退出条件：同一日期和事实版本上的总览、详情一致，快速切换不会显示错误对象或旧结果。

- [ ] 上游 AFK 回溯或恢复事件触发后，两边读取同一版有效事实；不继续显示回溯前数值。

- [ ] 不把后台心跳频率扩大为每秒全库查询；量测新增重读和计算次数，仅解决已证明的刷新差异。
