# 系统架构

Patina 的活动事实由常驻宿主提交。窗口、操作系统探测和浏览器扩展各有独立的生命周期。改动现有功能时，可从相关数据流找到负责模块；添加能力时查[代码落点](#代码落点)。

## 桌面进程

Patina 是使用 Rust、GPUI 和 SQLite 的 Windows 桌面应用。所有桌面进程运行同一个 `patina.exe`。后台 Patina 持有每个 profile 的写锁、Recorder、托盘、工具与更新服务。主窗口 Patina UI、小窗 Patina Mini 和工具通知共享一个按需启动的窗口进程，通过桌面协议读写状态。最后一个窗口关闭后，窗口进程退出，后台继续采样和调度到期任务。Patina Probe 工作进程负责有时限的原生观察。

Windows 前台观察经过 tracking 决策，在同一事务中提交活动事实和派生状态的修订。窗口通过宿主读取数据并发出操作请求。浏览器扩展经本机协议提供网页观察，有效活动区间由 Recorder 决定。

### 窗口与常驻进程

窗口进程管理负责握手、连接代次、请求编号、在途上限及退出。桌面请求按操作选择并行、串行或排空在途任务，再使用实际窗口身份校验敏感操作。数据库移动或恢复成功后按请求重启宿主。更新交接时，宿主完成收尾并写出退出凭据，安装器才能替换程序。业务操作区分冲突与普通拒绝，协议和客户端保留错误类别，到界面展示时才转成文字。[窗口进程管理](../apps/patina/src/window_process.rs) · [请求分派](../apps/patina/src/requests.rs) · [桌面协议](../crates/desktop-protocol/src/lib.rs)

宿主通过 Recorder 写入采样事实及对应的汇总修订。窗口按可见页面请求具名结果，在 GPUI 实体上保存选择、草稿、焦点和待处理的请求。关闭窗口时这些交互状态可以一起释放。

### 主窗口与 Mini

[主窗口](../apps/patina-ui/src/windows/main/mod.rs)持有页面导航和未保存编辑的确认。[页面实体](../apps/patina-ui/src/features)管理各自的选择、查询与草稿。[宿主客户端](../apps/patina-ui/src/client/mod.rs)按请求编号分派回复，连接结束时通知等待者。工具页用下拉框选择已安装的工具。首次打开优先显示提醒，重开时恢复此 profile 上次选择的已安装工具。Mini 指定的工具优先于保存的选择。面板动作交给常驻工具服务。共享布局、输入、选择控件、键盘焦点、主题与色板归 [QuietPro](../crates/quietpro/src/lib.rs)。

#### Mini 生命周期

[Mini](../apps/patina-ui/src/windows/mini/mod.rs)读取当前活动和工具状态，点击工具时由主窗口导航。拖动标题栏或收起的把手可移动窗口。松开时按指针所在显示器的工作区和缩放判断顶部、左侧或右侧停靠，其余位置保持悬浮。窗口模块负责坐标和贴边裁剪，宿主在拖动结束或切换图钉时保存位置和固定状态。重开时读取同一份资料，包括旧版保存的位置。[窗口几何](../apps/patina-ui/src/windows/mini/geometry.rs) · [原生窗口测试](../apps/patina/tests/today/mini.rs)

### 运行身份与持久化隔离

Windows 按当前用户的 `Run` 项启动 Patina。每份资料的登记名取 `Patina.` 加资料摘要的前十个十六进制字符；宿主核对完整程序路径与资料参数后才修改已有命令。默认资料使用 `--autostart`，显式资料使用 `-a "<资料上级目录>"`。安装完成后的普通启动会迁移相符的旧项，登录启动保留 Windows 正在枚举的清单。[登记与迁移](../apps/patina/src/login.rs)

登录命令读取该资料的自启偏好。开启时按已保存的暂停和静默设置启动，关闭时直接退出。Explorer 暂时不能接收托盘图标时，后台继续持有资料锁、处理窗口唤出并按原设置采样。托盘会限次补试，收到 `TaskbarCreated` 后按最新的图标偏好重新登记。[后台启动](../apps/patina/src/lib.rs) · [托盘生命周期](../apps/patina/src/tray.rs)

开启登录自启时，设置页会核对该资料的 Windows 启动命令和系统禁用状态。原因不明的缺项由用户点「修复启动项」补回。已被 Windows 禁用的启动项可从系统启动设置管理，返回 Patina 后会刷新状态。命令归属冲突或系统状态不可读时，设置页会显示相应提示。[启动项读写](../apps/patina/src/login.rs) · [设置页](../apps/patina-ui/src/features/settings/mod.rs)

新安装的用户资料位于 `%APPDATA%/Patina/`。数据库和备份默认随 Windows 漫游用户配置一起迁移。已设置的自定义数据库目录继续使用原路径。从 v1.10.0 升级时，安装器沿用旧数据库和备份，详见[Windows 安装与更新](release.md#windows-安装与更新)。

启动时优先使用 Roaming 里的桌面配置。以前在 Local 建立的桌面配置可继续原地使用，其中依次查找 `Patina`、`Patina.Desktop` 和早期开发版目录。开发启动器默认使用 `%LOCALAPPDATA%/Patina.Dev/Patina/`，自动化测试使用临时目录。`--profile-parent` 或 `PATINA_PROFILE_PARENT` 可将查找范围限定在指定的绝对父目录。桌面入口按规范化后的资料路径建立单实例身份。

Windows 任务管理器展开 Patina 组时，子进程使用公共文件描述 `Patina`。在「详细信息」页启用「命令行」列可识别角色。后台没有 `--role` 参数，窗口进程带 `--role "Patina UI"`，探测进程带 `--role "Patina Probe"` 和探测类型。主窗口和 Mini 同时打开时共用同一个 PID。

### Windows 探测

[Windows 适配](../crates/windows-integration/src/lib.rs)提供前台观察、图标、系统凭据、Job 和平台时钟。窗口输入与焦点留在窗口进程，活动规则接收时钟和采样事实。

#### 原生探测的隔离与回收

不可可靠取消的 Windows 前台、名称、图标、媒体和音频探测各自在独立的 [Patina Probe 工作进程](../crates/windows-integration/src/windows/native_probe.rs) 中运行。录制宿主按需从自身映像直接启动各工作进程，命令行中的探测类型标明其职责。

每个工作进程与宿主通过独立的匿名管道直接通信。宿主校验协议版本、产品版本、帧长度和响应序号，工作进程只接受所属通道的请求。宿主用单独的 Windows Job 回收超时通道。只有确认旧进程及通信线程结束后，才允许替换该工作进程。

helper 的存活由现有诊断观察线程通过该世代持有的进程句柄非等待检查，不获取请求通道的准入锁，也不新增轮询线程。进程仍存活时不读取异常记录或访问请求发送器。确认退出后，进程 owner 保存唯一退出事实并关闭发送器，使空闲通信线程能够结束；只有仍为当前世代的观察器才能清除当前 PID 与上次响应缓存、发布退出计数，晚到的旧观察不能覆盖替代进程。退出码、创建 / 退出 FILETIME、已取得的清理耗时及历史异常分别保留，未知耗时不记零。下一次请求先确认旧进程和通信线程已回收，再创建新世代；已经发送的失败请求不自动重放。退出码与本进程是否请求过终止属于观察事实，不能单独确定故障 API 或外部终止来源。

#### 原生异常证据

helper 的未处理异常使用预留的固定大小共享记录保存异常码、参数、指令 / 栈指针、线程和请求阶段；所属映像查询为尽力补充。记录器不恢复异常，不在异常线程写文件或格式化数据。持有探测通道的调用方确认工作进程退出后读取记录，将最近一次已记录异常或非主动失败退出与最近退出分开保留。异常记录已写入后发生的超时清理不能抹掉该事实。强制终止、快速失败、损坏的异常栈或被替换的处理器可能没有上下文，缺少记录不等于没有崩溃。共享记录随进程结束由系统回收，不能在管道线程返回时与其他线程的异常处理竞争释放。

#### 名称、图标与音频资源

名称 / 图标 helper 只缓存有界字符串。Shell 缓存未命中的 COM 调用使用同一 `native_probe` 协议、Job 和回收 owner 启动一次性 Shell 子进程；响应须在子进程正常退出且通信线程结束后才可交付，失败或超时沿现有隔离与冷却边界处理。父 Job 仍覆盖实际 Shell 子进程，无法确认回收时不再创建新进程。此边界回收 Shell 工作线程及进程内系统组件保留的资源，不声称应用能直接释放系统组件内部的 COM 代理。

音频 helper 在 MTA 中持有当前设备的会话管理器。注册新会话通知后只进行一次初始枚举，按原生会话实例身份合并通知，每次查询读取当前状态并释放已过期会话。通知队列与持有的会话集合均有上限；溢出、设备变化或原生读取失败使整个集合失效，下次请求重建，不能把不完整集合报告为成功。回调只入队或标记失效，不在回调内注销；注销通知并释放接口后才结束 apartment。

#### 诊断边界

[录制运行快照](../crates/activity/src/engine/tracking/runtime_snapshot.rs)保存采样和提交进度，探测子进程另行记录退出和原生异常。用快照定位停顿阶段，判断具体系统调用的故障仍需要相应的原生证据。

## 活动与持久化

### 录制与活动资格

[追踪引擎](../crates/activity/src/engine/tracking)统一决定应用的有效活动区间，协调转换、暂停、排除、电源、watchdog 和恢复边界。转换失败不得推进已提交状态；失效资格必须先反映到快照，旧采样、请求和持续参与状态不得跨停止边界复用。中断恢复使用最后成功采样，普通心跳不证明活动；证据缺失或无效时以会话起点结束，不补记停机时间。

会话事实提交后才调度名称和图标补全，采样与转换不等待可选元数据。名称结果绑定原连接池、会话 ID、exe、开始时间和恢复世代，只回填仍为空的名称；已删除记录不复活，已取得名称不覆盖。未知名称可用 exe 生成展示标签，正式名称过滤不消费该回退值。过载或探测失败可以留下未知名称，不能因此延迟记录、改写应用身份或绕过隐私规则。

采样、提交和展示进度分别观察；普通心跳与旧前台回退不计为成功采样。tracker panic 后保持停止并报告，不能在尚未对账已交给 SQLite 工作线程的操作时启动另一个写侧。

`engine/web_activity` 根据原生追踪资格处理网页观察，跨仓契约见 [Web Activity 协议](./web-sync-protocol.md)。详情只消费有效事实；轻量工具由自己的 owner 决定时间语义。

匿名活动由 `data/repositories/anonymous_activity.rs` 保存独立 UUID、时间边界与网页子集标记，不保存具名外键或身份。具名封口与匿名开始共享事务；暂停、空闲和恢复沿用追踪边界。匿名心跳只推进有效观察，关闭区间进入既有小时投影脏区维护。读侧使用 `activity:anonymous` 作为派生展示键，不能把该键当作可配置应用、域名或图标查询目标。备份合并按 UUID 幂等，恢复追踪不反向识别匿名事实；身份删除不触碰匿名时间，按时间清理与全量清理覆盖匿名记录。

新增事实表通过追加迁移进入现有库，不回填过去的排除空白。新版恢复不含匿名集合的历史 SQLite 快照时，匿名集合为空。旧程序不能被视为新 schema 的安全写入器；回退须使用升级前备份与对应版本的正式恢复路径，不能直接让旧程序续写升级后的数据库。

### 本地数据读取通道

[后台入口](../apps/patina/src/lib.rs) 持有资料写锁、Tokio 运行时和 SQLite 连接池。[录制器](../crates/activity/src/recording/desktop.rs) 启停采样并按最后成功采样时间封口。托盘只持有录制控制句柄。历史与统计使用 `ActivityQueries`，分类使用 `Classification`。两者可直接接入已经打开的连接池。桌面请求将历史、趋势、今日、近期和图标读取提交到既有 Tokio 工作线程，Windows 消息线程继续处理托盘与窗口事件。当前前台活动和最后采样时间由录制控制句柄提供。[活动查询](../crates/activity/src/recording/queries.rs) · [分类操作](../crates/activity/src/recording/classification.rs)

#### 活动派生状态与应用关联

跨启动、可重建的活动派生状态由 Rust `data/activity_read_model/*` 持有：

- `recorded_app_catalog` 提供完整应用目录、搜索和 keyset 分页
- `activity_hourly_effective` 提供 Dashboard、History 汇总区和 Data 所需的有效活动聚合
- revision、state 与 dirty 表和事实写入处于同一 SQLite 事务边界
- 后台维护可以分批重建；状态不可信、范围脏或存在活动会话时，读取在同一快照内按范围回退到事实
- History 精确时间线不由小时汇总伪造，仍读取事实和标题样本
- 数据库覆盖恢复后先让派生状态失效，再由后台幂等重建

小时投影在来源优先级确定后按小时和应用归并原生片段，导入仍保留必要的批次身份。原生重叠时长可以累计超过一小时，存储分行不能钳制总量。非整小时边界先读取完整小时的占用事实、完成来源分配，再精确裁剪；不能由汇总时长按比例推算局部分布。

页面通过活动查询读取活动事实和汇总，展示时应用分类与别名。可编辑规则单独持久化。

应用关联使用独立的成员到主程序设置，不修改 canonical executable 或原始会话。活动查询在分类统计中解析归属。配置 repository 在同一事务中检查预期旧归属与最终完整关系，拒绝自身关联、嵌套和循环。来源优先级、时间裁剪与原程序排除先于归属聚合，精确明细保留原程序边界。备份恢复验证合并后的完整关系。

存储页按时间清理活动记录，保留应用和网站的用户配置。记录删除事务只检查本次涉及的对象。仍有活动记录、已保存的关联、分类配置或使用提醒引用时保留图标，否则一并移除数据库中的图标缓存。

#### 存储位置与启动控制状态

启动时按 profile 解析数据库，位置与待执行的迁移写入该 profile 的 database-location.json。选择目标、校验、分阶段迁移及中断恢复由[原生设置与存储](#原生设置与存储)管理。备份恢复沿用当前机器的存储位置。

#### 网页关联与历史清理

[网页域名规则](../crates/activity-model/src/web_links.rs)使用锁定的公共后缀数据解析可注册主域名，包含私有托管后缀。缺省自动归组，完整域名例外优先；IP、本地主机及未知后缀不猜测归属。组目标带独立类型和无前缀域名，在字符串索引中序列化为对象，与实际根域名互不覆盖。版本 2 规则仅保存独立例外及组展示设置；分类事务保留预期旧值检查、幂等重放及冲突拒绝。后缀数据随依赖升级，升级需复测租户边界，不在运行时联网获取规则。

`data/repositories/web_links.rs` 在同一数据库快照中提供规则、原域名设置、主域名映射、全历史时长及图标，范围读取同时返回原始事实；聚合修订包含规则快照摘要。分类页消费该映射。图标使用具名且允许记录的成员，同源重叠区间去重，时长相同时按完整域名排序。原域名匿名策略先于展示归属，精确明细和导出保留原始身份。

启动及备份恢复共用事务迁移：旧手动关系和组展示设置存入 `__web_grouping_backup_v2` 恢复副本后移除，原始域名设置及事实不变；更早自动格式中的明确例外转换为版本 2。分类承接使用一次性事务标记：尚无新版规则的组继承组内累计使用时长最长域名的分类，时长相同按完整域名排序，最长域名未分类时不猜测分类；既有新版规则与独立例外优先。分类迁移与关系转换共用入口及事务，不依赖安装版本号；后续用户清除分类不会在重启时恢复。合并恢复优先保留目标库已有新规则，未知格式拒绝并回滚。恢复副本保留原规则 JSON，可用于人工恢复旧配置；新版本不双写旧格式，也不承诺旧版本可读取新配置。

分类页的垃圾桶删除所选对象的历史、专属配置和图标。确认框列出受影响的程序或域名、需要解除的关联、要删除的专属提醒，以及因其他应用共用而保留的同名提醒。删除主程序会解除与成员的关联，保留成员自身的数据。删除网站组会保留独立例外及其数据，删除单个独立域名只移除它自己的例外设置。提交时在同一事务内重新核对确认范围，范围改变需重新确认。匿名活动独立存储。刷新、重启与升级不能恢复已删记录。允许记录的域名再次产生真实活动时可以重新显示；主动恢复含历史的备份仍按恢复契约处理。

#### 读取与备份边界

活动查询和写入操作各自拥有 SQL、参数绑定和事务。页面消费具名的查询结果，负责展示格式、图表组合与时间线几何。精确会话与标题须在同一读取快照中取得。

#### 备份与恢复

备份与恢复沿用同一 owner 规则：

- SQLite 快照容器、manifest、摘要、格式识别和恢复编排归 `data/backup/*`
- [存储层](../crates/storage/src/lib.rs)负责数据库文件切换、WAL checkpoint、连接池重开和位置迁移的中断恢复
- 合并去重由各数据域 repository 持有，不能把表级 SQL 上提到 命令分派、宿主入口或窗口
- 原生存储服务协调备份、恢复及运行中任务。
- 恢复只接受 SQLite 数据快照；旧结构化 JSON ZIP 读取器已退役。源文件身份、容器和候选库校验先于恢复引起的计时封口，执行消费同一准备副本。历史 SQLite 快照仍按受支持的 migration 契约升级
- 合并恢复按快照导出时刻结算运行中的自由专注和番茄时钟，导入的任务保持暂停，目标库的活动任务继续运行。定时提醒以持久化身份判重，已推进、改名或暂停的目标提醒保留当前状态。缺少该身份的旧快照按源数据库摘要和源行号识别重复导入；不同旧快照里的提醒可能重复，优先保留无法确认同源的记录。
- WebDAV 下载先校验归档；索引含归档摘要时，下载文件还须匹配该摘要才能进入恢复确认。旧条目和手动备份可沿用无摘要的预览校验。
- WebDAV 仅将明确声明当前格式的有效索引条目提供给恢复操作；未知条目及额外字段原样保留。上传与轮换不能用过滤后的列表覆盖完整索引，也不能删除被其他条目引用的对象
- 自动备份的时间声明、重试与调和决策归备份专用 `engine/backup_scheduler.rs`；目标执行、运行账本和保留策略分别归 `data/scheduled_backup/` 与其 repository，不为未来定时导出提前建立通用任务框架
- WebDAV 自动备份只有在本地快照校验、不可覆盖上传、远端全量回读校验和索引发布全部完成后才可记为成功；旧自动对象必须在新备份成立后，凭精确路径、来源、目标身份与 ETag 等所有权证据清理，证据不足时保留对象并记录警告

#### WebDAV 凭据与跨资源保存

- WebDAV 地址、用户名和远端目录可作为非秘密配置持久化；密码不得进入 SQLite、事件载荷、远端索引或日志。返回密码的请求限于主窗口用户明确点击“显示密码”触发的 `DavReveal`：handler 必须执行真实窗口 caller guard，窗口不得在打开弹窗时预取，隐藏或关闭弹窗后必须清除已读取的明文预览；mini 和其他窗口不得获得该命令
- WebDAV 配置保存由 [远程备份配置](../crates/activity/src/data/remote_backup_config/core.rs) 协调。完整校验后先创建不可变候选凭据，SQLite 事务原子提交配置、凭据引用和保存标识，再清理旧凭据。[Windows 凭据存储](../crates/windows-integration/src/credentials/store.rs) 在 profile 私有目录记录不含秘密的归属凭证；凭据只按本机归属和配置身份读取。保存、删除和网络快照取得共用锁，网络请求持有已取得的完整配对；清理失败不改变已提交结果，可在后续读取中重试。备份不授予本机凭据访问权：覆盖恢复解绑，合并保留已有配对或将新增配置标为待配置。旧凭据只为无引用的现存配置读取，首次保存转换后退役；回退到不支持引用协议的旧程序需要重新配置密码

#### 追踪快照一致性

- main、mini 的 tracking 快照同时携带暂停标志、窗口与运行状态，读取与暂停 / 恢复共用 transition 锁。每个窗口在其快照更新中共用请求序号，只接受最新请求；失败保留最后有效值。订阅先于首次读取，卸载使未完成请求失效；其他设置更新不能覆盖已接受的暂停状态

#### 自动任务的共享边界

- 自动导出的日历周期、到期槽位、补跑与重试决策归导出专用 `engine/export_scheduler.rs`；配置与运行账本归 `data/repositories/scheduled_export.rs`，文件生成、格式校验、不可覆盖发布和崩溃对账归 `data/scheduled_export/`，不得与自动备份合并成通用任务框架
- [存储服务](../crates/activity/src/recording/storage.rs)定期唤醒已配置的备份和导出任务。各任务管理自己的配置、运行账本、重试和数据动作。

### 数据库与恢复

活动查询、表级变更及备份合并属于 `crates/activity/src/data`。SQLite 连接池、迁移、文件位置和可恢复切换属于 `crates/storage`。窗口只通过具名协议请求读取或写入。

`data/repositories/web_activity` 维护网页事实及其原生会话关联 `web_activity_native_sessions`，不推测关联旧历史。原生结束与关联网页裁剪、网页停用与当前网页结束，均须原子提交并更新修订。删除原生记录只清除关联，网页历史仍由其清理入口管理。

备份恢复使用归档自身的采样和观察证据结束开放活动，并映射会话身份；不得借用目标库心跳延长归档记录，也不得复用恢复前的活动资格。

### 原生设置与存储

[常驻设置用例](../apps/patina/src/requests/settings.rs) 核对原设置，依次变更登录项、托盘可见性并提交偏好。失败时恢复已应用的系统效果，同时保留补偿失败的诊断。[设置窗口](../apps/patina-ui/src/features/settings/mod.rs) 拥有主题和语言预览，取消或离开页面时还原未保存的预览。[存储界面](../apps/patina-ui/src/features/settings/storage.rs) 拥有导出、导入、备份、恢复和定时配置弹窗；[存储服务](../crates/activity/src/recording/storage.rs) 复用共享数据协议与事务，持久保存按格式区分的导出偏好。

原生数据目录迁移在所选目录下使用 `Patina` 子目录，所选目录本身已名为 `Patina` 时直接使用它。数据库和本地备份在重启时一起迁移；[迁移实现](../crates/storage/src/location/migration.rs) 拒绝覆盖已有目标，用暂存目录确认发布归属，持久保存新位置后才清理已确认复制的源文件。共享的数据库、导入导出和备份模块仍由活动数据及存储模块维护。

## 协议与外部能力

### 浏览器扩展伴生边界

`Patina Web Sync` 浏览器扩展是 `Patina` 的外部 companion，不属于主仓库内的桌面页面、常驻宿主 或发布产物。

边界规则如下：

- `Patina` 拥有本机 HTTP 接收端、token 校验、网页活动写入、备份恢复、清理历史、History / Classification 读模型和 Settings 配置说明
- `Patina Web Sync` 独立仓库拥有 Chromium / Firefox 扩展源码、manifest 版本、商店素材、三店提交、AMO 公开 listed XPI 和扩展 release asset
- 两者通过 [`web-sync-protocol.md`](./web-sync-protocol.md) 定义的本机协议协作
- 不把浏览器扩展源码、构建脚本或商店发布流程重新放回 `Patina` 主仓库
- 不为了扩展分发把 `Patina` 主应用发布流程重新绑定到扩展版本号

### 命名与跨层协议

Rust 模块、函数与字段使用 snake_case，类型使用 PascalCase。数据库、备份格式、宿主消息和独立发布的 Web Sync 协议各自维护兼容边界。协议字段的序列化名称与既有数据保持兼容。

活动（activity）是被记录的应用或网页使用情况。采样（sample）是一次观察，录制器（Recorder）按跟踪规则把连续使用归入活动会话（session）。历史页面按日期读取并展示记录（record）。涉及 Windows 登录会话或测试桌面时，在名称中标明所属上下文。

工具（tool）是用户在工具页选择的功能。插件（plugin）是交付该功能的可安装包，插件宿主负责校验、加载和执行。桌面窗口通过 `WindowRequest` 提交读取或修改操作，宿主以 `Reply` 返回结果。窗口关闭等已经发生的事实以事件表达。

### 工具插件

主窗口在「分类」与「设置」之间提供「工具」入口。窗口负责绘制插件声明的面板、收集表单值和呈现安装确认。常驻宿主登记插件身份、运行 Wasm、调度到期任务并保存状态。关闭最后一个窗口后，已有计时继续推进。Mini 与主窗口读取同一份计时和提醒投影，点击状态时由主窗口完成导航和未保存编辑确认。[主窗口](../apps/patina-ui/src/windows/main/mod.rs) · [常驻工具服务](../apps/patina/src/tool_service.rs)

插件运行时依赖 SDK 中的包、安装和 guest 契约。API 3 插件用嵌套的行、列和网格声明页面与字段弹层，决定控件顺序、间距和对齐。API 4 插件可通过 `selected_tab` 指定当前标签，收到 `SelectTab` 事件后把标签 ID 存入自己的状态。API 5 提供活动目标选择器。具有提醒能力的插件可接收用户选定的目标类型、标识和显示名称，候选目录和搜索文字由窗口管理。API 6 支持用字段权重按比例分配行内剩余宽度。窗口按声明绘制 Quiet Pro 组件，兼容 API 2 的模板页面和 API 1 的顺序面板。插件在清单中声明任务能力。后台按插件身份绑定任务存储，通知和快捷入口携带所属安装实例。[SDK 页面契约](../crates/plugin-sdk/src/layout.rs) · [SDK 安装契约](../crates/plugin-sdk/src/installation.rs) · [后台绑定](../apps/patina/src/bundled_tools.rs)

插件以普通 ZIP 分发。每个目录包含清单、Wasm 和发布者签名，以及可选的语言资源。宿主校验资源范围、包摘要和 API 版本，并在安装前列出所需能力。每个 ID 只有一个安装目录。同一发布者更新该 ID 时继承任务和状态，完全相同的内容沿用原实例。每个插件都使用 Ed25519 签名，更新须通过原公钥校验。插件只能通过声明的能力访问自己的任务。[包校验与运行时](../crates/plugin-host/src/lib.rs) · [插件作者指南](../plugins/counter/README.md)

首次启动默认安装提醒和专注。两者与后来安装的插件使用相同的 SDK、能力和卸载流程。用户从 ZIP 安装的版本在重启后继续使用。卸载只清理该插件的任务、历史、计时、通知和私有状态，并记住卸载选择。相同能力的多个插件可以同时工作，旧版提醒和专注沿用原有的数据库记录与备份身份。[预装插件](../plugins/bundled) · [任务存储](../crates/activity/src/recording/tools.rs) · [通知派发](../apps/patina/src/tool_events.rs)

API 7 插件可声明通知的标题、正文、按钮和延时选项。Patina 负责投递、窗口布局和提示音。用户选择操作后，宿主校验通知所属实例和操作 ID，再交给插件更新任务。[SDK 通知契约](../crates/plugin-sdk/src/notification.rs)

### 桌面更新

[`crates/updater`](../crates/updater/src/lib.rs) 拥有更新清单、版本比较、HTTPS 下载、Minisign 验签和安装交接。常驻宿主持有更新服务，窗口只请求操作并读取状态；关闭窗口或切换导航不会取消下载。[关于页](../apps/patina-ui/src/features/about/mod.rs) 展示版本差异、更新说明、下载进度和失败后的重试与手动下载入口，在下载完成后提供独立安装确认。安装前保存返回页面，新窗口启动时一次性消费该记录。

安装请求由[桌面用例](../apps/patina/src/requests.rs)串行处理，只能执行服务持有并再次验签的安装包。启动安装器后，宿主关闭窗口进程、等待在途请求、停止工具和后台作业、结算录制，再关闭数据库。宿主确认收尾成功后写入退出凭据。[NSIS 安装器](../packaging/windows/patina.nsi)等待宿主退出并检查该凭据，之后替换程序文件。安装器不清理用户数据；包格式、签名与分发规则见[发布规范](release.md#windows-安装与更新)。

### 共享与兼容边界

长期默认是一个能力只有一个当前实现和一个真实 owner。完成替换时，应迁移调用方并删除被替代实现；不得为了降低眼前改动量，长期并排保留“旧实现 + 新实现”。

源码名称必须表达业务语义或边界差异，不表达实现的新旧顺序：

- 不使用 `fooV2`、`foo_v3`、`NewFoo`、`NextFoo`、`FooLatest` 等函数、类型、模块、service 或 command 名称
- 不用 `LegacyFoo`、`CompatFoo` 把临时兼容逻辑伪装成长期 owner；确实读取旧格式时，名称必须指向具体边界，例如冻结的备份格式 reader，并附带退出条件
- 两种行为确实需要同时存在时，按领域语义命名，例如按来源、策略、格式或能力区分，而不是按 `V1 / V2` 区分
- 版本号只用于真正被版本化的外部或持久化事实，例如发布版本、协议版本、备份格式、数据库 schema 和 migration；不得用这些必要版本事实为普通实现并行化提供借口

默认不新增兼容壳、转发层或历史适配层。只有已发布数据、外部协议、跨版本升级或仍在支持窗口内的真实调用方要求兼容时，才允许例外存在，并且必须满足：

- 它确实在服务兼容或平滑迁移
- 它不承接新的厚逻辑
- 它有明确 owner
- 它有可验证的退出条件和删除时机
- 它不会重新把边界变模糊，也不会形成 `V1 -> V2 -> V3` 转发链

如果一个“临时例外”开始承接新功能，它就不再是例外，而是在制造新的遗留层。

### 本地化

本地化的人工源、生成边界、桌面页面与 Rust 消息运行时的职责统一由 [`localization.md`](./localization.md) 定义。架构层只要求 locale 作为显示派生和缓存的显式输入，语言无关 read model 不携带本地化字符串，generated 文件不成为人工 owner。
